# 🧩 SPN-087 Remove obsolete layout CSS from Storybook examples

## Story

As the [Owner](../product/personas.md#owner), I want the design examples to stay easy to maintain, so that changing a screen does not unexpectedly break another. Collaborators, Operators and link guests keep the same reviewed layouts and interactions.

## Scenarios

### Keep the accepted layouts while removing old rules

Given the retained production stories, native fixtures and shared controls,
When obsolete rail-plus-sidebar declarations and their later overrides are consolidated,
Then each retained composition and breakpoint has one coherent effective layout,
And light, dark, phone, dark-phone and tablet views retain their appearance and behavior.

### Keep screen changes local

Given Dashboard, Editor, Profile and Administration have separate responsibilities,
When remaining fixture CSS and source are organized into plain modules,
Then retained story IDs, shared controls and persona permissions still work,
And no new framework or speculative abstraction is introduced.
