# 🧩 SPN-087 Remove obsolete styles and unused or disconnected code

## Story

As the [Owner](../product/personas.md#owner), I want obsolete and disconnected code removed, so that maintaining Spinel does not leave confusing paths that can accidentally break it. Collaborator, Operator and Link guest behavior stays intact.

## Scenarios

### Retire only proven unused code

Given production, library, server, script and Storybook entry points,
When obsolete styles, unused exports/assets/modules or disconnected leftover paths are identified,
Then each removal has evidence that no runtime, dynamic registration, build, test or supported operator entry point still needs it,
And retained behavior, persistence, access and diagnostics contracts are unchanged.

### Preserve accepted layouts and fixtures

Given production/native stories and shared controls,
When superseded rail/sidebar CSS and stale examples are consolidated or retired,
Then retained IDs, interactions and light/dark/phone/dark-phone/tablet layouts remain valid.

## Rules

- [Broader cleanup scope](../implementation/SPN-087.md#-unused-and-disconnected-code), owner chat 2026-11-22, expands CSS-only cleanup. Effort L includes a repository-wide usage inventory, dynamic/native entry-point checks, bounded removals and verification. Checkpoint after inventory; split independently useful areas before a broad rewrite and retain every remaining owner/estimate.
- Existing [draft PR #281](https://github.com/mxbaylee/spinel/pull/281) is a useful unmerged CSS/Storybook candidate, not completion of the expanded scope. Integrate it against current main and reassess its retained evidence; preserve unique prior work.
- Recheck the original PR #125 observation at `dc9170f` against current `src/ui/redesign/mockups.css`, retained Controls/native fixtures and production migrations. Do not revive retired Redesign screens or delete shared controls because their historical folder is named redesign.
- Inspect TypeScript imports/exports, lazy modules, SDK/plugin registration, workspace public APIs, scripts/config, stories, CSS selectors and assets. No-reference search alone does not prove dead code. Retain historical/evidence assets and externally consumed entry points unless their retirement is established.
- Follow [sustainable testing](../testing.md), [diagnostic maintenance](../diagnostics.md#emitter-maintenance-inventory) and the [production-story rule](../implementation/storybook-production-migration.md#migrate-stories-with-their-ui-tickets). Preserve diagnostic contracts or explicitly reassess any change.
- Use plain existing modules, with no speculative abstraction or new cleanup framework. Unexplained runtime hangs are defects to investigate separately, not permission to delete the path. SPN-089 retains ownership of SPN-146 diagnostics until its inherited hosted performance gate is met.

## Out of scope

- New UI/features, changed design/permissions/persistence, speculative refactoring, or deleting evidence to reduce repository size. Branding (SPN-150), action consistency (SPN-162) and title cues (SPN-089) keep their own outcomes.

## Verify

- Contract/negative: every proposed removal has entry-point/consumer evidence and retained behavior coverage. Use existing owning unit/integration suites, typecheck, lint and build checks at the lowest meaningful layer; maintain selected source/shared dependencies in CI.
- Reuse deterministic isolated fixtures and their readiness/cleanup; no new broad test matrix. For CSS/story changes run the full existing Storybook interaction suite and before/after captures at all five established variants; retain production/native IDs, font/layout readiness and tablet touch explanations.
- Review actual changed app states plus before/after light/dark/phone captures independently against the playbook (agent review only). Pure nonvisual code removals need focused behavioral evidence, not routine screenshots.
- Preserve the audit, exact source/check identities, negative cases, failures and dispositions; fewer lines/tests alone are not acceptance. Historical retired-mock capture issues do not justify restoring obsolete examples.
