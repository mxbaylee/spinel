# 🛂 SPN-158 Wait for writable admission after restore

## Story

As the [Operator](../product/personas.md#operator), I want the restore crash check to authenticate only after the restored application admits work, so that its result tests acknowledged-write recovery instead of racing a legitimate maintenance pause.

## Scenarios

### A restored application must admit work before authentication

Given the restore decision is durable but the application remains paused,
When its session endpoint returns signed-out and its maintenance endpoint answers,
Then the fixture still waits for application-observed running admission,
And it authenticates once only after that admission and the expected signed-out state are both observed within the existing deadline.

### The acknowledged write survives the intended crash

Given the restored application admits work and the owner authenticates,
When the fixture writes and acknowledges its marker, requests the postcommit cut and sends SIGKILL,
Then reconciliation preserves the selected candidate, acknowledged rows and retained evidence,
And original authorization, failure and orphan-cleanup assertions remain enforced.

## Rules

- Registration only. [The first failure and source-proven readiness gap](../implementation/SPN-158.md#-first-failure-and-proven-readiness-gap) distinguish a postcommit/pre-SIGKILL authentication HTTP 503 from an unproved crash-recovery failure. The historical response body and phase were not retained; do not invent its exact cause. Agent judgment, 2026-11-13.
- Complete **M** scope includes fixture integration, a deterministic admission negative control, safe stage diagnostics, existing authority/persistence/cleanup contracts and actual Linux acceptance. [Scope and all four personas](../implementation/SPN-158.md#-complete-outcome-and-persona-decision). Reassess before expanding into a demonstrated product defect.
- Strengthen the existing single 20-second readiness wait to require application-observed phase `running` and the existing session 401 condition. Do not add a second wait budget, retry an authentication mutation, weaken MaintenanceGate, increase deadlines, skip a case or rerun unchanged failures until green.
- Share the exact readiness probe with the existing maintenance HTTP fixture. A deterministic paused state must expose maintenance HTTP 200 and session 401 while auth-options stays 503 without an auth write; running permits authentication options. Reverting to session-only readiness must fail the control.
- Preserve SPN-157's complete L investigation of its two different supervisor failures. This fixture repair does not complete those scenarios or waive SPN-090's current-head validation. Follow [sustainable testing](../testing.md).

## Out of scope

- General authentication retries, product admission changes, a replacement fixture framework, the two SPN-157 handoff failures, and phone behavior changes.

Keep fixed-category stage/phase diagnostics free of credentials or document contents.
- Readiness/cleanup: retain the single existing deadline, original session/authentication/content assertions and owned-process cleanup; preserve the first failure on timeout or exit. The real Linux postcommit case owns acknowledgement, cut, SIGKILL, reconciliation, exact durable rows and retained-evidence verification.
- Routing/evidence: include the shared restore HTTP helper, crash fixture, maintenance gate/status, application release/resume and supervisor paths in existing CI ownership. Preserve exact source/base/run/attempt and the negative control, actual Linux result and cleanup; no local mock or later green run establishes the unknown historical cause.
