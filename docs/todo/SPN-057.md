# 🛰️ SPN-057 Order and store every edit on Spinel's own sync server

## Story

As the [Operator](../product/personas.md#operator), I want the server to put every co-editor's edits in one order and store them in Spinel's own SQLite tables, so that collaboration runs on code we control, with the same backups, access checks and bounded memory as the rest of the app.

## Scenarios

### Edits get one order

Given two editors send edits based on the same revision,
When the server receives them,
Then it transforms the later one with SPN-056, assigns consecutive revisions, stores both and sends each client what it is missing.

### A revoked editor is stopped

Given an editor's grant, session or guest link is revoked while connected,
When their next edit arrives,
Then it is refused before it is stored or broadcast, as today.

## Rules

- Keep today's boundaries from docs/collaboration.md: the same SQLite file (#37), single-use document-scoped socket tickets, Origin checks, a 500 ms access scan before commits, viewer and Operator refusals, the cross-unit and 10 MiB checks and the denied-edit audit (#49).
- Build the ordering and log as `lib/sync-server/` (AGENTS.md), with storage behind an interface. Spinel's SQLite adapter, sessions and grants stay in `src/server/` and plug into it. Owner, chat 2026-10-19.
- Keep docs/history.md's checkpoints, restore generations and the retryable purge queue (#43) working against the new log. Grooming #92, 2026-10-19.
- Materialize snapshots by applying the log to a headless open-source Univer instance. Keep the eight-unit cache and the idle eviction.
- Behind a server flag, off by default: SPN-059 switches documents over. TypeScript only.

## Out of scope

- The browser client and presence (SPN-058). Migrating existing documents (SPN-059).

## Verify

- Unit: ordering, transform-on-receive, duplicate submission ignored by mutation ID, and every refusal above, ported from `service.test.ts` and `transport.test.ts`.
- A two-socket test client exchanges edits through the real transport and ends with identical snapshots.
