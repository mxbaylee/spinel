# 🛰️ SPN-057 Order and store every edit on Spinel's own sync server

## Story

As the [Operator](../product/personas.md#operator), I want the server to put every co-editor's edits in one durable order, so that collaboration runs on code we control, with the same recovery, access checks and bounded memory as the rest of the app.

## Scenarios

### Edits get one order

Given two editors send edits based on the same revision,
When the server receives them,
Then it transforms the later one with SPN-056, assigns consecutive revisions, durably commits both and sends each client what it is missing,
And it acknowledges a submission only after that commit; retrying its mutation ID returns the same result without a second edit.

### A revoked editor is stopped

Given an editor's grant, session or guest link is revoked while connected,
When their next edit arrives,
Then it is refused before it is stored or broadcast, as today.

## Rules

- Keep today's boundaries from docs/collaboration.md: single-use document-scoped socket tickets, Origin checks, a 500 ms access scan before commits, viewer and Operator refusals, the cross-unit and 10 MiB checks and the denied-edit audit (#49). Preserve authorization and durable edit commit as one safe write boundary, without a revocation race.
- Build the ordering and log as `lib/sync-server/` (AGENTS.md), with storage behind an interface. Application storage, sessions and grants stay in `src/server/` and plug into it. SQLite is the current adapter, not a permanent requirement: before SPN-038, choose one coherent backend if removing Pro makes another simpler. This supersedes #37's same-SQLite-file requirement while retaining its consistency and access guarantees. Do not build multiple adapters speculatively. Owner, chat 2026-10-21.
- Keep docs/history.md's checkpoints, restore generations and the retryable purge queue (#43) working against the new log. Grooming #92, 2026-10-19.
- Materialize snapshots by applying the log to a headless open-source Univer instance. Keep the eight-unit cache and the idle eviction.
- Behind a server flag, off by default: SPN-059 switches documents over. TypeScript only.
- Merge with `lib/sync-transform` (SPN-056): transform each incoming edit past the edits accepted since its revision with `side: 'right'`. Refuse an edit it throws on, logging a `RefusedEditError`'s reason (`'moved-cells'`, a drag or shift and a concurrent edit in its area; `'format-race'`, a number-format change and a concurrent write to its cell that sets no value; or `'growth'`). Owner, chat 2026-10-20. After merging, refuse an edit that would leave a workbook with no sheet or no visible sheet, which no pairwise transform can prevent (lib/sync-transform/README.md).

- Preserve MCP credential expiry/scope/disconnect and account/grant revocation at the final write boundary. Keep exact-revision rejection for stale assistant writes and stable retry identity, rather than transforming them as ordinary edits. Native Formula metadata must survive Doc mutations and materialization (SPN-034/SPN-033; grooming, 2026-10-20).

- The `lib/*` workspace and shared checks already exist from SPN-033. Extend them for this package, including its manifest in both Dockerfile stages before `npm ci`; do not recreate scaffolding (grooming, 2026-10-20).

## Out of scope

- The browser client and presence (SPN-058). Migrating existing documents (SPN-059).

## Verify

- Unit: ordering, transform-on-receive, durable acknowledgment, commit failure, duplicate/retried submission after reconnect or server restart, and every refusal above, ported from `service.test.ts` and `transport.test.ts`.
- A two-socket test client exchanges edits through the real transport and ends with identical snapshots.
