# 🛰️ SPN-057 Order and store every edit on Spinel's own sync server

## Story

As the [Operator](../product/personas.md#operator), I want the server to put every co-editor's edits in one durable order, so that collaboration runs on code we control, with the same recovery, access checks and bounded memory as the rest of the app.

## Scenarios

### Edits get one order

Given two editors send edits based on the same revision,
When the server receives them,
Then it transforms the later one with SPN-104's library, assigns consecutive revisions, durably commits both and sends each client what it is missing,
And it acknowledges a submission only after that commit; retrying its mutation ID returns the same result without a second edit.

### A revoked editor is stopped

Given an editor's grant, session or guest link is revoked while connected,
When their next edit arrives,
Then it is refused before it is stored or broadcast, as today.

- Keep today's boundaries from docs/collaboration.md: single-use document-scoped socket tickets, Origin checks, a 500 ms access scan before commits, viewer and Operator refusals, the cross-unit and 10 MiB checks and the denied-edit audit ([#49](../implementation/SPN-017.md#legacy-decision-49-document-bound-websocket-admission)). Preserve authorization and durable edit commit as one safe write boundary, without a revocation race.
- Build the ordering and log as `lib/sync-server/` (AGENTS.md), with storage behind an interface. Application storage, sessions and grants stay in `src/server/` and plug into it. SQLite is the current adapter, not a permanent requirement: before SPN-038, choose one coherent backend if removing Pro makes another simpler. This supersedes [#37](../implementation/SPN-012.md#legacy-decision-37-one-database-for-collaboration-recovery)'s same-SQLite-file requirement while retaining its consistency and access guarantees. Do not build multiple adapters speculatively. Owner, chat 2026-10-21.
- Keep docs/history.md's checkpoints, restore generations and the retryable purge queue ([#43](../implementation/SPN-012.md#legacy-decision-43-authenticated-collaboration-boundary)) working against the new log. Grooming [#92](../implementation/integration-boundaries.md#legacy-decision-92-stable-integration-boundaries), 2026-10-19.
- Materialize snapshots by applying the log to a headless open-source Univer instance. Keep the eight-unit cache and the idle eviction.
- Before persisting or broadcasting a candidate batch, enforce valid worksheet IDs and an unambiguous name-to-ID mapping with case-insensitively unique worksheet names. Reject an invalid candidate atomically; never rely on native snapshot reopening to rename colliding sheets ([first-pass review](https://github.com/mxbaylee/spinel/pull/151#pullrequestreview-5644879820)).
- Behind a server flag, off by default: SPN-059 switches documents over after SPN-056's integrated review. TypeScript only. The library prerequisite is SPN-104 under the [staged landing](../implementation/sync-staged-landing-2026-10-25.md#land-the-library-and-retain-spn-056-for-integrated-review).

- Preserve MCP credential expiry/scope/disconnect and account/grant revocation at the final write boundary. Keep exact-revision rejection for stale assistant writes and stable retry identity, rather than transforming them as ordinary edits. Native Formula metadata must survive Doc mutations and materialization (SPN-034/SPN-033; grooming, 2026-10-20).

- The `lib/*` workspace and shared checks already exist from SPN-033. Extend them for this package, including its manifest in both Dockerfile stages before `npm ci`; do not recreate scaffolding (grooming, 2026-10-20).
