# 🛰️ SPN-057 Order and store every edit on Spinel's own sync server

## Story

As the [Operator](../product/personas.md#operator), I want the server to put every co-editor's edits in one durable order, so that collaboration runs on code we control, with the same recovery, access checks and bounded memory as the rest of the app.

## Scenarios

### Edits get one order

Given two editors send edits based on the same revision,
When the server receives them,
Then it transforms the later one with SPN-056, assigns consecutive revisions, durably commits both and sends each client what it is missing,
And it acknowledges a submission only after that commit; retrying its mutation ID returns the same result without a second edit.

### A revoked editor is stopped

Given an editor's grant, session or guest link is revoked while connected,
When their next edit arrives,
Then it is refused before it is stored or broadcast, as today.

Retain File admin role semantics and content-blind Operators. Port Space transport/history tests alongside ordinary ones; see docs/implementation/SPN-092.md and SPN-079.md. Grooming, 2026-10-22.

- Keep today's boundaries from docs/collaboration.md: single-use document-scoped socket tickets, Origin checks, a 500 ms access scan before commits, viewer and Operator refusals, the cross-unit and 10 MiB checks and the denied-edit audit ([#49](../implementation/SPN-017.md#legacy-decision-49-document-bound-websocket-admission)). Preserve authorization and durable edit commit as one safe write boundary, without a revocation race.
- Build the ordering and log as `lib/sync-server/` (AGENTS.md), with storage behind an interface. Application storage, sessions and grants stay in `src/server/` and plug into it. SQLite is the current adapter, not a permanent requirement: before SPN-038, choose one coherent backend if removing Pro makes another simpler. This supersedes [#37](../implementation/SPN-012.md#legacy-decision-37-one-database-for-collaboration-recovery)'s same-SQLite-file requirement while retaining its consistency and access guarantees. Do not build multiple adapters speculatively. Owner, chat 2026-10-21.
- Keep docs/history.md's checkpoints, restore generations and the retryable purge queue ([#43](../implementation/SPN-012.md#legacy-decision-43-authenticated-collaboration-boundary)) working against the new log. Grooming [#92](../implementation/integration-boundaries.md#legacy-decision-92-stable-integration-boundaries), 2026-10-19.
- Materialize snapshots by applying the log to a headless open-source Univer instance. Keep the eight-unit cache and the idle eviction.
- Behind a server flag, off by default: SPN-059 switches documents over. TypeScript only.
- Merge with `lib/sync-transform` (SPN-056): transform each incoming edit past the edits accepted since its revision with `side: 'right'`, passing `{ cells }`: the cells at that edit's base revision, styles inline (the replay merge, [SPN-056 decision 29](../implementation/SPN-056.md), chosen over the rule-based merge by an independent comparison, 2026-10-23). Serve them from per-revision before-images of the cells each accepted edit touched, rolled back from the live document within the retention window, rather than a full snapshot per revision. Refuse an edit it throws on and resync its sender: a `TypeError` means a malformed or forged batch, such as an absolute write whose unclaimed keys differ from its base cell; log a `RefusedEditError`'s reason, one of those in the lib's [Contract](../../lib/sync-transform/README.md#contract). Owner, chat 2026-10-20, with the reasons `'moved-cells'` and `'growth'` (`'format-race'` is gone under decision 29); owner, chat 2026-10-22, for `'name-race'` and `'formula-race'` ([SPN-056 decisions](../implementation/SPN-056.md)). Store and broadcast the transform's output as returned, params and `trigger` included, since a later transform reads them. After merging, refuse an edit that would leave a workbook with no sheet or no visible sheet, which no pairwise transform can prevent (lib/sync-transform/README.md). Validate the final candidate before persistence or broadcast: worksheet IDs, snapshot keys and order must agree, and sheet names must be unique case-insensitively. Refuse the whole batch rather than relying on reopen-time renaming; the transform only sees concurrent assignments, not unchanged names ([decision 37](../implementation/SPN-056.md#37-refuse-concurrent-worksheet-identity-collisions), agent correction, 2026-10-25).
- Detect divergence the transform can't see. At each commit, store a hash of the cells (or Doc body) the revision touched, as Univer serializes them; ignore keys Univer adds only when it applies an edit, as `lib/sync-transform/tests/fuzz.test.ts` does. A client with nothing pending sends the hash for the latest revision it has applied (SPN-058). On a mismatch, resync that client as for a refused edit, and record `sync.divergence.detected`. Owner, chat 2026-10-23. Capturing redacted shapes of the revisions since its last match still requires the owner decision on [SPN-032's proposal](../implementation/SPN-032.md#reproducing-a-refusal-without-document-content): it retains layout, lengths, equality patterns, formats, functions and some verbatim values, so it does not guarantee content-blind exports. Until decided, record only allowlisted metrics. Any approved shape capture must meet the proposal's faithful-replay and size limits or omit the shape; this qualification does not approve collection or relax the content/privacy acceptance below. Agent clarification, 2026-10-25.
- Record SPN-056's sync refusals and silent drops as listed in [its events](../implementation/SPN-032.md#sync-transform-refusals-and-drops), registered in `@spinel/diagnostics` with their validators. SPN-032 landed its event store first, so the events moved here. Redacted refusal shapes [need the owner](../implementation/SPN-032.md#reproducing-a-refusal-without-document-content); until decided, record only the metrics. Owner request, chat 2026-10-22.

- Preserve MCP credential expiry/scope/disconnect and account/grant revocation at the final write boundary. Keep exact-revision rejection for stale assistant writes and stable retry identity, rather than transforming them as ordinary edits. Native Formula metadata must survive Doc mutations and materialization (SPN-034/SPN-033; grooming, 2026-10-20).

- The `lib/*` workspace and shared checks already exist from SPN-033. Extend them for this package, including its manifest in both Dockerfile stages before `npm ci`; do not recreate scaffolding (grooming, 2026-10-20).
