# 🎭 SPN-126 Exercise restore edge cases in real browsers

## Story

As the [Owner](../product/personas.md#owner), I want restore's interruption and old-client behavior proven in real browsers, so that an open tab or offline device cannot bring discarded work back.

## Scenarios

### An old Doc tab and an offline queue meet a restored workspace

Given an Owner tab with an open Doc and a Collaborator device with offline edits queued,
When the Operator restores a backup and service resumes,
Then the old tab and the queued edits are refused or isolated as the native fences specify, the UI says so,
And the restored content and the post-restore notice are what both accounts see after signing in again.

### The Operator works through the Admin UI

Given a configured catalog,
When the Operator selects a saved backup, double-clicks confirm, cancels a preparation and lets a passkey check expire,
Then each path shows its documented state and no second restore starts.
