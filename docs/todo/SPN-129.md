# 🪶 SPN-129 Validate PR text edits without replacing code evidence

## Story

As the [Operator](../product/personas.md#operator), I want title/body edits to
validate PR policy cheaply, so that documentation updates do not rerun code tests.

## Scenarios

### Text edits preserve genuine code evidence

Given passing, pending or failed validation on the current source and base,
When only the PR title or body changes,
Then cheap PR-policy validation runs without cancelling code work,
And actual repository rules preserve the prior code state and merge readiness.

### Base changes require fresh full validation

Given a PR whose base changes or whose edit payload is ambiguous,
When event routing handles the edit,
Then full validation tests the immutable new source/base range,
And subsequent text edits cannot hide pending or failed base validation.

- Retained SPN-115 acceptance, estimated L including router capability, credential/setup, integration and hosted verification. [Split record](../implementation/SPN-115.md#conservative-edit-routing-and-explicit-remainder), agent decision 2026-11-01.
- Keep all seven required names and protections. No copied passes, fake-green skipped gates, dispatch-only substitute or admin bypass. Investigate trusted event routing before selecting an architecture.
- Full validation on edits remains the safe fallback until all transitions pass actual protected-merge checks. Distinct job names alone failed: rule suite 4844981368 and completed diagnostic 41352830393.
- Follow [sustainable testing](../testing.md); carry the test plan and failure dispositions through progress checkpoints. Weigh all four personas and document capability/setup requirements.
