# ✂️ SPN-074 Stop offering Slides

## Story

As the [Owner](../product/personas.md#owner), I want **New** to offer only the types Spinel actually builds, so that I never create a slide deck that can't be edited. [Collaborators](../product/personas.md#collaborator) see the same.

## Scenarios

### Creating

Given the **New** menu,
When I open it,
Then it offers Folder, Sheet and Doc,
And the API refuses a new `slides` item with "Choose Folder, Sheet or Doc."

### Searching

Given the search type filter,
When I open it,
Then it offers only Folder, Sheet and Doc.

## Rules

- May land before SPN-047: removing unsupported Slides does not wait for the redesign. Existing design patterns, stories, light/dark/phone screenshots and owner approval still apply. Owner, chat 2026-10-20; #104.
- Spinel drops Slides. Univer's Slides is the closed `@univerjs-pro/slides`, and Spinel is moving off Univer Pro so nothing is watermarked. SPN-009 is retired. Owner, chat 2026-10-19.
- Remove Slides entirely: item kinds, database schema, creation, filters, read paths, placeholders, stories and fixtures. Spinel has never been in production; no legacy rows, compatibility or migration are required. Owner correction, chat 2026-10-20, #104.
- Keep stories and screenshots for the changed New and search states (AGENTS.md).
- Update folders.md and sharing.md, which still describe the placeholder, and drop the SPN-074 notes there.

## Out of scope

- Presentations by any other means.

## Verify

- Unit: creating `slides` is refused; valid item kinds, database schema and search filters allow only Folder, Sheet and Doc.
- Playwright: **New** and the search type filter show only Folder, Sheet and Doc.
