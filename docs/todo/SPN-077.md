# 💠 SPN-077 Recognize Docs, Sheets and Spaces by their gem facets

## Story

As the [Owner](../product/personas.md#owner), I want Docs, Sheets and Spaces to have recognizable gem-facet icons, so that I can distinguish them in creation controls, lists and shared previews. [Collaborators](../product/personas.md#collaborator) and [Link guests](../product/personas.md#link-guest) see the same identity.

## Scenarios

### Distinct shapes at every size

Given the three entity icons,
When I view them in light or dark mode at small UI and large social-card sizes,
Then Docs are blue, Sheets green and Spaces purple, each with its own recognizable angular silhouette and subtle facet shading,
And labels and shape identify the type without depending on colour alone.

### Existing surfaces use the artwork

Given I create, browse or share an existing Doc or Sheet,
When its creation control, file row or authorized social preview appears,
Then it uses the matching facet (beside the retained native type selector for creation), and long titles and emoji retain the current bounded layout.

### Space artwork before Spaces ship

Given Spaces are not implemented,
When I open Storybook,
Then I can review the Space icon in labeled creation, list/sidebar and social-card examples alongside Docs and Sheets,
And the app gains no unsupported Space action or public Space route.

## Rules

- Owner requests this as the next implementation ticket, before the redesign and Spaces, chat 2026-10-20. No dependency on either; existing visual approval gates remain.
- Follow [entity iconography](../design/entity-icons.md). Use original scalable SVG geometry, shared by UI and the existing server social-card renderer; retain the app's heart-gem logo/favicon. No raster-generated icon or new rendering service.
- Keep compact raw SVG assets with a consistent viewBox and theme palette values that retain each hue. Optimize without requiring a new dependency solely for three small assets; SVGs contain no scripts, external resources or embedded raster images.
- Existing social cards remain PNG outputs with the same title/type-only authorization, revocation, concurrency and cache boundaries. Space samples are static fixtures until an authorized Space sharing route exists.

## Out of scope

- Building Spaces, changing permissions, redoing layouts, redesigning the app logo, or adding icons for hypothetical content types.

## Verify

- Storybook: all three shapes at 16/24/32 and social sizes, both themes, phone controls, text-adjacent and standalone accessible uses; actual build-time social renderer fixtures, including emoji and long/unbroken titles.
- Browser: current Doc/Sheet create/list/share flows still work; PR screenshots cover changed surfaces in light, dark and phone widths. Check SVG output, accessible names, palette contrast and existing social privacy/revocation tests.
