# 📘 SPN-046 Write a design playbook from a competitor audit

## Story

As the [Owner](../product/personas.md#owner), I want a written design playbook with reusable components, so that redesign work looks minimal, consistent, and familiar to people who use other spreadsheet apps.

## Scenarios

### Comparable screens

Given public screenshots and documentation for Google Sheets, Excel for the web, Apple Numbers and Zoho Sheet,
When the playbook is written,
Then each Spinel screen (file list, editor chrome, sharing, settings, sign-in, admin, guest view, empty and error states) has a short comparison and the pattern Spinel adopts.

### Component catalogue

Given `npm run storybook`,
When it opens,
Then every reusable shell component renders in light and dark mode with its states (empty, loading, error, disabled).

## Rules

- Start from the approved gem-rail mockup, `30a4a61^:docs/design/gem-rail-mockup.tsx`, and the landed SPN-027 theme. Owner, chat 2026-10-19.
- Decide the dashboard's layout (search and filters, Shared with me, row actions, header actions) and the editor's default layout, so SPN-048 and SPN-049 only build. Record "status changes never move the layout" as a pattern. Owner, chat 2026-10-19.
- Every ticket that changes the UI depends on this one: SPN-009, 013, 032, 033, 035, 036, 039, 042, 043, 045, 047–050, and SPN-051/052 through SPN-039. Cover the patterns they need. Owner, chat 2026-10-19.
- The landing PR adds an AGENTS.md rule: UI changes follow `docs/design/`, and a ticket that needs a missing pattern adds it there in its own PR. Owner, chat 2026-10-19.
- Markdown in `docs/design/`, plus Storybook stories for components in `src/ui/` and `web/`. Owner, chat 2026-10-19.
- The direction is a more minimal design: each screen says which controls are always visible and which sit behind a menu. Owner, chat 2026-10-19.
- The playbook's token list is the existing theme tokens (`docs/theme.md`), not a parallel set.
- Audit from public material only. Never sign in to a third-party product, and describe patterns rather than copying their assets. Grooming, 2026-10-19.
- Storybook is a devDependency; stories are `.stories.tsx`. Cover the Operator's admin screens and the Link guest's view too.

## Out of scope

- Applying the redesign (SPN-048, SPN-049, SPN-050). CI checks (SPN-047).

## Verify

- The Storybook build succeeds. A reviewer can open each screen's section and find a comparison, an adopted pattern and the stories it uses.
