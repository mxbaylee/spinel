# 🔬 SPN-134 Diagnose incomplete historical mobile callback runs

## Story

As the [Operator](../product/personas.md#operator), I want an incomplete historical callback run to identify its failing phase and cause, so that a required comparison can be repaired without uncertain reruns.

## Scenarios

### An incomplete baseline has an evidence-backed disposition

Given the retained historical mobile callback timeout,
When its owned browser, input, tracing and cleanup boundaries are inspected,
Then the original failure has a supported cause and bounded repair or explicit follow-up owner,
And a complete historical/candidate comparison still proves input, content and callback ownership.

## Rules

- Active diagnosis uses the [bounded phase/progress protocol](../implementation/SPN-134.md#resume-checkpoint-and-bounded-diagnostic-protocol): one first-attempt historical/candidate pair per existing preset on the committed source, with no additional sample solely to seek green. Original cause and complete current acceptance remain open. Agent judgment, 2026-11-02.

- Follow [sustainable testing](../testing.md); keep the Verify plan and progress evidence current. [Policy](../implementation/SPN-115.md#guidance-for-every-open-ticket-and-progress-checkpoint), owner 2026-11-01.
- Preserve the original 420000 ms timeout at the last persisted typing phase; missing counters/analysis are unavailable evidence, not proof of browser errors or data loss. [Origin and diagnostic boundary](../implementation/SPN-134.md#historical-mobile-callback-timeout), agent judgment 2026-11-02, originating in the SPN-071 main push / PR #226.
- Keep the immutable historical baseline, workload, throttle, first-attempt/no-retry policy, callback caps, input/content checks and existing budgets. A successful candidate or later comparison does not retroactively pass the failed run.
- Prefer bounded nonsecret phase/process observations in the existing callback fixture. Do not introduce a generic retry framework, instrument primary latency samples or retain credentials/document contents in diagnostics.
- Initial M covers phase attribution and a bounded fixture/observation repair if demonstrated. Reassess effort before wider investigation; any distinct product defect requires its own evidence-backed scope. Filing a follow-up does not satisfy an unresolved required comparison.

## Out of scope

- SPN-120's named historical fixture cases, native desktop identity/storage cleanup, physical-device provider capability and SPN-133 flush latency.
- Changing baseline callback behavior, silently skipping a comparison or extending timeouts to obtain a pass.

## Verify

- Inspect the retained baseline partial JSON, job log, failure captures and current callback harness before running anything. Declare a small fixed diagnostic sample, source/browser/runtime and hypothesis; retain all results without assertion retries.
- Extend the nearest `e2e/doc-responsiveness-callbacks.spec.ts` / fixture / trace-owner tests only where needed. Prove missing input, incomplete tracing and unexpected owned-process exit still fail with the first cause preserved; cleanup must remain bounded.
- Run the complete existing mobile baseline/candidate comparison on the final source and retain full raw callback evidence, attempt identities, content and input verification, no post-disposal callbacks and cleanup. Verify changed helper/observation dependencies select the required owners. Diagnostics alone do not prove acceptance.
