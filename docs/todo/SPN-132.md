# ⌨️ SPN-132 Keep native Doc typing responsive during long edits

## Story

As the [Collaborator](../product/personas.md#collaborator), I want long typing
sessions to remain responsive without changing my text, history or shared edits.

## Scenarios

### Ordinary typing uses bounded composition work

Given a native Doc receives ordinary keyboard edits through synchronization,
When the existing history group fills,
Then known paragraph-preservation metadata does not bypass balanced composition,
And text, selection, Undo/Redo, peer content and save completion remain exact.

### Rich or unrecognized input stays native

Given an insertion contains structural content or unsupported metadata,
When the group flushes,
Then the existing native fallback preserves every field and publication boundary.

## Rules

- Follow the [scope and evidence decision](../implementation/SPN-132.md#separate-the-pre-existing-typing-correction-from-spn-071); this pre-existing defect is a prerequisite correction for SPN-071, whose original acceptance remains intact.
- Accept only an absent or own exactly-true native preservation marker; keep all other guards, limits, timers and ownership semantics.
- Retain first failures and incomplete trace limits; preliminary allocation proof is not browser timing acceptance. Do not add the abandoned template shortcut.
- Keep the temporary patch's upstream removal owned by SPN-122.

## Out of scope

New composition algorithms, metadata normalization, performance waivers and SPN-071's personal hiding/access UI.

## Verify

- Existing ES/CJS dependency patch tests: exact native publication/snapshot parity, marked/unmarked/mixed groups, inverse inserts, malformed markers, structural fallback and measured work reduction with a disabled-guard negative control.
- Existing normal desktop/mobile responsiveness and native Doc/sync/browser checks: unchanged fixtures, budgets, retry policy and exact saved/peer/Undo/Redo evidence; retain first failures and runtime identities.
- Shared dependency owner: `scripts/dependencies/patch-univer-docs.ts`, native core marker and `lib/sync-client/src/capture.ts`; keep CI routing complete. No new service, UI pattern or routine screenshots.
