# 🔁 SPN-059 Move every document onto Spinel's sync and remove Univer collaboration

## Story

As the [Owner](../product/personas.md#owner), I want every existing Sheet and Doc, with its history, to move onto Spinel's own sync, so that Univer's unlicensed limits or a change on their side can't take away editing together.

## Scenarios

### Existing documents open unchanged

Given documents, checkpoints, named versions and restore generations stored by Univer collaboration,
When the server starts with this ticket deployed,
Then each document migrates once, opens with identical content and history, and stays editable by two people with presence.

### An interrupted migration

Given the server stops partway through migrating,
When it starts again,
Then finished documents aren't migrated twice, and unfinished ones resume from their last confirmed state.

## Rules

- Replaces SPN-014's acceptance. Preserve landed session and grant checks, guest identity and revocation, checkpoint materialization, restore generations and purge handling, with their regressions. Grooming #92, 2026-10-19.
- Migrate from each unit's materialized snapshot using the public materializer, fenced like today's `preparing` marker. Run it once at startup, and let the Operator see progress in the logs.
- Remove the flag and every `@univerjs-pro/collaboration*` package. If SPN-075 has landed, also remove `@univerjs-pro/license` and add the check that fails on any `@univerjs-pro` dependency; otherwise SPN-075 does (AGENTS.md).
- Hide menus whose mutations SPN-056 can't transform.
- Rewrite docs/collaboration.md to describe the new design, and drop the Univer limits text (SPN-010 and SPN-013 were retired, owner chat 2026-10-19).

- Carry Formula definitions through migration without calculated values and test native formula edits. Retain MCP credential/scope/revocation, exact-base writes and retry identity at the replacement sync boundary (SPN-034/SPN-033; grooming, 2026-10-20).

## Out of scope

- New collaboration features. Offline editing (SPN-053).

## Verify

- Every existing collaboration, guest and revocation, checkpoint, restore-generation and purge regression passes against the new module.
- A long-running two-editor Playwright fuzz run finds no divergence. Migration test on a copy of a seeded database, including an interrupted run.
