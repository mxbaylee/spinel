# 🔭 SPN-047 Redesign Spinel's screens from a review of Storybook and competitors

## Story

As the [Owner](../product/personas.md#owner), I want an AI design review of every Spinel screen against the products people already know, so that Spinel looks calm and finished instead of ugly and cluttered. [Collaborators](../product/personas.md#collaborator) and [Link guests](../product/personas.md#link-guest) use the same screens.

## Scenarios

### Every screen is reviewed

Given the Storybook stories and Playwright screenshots of the editors, sign-in and guest pages,
When the agent compares each screen with Google Sheets and Docs, Excel for the web, Apple Numbers, Notion and Dropbox,
Then each page in docs/design gets side-by-side notes, a list of what is cluttered or ugly and why, and an adopted redesign,
And the comparison includes shared controls such as selectors, menus and dialogs, with Base UI as their component foundation.

### The redesign is visible before anyone builds it

Given the adopted redesign,
When the PR opens,
Then it has light, dark and phone-width screenshots of mockup stories for every screen, before and after,
And it merges only after the owner approves them.

### The UI tickets build it

Given the redesign merged,
When the next UI ticket starts,
Then its ticket describes the redesigned screen, and screens no ticket covered (Share dialog, Admin, guest pages, the revoked-link page) have tickets.

## Rules

- AI review, not CI checks; those moved to SPN-060. A prerequisite of every ticket that adds or changes a screen, with owner-authorized pre-redesign work: SPN-074 removed unsupported Slides (#104), SPN-044 and SPN-034 landed branding and OAuth connections, and SPN-033 landed live Doc formulas (#113), and SPN-077 landed entity facets, including Storybook-only Space examples, and SPN-036 may build profile settings before the redesign (owner, chat 2026-10-20). Existing screenshot and approval gates still apply. Owner, chat 2026-10-19.
- Public pages and screenshots only. Never sign in to a competitor, never copy their assets, and describe the patterns rather than imitating them (as SPN-046's audit did).
- Include the landed OAuth consent/connection screens, Formula states and SPN-077 entity facets in the inventory. The playbook's principles still hold: one primary action, no hover-only controls, status never moves layout, never colour alone. Refine tokens, type and spacing where it helps, and keep presetStyles.test.ts contrast.
- Add `npm run screenshots -- <story ids>` to capture light, dark and phone shots for any PR, since every UI PR now needs them (process.md).
- Update every ticket that depends on this one (each screen in docs/design/README.md's table) and SPN-060 to the new design, and remove each one's dependency on this ticket.

- Add the planned Space file and internal navigation, guest links, recoverable internal trash, phone layout and role matrix to the playbook/mockup inventory before SPN-078 builds them. SPN-079 later adds file Admin with one Owner inheriting Admin; server Operator remains separate (#116–#118).

- Adopt Base UI for shared controls actually used by the redesign mockups, using existing React/Vite, plain CSS and light/dark tokens. It supplies accessible behavior, not a predetermined Material theme; compare visual treatments with competitors. Verify keyboard, focus, screen-reader semantics, touch, portal/theme behavior, licensing and bundle impact. Add shared component stories; do not maintain competing primitive libraries or migrate unrelated screens here. Owner, chat 2026-10-20; #120.

## Out of scope

- Building the screens themselves, beyond mockup stories, shared tokens and the Base UI components those mockups use. Consumer migrations stay in their screen tickets.

## Verify

- The PR's screenshots, approved by the owner. Storybook builds with the new mockup stories. backlog:check passes with the updated tickets.
