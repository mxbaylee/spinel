# 📏 SPN-047 Check design consistency automatically in CI

## Story

As the [Owner](../product/personas.md#owner), I want CI to flag design drift, so that new tickets keep the playbook's look without me reviewing every pixel.

## Scenarios

### A raw colour is rejected

Given a change adds a hex colour or pixel spacing outside the theme tokens,
When Lint runs,
Then it fails and names the file and line.

### A visual change is visible

Given a change alters a component,
When the visual check runs,
Then the affected stories' light and dark screenshots differ from the stored ones, and CI fails until they are deliberately updated.

### An accessibility regression fails

Given a story with an axe violation,
When CI runs,
Then it fails and names the rule and component.

## Rules

- Three checks: token lint (stylelint or equivalent), Playwright screenshot comparisons of SPN-046's stories, and axe-core over the stories. Keep the existing contrast tests (`presetStyles.test.ts`). Grooming, 2026-10-19.
- Run them inside the existing required jobs (Lint, Playwright smoke). A new required job would need the owner to change the repository ruleset. Grooming, 2026-10-19.
- Generate snapshots in CI's Linux environment so fonts and rendering are deterministic. Document how to update them.
- If memory limits block local runs, follow the CI-first exception in process.md (#52).

## Out of scope

- The playbook's content (SPN-046). Full-page screenshot tests of live documents.

## Verify

- One deliberately failing fixture per check, proving that each check fails, then is reverted. Also a short docs section on updating snapshots.
