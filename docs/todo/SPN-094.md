# 🧰 SPN-094 Add plugins for document types and file conversion

## Story

As the [Operator](../product/personas.md#operator), I want to install optional document-type and conversion plugins, so that the [Owner](../product/personas.md#owner) and [Collaborators](../product/personas.md#collaborator) can use formats such as slides or kanban boards, or Office conversions, without bundling every editor and converter into Spinel.

## Scenarios

### Enable a document type or converter

Given the installer configures a compatible trusted plugin,
When an authorized person opens New, an existing plugin document, Import or Export,
Then only the plugin's declared type/editor or conversion capabilities appear, and supported creation, editing, reload and transfer paths use Spinel's access and persistence boundaries.

### A missing or failing plugin

Given a plugin is absent, incompatible, disabled or fails conversion,
When a person opens its document or uses its format,
Then unsupported choices fail clearly, existing content remains preserved and identifiable, no partial file/output is accepted, and core Sheets/Docs remain usable.

## Rules

- Optional post-launch backlog work after SPN-038, covering both new document types (for example slides or kanban) and format conversion. This does not restore built-in Slides or promise an Office converter; concrete plugin implementations are separate follow-ups. Owner, chat 2026-10-21; fixed-phase sequencing in decision [#129](https://github.com/mxbaylee/spinel/issues/129).
- Define a small versioned contract for type identity, metadata/artwork, stored payload/schema version, supported viewer/editor and conversion capabilities. Converters declare kinds, extensions/media types, directions and loss/errors. Document install/configure/disable/upgrade and trusted-code boundaries; do not promise a sandbox for arbitrary uploaded code.
- The host retains account/item access, revocation, fresh IDs, payload/image validation, size/resource limits and atomic save/import cleanup. Document which collaboration/history/offline/Space capabilities a type supports; unsupported capabilities are explicit, never silently enabled. Preserve guest restrictions, Operator content isolation and native Sheet/Doc behavior.
- Persist plugin type/version with content so missing/disabled plugins cannot destroy data or masquerade as another type. Verify rename/move/trash/restore and backup/restore of plugin documents; upgrades need an explicit recoverable schema transition. Plugins do not receive account credentials through the supported interface.
- Exports receive only currently authorized content; Formula results require access to every source, otherwise a placeholder. Imports never promote cached private results into live source bindings. Keep original files unchanged and disclose conversion loss.
- Prove the foundation with a minimal reference document-type plugin and fixture conversion; reuse SPN-093's CSV converter if available. Keep scope to document types/converters, not a general UI-extension framework or marketplace. No automatic installation, new service or new Pro package. Record the architecture and licensing choices before implementation; split the XL work into reviewable delivery slices then.
- Discuss eventual extraction of the existing Sheets, Docs and pages implementations into libraries/plugins in this ticket's design notes. Identify useful boundaries and what the supported plugin contract would need; extraction is follow-up work, not this ticket's acceptance, and no separate ticket is allocated yet. Avoid speculative abstractions solely for that possibility. Owner, chat 2026-10-21.

## Out of scope

- Full Slides/kanban/Office implementations, extracting existing Sheets/Docs/pages into libraries, CSV import itself (SPN-093), user-uploaded executable plugins, automatic installation and built-in PDF uploads. Existing native backup/import stays supported.

## Verify

- Unit/integration: capability/version registration, payload validation, create/save/reload, missing/disabled plugin preservation, upgrade/restore, fixture conversion/loss/errors, limits/cleanup and unchanged core paths.
- Browser/API: reference type in New/open/edit/view; correct access and revocation, private Formula sources, no guest/Operator scope expansion, honest unsupported actions and accessible light/dark/phone states. Include plugin-author and installer examples.
