# 💾 SPN-055 Protect pending edits and show offline storage limits

## Story

As the [Owner](../product/personas.md#owner), I want to see which downloads and pending edits remain on this device, so that I can manage space without accidentally discarding work or relying on a missing copy. [Collaborators](../product/personas.md#collaborator) get the same within their permissions; the [Operator](../product/personas.md#operator) gets bounded storage and diagnosable failures without document access.

## Scenarios

### Storage stays honest

Given I have downloaded documents, one with unsynced edits,
When the browser evicts storage, the device runs out of space, or Spinel updates its storage schema,
Then a missing copy never shows as available offline, Spinel's own cleanup preserves pending work, and **Remove from device** requires explicit recovery/deletion of pending changes.

### Leaving an account with pending work

Given I have unsynced changes and no connection,
When I sign out or switch accounts,
Then private local access locks immediately, preservation/deletion is explicit, another account cannot read the work, and remote logout finishes on reconnection without claiming it already happened.

## Rules

- Migrated decision records: [Initial mobile and installable shell](../implementation/SPN-028.md#legacy-decision-82-initial-mobile-and-installable-shell), [Complete opted-in offline product](../implementation/SPN-039.md#legacy-decision-83-complete-opted-in-offline-product).

- Follow the [device data and storage lifecycle](../offline.md#device-data-and-storage-lifecycle): request persistence and report its result, per-item usage, quota/partial-download failures and missing stores; preserve pending edits and a compatible offline editor through interrupted schema/app updates. Owner, chat 2026-10-19; [#83](../implementation/SPN-039.md#legacy-decision-83-complete-opted-in-offline-product).
- Browser eviction, user-cleared storage and device loss can destroy the only unsynced copy. Persistence is a request, not a guarantee; server backups or a database change cannot recover edits that never durably reached the server. Protect against Spinel's own cleanup without promising survival of external deletion. Owner, grooming 2026-10-21.
- Retain account/epoch isolation, viewer restrictions, revocation handling and guest/token exclusion from the offline contract. Finish an offline sign-out on `/setup` and `/invite` as well as ordinary startup; avoid creating empty per-account databases when `indexedDB.databases` is unavailable. SPN-039 review leftovers, carried forward 2026-10-21.
- Preserve stable ordinary-item links `/?item=<uuid>` and exact account Space-child links `/spaces/<spaceId>?item=<itemId>` through rename/move; an unavailable explicit child never opens another page. Keep shortcuts distinct from downloads and retain per-child preparation. Personal pinning stays removed ([#128](../implementation/SPN-047.md#legacy-decision-128-remove-personal-pinning)). Shared lifecycle belongs here; actual installed-device behavior and manifest/icons are SPN-090. Owner, grooming 2026-10-21; Space handoff, 2026-10-25.

- Sign out offline with pending edits, revisit normal/setup/invite routes, reconnect and switch accounts; verify locking and eventual logout. Simulate missing `indexedDB.databases` and check bounded account stores without creating empty databases.
