# 📌 SPN-099 Run Univer core unpatched once upstream ships the fixes

## Story

As the [Owner](../product/personas.md#owner), I want Spinel to run Univer's own `@univerjs/core` unchanged, so that upgrading Univer never breaks installs or silently changes how concurrent edits merge.

## Scenarios

### Upgrading to a release with the fixes

Given a Univer release ships the fixes Spinel patches today,
When Spinel upgrades to it,
Then `npm ci` installs core unmodified, and two people editing a Doc at once still end up with the same document.

### Upstream fixes it another way, or declines

Given upstream merges a different fix, or none,
When Spinel upgrades,
Then Spinel adapts to upstream's behaviour and does not patch core again.

## Rules

- Migrated decision records: [Guarded open-source paragraph repair](../implementation/SPN-012.md#legacy-decision-46-guarded-open-source-paragraph-repair).

- Register the existing branch-reserved ID unchanged; wait for SPN-056's transform library and tests before implementation ([focused registration, 2026-10-23](../implementation/grooming-dependency-registration-2026-10-23.md#preserve-spn-099-and-separate-dependabot-enablement)).
- `scripts/dependencies/patch-univer-core.ts` is temporary. It refuses any core other than 1.1.0, so a Univer upgrade fails at install until this ticket is done. Owner, chat 2026-10-22.
- Link fixes (joining split ranges, lone `$n` ids, negative retains): upstream PR [dream-num/univer#7938](https://github.com/dream-num/univer/pull/7938).
- Paragraph REPLACE repair ([decision #46](../implementation/SPN-012.md#legacy-decision-46-guarded-open-source-paragraph-repair)): it is still wrong upstream in 1.2.0. Send upstream a PR for it before starting the rest.
- Text style transform fix (`transformTextRuns`): a winning REPLACE style's falsy keys, such as the format painter's `bl: 0`, override a concurrent COVER style, as its truthy keys do. Not yet sent upstream.
- Not patched: `transformParagraph`'s both-COVER branch has the same truthiness flaw (`if (paragraph.paragraphStyle[key]) delete …`), but no current Univer command reaches it. If a falsy COVER paragraph key ever appears, patch it the same way (`!== void 0`).
- Which fixes `lib/sync-transform`'s own tests need, measured against stock 1.1.0 (SPN-056, 2026-10-24): without the canonical link ranges or the falsy-key style fix, docs and fuzz tests fail and the two screens differ. Without the paragraph REPLACE repair or the negative-retain fix, only `patch-univer-core.test.ts` fails. Keep both: the paragraph repair is reachable, since `src/docs.ts` composes text edits, and the negative-retain fix protects the editors that add links through `BuildTextUtils.customRange.add` (SPN-058's client), which the library never calls.
- Roll forward: if upstream fixes any of them differently, take upstream's behaviour and change `lib/sync-transform` and its tests to match, rather than keep the patch. Owner, chat 2026-10-22.
- Upgrade every `@univerjs/*` package together.
- Remove all of it: the script, its test, the `postinstall` line, the THIRD-PARTY-NOTICES row, "Pinned open-source paragraph repair" in docs/collaboration.md, and the patched-core paragraph in lib/sync-transform/README.md.

## Out of scope

- Removing the Pro packages (SPN-059, SPN-075).

- A search for `patch-univer-core` finds nothing. Playwright smoke passes.
