# 📌 SPN-099 Run Univer core unpatched once upstream ships the fixes

## Story

As the [Owner](../product/personas.md#owner), I want Spinel to run Univer's own `@univerjs/core` unchanged, so that upgrading Univer never breaks installs or silently changes how concurrent edits merge.

## Scenarios

### Upgrading to a release with the fixes

Given a Univer release ships the fixes Spinel patches today,
When Spinel upgrades to it,
Then `npm ci` installs core unmodified, and two people editing a Doc at once still end up with the same document.

### Upstream fixes it another way, or declines

Given upstream merges a different fix, or none,
When Spinel upgrades,
Then Spinel adapts to upstream's behaviour and does not patch core again.

## Rules

- Migrated decision records: [Guarded open-source paragraph repair](../implementation/SPN-012.md#legacy-decision-46-guarded-open-source-paragraph-repair).

- Preserve the registered ID ([focused registration, 2026-10-23](../implementation/grooming-dependency-registration-2026-10-23.md#preserve-spn-099-and-separate-dependabot-enablement)). SPN-104 has delivered the required transform library and regression tests; this ticket does not wait for the retained SPN-056 integrated review ([staged landing, 2026-10-25](../implementation/sync-staged-landing-2026-10-25.md#land-the-library-and-retain-spn-056-for-integrated-review)).
- `scripts/dependencies/patch-univer-core.ts` is temporary. It refuses any core other than 1.1.0, so a Univer upgrade fails at install until this ticket is done. Owner, chat 2026-10-22.
- Link fixes (joining split ranges, lone `$n` ids, negative retains): upstream PR [dream-num/univer#7938](https://github.com/dream-num/univer/pull/7938).
- At implementation start, recheck the linked upstream PR and paragraph/style-fix status against the selected release; record the disposition and submit only missing fixes. The earlier source checkpoint found the paragraph REPLACE repair absent in 1.2.0 ([decision #46](../implementation/SPN-012.md#legacy-decision-46-guarded-open-source-paragraph-repair)); this grooming does not claim a fresh upstream release review.
- Text style transform fix (`transformTextRuns`): a winning REPLACE style's falsy keys, such as the format painter's `bl: 0`, override a concurrent COVER style, as its truthy keys do. The earlier checkpoint had not submitted this fix; recheck that status before duplicating upstream work.
- The unpatched `transformParagraph` both-COVER truthiness case remains a regression/upstream compatibility concern; no producer reached it at the source checkpoint. If a supported producer reaches it, preserve a reproducer and adapt to the chosen stock upstream behavior without introducing another local core patch, consistent with this ticket's roll-forward policy.
- Which fixes `lib/sync-transform`'s own tests need, measured against stock 1.1.0 (SPN-056, 2026-10-24): without the canonical link ranges or the falsy-key style fix, docs and fuzz tests fail and the two screens differ. Without the paragraph REPLACE repair or the negative-retain fix, only `patch-univer-core.test.ts` fails. Keep both: the paragraph repair is reachable, since `src/docs.ts` composes text edits, and the negative-retain fix protects the editors that add links through `BuildTextUtils.customRange.add` (SPN-058's client), which the library never calls.
- Roll forward: if upstream fixes any of them differently, take upstream's behaviour and change `lib/sync-transform` and its tests to match, rather than keep the patch. Owner, chat 2026-10-22.
- Upgrade every `@univerjs/*` package together.
- Remove all of the core repair: the script, its test, its command in `postinstall`, the THIRD-PARTY-NOTICES row, "Pinned open-source paragraph repair" in docs/collaboration.md, and the patched-core paragraph in lib/sync-transform/README.md. Preserve any independent install step still needed, including the [UI resize callback guard](../implementation/dependency-react-19.md#native-print-resize-callback-repair), and assess that guard against the selected upstream UI release separately.
- Also assess the independent [retained drawing geometry repair](../implementation/SPN-056.md#retain-collapsed-drawing-geometry-through-native-refresh) against the selected `@univerjs/sheets-drawing` release. Its guarded ES/CJS postinstall step must remain until stock native resize/refresh passes the zero/signed extent and continued-queue regressions; do not remove it just because core becomes unpatched.
