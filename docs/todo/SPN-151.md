# 🔑 SPN-151 Remove leftover BrowserStack hosted resources

## Story

As the [Owner](../product/personas.md#owner), I want the hosted leftovers of the dropped BrowserStack harness removed, so that the repository carries no unused secrets, branches or labels.

## Scenarios

### No BrowserStack resource remains in the repository settings

Given the BrowserStack code and workflow were removed from the repository,
When the owner lists its branches, secrets and labels,
Then none refer to BrowserStack.

- Preserve the accepted scope and allocation provenance in the [registration decision](../implementation/SPN-151.md#-registration-and-retained-scope); this registration does not claim implementation or acceptance. Agent judgment, 2026-11-13.

- Follow [sustainable testing](../testing.md); keep the Verify plan and progress evidence current. [Policy](../implementation/SPN-115.md#guidance-for-every-open-ticket-and-progress-checkpoint), owner 2026-11-01.
- Context: the owner dropped BrowserStack for SPN-090 phone acceptance on 2026-11-13 ([decision](https://github.com/mxbaylee/spinel/blob/67111d9c106c6518b813c6f1cf332068526c254c/docs/implementation/SPN-090.md#-owner-decision-2026-11-13-real-phones-replace-browserstack-for-spn-090)). SPN-090 has landed and removed the harness/workflow; hosted cleanup still needs separate evidence.
- The remote `ci/browserstack-accounting` branch is handled by the owner-authorized [2026-11-22 cleanup](../implementation/grooming-2026-11-22.md#-remote-branch-cleanup), preserving its complete ledger under an archive tag. The merged `docs/implementation/SPN-090-browserstack-history.json` also retains totals. Verify the cleanup receipt; do not repeat that deletion.

## Out of scope

- Deleting the recorded BrowserStack reports and narrative in `docs/implementation/`; they stay as history.

## Verify

- Contract/negative case: no unused BrowserStack branch, repository secret or label remains, and the previously active provider key is revoked/inactive in the BrowserStack account. A missing GitHub secret does not prove provider revocation; an active or unverified provider key leaves acceptance incomplete.
- Suite/layer/fixture: repository listings (`git branch -r`, `gh secret list`, `gh label list`) plus authoritative redacted BrowserStack account-side revoked/inactive-key confirmation, using the available documented provider controls. Do not expose any credential value, invent an API endpoint or allocate a device session.
- Fixture readiness/cleanup: confirm source/workflow removal and live consumers, preserve history, and retain the recorded individual deletion authorization before taking any cleanup action. If account access is unavailable, record that concrete execution prerequisite and next action; keep provider revocation pending rather than inferring it from GitHub cleanup.
- Environment and source/shared dependencies: GitHub repository settings and authorized access to the BrowserStack account's key-management state; no source changes or paid-device run.
- Evidence: timestamped post-cleanup repository listings and redacted authoritative provider confirmation with non-secret account/key context, method and revoked/inactive result, or an explicit unavailable-access record. Retain historical evidence and original failure dispositions. [Cleanup evidence boundary](../implementation/SPN-151.md#-branch-specific-cleanup-evidence).
