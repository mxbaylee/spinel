# 🧷 SPN-076 Share a Doc with its formula sources

## Story

As the [Owner](../product/personas.md#owner), I want to know which source Sheets a recipient needs and share them deliberately, so that a report is useful without accidentally revealing other documents. [Collaborators](../product/personas.md#collaborator) need an explanation when another owner must grant access.

## Scenarios

### Sharing the report alone

Given a Doc contains formulas using another Sheet,
When I share it with a friend who cannot read that Sheet,
Then the dialog explains that some formulas will be unavailable and leaves **Also share source spreadsheets** unchecked,
And sharing the Doc alone leaves all source permissions unchanged.

### Including sources deliberately

Given I can share the required sources,
When I select that option,
Then the dialog lists the exact sources and recipient's proposed view access before I confirm,
And it never downgrades existing access or grants edit access implicitly.

### Another owner's source or a public link

Given I cannot share a required source or am creating a public link,
When I review dependencies,
Then inaccessible source names are not disclosed, another owner's grant is explained, and no public source link is silently created.

## Rules

- Migrated decision records: [Live authorized document formulas](../implementation/SPN-033.md#legacy-decision-113-live-authorized-document-formulas).

- SPN-047 handoff: One sharing task lists exact authorized source dependencies with unchecked opt-in; never grant sources implicitly. Follow [the composed design](../design/formulas.md) and decision [#126](../implementation/SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits) (2026-10-20); preserve current behavior and owner screenshot approval.

- Sharing suggestion from owner, chat 2026-10-20. SPN-033's unavailable state is the safe default; never substitute a saved result for permission. [#113](../implementation/SPN-033.md#legacy-decision-113-live-authorized-document-formulas).
- Recheck host and source sharing authority at confirmation. Report any partial failure accurately and leave formulas governed by each viewer's actual access.
- Public source publication requires a separately reviewed explicit flow; a host link alone remains host-only ([#72](../implementation/SPN-016.md#legacy-decision-72-scoped-anonymous-link-capabilities)). Operators cannot see source names or content.
- Update docs/design/sharing.md in its own prerequisite PR before building the new dialog pattern; screenshots and owner approval remain required.

- For Space-contained Docs, sharing acts on the outer Space, never a child. Same-Space sources already inherit access and need no checkbox. External standalone sources remain explicit; if an external source belongs to another Space, list and confirm access to that entire Space, never fabricate a child grant. Preserve guest cross-Space isolation (SPN-078, [#116](../implementation/SPN-078.md#legacy-decision-116-spaces-remain-files-in-folders)/[#117](../implementation/SPN-078.md#legacy-decision-117-whole-space-guest-capability)).

## Out of scope

- Automatic access requests, notifications, transitive sharing of unrelated documents, and copying source values into the host.

## Verify

- Unit and browser: unchecked default, exact source list, read-only grants, existing roles retained, source-owner refusal, revoked authority during confirmation, partial failure, and public-link isolation.
