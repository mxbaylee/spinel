# 🌗 SPN-088 Use a theme-aware palette in native editors

## Story

As the [Owner](../product/personas.md#owner), I want a small set of colors that remains readable in light and dark editors, so that styling a sheet or document does not depend on someone else's display preference.

## Scenarios
### A usable dark editing surface

Given a Sheet or Doc with default colors, legacy presets and custom formatting,
When an Owner, Collaborator or link guest changes the browser theme,
Then native editor chrome, formula input, headings and default canvas/text remain readable,
And the change does not rewrite saved formatting, add revisions or alter exported colors.

### Eight logical color choices when supported

Given a supported public Univer extension can customize the native color picker,
When I choose one of eight named semantic colors,
Then it has tested light/dark display pairs and a stable stored meaning,
And viewers see the same logical choice without gaining edit permissions.

### Honest fallback

Given public APIs cannot replace or extend the picker safely,
When feasibility is recorded,
Then keep the native picker and usable dark rendering without a separate persistent palette bar,
And document the limitation rather than patching SDK internals or changing user formatting.

## Rules
- Owner request, 2026-10-21, decision #126: aim for eight theme-aware choices; a usable native dark mode is acceptable meanwhile. Picker replacement is unverified, not promised.
- Investigate public APIs only; no Pro additions, private picker patches or global CSS inversion. Theme switching is supported: https://docs.univer.ai/guides/docs/ui/themes.
- Revisit `installCanvasColors` carefully: it currently avoids double-inverting mapped presets. Preserve legacy sixteen fill pairs, custom/imported colors, rich text, editing, exports and profile colors; update `docs/theme.md` with explicit storage/display semantics.
- SPN-050 owns removal of the separate fill toolbar. This ticket owns native palette feasibility and complete dark-canvas behavior, including Docs. Operator gains no document access or extra service.

## Verify
- Contrast tests; theme round trips, unchanged snapshots/revisions/exports and editor identity; legacy/custom colors and permission boundaries.
- Native Sheet/Doc Storybook and browser screenshots in light, dark and phone widths; public API feasibility evidence and owner review.
