# 🧬 SPN-056 Merge concurrent Sheet and Doc edits with Spinel's own code

## Story

As a [Collaborator](../product/personas.md#collaborator), I want my edits and the Owner's to merge the same way on both screens when we edit at the same moment, so that co-editing never loses or scrambles either person's work once Spinel stops using Univer's closed-source collaboration.

## Scenarios

### Two edits at once

Given two clients start from the same revision of a Sheet or Doc,
When each applies a different edit and then receives the other's,
Then both end with the same document, and neither edit is lost.

### Rows move under a cell edit

Given one person inserts, deletes or moves rows or columns while another edits a cell, range or merge below them,
When both edits are merged,
Then the cell edit lands on the same content it targeted.

## Rules

- First of four tickets that replace Univer collaboration (SPN-056 to SPN-059, split from SPN-014). The owner decided to rewrite it. Owner, chat 2026-10-19.
- Build it as `lib/sync-transform/`, a module that could be published on its own (AGENTS.md). Univer packages are peer dependencies. Owner, chat 2026-10-19.
- Cover the mutations Spinel's editors can produce today: the sheets core preset (cell values and styles, row and column insert, remove, move, size and hide, merges, number formats, frozen panes, sheet add, remove, rename, reorder and tab colour, range moves) plus sheet and doc drawings. Docs use open-source `JSONX`/`TextX` `transform` and `compose` from `@univerjs/core`.
- Derive transforms from the open-source mutation definitions in `@univerjs/sheets` and `@univerjs/docs`. Never read, decompile or copy `@univerjs-pro/collaboration` (AGENTS.md). Today's Pro transforms are about 295 type files, mostly row/column moves and protection.
- A mutation without a transform is rejected rather than guessed at. List which menus can produce it, so SPN-059 can hide them.
- Pure TypeScript with no server or DOM dependency, so SPN-057 and SPN-058 share it.
- Spike row/column moves against range edits first. If they alone exceed this ticket, split them off.

## Out of scope

- Range and worksheet protection, filters, conditional formats, data validation, comments and hyperlinks, which Spinel doesn't load. The server and client (SPN-057, SPN-058).

## Verify

- Unit: each transform pair, including insert-then-delete and move-over-move.
- A seeded fuzz test: two simulated clients make random edits from the supported set, and 100,000 operations converge to identical snapshots. It prints the seed when it fails.
