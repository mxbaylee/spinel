# 📴 SPN-039 Use selected documents offline and sync safely

## Story

As the [Owner](../product/personas.md#owner), I want Spinel and my file list to open without a connection, choose documents to keep on this phone, and reopen my edits later, so that I can work away from the network without losing changes. Signed-in [Collaborators](../product/personas.md#collaborator) get the same experience within their document permissions.

## Scenarios

### Launch and browse offline

Given this account has prepared its installed app online and downloaded a Sheet and a Doc with images,
When I close it, enable airplane mode and launch it again,
Then my local theme and last-synchronized folder/file catalog appear without a server request being required; downloaded items open completely while other known items clearly say they need a connection.

### Save, restart and reconnect

Given I edit a downloaded item offline while a collaborator edits its live version online,
When local saving completes, I close/reopen offline and later reconnect,
Then my committed edits survive with clear local-save/synced states, no duplicate replay or silent overwrite; access loss, deletion or history replacement preserves pending work for explicit recovery without writing into a forbidden or replaced document.

### Open a document from the home screen

Given a downloaded item has a stable link,
When I use the supported browser's home-screen shortcut flow and later launch it online or offline,
Then it targets that same item after rename/move and uses the store containing its downloaded content, with a documented useful fallback where separate item icons are unsupported.

## Rules

- The complete [offline acceptance contract](../offline.md), including all four personas, storage/access lifecycle and device evidence, is required. Owner's draft, chat 2026-10-18; #83 records this scope and supersedes #82's no-offline-feature policy for this follow-up when implemented. SPN-028 owns installation/touch and the initial generic fallback; public deployment and Slides are not prerequisites.
- Start with the contract's bounded public-SDK cold-start/restart probe, then implement through the existing collaboration boundary. Failure requires exact evidence and concrete integration work, not closure or silent reduction. Split per process.md with every unmet acceptance criterion on an open ticket. Engine replacement or paid/licensing changes retain existing owner decisions.
- Scope storage to the opted-in instance/account/device; preserve viewer/editor rights, guest/authentication exclusions and pending work through failures/account changes. Revalidate before remote reads/sync; preserve item/unit/generation/operation identity without whole-snapshot overwrite. Sync while running; separate pins, downloads and shortcuts, verify persistence before claiming a save, and update affected docs/tests as specified in the contract.

## Out of scope

- Native apps, guest/admin offline mode, Slides, offline creation of new items/images, offline folder/sharing administration, and guaranteed synchronization while the app is closed.

## Verify

- Exercise both Sheets and Docs: download online, terminate, launch/edit/reopen twice offline, reconnect alongside another editor, then verify both views and server state. Include existing images, same-cell/text edits, lost acknowledgements, history restore, revoked/view-only access and account isolation.
- Test incomplete downloads, unavailable items, failed writes/eviction, removal with pending work and application/storage updates. Run deterministic CI cases plus actual Android Chrome/Firefox and iPhone Safari Home Screen checks; record browser versions, item-link launch/storage behavior and supported fallbacks. An open-tab disconnect or mobile viewport alone is insufficient evidence.
