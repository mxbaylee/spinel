# 🪩 SPN-150 Review and complete Spinel branding across the product

## Story

As the [Owner](../product/personas.md#owner), I want Spinel’s identity and document artwork used consistently, so that every screen and creation choice feels like the same product.

## Scenarios

### Branding has no unexplained gaps

Given the homepage New dropdown, navigation, loading, account/Admin, editor/guest, empty/error and installed-app entry surfaces,
When their use of the existing gem, wordmark, entity artwork and theme is reviewed,
Then missing or inconsistent branding is corrected, including branded type icons in the homepage New choices,
And accessible text, contrast, focus and phone layouts remain clear.

### A slow start looks like Spinel

Given initial HTML or app loading is visible,
When startup is slow,
Then both show the Spinel wordmark and gem with gentle motion that respects reduced motion.

## Rules

- [Expanded branding scope](../implementation/SPN-150.md#-product-branding-review), owner chat 2026-11-22; SPN-152 is dropped, not repurposed. Preserve the original loading acceptance and [allocation provenance](../implementation/SPN-150.md#-registration-and-retained-scope).
- Effort M: inventory all visible entry/identity/type surfaces first, classify intentional absence versus a gap, then apply existing artwork and verify every changed state. Reassess before new artwork, a new pattern or broad redesign; record remaining work explicitly if split.
- Current baseline: `web/index.html` has an empty root; `web/App.tsx` uses loading text. `web/Dashboard.tsx` New choices supply labels but no icons. Earlier unmerged SPN-090 loading proposals are historical evidence.
- Reuse `GemLogo`, `EntityIcon`, existing app icons and theme tokens; do not replace user-selected file identity or turn functional actions into decorative branding. Distinguish type artwork from item identity and action icons.
- Follow the [design playbook](../design/README.md), [sustainable testing](../testing.md) and production-story rule. Add any missing design pattern in its own reviewed PR first. Coordinate title cues with SPN-089 and action consistency with SPN-162; SPN-087 preserves behavior.

## Out of scope

- New brand identity, startup diagnostics/progress or changed permissions; a separate physical-phone qualification campaign.

## Verify

- Contract/negative: inventory each surface and disposition; missing type artwork and inconsistent startup branding must be detectable. Existing `GemLogo`/`EntityIcon` stories, `web/Dashboard.stories.tsx` and `e2e/branding.spec.ts` own their distinct boundaries; verify actual paths at kickoff.
- Reuse production-component stories for affected states and reduced-motion checks; await fonts/layout/interaction readiness and clean up fixture state. Existing branding e2e owns browser/app metadata, not duplicate component permutations.
- Route affected branding assets, components, HTML, shared styles/tokens and fixtures to their owning checks. Preserve accessible names and contrast for all personas.
- Retain the complete audit, proposed designs and actual light/dark/phone captures with source/theme/viewport identities; obtain independent nonimplementing visual approval, explicitly agent review only.
