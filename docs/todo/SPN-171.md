# 🪓 SPN-171 Remove dead behavior inside live modules

## Story

As the [Operator](../product/personas.md#operator), I want unused branches, flags and test-only paths inside live modules removed with evidence, so that maintained paths are simpler without losing recovery or CLI entry points.

## Scenarios

### Retire only proven dead behavior

Given the importer-less modules, public APIs and entry points that [SPN-087's inventory](../implementation/SPN-087.md#-repo-wide-inventory-checkpoint-2026-11-23) retained,
When a branch, flag, export or test-only path inside a live module has no production caller,
Then it is removed only with feature-level evidence, and Owner, Collaborator, Operator and Link guest behavior, persistence, access and diagnostics contracts are unchanged.

## Rules

- Continues SPN-087's expanded scope; its owner, persona impacts and the remaining estimate carry over. SPN-087 landed the inventory, 22 CSS classes, seven exports and functions, the editor state machine and `coast.jpg`.
- Known candidate: `sanitizeBootstrapSnapshot` in `src/shared/bootstrapEvidence.ts` is used only by tests. Removing a test-only export also removes its tests, so review per feature. Other test-only exports are not yet enumerated; the [inventory file](../implementation/evidence/SPN-087/inventory-2026-11-23.json) lists the candidates.
- A no-reference search is not proof. Check imports, lazy modules, SDK/plugin registration, scripts, config, stories, selectors and dynamic names. [Reviews grade code removal](../implementation/SPN-087.md#decision-code-removal-in-the-review-rubric).
- Retain evidence assets and externally consumed entry points. SPN-089 owns SPN-146 diagnostics and the doc-native scripts. Do not revive retired Redesign screens. Use plain modules and no cleanup framework. Preserve or explicitly reassess [diagnostic contracts](../diagnostics.md#emitter-maintenance-inventory).
- Follow [sustainable testing](../testing.md); keep the Verify plan and progress evidence current. [Policy](../implementation/SPN-115.md#guidance-for-every-open-ticket-and-progress-checkpoint), owner 2026-11-01.

## Out of scope

- New features, changed design, permissions or persistence, and deleting evidence. Runtime hangs are separate defects, not cleanup by deletion. Branding (SPN-150), action consistency (SPN-162) and title cues (SPN-089) keep their own outcomes.

## Verify

- Contract/negative case: each removal's caller search plus the owning test layer, per [docs/testing.md](../testing.md).
- Fixture readiness/cleanup: existing deterministic fixtures only.
- Environment and source/shared dependencies: typecheck, lint and the unit suite that owns each touched module.
- Pure non-visual removals need focused behavioral evidence, not screenshots; fewer lines or tests alone is not acceptance.
- Evidence: PR records every removal with proof and every retained candidate with its reason; CSS or story changes add the full Storybook suite and five-variant before/after captures.
