# 🌅 SPN-003 Set up the first admin on a new instance

## Story

As the [Operator](../product/personas.md#operator), I want to claim a brand-new instance as its admin, so that nobody else can reach it first and lock me out.

## Scenarios

### Claiming a new instance

Given a server with no users,
When I run the setup command on the server,
Then it prints a one-time setup link that expires in 30 minutes,
And opening it lets me register a passkey as the admin,
And the admin account lands on the admin panel, with no dashboard or documents.

### Setup is closed once claimed

Given an admin exists,
When anyone opens a setup link or runs the command again,
Then setup is refused and no account is created.

## Rules

- The setup secret is only shown on the server's console, never over the network. Grooming, 2026-10-17.
- Admin is a flag on the user (`is_admin`), as in the PRD schema.
- The setup command is a TypeScript script (`.ts`), never `.js` or `.mjs`. Owner, chat 2026-10-17.
- Admin accounts can't view, edit or create documents, including through share links. The Operator invites a separate everyday account for that (SPN-004). Owner, chat 2026-10-17.

## Out of scope

- Inviting other people (SPN-004).

## Verify

- Unit tests: setup only while no users exist; token is single-use and expires.
- Playwright: claim a fresh instance, then confirm a second claim fails.
