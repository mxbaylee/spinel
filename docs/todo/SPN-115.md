# 🪡 SPN-115 Run Univer Docs UI unpatched after the callback fixes ship

## Story

As the [Owner](../product/personas.md#owner), I want Spinel to use stock Univer Docs UI once its callback fixes ship, so that upgrades preserve responsive editing without a local SDK patch.

## Scenarios

### A suitable upstream release replaces the temporary repair

Given a released Univer version owns cursor and zoom callbacks through replacement and disposal,
When Spinel upgrades all Univer packages together and removes the temporary Docs UI repair,
Then installation leaves Docs UI unmodified and the SPN-113 callback, responsiveness, content, selection, sync and Undo/Redo regressions pass.

### Upstream takes a different approach

Given upstream changes or declines the proposed repair,
When a candidate release is evaluated,
Then use supported upstream behavior and retain the original acceptance requirements; an unsuitable release leaves this ticket open.

## Rules

- Owner requested an upstream PR and a later unpatch ticket like SPN-099 in chat, 2026-10-27; [temporary repair and removal decision](../implementation/SPN-113.md#temporary-open-source-repair-and-upstream-removal). This follow-up is after launch, like SPN-099, and does not delay launch once SPN-113 is complete.
- The prepared [upstream source repair and evidence](https://github.com/mxbaylee/spinel/tree/7e16a4d49a94e47841c81610c36c100c2582873f) preserve both timeout fixes and lifecycle tests. Upstream publication currently needs GitHub integration write access to `mxbaylee/univer` (HTTP 403); publish the prepared branch/PR, then add its actual URL to `upstream_prs`. No PR or release is implied by this source checkpoint.
- Recheck the actual upstream PR and selected release before implementation. PR merge alone is insufficient: the released packages must include both fixes, keep all `@univerjs/*` versions aligned and pass the registered acceptance on stock code.
- Remove `scripts/dependencies/patch-univer-docs-ui.ts`, its patch-specific tests, its postinstall command, the Docs UI notice and maintained temporary-repair instructions. Preserve behavioral lifecycle regressions beside the code they cover.
- Preserve independent core, UI-resize and drawing repairs until their own release checks pass; SPN-099 remains separate. Do not introduce a replacement local callback patch to avoid adapting to supported upstream behavior.

## Out of scope

- Removing other SDK repairs or relaxing SPN-108/SPN-113 latency, integrity or permission gates.

## Verify

- Fresh `npm ci` leaves Docs UI byte-identical to the selected published package; no executable `patch-univer-docs-ui` references remain.
- Native desktop/mobile callback lifetimes, blinking, zoom, exact content/selection, Undo/Redo, saved/peer convergence, composition and denied/revoked access pass; all required CI and independent reviews pass.
