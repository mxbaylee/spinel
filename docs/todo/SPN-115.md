# 🧭 SPN-115 Run CI coverage for the changes that need it

## Story

As the [Operator](../product/personas.md#operator), I want CI to run the coverage required by each change, so that updates get prompt, trustworthy feedback without repeating unrelated expensive work.

## Scenarios

### Select coverage without silently losing a required gate

Given a known change range and PR event, main push or scheduled/manual full run,
When CI computes and publishes its test plan,
Then relevant correctness checks run automatically and labels can add coverage,
And each stable required aggregate fails if its selected evidence is missing, cancelled or unsuccessful.

## Rules

- Follow the [CI audit and proposed routing contract](../implementation/ci-reliability-2026-10-28.md#coverage-routing), agent judgment responding to the owner's flaky-main/PR-label question, 2026-10-28. Implement policy changes here after this registration lands; existing gates still apply to its own PR.
- Separate current-candidate native typing/content/save/peer/undo/composition/permission checks from the historical paired baseline/profile comparison. Keep affected correctness and existing latency contracts automatic; run full comparisons for relevant performance/input/history/SDK/harness changes, `ci-performance`, `ci-full`, and scheduled/manual full coverage.
- Classify the complete immutable change range and dependency closure, including deleted/renamed paths, auth, persistence, sync, runtime, build and lockfiles. Unknown paths, missing ranges and ambiguous events select full coverage. A label can add work, never remove path-required work.
- Isolate title/body-only edits to cheap PR validation without cancelling or replacing pending/failed code evidence with green skipped checks. Base retargets and ambiguous edits require full validation; label events recompute the plan. Preserve the immutable event base and seven required check names.
- Map every repeated phone scenario to its HTTP/HTTPS, development/production and instrumented/plain contract before removing duplicate executions. Keep unique behaviors and all assertions; stage broader soak/transition/container routing only with equivalent coverage evidence.
- Introduce scheduled/manual full coverage before reducing routine coverage and retain every failure artifact. BrowserStack/live-provider runs keep their existing authorized path/manual scope. Leave PR-result reuse to a separate future decision; main still runs its selected validation.
- Preserve `failOnFlakyTests`, exact content/access/integrity assertions, bounded retries and existing budgets. Routing does not resolve SPN-116's failures or waive SPN-113 acceptance. Operator feedback improves; all other personas retain their existing protection.

## Out of scope

- Repairing application/runtime defects, weakening acceptance, or deleting tests solely because they fail intermittently.

## Verify

- Classifier and aggregate tests cover ordinary and unknown paths, dependency changes, labels added/removed, metadata edits, base retargets, direct pushes, missing/cancelled jobs and scheduled/manual runs. Publish selected/inapplicable reasons and verify expected check names on actual GitHub events.
- Full final-revision CI plus a bounded before/after job-duration and coverage comparison; unchanged candidate correctness and first-attempt failure behavior. Update maintained workflow policy with the implemented scope.
