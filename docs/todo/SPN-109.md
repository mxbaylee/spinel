# 📦 SPN-109 Configure backup destinations and download encrypted workspace backups

## Story

As the [Operator](../product/personas.md#operator), I want clear backup policy and an encrypted download in Admin, so that I can retain a recovery copy without using a shell.

## Scenarios

### Download without cloud configuration

Given a recovery key and valid runtime/image metadata,
When I freshly authenticate and request a workspace backup,
Then the real shared backup job creates an encrypted bundle and streams an authorized download,
And cancellation, expiry and restart clean bounded staging without exposing contents.

### Choose an automatic destination

Given validated deployment configuration for filesystem or DigitalOcean Spaces,
When automatic backup runs,
Then publication, catalog retrieval and retention use the shared recovery services,
And Admin shows effective policy, actual destination and separate offsite/verification coverage.

## Rules

- Follow the [backup-options decision](../implementation/SPN-063.md#proposed-backup-options-and-assisted-restore) and [local implementation boundary](../implementation/SPN-063.md#accepted-decision-implement-recovery-before-deployment), owner chat 2026-10-27; originating implementation PR #205.
- Keep SQLite concrete. Extend existing destination transport; preserve current filesystem/Spaces configuration compatibility and independent CLI recovery.
- Deployment owns credentials/policy. Fixed workspace/diagnostics dataset names; no arbitrary file/SQL/backend input. Live TTL, artifact retention and document history stay independent.
- Fresh Operator authorization, CSRF/origin protection, private job state and short-lived delivery capability. Stream bounded bytes; no browser/server buffering of whole archives, content preview or key bundled with download.
- A catalog shows only complete artifacts and holds active selections against retention. Spaces needs actual private-access/signing/publication tests; actual encrypted mount, credential rotation, capacity/performance and timed cold recovery remain SPN-038 launch gates.
- Owner narrowed this delivery to filesystem and DigitalOcean Spaces in [PR #207](https://github.com/mxbaylee/spinel/pull/207#issuecomment-6459209587); its reserved SPN-114 moves the AWS S3 preset after launch. Do not allocate SPN-114 again or reintroduce AWS as a launch prerequisite. The PR's [passing Spaces probe](https://github.com/mxbaylee/spinel/actions/runs/40621660304/attempts/2) is real provider evidence, not a merged feature or target-host acceptance. [Current checkpoint](../implementation/grooming-2026-10-27.md#concurrent-work), grooming 2026-10-27.
- Operator gains a simple export; Owner keeps a complete encrypted workspace; Collaborator and Link guest permissions and acknowledged work remain protected. Independent light/dark/phone review applies.

## Out of scope

- Live workspace activation (SPN-112), edit pause/restart control (SPN-111), diagnostics event expiry (SPN-110), AWS S3 preset (SPN-114 reserved in PR #207).

## Verify

- Real local browser create/download round trip, key/auth/cancel/large-input failures, job contention, catalog/retention holds and restart cleanup; no cloud credentials in manual-only mode.
- Destination contracts and supported real-provider acceptance; current light/dark/phone stories, screenshots and independent visual review.
