# 🪴 SPN-048 Declutter the dashboard

## Story

As the [Owner](../product/personas.md#owner), I want a calm dashboard that leads with my files, so that I can find a document without scanning past controls. [Collaborators](../product/personas.md#collaborator) get the same layout within their access.

## Scenarios

### Files first

Given I open the dashboard,
When it loads,
Then the file list is the main content, and search and filters follow [the dashboard pattern](../design/dashboard.md).

### Shared items in the sidebar

Given things are shared with me,
When I look for them,
Then they are where the playbook puts them, not in a drawer above my files.

### One search, two ways to refine it

Given I am finding an accessible file,
When I type plain text with optional qualifiers such as `type:sheet tag:travel`, or choose the same values in **Search options**,
Then both edit one query and show the same labelled, colored, individually removable chips,
And clearing a chip changes only that filter; clearing search returns to my prior folder context.

### Quieter rows and header

Given a row in the file list,
When I want to tag, pin, move or trash it,
Then those actions are where the playbook puts them, reachable by keyboard and touch,
And the header follows the playbook's header pattern.

## Rules

- SPN-047 handoff: One optional rail-pink navigation column with pins; folders and permanent Trash in My files; list/grid views with filename-hash emoji defaults (picker deferred to SPN-086); one New menu, scoped search and row More; tablet/phone drawer. Follow [the composed design](../design/dashboard.md) and decision #126 (2026-10-20); preserve current behavior and owner screenshot approval.

- All four areas are cluttered: the search/filter panel, the Shared-with-me drawer, per-file controls and header actions. Owner, chat 2026-10-19.
- Build what [docs/design/dashboard.md](../design/dashboard.md) decides. Design changes go back into the playbook, not only into this PR. Owner, chat 2026-10-19.
- Reorganise, don't remove: search (SPN-022), shared filing (SPN-018), tags, pins, trash and import all stay reachable, and their tests still pass. No hover-only actions, because the installed phone app (SPN-028) has no hover.
- Owner refinement, 2026-10-20, [#126](https://github.com/mxbaylee/spinel/issues/126): replace separate filter rows with one search field and **Search options** form/help using the same query. Optional qualifiers and chips map only to existing `q`, `type`, `owner`, `tag`, `modified` fields; preserve [search matching, bounds, scope and authorization](../search.md). No new backend grammar or index.
- Plain text remains sufficient; the form requires no syntax knowledge. Chips have text labels and explicit remove controls, never color alone. Support keyboard editing/removal, touch, paste, incomplete/invalid qualifiers and a plain-text fallback without silently dropping filters or broadening scope. Keep the current folder/search scope visible and preserve retrieval state when opening and returning from a file (#126).
- Keep ancestor breadcrumbs, the current folder title and its search/list together; show the current folder name once. Resolve displayed paths only from accessible metadata; Operators and Link guests gain no file search (#126).

- A Space (SPN-078), when available, is one file row inside existing folders, using SPN-077 artwork. Its internal tree belongs inside the opened file; it does not replace dashboard folders or personally filed shares (#116).

## Out of scope

- The editor screens (SPN-049). The sidebar's theme and profile controls (SPN-045). Saved searches, Boolean/regex syntax, content indexing and new search filters.

## Verify

- The existing dashboard Playwright flows pass, updated only for new locations. Before/after screenshots in light, dark and phone width are in the PR.
- Unit: qualifiers/form/chips round-trip to the same existing query; malformed input, literal colons, quoted values and limits never silently alter search. Storybook/Playwright: plain text, options form, active/removable chips, keyboard/touch, empty/error results, nested breadcrumbs and file-return state; retain shared-path privacy and denied Operator/Guest coverage.
