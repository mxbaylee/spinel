# 🛡️ SPN-017 Enforce permissions on live connections

## Story

As the [Owner](../product/personas.md#owner), I want the server to refuse edits from anyone who only has view access, even over a live connection, so that sharing for viewing can never change my document.

## Scenarios

### Connecting

Given someone opens a document,
When their browser opens the live connection,
Then the server checks their session or link token and their role before accepting it,
And refuses it with no document data if either is missing.

### View-only connections

Given a viewer's connection,
When it sends an edit,
Then the server drops it, logs it and the document is unchanged.

### Access changes mid-session

Given an editor is downgraded to viewer or removed,
When they next send an edit,
Then it is refused and their editor switches to read-only or closes.

## Rules

- Check on the upgrade request, not after. PRD §4.
- Treat every client message as untrusted, including from editors. Refuse admin sessions on every document route and connection (SPN-003).

## Out of scope

- The permission model itself (SPN-015).

## Verify

- Unit tests that send edits from view-only and revoked connections.
- A test that opens a raw WebSocket without a cookie and gets nothing.
