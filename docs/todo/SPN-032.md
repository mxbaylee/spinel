# 📈 SPN-032 Show server health and export structured diagnostics

## Story

As the [Operator](../product/personas.md#operator), I want server health and downloadable frontend/backend diagnostics, so that I can investigate trouble and have an external agent inspect a reproduced scenario without exposing document contents.

## Scenarios

### At a glance

Given I am the admin,
When I open Diagnostics,
Then I see memory use against the 2 GB budget, live editor connections, application/collaboration and diagnostics database sizes and growth, and the last run of pruning, purge and backup jobs.

### Something is wrong

Given a job failed or memory is above 80%,
When I open the admin panel,
Then a banner says what and since when.

### Inspect a reproduced scenario
Given frontend, backend and library instrumentation emits structured events,
When I exercise a scenario and download diagnostics as the Operator,
Then I receive a consistent standalone SQLite snapshot with JSON details, leveled logs and typed metric observations,
And I can correlate user/file IDs, route templates and operation/run IDs and query it locally; the admin panel has no query UI.

### Clear diagnostics
Given I am the Operator,
When I confirm Truncate diagnostics,
Then stored and queued records before the clear boundary, including user feedback when present, are removed without touching documents, accounts, backups or collaboration state,
And new records can continue; cancel changes nothing and a failed clear is not reported as successful.

## Rules

- SPN-047 handoff: Backups & health section: status words, last success and action/guide; no document details. Follow [the composed design](../design/admin.md) and decision #126 (2026-10-20); preserve current behavior and owner screenshot approval.

- Use docs/deployment.md as the measured host baseline. Report unimplemented jobs as not configured; collect metrics without granting the app a Docker control socket or access to document contents. Decided 2026-10-17 in #23.
- Reuse the landed backup status and instrument the existing history-prune scheduler, trash expiry, collaboration purge queue and restore-generation cleanup. Account metadata in docs/admin.md is separate; aggregate health remains absent. PRD §9 item 3; grooming #60, 2026-10-18.
- Health cards remain read-only. Diagnostics adds only Download and confirmed Truncate; no live query API, SQL console or log browser. Owner, chat 2026-10-22; [scope and decisions](../implementation/SPN-032.md).
- Use a separate diagnostics SQLite database on the protected data volume, with versioned schema, indexed event envelope and validated JSON details. Logs have levels; metric types/units/numeric values have explicit semantics. Keep raw observations initially; advanced rollups/compaction are deferred.
- Provide a shared typed, optional instrumentation interface for libraries and frontend/backend code. Adapters own batching, database writes and browser transport; pure transforms never do I/O. Evaluate Pino's Node/browser support before building a logger; no dependency is selected by this ticket alone.
- Include authenticated user IDs, authorized file IDs, route templates and opaque correlation IDs when relevant. This supersedes the earlier counts-only diagnostic restriction for these identifiers only. Automatic diagnostics never collect document titles/content, edits/formulas, credentials, share tokens or raw URLs/query strings; sanitize log messages and JSON too. Server assigns actor identity and validates file context; client origin remains explicit and untrusted. SPN-098 separately permits explicitly submitted feedback text.
- Browser telemetry uses an authenticated, origin-checked bounded transport; prefer a small socket adapter if it fits the public transport boundary. Revocation/disconnect stops collection for that session; no Pro internals or coupling to durable edit delivery. Only Operators can download/truncate; guest telemetry, if supported, is limited to its current grant and a non-secret pseudonymous actor.
- Bound event size, queues, ingest rate and total storage from the start; drop/report diagnostics loss without failing edits. Download uses a consistent snapshot, never a raw live DB/WAL copy; clean up temporary exports. Truncate cannot resurrect buffered/retried pre-clear records. Exact limits and retention defaults are implementation decisions to document.
- Also show free space on the encrypted volume against backup staging (twice the database plus 256 MiB) and nearness to the 5 GiB backup upload ceiling (docs/backups.md). Grooming, 2026-10-19.
- Report physical database and WAL bytes without double-counting shared application/collaboration files; show diagnostics separately and keep volume free space distinct. Clearing records need not shrink the file immediately. Owner confirmed DB size visibility, chat 2026-10-22.
- Record SPN-056's sync refusals and silent drops as listed in [its events](../implementation/SPN-032.md#sync-transform-refusals-and-drops); redacted refusal shapes [need the owner](../implementation/SPN-032.md#reproducing-a-refusal-without-document-content). Owner request, chat 2026-10-22.
- Add an unauthenticated `/healthz` that reveals nothing but up or down, and document one free external check that hits it, because an in-app page can't report a server that is down or waiting for its volume to be unlocked after a reboot. Grooming, 2026-10-19.

## Out of scope

- Paging, hosted monitoring, an in-product agent, a query interface, comprehensive tracing, advanced compaction and instrumenting every operation.

## Verify

- Unit: metric/log validation, identity spoofing/redaction, current access, limits/drop behavior, deduplication where retries exist, concurrent export/truncate, buffered-event clearing and `/healthz` minimality.
- Browser: seeded health/failure states, frontend-to-store correlation, Operator-only download/truncate, cancellation/failure and expired sessions. Open the exported SQLite file and run documented example SQL; prove it contains the scenario's logs/metrics and no app tables or secrets. Storybook covers new controls in light/dark/phone; owner approval remains required.
