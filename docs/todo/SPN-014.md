# 🛠️ SPN-014 Replace Univer collaboration with our own sync

## Story

As the [Owner](../product/personas.md#owner), I want a fallback for co-editing that Spinel controls, so that Univer's unlicensed limits or a change on their side can't take away editing together.

## Scenarios

### Switching over

Given the owner has decided Univer's collaboration is unusable,
When this ticket lands,
Then two editors can edit the same sheet and doc with presence, as in SPN-012,
And existing documents open with no loss.

## Rules

- We use Univer's collaboration as-is or build our own. Only start this when the owner says so, using SPN-010's findings. Owner, chat 2026-10-17.
- Replace the module SPN-012 isolates; keep the editor and storage untouched where possible.
- The sync server and client are TypeScript, never `.js` or `.mjs`. Owner, chat 2026-10-17.
- Expect the hard parts to be merging concurrent edits to the Univer document model and reconnect replay. Spike those first and split the ticket if they are bigger than this one.

- Preserve landed session/grant checks, guest identity and revocation, native checkpoint materialization, restore generations and purge handling, with their regressions. Replacement cannot reset the baseline to SPN-012 alone. Grooming #92, 2026-10-19.

## Out of scope

- New capabilities beyond the existing collaboration and its landed access/history integrations.

## Verify

- Existing collaboration, guest/revocation, checkpoint, restore-generation and purge regressions pass against the new module.
- A long-running two-editor fuzz test finds no divergence.
