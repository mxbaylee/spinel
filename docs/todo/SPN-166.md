# 🎲 SPN-166 Stop the sync-production smoke job from flaking

## Story

As the [Operator](../product/personas.md#operator), I want the `sync-production` Playwright smoke job to pass or fail for real reasons, so that a green gate means the sync paths work and a flake does not cost a re-run.

## Scenarios

### One transient reset does not decide the gate

Given the `sync-production` project runs its offline-recovery cases,
When the test server resets a connection during a setup request,
Then the cause is identified and either fixed or the case fails with a clear diagnostic, rather than passing on retry and still failing the job.

## Rules

- Follow [sustainable testing](../testing.md); keep the Verify plan and progress evidence current. [Policy](../implementation/SPN-115.md#guidance-for-every-open-ticket-and-progress-checkpoint), owner 2026-11-01.

- Observed on [PR 289](https://github.com/mxbaylee/spinel/pull/289), CI run 43789748511, attempt 1: `offline-recovery.spec.ts:342` ("Space child sheet: trashed live document yields one owned copy and leaves original untouched") hit `ECONNRESET` on `POST /api/items/<id>/collaboration` in `copySnapshot` and passed on retry. 99 passed, 1 flaky, and the job still exited 1. Re-running the failed jobs passed (attempt 2).
- The cause is **not diagnosed**: it could be the test server dropping a connection under load, a test setup race, or a product bug in that endpoint. Find out which before changing any test.
- Do not weaken the gate. No exclusions, added retries, relaxed assertions or budgets; a flaky pass must keep failing the job unless the cause is fixed. The `Playwright smoke` aggregate stays required.
- Check whether the same case or endpoint flaked on earlier runs (workflow history), and record the count.

## Out of scope

- Other Playwright projects, unless the same cause shows up there.

## Verify

- Contract/negative case: the reset reproduces or is ruled out with evidence, and the resulting fix or diagnostic is covered; suite/layer/fixture: the existing `sync-production` project and its fixture.
- Fixture readiness/cleanup: the existing offline-recovery fixture and server lifecycle.
- Environment and source/shared dependencies: `e2e/offline-recovery.spec.ts`, the collaboration endpoint, the CI plan for the `sync-production` job.
- Evidence: repeated runs of the project with no flake, linked by run id, and the workflow history count from before.
