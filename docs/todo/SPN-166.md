# 🎲 SPN-166 Stop the Playwright smoke jobs from flaking

## Story

As the [Operator](../product/personas.md#operator), I want the Playwright smoke jobs to pass or fail for real reasons, so that a green gate means the product works and a flake does not cost a re-run.

## Scenarios

### One transient failure does not decide the gate

Given a smoke project runs a case that has flaked (the examples below),
When it fails on a first attempt and passes on retry,
Then the cause is identified and either fixed or the case fails with a clear diagnostic, rather than passing on retry and still failing the job.

## Rules

- Follow [sustainable testing](../testing.md); keep the Verify plan and progress evidence current. [Policy](../implementation/SPN-115.md#guidance-for-every-open-ticket-and-progress-checkpoint), owner 2026-11-01.

- Observed on [PR 289](https://github.com/mxbaylee/spinel/pull/289), CI run 43789748511, attempt 1: `offline-recovery.spec.ts:342` ("Space child sheet: trashed live document yields one owned copy and leaves original untouched") hit `ECONNRESET` on `POST /api/items/<id>/collaboration` in `copySnapshot` and passed on retry. 99 passed, 1 flaky, and the job still exited 1. Re-running the failed jobs passed (attempt 2).
- The cause is **not diagnosed**: it could be the test server dropping a connection under load, a test setup race, or a product bug in that endpoint. Find out which before changing any test.
- Impact raised from M to L (agent decision, 2026-11-17, owner to confirm): the required `Playwright smoke` gate blocks every merge, and three cases in three projects have now cost reruns of about 20 minutes each on two PRs, which blocks the Operator's main job of landing tickets.
- More examples, all passing on retry and failing the job, none diagnosed:
  - [PR 294](https://github.com/mxbaylee/spinel/pull/294), CI run 43992274196, attempts 1 and 2: `restore.spec.ts:95` ("sheet preview is read only and restore preserves the state seen by both editors") in `development 2/2`, position 8 of 82, failed its first attempt both times and passed on retry. The preview popup never showed the heading "Preview — Restore example" in 5 s and showed the history page instead. It passed first try on main's run 43967042239 in the same position and passed locally twice. PR 294 changes nothing near it.
  - Same run, attempt 1: `offline-upgrade.spec.ts:675` ("interrupted emitted updates preserve exact native work, a live old client and cold offline startup") in the `offline-upgrade` project. The emitted worker stayed `installed` and never activated for 120 s; it passed on retry and on attempt 2.
- Do not weaken the gate. No exclusions, added retries, relaxed assertions or budgets; a flaky pass must keep failing the job unless the cause is fixed. The `Playwright smoke` aggregate stays required.
- Check whether each case or endpoint flaked on earlier runs (workflow history), and record the counts. If two examples share one cause, say so; if not, split by cause at the first checkpoint and keep the estimate honest (M was sized for one example).

## Out of scope

- Playwright cases that have not flaked in recorded history.

## Verify

- Contract/negative case: the reset reproduces or is ruled out with evidence, and the resulting fix or diagnostic is covered; suite/layer/fixture: the existing project and fixture of each example (`sync-production`, `development`, `offline-upgrade`).
- Fixture readiness/cleanup: the existing offline-recovery, restore preview and offline-upgrade fixtures and server lifecycle.
- Environment and source/shared dependencies: `e2e/offline-recovery.spec.ts`, `e2e/restore.spec.ts`, `e2e/offline-upgrade.spec.ts`, the collaboration endpoint, the CI plan for the affected jobs.
- Evidence: repeated runs of each affected project with no flake, linked by run id, and the workflow history count from before.
