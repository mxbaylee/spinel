# 🔌 SPN-058 Sync the editors and presence through Spinel's own client

## Story

As the [Owner](../product/personas.md#owner), I want Sheets and Docs to send my edits, show others' edits and show where everyone is through Spinel's own client, so that co-editing keeps working without Univer's closed-source client. [Collaborators](../product/personas.md#collaborator) and [Link guests](../product/personas.md#link-guest) see the same.

## Scenarios

### Editing together

Given two editors have a Sheet open,
When one types in a cell,
Then the other sees it within a second, and both see each other's cursor and selection.

### Reconnecting

Given my connection drops while I have unsent edits,
When it returns,
Then my pending edits are transformed against what arrived meanwhile and sent once, and nothing reports saved until the server confirms them.

## Rules

- Migrated decision records: [Offline ephemeral cursor handling](../implementation/SPN-012.md#legacy-decision-45-offline-ephemeral-cursor-handling), [Scoped anonymous link capabilities](../implementation/SPN-016.md#legacy-decision-72-scoped-anonymous-link-capabilities), [Profiles and public Sheet following](../implementation/SPN-036.md#legacy-decision-127-profiles-and-public-sheet-following).

- Exercise native Space children as well as standalone files: switching pages cannot leak a previous room, pending status or identity; root revocation/downgrade fences all child sessions. Retain SPN-043 reconnect/retry states and generic guest presence. Grooming, 2026-10-22.

- Capture local mutations from Univer's open-source command service, keep them in a pending queue, apply remote ones without echo, and replay after reconnecting. This queue becomes SPN-053's offline outbox, so give it a persistence hook.
- Build it as `lib/sync-client/` (AGENTS.md), with Univer packages as peer dependencies. Spinel's sockets, tickets and status wiring stay in `web/`. Owner, chat 2026-10-19.
- Preserve the save/status integration in `web/collaboration.ts`, with separate connection and durable-save meanings for SPN-042/SPN-043. Only a durable acknowledgment completes a pending write; a connected socket alone does not.
- XL reflects optimistic queue rebasing, reconnect/acknowledgment races, no-echo remote application, and Sheet/Doc presence integration and convergence proof. The reusable transform engine remains SPN-056; offline persistence remains SPN-053. Grooming at owner request, 2026-10-21.
- Presence: header circles, remote cursors and selections, and jump-to-range. Guests keep generic labels and empty avatars ([#72](../implementation/SPN-016.md#legacy-decision-72-scoped-anonymous-link-capabilities)). Use SPN-036's saved profile fields if that ticket has landed.
- Deliver saved profile colours and icon labels on the Doc canvas. SPN-036 ships profiles and Sheet colours; its experiment found the public Docs UI-disable switch breaks required services, with no public cursor-only switch. Owner, chat 2026-10-20.
- Behind the same flag as SPN-057. Keep today's image-insertion guard.
- Send what `lib/sync-transform` (SPN-056) needs: styles inline rather than as style ids, doc inserts marked `PRESERVE_INSERTED_PARAGRAPH_IDS`, and `index` on RemoveSheet. Copy each mutation before applying it, since Univer writes into the params it applies, and never set `derived` or any `sync-transform.*` key in params, which the transform reserves for its own writes. Keep a confirmed copy of the cells as the server last acknowledged them, advanced by each incoming edit and each acknowledgment, and pass it as `{ cells }` when transforming: the confirmed copy for the inflight batch, and the confirmed copy past the inflight batch when rebasing the buffer (the replay merge, SPN-056 decision 29). If the copy drifts from the server, convergence is lost, so SPN-057's divergence check resyncs it. Send the rebased output as returned, its `sync-transform.cells.claim` included; the server rejects an absolute write whose unclaimed keys differ from its base cell, so never edit it. Keep each mutation's `trigger`, which Univer sets to the command that sent it; the transform tells a command's rewrite of names and formulas from a person's edit by it (SPN-056 decisions 1 and 23). Mark the MoveRange of an insert or delete with shift `shift: {axis, kind, at, count}` (`at` and `count` are the range's start and size on the shift axis; a MoveRange with an empty `from.value` stays unmarked). Give new docs their `drawings` and `drawingsOrder` containers. Refuse locally a mutation outside `supportedMutationIds` instead of sending it. When the server refuses an edit (`RefusedEditError`, e.g. someone moved the same cells at the same moment), drop the pending edits from it on, reload the server's document and tell the person their move didn't apply. Owner, chat 2026-10-20. A client that reloads because an incoming edit cannot pass its own pending edits waits for the server's answer to the batch it already sent first, since the server may accept it (lib/sync-transform/README.md, "What a sender must do").
- Agent proposal, 2026-10-22, for this ticket to settle: Univer's row, column and shift commands re-send each name that refers to the edited sheet and each formula that reads it, moved or not, so each such edit races any concurrent one that rewrites references (lib/sync-transform/README.md, Known limits). Consider dropping, before sending, a name set equal to the name's current record and a formula rewrite whose `f` equals the cell's current formula, with a test that refusals fall and convergence holds. A remote write whose `trigger` is a style command (`set-style`, `clear-selection-format`) skips Univer's formula recalculation unless applied with `onlyLocal`, so apply remote edits so that every screen recalculates alike.

- The `lib/*` workspace and shared checks already exist from SPN-033. Extend them for this package, including its manifest in both Dockerfile stages before `npm ci`; do not recreate scaffolding (grooming, 2026-10-20).
