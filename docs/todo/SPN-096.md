# 📚 SPN-096 Move legacy decisions into implementation records

## Story

As the [Owner](../product/personas.md#owner), I want earlier decisions next to each ticket's implementation notes, so that future work can find the rationale and permission boundaries without reconstructing GitHub conversations.

## Scenarios

### Find an earlier decision
Given a decision issue or a ticket that cites it,
When I follow the maintained documentation,
Then I reach a local decision record with its date, status, original source, rationale, persona tradeoffs and affected rules,
And links from active tickets and maintained docs point to that record without losing historical provenance.

## Rules

- Owner requested migration after adopting repository decision records going forward, chat 2026-10-22. Follow [the record convention](../implementation/README.md). This ticket migrates history; new work already uses the convention.
- Inventory legacy decision issues (open and closed) and their inbound references, including decisions for landed/retired tickets. Map each to `docs/implementation/SPN-NNN.md`; use a named cross-cutting record for policy without one owning ticket. Keep one canonical entry and link related tickets to it.
- Preserve accepted/rejected/pending/superseded status and chronology; closing an issue alone is not proof the owner approved an option. Explicitly retain unresolved owner questions and supersession links. Do not invent consensus or silently change product scope.
- Keep source issue URLs/numbers as provenance and leave GitHub issues intact. Existing implementation records contain valuable evidence: extend them, do not overwrite them. Capture rationale concisely, not entire discussions or raw tool logs.
- Update legacy frontmatter/reference conventions only after every affected citation has a replacement; maintain an inventory mapping and validate links. All four personas' privacy, access and operational constraints survive the move.

## Verify

- Account for every decision issue and cited number in the migration inventory; check source-to-record mappings, unresolved questions and superseded decisions.
- Validate local links/anchors and backlog checks; independently sample records against their source discussions and review all access, recovery and destructive-action decisions.
