# 🪟 SPN-084 Apply the approved guest and unavailable screens

## Story

As the [Link guest](../product/personas.md#link-guest), I want to open a shared file with clear access and no unrelated controls, so that the interface supports my task without clutter.

## Scenarios

### Shared content stays central

Given the approved SPN-047 design and current access,
When I use this screen on desktop or phone,
Then the composed layout follows [the playbook](../design/guest.md),
And loading, empty, error and restricted states keep the same clear hierarchy.

## Rules

- Migrated decision records: [Approved redesign and its limits](../implementation/SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits).

- Include the landed Space View/Edit guest shell, scoped Pages navigation and root-link revocation/role-change across all open children. Preserve generic presence, no recovery/account/history controls and shared SPN-043 save failures. New layout must cover these existing routes, not just standalone GuestApp. Grooming, 2026-10-22.

- Use the minimal header and fixed status slots. No account rail, identities, history or native export. Revocation removes the title, content and actions; unavailable and offline screens remain generic.
- Build from `Redesign/Screens`: GuestViewer, GuestEditor, RevokedLink, OfflineLaunch, MissingFile; reuse the shared controls, tokens and screenshot runner. Proposed in SPN-047, 2026-10-20, decision [#126](../implementation/SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits); owner visual approval required before migration.
- Weigh all four personas: preserve content privacy for Operator/guests, recovery for Owner, and truthful access for Collaborator. No permissions are changed by visual consolidation.
- Adopt the shared semantic modal title icon for dialogs changed here. SPN-089 audits remaining omissions after screen migrations; do not defer this screen's pattern to that audit. Owner-approved grooming, 2026-10-21.

## Out of scope

- PDF engine (SPN-075), Space foundation/navigation/guest integration (SPN-078/SPN-091/SPN-092), changes to guest permissions.

## Verify

- Browser: current successful and failure/access flows, keyboard focus/return, touch, and light/dark/phone screenshots against the approved mockups.
- Storybook: composed screen and relevant states; owner approval of implementation screenshots.
