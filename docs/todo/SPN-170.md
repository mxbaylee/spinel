# ⌨️ SPN-170 Edit and delete Doc text on desktop and mobile

## Story

As the [Owner](../product/personas.md#owner), I want to revise Doc text reliably on my computer and phone, so that typing or deleting preserves the content I intend to keep.

## Scenarios

### Editing and deletion survive reopening

Given an editable modern Doc on desktop or mobile,
When I type, insert a paragraph, use Backspace or supported forward Delete, delete/replace a selection, and undo/redo,
Then exact text, surrounding formatting and caret/selection remain correct, including paragraph boundaries, Unicode and empty/start-of-document cases, and saved content survives reopening; read-only access still rejects edits.

### Mobile editing checks run only when requested

Given ordinary desktop coverage and a default-off mobile editing flag,
When the exact `ci-doc-editing-mobile` PR label is added or a manual run explicitly sets `run_doc_editing_mobile=true`,
Then the new mobile matrix runs once on the recorded requested revision; otherwise it stays unselected, including on later pushes, schedules, `ci-full` and unrelated manual runs, while desktop coverage keeps its normal automatic routing.

## Rules

- Owner report/request, chat 2026-11-19: Backspace trouble occurred in mobile Docs; exact symptom, device/build and cause are unconfirmed. Investigate and repair a reproduced defect; do not invent an SPN-090 finding or claim an unreproduced bug fixed. [Scope and provenance](../implementation/SPN-170.md#scope-and-provenance).
- Use the [explicit opt-in contract](../implementation/SPN-170.md#mobile-opt-in-contract); preserve existing automatic phone, permission and performance owners. This ticket adds a focused editing matrix, not a global mobile-CI opt-out.
- A phone viewport or desktop-generated Backspace is not actual software-keyboard proof. Retain a bounded own-device check of the reported path and record unavailable evidence honestly; no BrowserStack restoration or paid device execution. [Evidence boundary](../implementation/SPN-170.md#verification-plan-and-evidence-boundary).
- Follow [sustainable testing](../testing.md); keep the Verify plan and progress evidence current. Size includes reproduction, any repair, native input, persistence, routing and acceptance; reassess at the first capability checkpoint.

## Out of scope

- Sheets, image-paste repair (SPN-154), broad offline/performance rewrites and changing unrelated CI coverage.

## Verify

- Extend `e2e/documents.spec.ts` and the native fixtures in `e2e/doc-mobile.spec.ts`/`doc-touch.ts`; assert complete native/saved/reopened text, relevant metadata, undo/redo and denied mutation. Reproduce Backspace failure or retain a bounded negative control that detects missing/wrong deletion; direct model mutation cannot substitute for editing.
- Isolate synthetic Docs/accounts; wait for native focus, selection and durable save, then reopen. Close owned contexts, databases and processes; retain the first failure without sleeps, relaxed assertions, retries or budgets.
- Desktop uses existing development/production owners; select the smallest distinct opt-in mobile owners. Track editor/SDK patches, input helpers, sync/persistence, Playwright config, manifests and CI planner/workflow/aggregate dependencies; test default, full, label-added/retained/removed, manual true/false, scheduled and unknown-input selection.
- Requested mobile work that is missing, skipped, cancelled or failed must not pass its aggregate; unrequested work is explicitly inapplicable. Preserve exact source/device/browser/keyboard identity, traces, content assertions, actual trigger/collection results and all unrun physical evidence in the implementation record/PR.
