# 🧭 SPN-037 Run the backlog with independent review and CI gates

## Story

As the [Operator](../product/personas.md#operator), I want one documented instruction that works through the backlog, so that I do not have to supervise every ticket, review and merge.

## Scenarios

### Start and continue

Given the owner invokes the documented backlog run,
When a ticket meets its acceptance criteria, scores at least 95/100 from an independent subagent and passes CI,
Then the agent squash-merges it and picks again from the updated backlog.

### Repair or split

Given review findings or an oversized change,
When the agent weighs overlap with the ticket and the configured changed-line limits,
Then it fixes related work or records separate work in a ticket without deferring an acceptance blocker to pass review.

### Stop and resume

Given the backlog is finished, all remaining work is blocked, the owner stops the run, or execution limits approach,
When the agent stops,
Then it leaves a truthful checkpoint with merged work, pending branches/PRs, blockers and the next action.

## Rules

- Independent subagent verification, a 95% gate, scope/size-based repair or split, CI before merge and repetition through the backlog. Owner, chat 2026-10-17.
- Documenting the workflow does not start the whole backlog. A later instruction to read it and start working invokes the run. Owner, chat 2026-10-17.

## Out of scope

- A scheduler or background daemon; starting the remaining product tickets now.

## Verify

- Independent review: 94/100 triggers repair/re-review; oversized related fixes split safely; unrelated follow-ups get tickets.
- Failed or stale CI and unresolved owner verification prevent merge; all-blocked or interrupted runs leave resumable checkpoints.
- Existing checks pass; the existing process and PR template agree with the runbook.
