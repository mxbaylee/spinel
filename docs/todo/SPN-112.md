# 🛟 SPN-112 Restore a workspace backup through Admin

## Story

As the [Operator](../product/personas.md#operator), I want to restore a selected or uploaded workspace backup, so that I can recover deliberately with a verified rollback path.

## Scenarios

### Restore from configured storage or an upload

Given a complete encrypted bundle selected from the configured catalog or uploaded manually,
When I freshly authenticate and confirm the exact source, target and lost-work consequence,
Then Spinel stages and verifies the candidate before pausing,
And the supervisor preserves the original generation, activates the compatible candidate under maintenance, verifies recovery and resumes safely.

### Reject or roll back an unsafe candidate

Given a bad key, incompatible image, insufficient resources or failed activation,
When preparation or recovery fails,
Then the original dataset/source evidence remain preserved,
And the UI reports the failure without reopening an unknown generation or reviving revoked access.

## Rules

- Follow the [accepted local-first direction](../implementation/SPN-063.md#accepted-decision-implement-recovery-before-deployment) and [assisted restore contract](../implementation/SPN-063-backup-options.md#assisted-restore-is-a-supervised-maintenance-operation), owner chat 2026-10-27; originating PR #205.
- One preparation flow for configured and uploaded bundles. Manual upload needs no automatic destination; bare SQLite files are not complete recovery bundles.
- Build on [SPN-109's delivered policy, encrypted download and held-catalog contracts](../implementation/SPN-109.md); downloading a bundle does not authorize activation.
- Filesystem and DigitalOcean Spaces are the delivered destinations. AWS S3 remains post-launch SPN-114, not a restore prerequisite. [Refreshed scope](../implementation/grooming-2026-10-27.md#main-refresh-and-ci-follow-ups), grooming 2026-10-28 UTC.
- Use [SPN-111's independent authority, journal and supervisor](../implementation/SPN-111.md). Never replace an open SQLite file or authorize recovery from the archived auth database.
- Prepare catalog and upload inputs through the [same isolated verifier](../implementation/SPN-112.md#prepare-inside-the-existing-isolated-verifier), retaining verified data separately from activation authority; agent decision, 2026-10-29.
- Use [closed-file custody and a durable opening barrier](../implementation/SPN-112.md#closed-file-custody-and-opening-barrier); commit verified generation/epoch state before reopening writes, never roll back newly acknowledged work on restart. Agent decision, 2026-10-28 Pacific.
- Plan current/candidate/rollback/staging/WAL space and bounded transfers. A held point cannot expire during preparation/activation; cancellation/retry is idempotent.
- Reconcile recovery epoch, sessions/revocations, guest capabilities and accepted/offline retries. Use the [frozen current credential overlay](../implementation/SPN-112.md#credential-overlay-on-a-frozen-working-copy); previously revoked access and newer edits cannot silently return. Agent decision, 2026-10-28 Pacific.
- Cap [current sharing on the restored hierarchy](../implementation/SPN-112.md#current-sharing-on-the-restored-hierarchy), including dormant grants hidden by trash or disabled Space owners; preview sharing/filing losses. Agent decision, 2026-10-28 Pacific.
- Restore exact compatible immutable app/configuration; uploaded endpoints/secrets/schedules never overwrite current deployment policy automatically. Keep the independent CLI path.
- Operator gets guided recovery; Owner and Collaborator see discarded-work/rollback consequences; Link guest isolation/revocation survives. Independent light/dark/phone review applies.

## Out of scope

- Database-engine adapters, arbitrary database import, automatic unattended restore, provider provisioning.

## Verify

- Real local processes/containers and browsers cover selection/upload, content/images/history/grants, authority expiry, double-click/retry/cancel, old clients, interruption at every durable cutover, failed health checks and verified rollback.
- Actual selected-provider/host launch acceptance, independent CLI recovery and current light/dark/phone visual approval.
