# 🧽 SPN-141 Make native storage-loss preparation quiescent

## Story

As the [Operator](../product/personas.md#operator), I want native storage-loss checks to establish genuine storage absence, so that missing-copy recovery is tested without racing active cache writers.

## Scenarios

### Storage-loss preparation has an observable settled boundary

Given a native browser that already proved offline edits and reconnect,
When the fixture deliberately removes its offline storage,
Then active producers cannot recreate the removed shell cache during verification,
And the subsequent offline UI does not advertise or open a missing retained copy.

## Rules

- Follow [sustainable testing](../testing.md); keep the Verify plan and progress evidence current. [Policy](../implementation/SPN-115.md#guidance-for-every-open-ticket-and-progress-checkpoint), owner 2026-11-01.
- Preserve the [first Firefox failure, L scope and unchanged acceptance](../implementation/SPN-141.md#registration-and-scope), agent judgment 2026-11-04 after the owner requested continued SPN-120 repair.
- Current native storage acceptance passes, but the [independent mobile capacity-budget failure](../implementation/SPN-142.md#registration-and-scope) blocks integration until SPN-142 is accepted; keep this ticket's storage scope and fresh current-head gates.
- Identify cache producers and establish an observable quiescent boundary before deletion. Do not repeatedly delete until green, loosen the empty-cache/targeted-database checks, add arbitrary sleeps, extend budgets or repeat failed assertions.
- Preserve exact saved/offline/reconnect/conflict content and post-loss availability assertions. The observed failure is setup cache persistence, not demonstrated user data loss or a proven browser deletion defect.
- Keep original private-database targeting and bounded diagnostic/cleanup behavior; unrelated browser databases are context, not required deletion targets.

## Out of scope

- Safari JXA process resolution (SPN-140), broad storage/runtime migrations, product features and SPN-120's finite historical audit.

## Verify

- Extend scripts/ci/desktop-storage.test.ts and existing native harness controls for cache recreation after reported deletion, producer quiescence, denial/blocking/timeout and first-cause preservation.
- Inspect service-worker lifecycle and controlled pages before choosing the boundary; retain full native desktop routing for all source/shared dependencies.
- Declare one complete first-attempt native workflow per concrete repair before publication. Require actual Firefox deletion postconditions and subsequent missing-copy/offline-advertisement behavior; other selected browsers/gates remain mandatory.
- Preserve every run/source/tested identity, first failure, operation timeline, useful screenshot and both exact-source independent reviews. Mocks or retries cannot replace native proof.
