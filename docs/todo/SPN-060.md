# 📐 SPN-060 Check design consistency automatically in CI

## Story

As the [Owner](../product/personas.md#owner), I want CI to flag design drift after the redesign lands, so that new tickets keep the playbook's look without me reviewing every pixel.

## Scenarios

### A raw colour is rejected

Given a change adds a hex colour or pixel spacing outside the theme tokens,
When Lint runs,
Then it fails and names the file and line.

### A visual change is visible

Given a change alters a component,
When the visual check runs,
Then the affected stories' light and dark screenshots differ from the stored ones, and CI fails until they are deliberately updated.

### An accessibility regression fails

Given a story with an axe violation,
When CI runs,
Then it fails and names the rule and component.

## Rules

- SPN-047 handoff: Reuse npm run screenshots, fixed fixture time, theme/phone/tablet variants and named control semantics; include composed screens and actual Univer routes. Follow [the composed design](../design/redesign.md) and decision #126 (2026-10-20); preserve current behavior and owner screenshot approval.

- Moved from SPN-047 when that became an AI design review. Owner, chat 2026-10-19.
- Three checks: token lint (stylelint or similar), Playwright screenshot comparisons of the [Storybook stories](../design/README.md#storybook) plus the editors that boot Univer, and axe-core over the stories. Keep `presetStyles.test.ts`.
- Run them inside the existing required jobs (Lint, Playwright smoke). A new required job would need the owner to change the ruleset. Freeze the clock for stories that compute dates.
- Generate snapshots in CI's Linux environment. Document how to update them. Reuse SPN-047's screenshot script.
- If memory limits block local runs, follow the CI-first exception in process.md (#52).

- Include SPN-077 entity facets and, once built, SPN-078/079 Space and file-role stories in theme, accessibility and responsive coverage; static Space previews are not live routes (grooming, 2026-10-20).

## Out of scope

- The playbook's content (SPN-047).

## Verify

- One deliberately failing fixture per check, proving each one fails, then reverted. A short docs section on updating snapshots.
