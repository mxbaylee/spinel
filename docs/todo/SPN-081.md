# 🎚️ SPN-081 Apply the approved sharing dialog design

## Story

As the [Owner](../product/personas.md#owner), I want to sharing a file feels clear and compact, so that the interface supports my task without clutter.

## Scenarios

### Share Autumn plans

Given the approved SPN-047 design and current access,
When I use this screen on desktop or phone,
Then the composed layout follows [the playbook](../design/sharing.md),
And loading, empty, error and restricted states keep the same clear hierarchy.

## Rules

- People and guest-link access share one Base UI dialog. Changes confirm in place; inherited access, failed-write rollback and once-only guest-link reveal remain explicit.
- Build from `Redesign/Screens`: Sharing, PlannedFileAdmin; reuse the shared controls, tokens and screenshot runner. Proposed in SPN-047, 2026-10-20, decision #126; owner visual approval required before migration.
- Weigh all four personas: preserve content privacy for Operator/guests, recovery for Owner, and truthful access for Collaborator. No permissions are changed by visual consolidation.

## Out of scope

- Delegated file Admin (SPN-079), source-sharing options (SPN-076), new access policy.

## Verify

- Browser: current successful and failure/access flows, keyboard focus/return, touch, and light/dark/phone screenshots against the approved mockups.
- Storybook: composed screen and relevant states; owner approval of implementation screenshots.
