# ✏️ SPN-162 Name the offline download action as a command

## Story

As the [Owner](../product/personas.md#owner), I want the row menu to say **Make available offline**, so that I read it as an action rather than a status. [Collaborators](../product/personas.md#collaborator) see the same menu.

## Scenarios

### The menu names the action

Given a Sheet or Doc that is not downloaded on this device,
When I open its row menu,
Then the entry reads **Make available offline** and starts the download.

## Rules

- Follow [sustainable testing](../testing.md); keep the Verify plan and progress evidence current. [Policy](../implementation/SPN-115.md#guidance-for-every-open-ticket-and-progress-checkpoint), owner 2026-11-01.

- Owner request, chat 2026-11-16: **Available offline on this device** "could sound declarative". Raised during the SPN-156 phone run and deliberately kept out of that PR so its exact-head reviews and CI stayed valid.
- Current wording is asserted in more than the component. Known sites: `web/Dashboard.tsx` (the menu item), `e2e/offline-upgrade.spec.ts`, `web/OfflineStatus.stories.tsx`, `docs/offline.md`, and `docs/design/dashboard.md` (four places). Search for the old string before and after.
- Decide, and record, what the already-downloaded state of the same item says (for example whether a removal entry keeps its current wording). Weigh all four personas; Guest links have no offline store.

## Out of scope

- Changing what downloading does, or the offline badge wording.

## Verify

- Contract/negative case: the old string no longer appears in the UI, docs or tests, and the new entry starts the same download; suite/layer/fixture: the existing offline-upgrade e2e plus the story that renders the menu.
- Fixture readiness/cleanup: the existing offline fixtures; no new resources.
- Environment and source/shared dependencies: the files named in Rules.
- Evidence: a repository-wide search showing no remaining old wording, and the updated e2e result.
