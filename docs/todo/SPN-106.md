# 🔕 SPN-106 Avoid a protection warning when opening view-only Docs

## Story

As a view-only [Link guest](../product/personas.md#link-guest), I want to open and read a Doc without an unexplained protection warning, so that I can trust that ordinary reading is allowed. Account viewers need the same behavior.

## Scenarios

### Opening a view-only Doc

Given a plain Doc or one with header/footer date fields shared for viewing,
When I open it without attempting an edit,
Then no protection warning covers the document header on desktop or phone,
And the saved body, fields and permissions remain unchanged.

### An actual denied edit

Given a view-only Doc or an editor whose access has been revoked,
When an edit is attempted,
Then the edit remains refused with the established truthful feedback,
And authorized collaborators remain able to edit.

- Follow the [Storybook production migration rule](../implementation/storybook-production-migration.md#migrate-stories-with-their-ui-tickets): render changed UI states with production components, replace or retire this ticket's Redesign examples when landing, and leave no unowned stale design story. Owner, chat 2026-10-27.

- Found during [SPN-075 review, PR #186](https://github.com/mxbaylee/spinel/pull/186): production Doc guest light/dark/390px screenshots at `058559b` show the warning before any deliberate edit. The existing main Doc startup sequence is unchanged by PDF integration.
- OSS Univer 1.1.0 `DocUIController._initDateTimeFields` sends `doc.command.refresh-header-footer-fields` with `onOpen: true` for every opened Doc. `DocPermissionController` classifies it as an edit and emits a protection warning before its handler can no-op or check individual fields. Verify this source-backed diagnosis against a real viewer startup before repairing it.
- Use supported public plugin/configuration/command APIs or an upstream fix. Do not patch Pro code, bypass authorization, mute all permission errors or hide the warning with CSS.
- SPN-075 separately records startup notices and asserts that opening, resizing and downloading through Export creates no new notice. Preserve that distinction and its PDF behavior; this ticket fixes the existing reader initialization path.
- Weigh all personas: Owner retains saved field values and grants; Collaborator and Link guest get truthful reading/editing feedback; Operator gains no document access or new service.
