# 🧱 SPN-001 Scaffold the web app and server

## Story

As the [Operator](../product/personas.md#operator), I want one repository that builds, tests and runs the web app and its server with a single command, so that every later ticket starts from a working, checked base.

## Scenarios

### A fresh clone runs

Given a clean checkout with the Node version in `.nvmrc`,
When I run `npm ci` and `npm run dev`,
Then the web app opens in a browser and shows a placeholder dashboard served by the Node server,
And the server creates its SQLite database file on first start.

### CI checks every PR

Given a pull request,
When CI runs,
Then lint, typecheck, unit tests and a Playwright smoke test run alongside the backlog checks,
And all of them are required to merge.

## Rules

- Stack mirrors circus-health: TypeScript, React, Vite, Vitest, Node, Playwright, Prettier. Owner, chat 2026-10-17.
- SQLite, not Postgres: one process, one file, fits the 2 GB droplet. Owner, chat 2026-10-17.
- Build on the Univer SDK (`@univerjs/*`, Apache-2.0). Univer Workspace is a reference only: copy with attribution, never fork or deploy it. Owner, chat 2026-10-17.
- Univer's UI packages targeted React 18.3.1 when last checked; confirm their supported React version before choosing ours.
- Add the new CI jobs to the required checks list in `process.md`.

## Out of scope

- Sign-in (SPN-002), editors (SPN-007), deployment (SPN-029), theme (SPN-027).

## Verify

- `npm ci && npm run lint && npm run typecheck && npm test && npm run e2e` pass locally and in CI.
- The PR lists the new required check names for the owner to add to the `main` ruleset.
