# 🧵 SPN-122 Run native Doc composition unpatched after the upstream improvement ships

## Story

As the [Owner](../product/personas.md#owner), I want Spinel to use stock native Doc composition after a suitable upstream release, so that upgrades preserve responsive typing without a local SDK patch.

## Scenarios

### A suitable upstream release replaces the temporary improvement

Given a published Univer release composes native Doc groups without repeatedly copying growing prefixes,
When Spinel upgrades its aligned Univer packages and removes the temporary Docs patch,
Then installation leaves Docs unmodified and the original desktop/mobile latency, content, metadata, history and access requirements still pass.

### Upstream takes a different approach

Given the released implementation differs from the local balanced-fold candidate,
When the release is evaluated,
Then use supported upstream behavior and keep the registered acceptance requirements; an unsuitable release leaves this ticket open.

## Rules

- Effort L, full-scope review 2026-10-29: Current scope includes aligned-release/retained-guard qualification and the complete native composition/history acceptance. Reuse a proven release baseline from SPN-099/119; materially different upstream semantics require an explicit algorithm/scope reassessment. [All-ticket assessment](../implementation/grooming-2026-10-29.md#all-ticket-effort-and-impact-review).

- Follow the [SPN-121 temporary improvement and removal decision](../implementation/SPN-121.md#temporary-improvement-and-removal), agent judgment during the owner's SPN-118 completion request, 2026-10-29. This maintenance follow-up is after launch, like SPN-099 and SPN-119; it does not defer any current SPN-121 acceptance requirement.
- Recheck published OSS source and package bytes before implementation. No upstream PR has been submitted by this task, and a proposed or merged PR is not evidence that a released package includes the change. Coordinate any future upstream contribution and record its exact disposition.
- Keep all Univer package versions aligned. Assess core, Docs UI, UI-resize and drawing guards independently against the same selected release; coordinate SPN-099 and SPN-119 without removing their protections prematurely.
- Remove `scripts/dependencies/patch-univer-docs.ts`, its patch-specific tests, its postinstall command, the corresponding notice and maintained temporary-patch instructions. Preserve semantic and work-regression coverage beside the native behavior it protects.
- Include the real synchronized marker cases retained by [SPN-123](../implementation/SPN-123.md#native-marker-qualification-proof-and-repair), not only unmarked synthetic inserts. Preserve exact own-field representation, marked control/rich-shape fallback and actual-group receipt/peer/reopen/Undo/Redo regressions when qualifying stock source. Agent integration finding, 2026-10-30; removal ownership stays here.
- Retain the original 2,086-input workload, fourfold mobile throttle, registered timing budgets, first-attempt policy, 32-state grouping, 100-group history retention, complete actual-group Undo/Redo and native boundary/access checks. Any genuinely different history policy needs its own explicit persona decision and complete replay evidence.

## Out of scope

- Relaxing acceptance, attributing historical unprofiled spikes without evidence, or replacing this patch with another local composition algorithm instead of adapting to supported upstream behavior.

## Verify

- Fresh `npm ci` leaves `@univerjs/docs` byte-identical to the selected released package; no executable `patch-univer-docs` references remain.
- Original paired desktop/mobile acceptance and complete native history/metadata, divergent-cache, IME/segment, quiet-tail, saved/peer convergence and denied/revoked-access regressions pass on stock source; all required CI and both independent reviews pass.
