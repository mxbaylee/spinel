# 🧱 SPN-041 Download a complete, authorized copy of a document

## Story

As the [Owner](../product/personas.md#owner), I want a download to contain my whole document as it is right now, with its images and the exact version it came from, so that working offline can never start from a partial copy or be confused with a newer version. A signed-in [Collaborator](../product/personas.md#collaborator) gets the same within their existing access.

## Scenarios

### Downloading the current version

Given an authorized Sheet or Doc with several sheets or sections, images and preserved resources,
When the device requests a download bundle,
Then it receives the current snapshot, the revision and generation it represents, the account and access it was issued for, the pinned SDK version, and a manifest listing every image by same-item source, SHA-256, MIME type and byte length,
And downloading every listed image through the existing image route reproduces the document exactly.

### Access or generation changes during the download

Given a bundle request still being assembled,
When the session, the person's access or the live generation changes,
Then the request fails rather than returning another account's data or a replaced document,
And guests, operators and unrelated accounts cannot obtain a bundle.

## Rules

- The bundle is the live snapshot and its revision from the same read. The device never replays server changesets, so the exact-revision replay endpoint and changeset codec in draft PR #86 are not needed. Owner, chat 2026-10-19; supersedes #88's replay-base scope.
- Reuse the existing load path (`CollaborationStore.load`) and image access checks. Never fetch cross-item or remote images. Grooming, 2026-10-19.
- Recheck the session, access and generation after every asynchronous read. Keep the existing request and transfer limits. A bundle alone does not mean downloaded, durable or synced. #91, 2026-10-19.
- A viewer's bundle is marked read-only, and the device must open it read-only. Grooming, 2026-10-19.

## Out of scope

- Device storage, the outbox, the offline editor, catalog, launch and save states. Those stay with SPN-039.

## Verify

- Server unit tests: snapshot and revision consistency, generation identity, multi-sheet and Doc content, complete image manifests, preserved opaque resources, and rejection of malformed data with nothing partial returned.
- HTTP tests: owner, editor and viewer success with the right access; anonymous, admin, guest and unrelated-account rejection; session, access and restore races. Full CI and an independent review on the branch.
