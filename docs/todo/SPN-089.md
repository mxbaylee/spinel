# 💬 SPN-089 Check remaining dialogs for consistent title icons

## Story

As the [Owner](../product/personas.md#owner), I want dialogs to have a consistent visual cue beside their titles, so that actions remain recognizable across files, editors and settings. Collaborators, Operators and link guests get the same clarity within their permitted flows.

## Scenarios

### A coherent dialog heading

Given any product modal, including loading, error and destructive variants,
When it opens on desktop or phone,
Then an appropriate icon appears beside its visible title using shared sizing and alignment,
And the title, content, close control and actions remain readable without crowding.

### Preserve accessible meaning

Given keyboard or assistive-technology navigation,
When a dialog opens or closes,
Then its textual title remains its accessible name and focus handling is unchanged,
And decorative icons are hidden from assistive technology rather than announced twice.

- Follow the [Storybook production migration rule](../implementation/storybook-production-migration.md#migrate-stories-with-their-ui-tickets): render changed UI states with production components, replace or retire this ticket's Redesign examples when landing, and leave no unowned stale design story. Owner, chat 2026-10-27.

- Migrated decision records: [Approved redesign and its limits](../implementation/SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits).

- Owner direction, 2026-10-21, decision [#126](../implementation/SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits): every modal popup gets a title icon; implement through the shared dialog pattern and audit the complete modal inventory.
- Use existing semantic icons with the title, not color alone. Include nested confirmation, recovery, sharing, profile, Operator and guest dialogs; do not add decoration to tooltips or force SDK-owned dialogs through unsupported hooks.
- SPN-047's shared pattern and the screen migrations have landed. Inventory the remaining dialogs and fix omissions without repeating those migrations or creating another wrapper. A current starting point is `web/DocFormulas.tsx`'s native Insert/Edit formula dialog, whose heading has no title icon; shared Modal call sites and the Profile IconPicker already supply theirs. Recheck the complete inventory at implementation time. Owner-approved scope, 2026-10-21; source handoff, 2026-10-25.
- Include standalone dialogs not owned by a screen migration. Later feature tickets inherit the same pattern and verify their own new dialogs; this audit does not block their security or behavior work.

## Out of scope
