# 🔬 SPN-130 Diagnose the native desktop identity and storage-cleanup timeouts

## Story

As the [Operator](../product/personas.md#operator), I want the native desktop checks to identify the operation that timed out and clean up their owned resources, so that an unsuccessful run gives a useful diagnosis without uncertain reruns.

## Scenarios

### Safari identity is established before use and cleanup

Given a newly launched ordinary Safari process on the maintained Intel runner,
When the capability probe reads its PID, bundle and launch identity,
Then the read succeeds within the existing bound or reports its actual failed phase,
And cleanup acts only on an identity that was positively established.

### Firefox storage deletion has an observable completion boundary

Given the desktop offline flow has completed its retained-document and reconnect checks,
When it deliberately deletes the private worker, caches and database,
Then each asynchronous deletion reaches its required state or identifies the operation that remained pending,
And cleared downloads are no longer advertised as available.
