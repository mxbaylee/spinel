# 🗃️ SPN-067 Export all my files at once

## Story

As the [Owner](../product/personas.md#owner), I want to download every Sheet and Doc I own in one archive, with my folder structure, so that I have my own copy without asking the Operator for a backup. [Collaborators](../product/personas.md#collaborator) can do the same for what they own.

## Scenarios

### Exporting everything

Given I own folders, Sheets and Docs,
When I choose **Export all my files** and confirm,
Then I download a `.zip` of native Univer files in my folder structure, with images embedded and a manifest of names and dates.

### Bringing it back

Given that archive,
When I import it into another Spinel instance's My files,
Then the folders and documents come back as new items, as SPN-031's single-file import does.

### A big workspace

Given my files exceed what fits in memory at once,
When I export,
Then the archive streams, the page shows progress, and the server stays within its 2 GB budget.

## Rules

- SPN-047 handoff: My files More → Export all my files; a single progress/error task explains owner-only scope and preserves privacy. Follow [the composed design](../design/dashboard.md) and decision #126 (2026-10-20); preserve current behavior and owner screenshot approval.

- Only items I own and haven't trashed. Shared items, history, versions, shares and guest links aren't included (docs/files.md).
- Each file is the same native export as **Download Univer file**, so one importer handles both.
- Stream the zip and limit concurrent exports to one per account. Admins and guests can't export this native archive; PDF export with current read access belongs to SPN-075 (#103, owner, chat 2026-10-20).

- Formula references between imported archive members remap to their new item IDs deliberately; external/missing references stay unavailable instead of attaching to unrelated items. The archive contains definitions, never cached formula values (SPN-033, #113; grooming, 2026-10-20).

- Spaces are enabled: preserve each outer Space and its internal tree in the archive/manifest and remap its internal references on import; do not flatten it into independently shared files. Imported copies have one Owner and no carried grants or guest links (SPN-078, #116/#118).

## Out of scope

- CSV import (SPN-093), optional format plugins (SPN-094) and restoring history.

## Verify

- Unit: ownership scope, trash excluded, the manifest, and the streaming memory bound with a large fixture.
- Playwright: export a nested workspace, import it into a fresh instance, and compare names, folders and contents.
