# 🏷️ SPN-095 Keep defined names correct when two people edit rows and columns

## Story

As the [Owner](../product/personas.md#owner), I want named ranges to keep pointing at the right cells while a [Collaborator](../product/personas.md#collaborator) and I both insert, delete and move rows, so that formulas using the names stay right and the name box can come back.

## Scenarios

### A row edit in a sheet with a name

Given a workbook with a name that refers to rows 3–5 of a sheet,
When one person inserts a row above it while the other renames it,
Then both screens show the renamed name pointing at rows 4–6.

### Two people edit the same name

Given a name both people can see,
When both change what it refers to at once,
Then both end with the edit the server accepted first.

## Rules

- SPN-056 rejects defined-name mutations, so today a row or column edit that also updates a name is refused. Found in the SPN-056 review, 2026-10-19.
- Add the transforms to `lib/sync-transform/` as their own family, verified against headless Univer and in the combined fuzz, as SPN-056 does.
- Once they land, show the name box and defined-name manager that SPN-059 hides.

## Out of scope

- Formula results, which each client computes locally.

## Verify

- Unit: each defined-name pair, and a name against row and column inserts, removes and moves. The combined fuzz includes names.
