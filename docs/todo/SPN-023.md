# 🕰️ SPN-023 Keep a decaying history of every document

## Story

As the [Owner](../product/personas.md#owner), I want Spinel to keep snapshots of my documents, close together for recent work and further apart for older work, so that I can go back to any recent moment without the server filling up.

## Scenarios

### Recent work

Given I am editing,
When I work for an hour,
Then there is a snapshot about every 5 minutes, plus one at each idle break.

### Thinning older snapshots

Given snapshots older than an hour,
When the pruning job runs,
Then hours 1–24 keep one snapshot per spacing interval,
And anything older keeps only the last snapshot of each day.

## Rules

- Schedule from PRD §5. The PRD says "30-minute and 60-minute" for hours 1–24; read as 30 minutes for hours 1–6 and hourly for 6–24. Confirm with the owner when starting.
- Univer collaboration has its own optional history module. Check it against this design before building a second history (SPN-010 findings).
- Named versions (SPN-024) are never pruned. Snapshots are compressed in SQLite.

## Out of scope

- The history UI (SPN-025, SPN-026).

## Verify

- Unit tests for the pruning schedule with a fake clock, including day boundaries.
- A size check: a busy week of edits stays under a stated budget.
