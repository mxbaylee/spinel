# 🚢 SPN-029 Deploy privately on the droplet

## Story

As the [Operator](../product/personas.md#operator), I want one documented way to deploy Spinel to a small droplet that only my Tailscale network can reach, so that the instance is private and easy to update.

## Scenarios

### Deploying

Given a fresh Ubuntu droplet with 2 GB of RAM,
When I follow the deploy guide,
Then Spinel runs under Docker Compose and is reachable over HTTPS only from my tailnet,
And nothing answers on the droplet's public IP.

### Updating

Given a running instance,
When I deploy a new version,
Then it restarts with its data intact and editors reconnect on their own.

## Rules

- External IPv6 scanning is waived for this deployment; retain IPv6 firewall closure. Owner, chat 2026-10-17, recorded in #17.
- Gate every Compose start on private networking and an active LUKS mount; immutable images and systemd supervision. Decided 2026-10-17 in #16.
- Bind to `127.0.0.1`; expose only over Tailscale, with Caddy in front serving TLS 1.3 for HTTPS and WSS. PRD §7.
- The SQLite file lives on a LUKS-encrypted volume. Replaces the PRD's PostgreSQL encryption, since we use SQLite. Owner, chat 2026-10-17.
- Fits a $12 droplet (2 GB, 1 vCPU) with headroom; state the measured memory use.
- Secrets (Univer key, session secret) come from the environment, not the repository.
- Deploy and maintenance scripts are TypeScript (`.ts`) run by Node, never `.js` or `.mjs`. Owner, chat 2026-10-17.

## Out of scope

- Backups (SPN-030), diagnostics (SPN-032).

## Verify

- The guide, followed on a fresh droplet, with the owner's run noted in the PR.
- An external IPv4 port scan showing nothing open; no external IPv6 scan is required for SPN-029 (owner decision above).
