## Rules

- Follow the [failure ownership and investigation record](../implementation/SPN-121.md), agent judgment during the owner's SPN-116 completion request, 2026-10-28. The cap32 102.1 ms and cap24 107.7 ms maxima exceeded the same 100 ms mobile bound; their unprofiled artifacts establish pauses, not a common cause.
- Diagnose the measured interval before changing production code. Preserve both failures, exact source/runtime/browser, original artifacts and every bounded diagnostic attempt. A non-reproduction or passing integration run is not proof of repair or transient infrastructure.
- Coordinate one native investigation across SPN-111 and SPN-116; do not duplicate speculative batch tuning. Evaluate pinned public Apache-2.0 composition code and actual native action shapes. Allocation/coalescing hypotheses require reproduction with exact-content and metadata semantics.
- Preserve the original workload, fourfold mobile throttle, budgets, retries, flaky policy, native IME/segment boundaries and finite history. Any genuine history-policy change needs explicit all-persona tradeoffs and complete replay evidence. No proprietary Pro internals or SDK bypasses.
- This native work does not replace SPN-120's fixture audit or the separate development-runtime mitigation documented in [SPN-117](../implementation/SPN-117.md). Registration never waives a failing required gate on any PR. XL reflects sustained algorithmic and browser/runtime investigation despite a potentially small repair.

## Out of scope
