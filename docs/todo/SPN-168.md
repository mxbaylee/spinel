# 🔌 SPN-168 Name the cause of the Playwright test client ECONNRESET

## Story

As the [Operator](../product/personas.md#operator), I want a connection reset on a smoke test's own HTTP client to be explained, so that it is fixed at its cause and not retried away.

## Scenarios

### A reset names a dead process or a dropped connection

Given a smoke case fails its first attempt with `ECONNRESET`,
When the attempt's `econnreset-diagnostic` line is read,
Then it says whether the owned server had exited or restarted, or stayed alive and dropped one connection, and the cause is fixed.

## Rules

- Follow [sustainable testing](../testing.md); keep the Verify plan and progress evidence current. [Policy](../implementation/SPN-115.md#guidance-for-every-open-ticket-and-progress-checkpoint), owner 2026-11-01.
- Split from [SPN-166](../implementation/SPN-166.md#econnreset-on-the-test-client) with its full remaining estimate. `apiRequestContext … read ECONNRESET` recurs across endpoints (collaboration, `GET /api/items/<id>/sheet`, a Space item export) in `development 2/2` and `sync-production`; the cause is undiagnosed. A Node 5 s keep-alive reset was not reproduced in one standalone setup. The diagnostic reporter (`e2e/reset-diagnostics-reporter.ts`) already ships; this ticket needs an occurrence.
- Do not weaken the gate: no exclusion, added retry or relaxed assertion before the cause is known. A product bug in an endpoint is a product fix, not a test change.
- Read the `econnreset-diagnostic` lines and `playwright-report/reset-diagnostics-<project>.json` from the next failing run. If the server had exited, find why. If it stayed alive, find which side closed the connection and why.
- [Kickoff and captured occurrence](../implementation/SPN-168.md#-captured-occurrence), agent 2026-11-21: run 44447934232 has a first-attempt production snapshot reset before quota manipulation; the final owned process exited cleanly, but the closing side and cause remain unproven. Preserve this evidence and the original acceptance.

## Out of scope

- Failures that are not connection resets.

## Verify

- Contract/negative case: a reset is explained from captured evidence and the resulting fix is covered; suite/layer/fixture: the existing `development` and `sync-production` projects and owned server wrapper.
- Fixture readiness/cleanup: `scripts/e2e-server.ts` evidence and the owned process lifecycle.
- Environment and source/shared dependencies: `server/http.ts`, `e2e/reset-diagnostics-reporter.ts`, the CI plan for the affected jobs.
- Evidence: the captured diagnostic for one reset, and repeated runs with no flake, linked by run id.
