# ⏳ SPN-110 Expire diagnostic events after seven days

## Story

As the [Operator](../product/personas.md#operator), I want old diagnostic observations to expire automatically, so that operational storage and retention stay predictable.

## Scenarios

### Expire events by receipt time

Given diagnostics containing observations received before and after the configured cutoff,
When bounded maintenance runs with the default seven-day policy,
Then expired observations are removed using trusted server receipt time,
And current accounting, byte limits and visible failure status remain accurate.

## Rules

- Effort M, full-scope review 2026-10-29: Reuse the existing bounded diagnostics store and scheduler for receipt-time expiry, byte accounting and export coordination. Feedback durability stays separate; generalized retention policy or a new scheduler exceeds this scope. [All-ticket assessment](../implementation/grooming-2026-10-29.md#all-ticket-effort-and-impact-review).

- Implement the [independent retention policies](../implementation/SPN-063-backup-options.md#three-independent-retention-policies), owner chat 2026-10-27; originating PR #205.
- Diagnostics is disposable and separate from the workspace. Keep existing logical/physical/queue bounds; seven days is a maximum age, not a completeness promise.
- Deployment owns the validated retention policy. Cleanup is bounded, retryable and safe across restart/clock changes; status is numeric/static and content-free.
- Automatic diagnostics backup remains off by default. Exports and retained remote archives have independent retention; row deletion does not erase every historical copy.
- Do not apply event expiry to future submitted feedback (SPN-098), workspace history, trash, backups or the independent recovery journal.
- Expire selected observation rows rather than invoking whole-store truncate. Preserve feedback/export semantics, the explicit truncate-generation fence and live logical-byte accounting. [Retention integration](../implementation/grooming-2026-10-27.md#carry-forward-landed-work), agent judgment 2026-10-27.
- Coordinate with [SPN-098's paired exports](../implementation/SPN-098.md#paired-user-and-system-downloads), owner chat 2026-10-29: TTL may remove live observations while an existing bounded immutable export pair retains its captured rows. Report known retention gaps without claiming completeness; old feedback survives even when its associated metrics do not. Neither ticket waits for the other.
- Operator gains bounded upkeep; the other personas benefit from minimizing retained operational observations without any change to document or access retention.

## Out of scope

- General backup configuration/Admin exports (SPN-109), paired feedback export implementation (SPN-098), new instrumentation, feedback retention, external alert delivery.

## Verify

- Cutoff boundaries, forged client timestamps, clock changes, bounded batches, restart/failure, accurate byte accounting and continued ingestion under existing pressure limits. Preserve feedback and immutable paired-export membership while live observations expire; retain explicit truncate invalidation and truthful old-feedback/missing-context metadata.
