# 🗝️ SPN-061 Recover admin access from the server console

## Story

As the [Operator](../product/personas.md#operator), I want to regain the admin account from the server console when its passkeys are lost or the hostname changes, so that a lost phone or a new domain can't lock everyone out of invitations and recovery.

## Scenarios

### Every admin passkey is gone

Given an instance with users whose only admin can no longer sign in,
When I run `npm run setup -- --recover-admin` on the server,
Then it prints a one-time link valid for 30 minutes, and claiming it registers a new passkey on the existing admin account,
And the old passkeys and sessions are revoked, and no new account is created.

### The hostname changed

Given `APP_ORIGIN` now names a new hostname, so every passkey is unusable,
When I recover the admin this way and issue recovery invites,
Then each person re-enrolls on the new hostname, and their accounts and documents are unchanged.

## Rules

- Console-only, like first setup: the secret appears only in console output and the link's fragment, and is never sent over the network (setup.md, #10).
- Recovers an existing admin, chosen by ID or name when there are several. It never creates an admin, promotes a member or reactivates a disabled account. It works whether or not the admin has passkeys.
- Same claim integrity as setup: Ed25519 proof of possession, single-use challenges and a transaction that rechecks the target before swapping credentials (#58).
- Log a structured `admin.recovered` event with the account ID and time.
- Document it in setup.md, and in deployment.md's hostname-change steps (SPN-038).

## Out of scope

- Public or email recovery. Recovering members, which the existing recovery invites cover.

## Verify

- Unit: expiry, wrong target, disabled admin refused, concurrent claims, and old sessions revoked.
- Playwright: lose the admin passkey on a disposable instance, recover from the console, sign in as admin and issue a recovery invite.
