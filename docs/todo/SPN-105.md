# 🛡️ SPN-105 Update the vulnerable request body parser

## Story

As the [Operator](../product/personas.md#operator), I want malformed compressed requests to leave Spinel running, so that Owners, Collaborators and Link guests do not lose service because of a request-body decoder error.

## Scenarios

### A malformed compressed request cannot stop the server

Given a running instance with the resolved request-body parser,
When it receives a valid compressed frame followed by trailing bytes,
Then the server stays running without an uncaught decoder error, and a subsequent ordinary request still succeeds.

### The vulnerable dependency is removed

Given the lockfile currently resolves body-parser 2.3.0,
When the compatible fixed release is installed,
Then the resolved version is no longer affected by GHSA-27r3-jxmh-p828 and ordinary JSON, parser limits, authentication and Origin checks keep their behavior.

## Rules

- Effort M, full-scope review 2026-10-29: The current outcome includes parser/process-survival verification and immutable historical-client dependency/postinstall isolation. Keep these two related validation boundaries focused; other package updates remain outside this fix. [All-ticket assessment](../implementation/grooming-2026-10-29.md#all-ticket-effort-and-impact-review).

- Register the existing defect separately from SPN-067 and fix it before deployment or public exposure. [Scope and evidence](../implementation/SPN-105.md#register-the-existing-parser-advisory), agent implementation and independent review, 2026-10-26.
- The verified upstream fix is body-parser 2.4.0; use that or a later verified compatible fix. Keep dependency changes narrow and preserve the pinned lockfile. [Maintainer advisory](https://github.com/expressjs/body-parser/security/advisories/GHSA-27r3-jxmh-p828).
- The archive upload deadlines do not mitigate this decoder error. Do not mark the advisory resolved until the dependency and subprocess regression are verified.
- Preserve historical-client verification when changing dependencies: build the immutable offline client with its own lockfile and postinstall patches, never current patched package bytes merely because versions match. PR #212 already prepares this correction; verify it after current-main integration rather than duplicating it. [Retrospective finding](../implementation/grooming-2026-10-29.md#merged-code-review), grooming 2026-10-29.

## Out of scope

- Archive behavior, authentication policy, general dependency refreshes and deployment.

## Verify

- Subprocess HTTP regression: malformed compressed input does not terminate the server, and a following request succeeds. Preserve ordinary compressed JSON and request-size/access behavior.
- Run the applicable parser/API regressions and all required CI gates. `npm audit --json` no longer reports GHSA-27r3-jxmh-p828 for the resolved tree.
