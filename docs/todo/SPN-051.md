# ✨ SPN-051 Create new documents while offline

## Story

As the [Owner](../product/personas.md#owner), I want to start a new Sheet or Doc while offline, so that I can begin work without waiting for a connection. Signed-in [Collaborators](../product/personas.md#collaborator) can do the same where they are allowed to create items.

## Scenarios

### Creating offline

Given the app was prepared online and I am offline,
When I create a Sheet in a downloaded folder and edit it,
Then it opens, my edits save on this device, and the file list marks it as not yet uploaded.

### Uploading once

Given an item created offline,
When I reconnect, including after a lost acknowledgement or a retry,
Then the server has exactly one item with all my edits, in the folder I chose, visible to people with access to that folder.

### The folder changed while offline

Given the folder was deleted or my access was removed while I was offline,
When I reconnect,
Then the item stays on this device for explicit recovery, such as choosing another folder, and nothing is written where I lack access.

## Rules

- This extends the [offline contract](../offline.md) and reverses its "no offline new-item creation" boundary. Owner, chat 2026-10-19.
- Use client-generated stable item IDs, so creation retries are idempotent. Grooming, 2026-10-19.
- Follow docs/offline.md's storage, account-isolation and persistence-before-claiming-saved rules (SPN-039, SPN-053), and update `docs/offline.md`.
- Guests, admins and view-only folders can't create items, offline or online. Collaborators create only in their own folders until SPN-069 lets folder editors create too.

## Out of scope

- Images in offline-created items, offline folder or sharing administration, and desktop-tab specifics (SPN-052).

## Verify

- Playwright: create offline, edit, reload offline, reconnect, and check the server has one item. Cover duplicate replay, a revoked folder and account switching. Run SPN-055's actual-device checks for this flow.
