# 🛠️ SPN-100 Enable reviewed dependency update pull requests

## Story

As the [Operator](../product/personas.md#operator), I want dependency updates proposed for review automatically, so that keeping Spinel current does not depend on remembering every upstream release.

## Scenarios

### Enable weekly update proposals

Given the reviewed updater configuration reaches the default branch,
When GitHub checks for updates each week,
Then npm dependencies, the Node image, Caddy and GitHub Actions are covered,
And proposed updates use the existing review and CI gates without automatic deployment.

## Rules

- Enable only `.github/dependabot.yml`; SPN-062 keeps the patching runbook and real hosted bump-PR acceptance ([split and persona rationale, 2026-10-23](../implementation/grooming-dependency-registration-2026-10-23.md#preserve-spn-099-and-separate-dependabot-enablement)).
- Configure npm, Docker, Docker Compose and GitHub Actions checks weekly on Monday at 09:00 America/Los_Angeles. Cover root npm workspaces, both Node Dockerfile stages, Caddy in `/deploy/compose.yaml` and Actions; the operator still selects `SPINEL_IMAGE`.
- Group existing Univer packages together for version updates and security updates. Keep immutable image digests and Action SHAs, and use the literal `⬆️ Bump ` title prefix. No new Pro packages, auto-merge or privileged PR workflow.
- Retain the existing registry configuration and seven-day npm version cooldown. A blocked or too-new version waits; never bypass curation through the public registry or another tarball. Cooldown does not replace curation, including for security updates.
- This configuration runs normal applicable CI; it is not a docs-only change. Validate the schema and check supported options against primary documentation/source before enabling it.

## Out of scope

- Host patching, deployment and the real hosted update log/bump-PR acceptance, which remain SPN-062.
- Updating dependency versions, replacing the existing registry, new credentials or automatic merges/deployments.

## Verify

- Schema validation and primary-source review cover all four ecosystems, schedules, groups, title prefix, cooldown and manifest paths.
- The configuration PR passes normal applicable CI and independent review. A representative title passes the backlog PR checker; record it as preparation, not evidence that the hosted updater ran.
