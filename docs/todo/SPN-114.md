# ☁️ SPN-114 Back up the workspace to AWS S3 after production launch

## Story

As the [Operator](../product/personas.md#operator), I want an AWS S3 destination after Spinel launches, so that I can choose that provider without changing the recovery format or operating a second backup system.

## Scenarios

### Publish to a private AWS bucket

Given an explicitly configured AWS region, private bucket and scoped credentials,
When automatic backup runs,
Then the shared recovery service publishes a complete encrypted workspace archive,
And catalog, download, retention and restore verification preserve their existing contracts.

## Rules

- Deferred until after production by the owner, chat 2026-10-27, during SPN-109. Local filesystem and DigitalOcean Spaces remain the supported destinations for SPN-109; [scope decision](https://github.com/mxbaylee/spinel/blob/5d22f64ecc91beb8b7526fa972eaaf27fc7f8369/docs/implementation/SPN-109.md#aws-s3-after-production).
- Reuse the existing destination transport and concrete SQLite archive; add no database adapters or new cloud SDK dependency.
- Prove AWS endpoint/signing and private access, including bucket-owner-enforced ACL behavior. Do not assume DigitalOcean's private ACL header works on AWS.
- Support only an explicitly tested versioning/lifecycle profile whose deletion behavior matches retention. Reject arbitrary endpoints and unsupported bucket profiles.
- Deployment owns policy and secrets; automatic backups require opt-in. Keep current local/Spaces configuration and independent CLI recovery compatible.
- Include real-provider publication/readback/download, anonymous-access denial, pagination, cleanup, retention and credential-rotation evidence using authorized credentials and bounded artifacts. No new account or bucket provisioning is implied.

## Out of scope

- Production launch, generic S3-compatible endpoints, multiple simultaneous destinations, database-engine adapters and live workspace restore.

## Verify

- Configuration and transport regression tests; real AWS contract with isolated-prefix cleanup; native Admin destination/policy states and independent light/dark/phone review.
