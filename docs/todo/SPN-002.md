# 🔑 SPN-002 Sign in with a passkey

## Story

As the [Owner](../product/personas.md#owner), I want to sign in with a passkey from my browser, 1Password or Proton Pass, so that my documents are protected without a password to remember or leak.

## Scenarios

### Signing in

Given an account with a passkey in my browser, 1Password or Proton Pass,
When I choose "Sign in" and pick it from the list my passkey manager shows,
Then I land on my dashboard with a session that survives a page reload.

### Adding another device

Given I am signed in,
When I add a passkey from my phone,
Then both can sign me in, and settings lists each by provider name ("1Password", "Proton Pass").

### Signed-out access

Given no session,
When I open any page or API route other than sign-in, invite and share links,
Then I am sent to sign-in and no document data is returned.

## Rules

- Start from circus-health's implementation in [docs/reference/passkeys](../reference/passkeys/README.md): its options, challenge handling and provider names. Move what's used into `src/` and delete that folder in this PR. Sign-in only, no PRF. Owner, chat 2026-10-17.
- Sessions are server-side rows in SQLite, sent as an HttpOnly, Secure, SameSite=Strict cookie, so they can be revoked. Chosen over JWTs in grooming, 2026-10-17.
- No password fallback. Recovery is the Operator issuing a new invite (SPN-004).

## Out of scope

- Creating accounts: first admin (SPN-003) and invites (SPN-004).

## Verify

- Unit tests for both ceremonies, counter checks and session expiry; Playwright with a virtual authenticator: register, sign out, sign in, add a second device.
- The owner signs in once each with a browser passkey, 1Password and Proton Pass; noted in the PR.
