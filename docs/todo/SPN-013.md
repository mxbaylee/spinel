# 🚦 SPN-013 Explain when collaboration is full

## Story

As a [Collaborator](../product/personas.md#collaborator), I want to be told plainly when I can't edit because the collaboration limit is reached, so that I wait or come back instead of thinking Spinel is broken.

## Scenarios

### Too many editors

Given a document already has the maximum number of editors,
When I open it,
Then I see it read-only with a message saying who is editing and that I'm in line,
And I switch to editing on my own when a place frees up.

### Too many live documents

Given the instance is at its limit of documents open for co-editing,
When I open another,
Then I can still edit it alone, or I'm told to wait, whichever the measured limits allow,
And the message says which.

## Rules

- Build the limits into the product rather than hiding them. Owner, chat 2026-10-17.
- The numbers come from SPN-010 and SPN-011's findings in `docs/architecture/collaboration.md`, kept in one config value each.
- Weighs the Collaborator and the Owner equally: whoever opened the document first keeps editing.

## Out of scope

- Raising the limits (SPN-011, SPN-014).

## Verify

- Unit tests for the queue: join, leave, promotion order.
- Playwright: open with one more editor than the limit and watch the queue promote.
