# 📱 SPN-072 Edit Docs comfortably on a phone

## Story

As the [Owner](../product/personas.md#owner), I want to read and edit a Doc on my phone, so that a journal entry or recipe can be written wherever I am. [Collaborators](../product/personas.md#collaborator) and [Link guests](../product/personas.md#link-guest) with edit links get the same.

## Scenarios

### Reading

Given a Doc opened in the installed app on a phone,
When it loads,
Then text wraps to the screen width at a readable size, with no sideways scrolling.

### Writing

Given I tap into the text,
When the keyboard opens and I type, select and format text,
Then the cursor stays visible above the keyboard and a compact toolbar offers bold, lists and headings.

## Rules

- SPN-049's [public zoom investigation](../implementation/SPN-049.md#phone-doc-fit-investigation-and-supported-fallback) found snapshot mutation in both public Doc zoom routes. Retain the native zoom/pan fallback until device-only fitting, saved/exported layout, selection and viewer behavior are verified; an operation without undo is not proof of a local presentation setting.

- SPN-049's [follow-up source investigation](../implementation/SPN-049.md#native-phone-navigation-evidence-repair) found the separate public `IUniverDocsUIConfig.fitToWidth`/`DocViewScaleService` route in OSS 1.1.0. It computes view scale separately from stored user zoom; the zoom-command mutation finding does not rule it out. The current core preset does not forward this config, and switching/configuring public plugins must preserve selection, collaboration, save/export geometry and viewer permissions. Verify that supported integration before choosing the phone reading/editing fallback; do not patch or CSS-scale the native canvas.

- The SPN-049 native navigation cases are authored, not yet passing evidence: populated editable and anonymous-viewer Docs at 390 px, actual wheel panning and native percentage zoom, exact saved insertion points and caret-anchor bounds, with light/dark captures. Their 50% fit-like view is not a readability guarantee. Wheel input is not touch/pinch; these cases do not prove keyboard avoidance, IME or screen-width reflow. Retain those limitations until this ticket's device and rendered-content checks establish support.

- SPN-047 handoff: Phone keeps title/status/More and a directly available people/count control; Share moves into More, and document content may pan without overflowing page chrome. Follow [the composed design](../design/editor.md) and decision [#126](../implementation/SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits) (2026-10-20); preserve current behavior and owner screenshot approval.

- Today only Sheets touch support is promised; Univer's mobile UI is experimental (docs/mobile.md). Use the public Docs API only; never patch Univer (AGENTS.md).
- If Univer Docs can't reach this through public APIs, record what works, ship a read-only phone view with a clear "Edit on a larger screen" note, and open a decision.
- Follow SPN-047's redesign for the phone editor chrome, with PR screenshots approved by the owner (process.md).

- Include Formula scalar/table reading and insertion/edit dialogs in phone checks, preserving all rows and usable touch targets (SPN-033, [#113](../implementation/SPN-033.md#legacy-decision-113-live-authorized-document-formulas); grooming, 2026-10-20).
