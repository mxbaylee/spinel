# 📑 SPN-065 Make a copy of a Sheet or Doc

## Story

As the [Owner](../product/personas.md#owner), I want to duplicate a Sheet or Doc, so that a monthly budget or a recipe template starts from last month's copy instead of an export and re-import. [Collaborators](../product/personas.md#collaborator) can copy what they can open into their own files.

## Scenarios

### Copying my document

Given a Sheet I own,
When I choose **Make a copy** from its row's More menu or the editor's menu,
Then "<name> (copy)" appears next to it, opens with the same content and images, and has its own new ID.

### Copying something shared with me

Given a Doc shared with me as a viewer or editor,
When I make a copy,
Then the copy is mine, in My files, and the original's owner, grants and guest link don't carry over.

## Rules

- Personal pinning and pinned-item UI are removed; do not reintroduce them. Owner, 2026-10-21, [decision #128](../implementation/SPN-047.md#legacy-decision-128-remove-personal-pinning).

- SPN-047 handoff: File More → Duplicate; destination/name task in one dialog; result confirmation in the list. Follow [the composed design](../design/dashboard.md) and decision [#126](../implementation/SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits) (2026-10-20); preserve current behavior and require [independent theme/persona screenshot review](../implementation/grooming-2026-10-26.md#agent-decisions-and-visual-review) on the PR.

- A copy takes the current saved state (every edit the server has confirmed), never a stale snapshot.
- Copy images into the new item's own image scope, so revoking access to the original never breaks the copy. Respect the existing 10 MiB content and 50 MiB image budgets (docs/files.md).
- No history, named versions, tags, shares or guest links come with it.
- Guests and server Operators cannot copy. Authorized everyday accounts, including File admins, retain read-based copy eligibility. Default placement is the current owned folder, otherwise My files; SPN-069 separately owns an explicit shared-folder destination and its ownership/creator attribution.
- Reuse the native import path's fresh-ID, image-validation and atomic-publication primitives (SPN-031), preserving the copy-specific Formula-binding contract below. Native import deliberately detaches source bindings; copying must not apply that policy. Grooming, 2026-10-25.

- Copies retain Formula definitions and deliberate source bindings, but no computed values or source grants; evaluate for the new viewer with current access (SPN-033, [#113](../implementation/SPN-033.md#legacy-decision-113-live-authorized-document-formulas); grooming, 2026-10-20).

- Space duplication is separate from copying a Doc/Sheet: do not expose an incomplete whole-Space copy action for the now-enabled Spaces. Copying authorized internal content into a new standalone Doc/Sheet retains fresh IDs and independent access; it does not move or share the original Space ([#116](../implementation/SPN-078.md#legacy-decision-116-spaces-remain-files-in-folders)).

## Out of scope

- Copying folders. Templates as a separate feature.

## Verify

- Unit: same-folder and My files placement, image re-scoping, budgets, Formula-binding preservation, read-authorized File admin eligibility, and refusal for guests and server Operators.
- Playwright: copy an owned Sheet with an image, edit the copy, and check the original is unchanged; copy a shared Doc as a Collaborator.
