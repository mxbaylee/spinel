# 🤖 SPN-034 Let assistants read and edit documents over MCP

## Story

As the [Owner](../product/personas.md#owner), I want an MCP server for my Spinel documents, so that an assistant I choose can read and update them with my permission.

## Scenarios

### Connecting an assistant

Given I create an access token in settings,
When an MCP client connects with it,
Then it can list, read and edit only the documents I can, and nothing else.

### Revoking

Given a connected assistant,
When I revoke its token,
Then its next request fails.

## Rules

- Spinel itself has no AI features. This is an optional interface, added later. Owner, chat 2026-10-17.
- Tokens are scoped per user and listed in the admin panel.
- The MCP server is TypeScript, never `.js` or `.mjs`, even where SDK examples are JavaScript. Owner, chat 2026-10-17.

- Resolve current grants on reads/writes and use the existing live collaboration commit boundary for edits; preserve token/account revocation and restore-generation fencing. Do not introduce whole-snapshot replacement of a live document. Grooming #92, 2026-10-19.

## Out of scope

- Any built-in assistant or AI feature.

## Verify

- Unit tests for token scope, token/account revocation, changed grants and restore races; writes use the same authoritative commit boundary.
- An MCP client test that reads and edits a document.
