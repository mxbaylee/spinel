# 🖌️ SPN-050 Move fill presets into the native fill picker or drop them

## Story

As the [Owner](../product/personas.md#owner), I want to colour cells from the sheet's own fill menu, so that colouring feels native instead of using a separate bar above the sheet.

## Scenarios

### Presets in the native picker

Given a public Univer plugin or menu API can extend the fill colour menu,
When I open the native fill menu,
Then the 16 presets appear there and keep their light/dark display mapping (`docs/theme.md`),
And the `FillPresets` bar above the sheet is gone.

### No public way: drop the bar

Given no public API can do it,
When this ticket lands,
Then the bar is removed and people use Univer's native colours,
And cells already filled with a preset look the same as before in both themes.

## Rules

- SPN-047 handoff: Fill presets in the existing Univer fill picker, never an additional persistent toolbar. Follow [the composed design](../design/editor.md) and decision #126 (2026-10-20); preserve current behavior and owner screenshot approval.

- The presets currently sit in a separate bar above the sheet (`src/ui/FillPresets.tsx`), which is unintuitive. Owner, chat 2026-10-19.
- Use a plugin or the native implementation only through Univer's public API. If neither works, drop the bar. Owner, chat 2026-10-19. Never patch Univer internals (AGENTS.md, #66).
- Keep the display mapping for stored preset pairs, so existing sheets don't change appearance even if the bar goes. Grooming, 2026-10-19. Confirm with the owner when starting.
- Keep the 16-colour palette constants, because SPN-036's profile colours use them.
- Record which path was taken, and why, in a closed decision issue, and update `docs/theme.md`.

## Out of scope

- Doc text colours, and new palettes. The editor layout (SPN-049).

## Verify

- Playwright: apply a preset (or a native colour) in light and dark; reload; a viewer sees it but can't apply it; existing preset cells are unchanged. Keep the `presetStyles.test.ts` contrast checks.
