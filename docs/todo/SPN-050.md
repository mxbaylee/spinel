# 🖌️ SPN-050 Remove the extra fill-preset toolbar

## Story

As the [Owner](../product/personas.md#owner), I want to colour cells from the sheet's own fill menu, so that a second toolbar does not take space above the sheet.

## Scenarios

### Use the existing native picker

Given a sheet with default, custom and legacy preset fills,
When this ticket lands,
Then the bar is removed and people use Univer's native colours,
And cells already filled with a preset look the same as before in both themes.

## Rules

- SPN-047 handoff: fill controls stay in the existing Univer picker, never an additional persistent toolbar. Follow [the composed design](../design/editor.md) and decision #126 (2026-10-20); preserve owner screenshot approval.

- The presets currently sit in a separate bar above the sheet (`src/ui/FillPresets.tsx`), which is unintuitive. Owner, chat 2026-10-19.
- SPN-088 alone owns public-API feasibility for eight theme-aware native picker choices, including its fallback. Do not first investigate inserting sixteen choices here. Owner-approved grooming, 2026-10-21.
- Keep the display mapping for stored preset pairs, so existing sheets don't change appearance when the bar goes. Grooming, 2026-10-19; retained 2026-10-21.
- Keep the 16-colour palette constants, because SPN-036's profile colours use them.
- Update `docs/theme.md` to distinguish retained stored colors from the removed entry point.

## Out of scope

- Native palette customization and Doc text colours (SPN-088). The editor layout (SPN-049).

## Verify

- Playwright: apply a native colour in light and dark; reload; a viewer sees it but can't apply it; existing preset cells are unchanged. Keep the `presetStyles.test.ts` contrast checks and the sixteen profile colors.
