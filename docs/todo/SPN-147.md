# 📤 SPN-147 Send the remaining Univer patches upstream

## Story

As the [Owner](../product/personas.md#owner), I want each local Univer patch that has no upstream PR to be offered upstream, so that Spinel can drop the patch on a release and every persona keeps the behavior it fixes.

## Scenarios

### Every patch has an upstream outcome

Given each patch in `scripts/dependencies/patch-univer-*.ts`,
When this ticket is done,
Then its header links an upstream PR or issue, or states why none applies,
And the ticket that removes the patch (SPN-099, SPN-119, SPN-122) names that link.

### Upstream takes another direction

Given upstream answers with a different fix,
When the answer is recorded,
Then the removal ticket follows upstream and keeps the acceptance the patch protected.

## Rules

- Already filed, so not part of this ticket: custom-range fixes in `patch-univer-core.ts` ([univer#7938](https://github.com/dream-num/univer/pull/7938)) and the zoom repair in `patch-univer-docs-ui.ts` ([univer#7969](https://github.com/dream-num/univer/pull/7969)).
- Candidates with no PR on record, checked against the headers on 2026-11-10 (agent judgment, owner request in chat):
  - the pooled shared `MessageChannel` in `patch-univer-core.ts` (SPN-146, lands with its PR), where upstream opens one channel per `requestImmediateMacroTask` call;
  - the native Doc composition helper in `patch-univer-docs.ts` (SPN-121/122);
  - the `virtual-list` repair in `patch-univer-ui.ts`;
  - the sheet drawing geometry refresh in `patch-univer-drawing.ts`.
- Depended on by [SPN-122](SPN-122.md) (Docs composition) and [SPN-099](SPN-099.md) (core, for the pooled channel), whose removals cannot start until their upstream PRs exist. When a PR is filed, add its URL to that ticket's `upstream_prs`. The `virtual-list` patch has no removal ticket yet: name its owner or file one. The drawing patch's removal is assessed in SPN-099.
- Depends on nothing open; SPN-146 has landed.
- Re-read each patch against the current upstream `dev` branch before writing it up. Send only what still applies, as a small PR with a failing test, and no `@univerjs-pro` code or behavior.
- A patch that cannot be offered (design disagreement, Pro-only code path) gets a header note saying so; this is a recorded outcome, not a failure.
- Follow [sustainable testing](../testing.md); keep the Verify plan and progress evidence current. [Policy](../implementation/SPN-115.md#guidance-for-every-open-ticket-and-progress-checkpoint), owner 2026-11-01.

## Out of scope

- Removing a patch or upgrading Univer (SPN-099, SPN-119, SPN-122).
- Changing patch behavior; headers and removal tickets only.

## Verify

- Contract: every patch header carries an upstream link or a stated reason; suite/layer: `scripts/dependencies/*.test.ts` header check if one exists, else reviewer inspection.
- Fixture readiness/cleanup: none; no runtime state.
- Environment and source/shared dependencies: patch scripts and the removal tickets' text; routing unchanged.
- Evidence: PR body lists each patch with its upstream link or reason.
