# 🔏 SPN-149 Preserve session-revocation closure evidence across navigation

## Story

As the [Owner](../product/personas.md#owner), I want revocation checks to prove an old session and its socket lose access even when the page navigates, so that a passing check means the full security contract was exercised.

## Scenarios

### Navigation cannot hide a required closure observation

Given the retained failure with sign-in visible but no observed WebSocket close,
When socket/session/navigation ordering is investigated within a declared sample,
Then a demonstrated observation race receives a verified correction, or the sample ends with an explicit inconclusive/not-reproduced disposition,
And a still-live socket or retained authorization cannot pass as successful revocation.

## Rules

- Owner approved this M, pre-launch outcome during grooming, chat 2026-11-12. Preserve the [registration, first failure and persona decision](../implementation/SPN-149.md#-registration-and-scope).
- Follow [sustainable testing](../testing.md). Inspect current observer/server/session ownership and preserve the missing first-attempt timeline. Navigation overtaking the observer is a hypothesis, not an established historical cause or security defect.
- Before execution declare one hypothesis, exact source/runtime, small fixed first-attempt sample, resource budget and stop condition. Reassess scope before a demonstrated product/session defect or broader protocol change.
- Preserve actual socket termination, denied requests, editor removal, surviving-login continuity, successful queued writes from the surviving login, no later broadcasts and saved/reloaded content. Sign-in UI alone is not server-closure proof.
- Keep original deadlines, `failOnFlakyTests`, privacy and owned cleanup. Do not delete closure coverage, increase timeouts or retry failed assertions. An inconclusive diagnosis does not waive a failed current-head gate.
- This later case is separate from SPN-120's finite auth-heading/navigation/recovery/snapshot inventory and SPN-145's worker activation.

## Out of scope

- New authentication policy, a generic retry framework, or claiming product/security defects from missing observer events alone.

## Verify

- Reuse `e2e/collaboration.spec.ts` and its isolated auth/server/browser fixtures. Add focused controls for any demonstrated observer ordering; a socket kept live and an authorization check left active must still fail.
- Observe socket establishment and revocation/navigation boundaries without sleeps; retain content-free first-failure evidence and bounded cleanup of owned contexts, intercepted writes and server state.
- Focused tests own the observation negative controls; the existing two-login Chromium collaboration journey owns real closure, denied access, surviving-login/queued-write/broadcast and saved-content proof. Reuse auth/session regressions for changed authority code.
- Track auth/session, sync transport, navigation, shared fixtures and harness dependencies in existing CI routing. Preserve exact source/tested identities and all attempts; stop at the declared sample limit, record its supported disposition, and retain both reviews and selected current-head gates.
