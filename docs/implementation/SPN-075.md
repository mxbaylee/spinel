## Legacy decision 103: Direct PDF for every current reader

**Recorded:** 2026-10-20. **Status:** accepted, implementation pending.
**Authority:** Owner, chat 2026-10-20.
**Source:** [original decision #103](https://github.com/mxbaylee/spinel/issues/103).

**Question:** Should PDF output be one direct-download capability for everyone with current read
access?

**Options considered in the original source:**

A — combine the tickets into direct PDF export for all current readers; the renderer must own
pagination and download behavior. B — keep role-specific tickets and the browser print dialog; this
conflicts with the owner's direction.

**Outcome, rationale and current boundary:**

Replace Print with one direct PDF download for every current reader, including account Viewers and
link guests. Preserve complete native formatting/images and produce watermark-free output while
removing the Pro print dependency; do not merely open a browser print dialog. The Operator gains no
document access and guest PDFs exclude account identity metadata. This supersedes decision
[#70](SPN-031.md#legacy-decision-70-original-browser-printing)'s product direction, not native-file
export restrictions. SPN-075 and its prerequisite feasibility work still own delivery; this choice
alone proves no renderer fidelity.

**Persona tradeoffs recorded at the time:**

Owner and Collaborator get one predictable PDF action, including account viewers. Link guests get
the same output with current link access and without account identity metadata. Operator retains no
document access and needs bounded resource use on the 2 GB instance.

## Legacy decision 106: Deterministic PDF pagination

**Recorded:** 2026-10-20. **Status:** accepted, agent defaults awaiting implementation.
**Authority:** Agent grooming judgment, 2026-10-20.
**Source:** [original decision #106](https://github.com/mxbaylee/spinel/issues/106).

**Question:** What deterministic pagination defaults replace the browser print dialog in SPN-075?

**Options considered in the original source:**

A — default to A4 portrait with 12.7 mm margins, all visible worksheets in workbook order with
subset selection, shrink wide Sheets to one page across without enlarging and paginate vertically;
preserve stored Doc page dimensions, margins and explicit breaks, falling back only when absent. B —
leave pagination unspecified until implementation, making completeness difficult to review. C — add
page-setup controls now, expanding the ticket.

**Outcome, rationale and current boundary:**

Default Sheets to A4 portrait with 12.7 mm margins, all visible worksheets in workbook order with
subset selection, shrinking wide sheets to one page across without enlargement and paginating
vertically. Include image extents; omit hidden worksheets/rows/columns and keep paper light in both
themes. Preserve stored Doc page dimensions, margins and explicit breaks, falling back only when
absent. This avoids unspecified output without adding page-setup UI. It selects no
dependency/service and is not an owner preference or completed fidelity check.

**Persona tradeoffs recorded at the time:**

Owner and Collaborator need complete, repeatable readable copies; Link guests should get identical
output without knowing printer settings; Operator needs bounded rendering rather than a separate
print service.

## Production integration and atomic authorization

Date: 2026-10-26. Status: accepted implementation direction; verification pending.
Decider: agent judgment under the owner's request to implement and merge SPN-075.

Use the existing standalone renderer in a disposable, resource-bounded Node
process. Account and guest routes resolve the current server-confirmed native
snapshot through the existing document credentials and exact Space-child scope.
The PDF route does not broaden native JSON export. The client waits for confirmed
saves, offers visible worksheet selection, and downloads a complete PDF without
opening a browser print dialog.

Retain the process-wide transfer reservation through preparation, rendering,
final authorization and response completion. Serialize native rendering against
Formula calculation, bound snapshots, images, output and wall time, monitor native
RSS, and terminate cancelled work before releasing its reservation. Only prepared
content and image bytes enter the renderer; no credentials or network requests do.

Revalidate host credentials, exact child scope, restore generation, images and
every Formula source immediately before publication. A lost host/session/link
aborts the export. A lost Formula input discards the entire old PDF and that whole
Formula result; one bounded rebuild uses a neutral unavailable placeholder.
Repeated access changes fail rather than publishing stale or partial values.

Compared with browser rendering, this keeps native layout and large image copies
off phones. Compared with a separate rendering service, it reuses the current
deployment while retaining hard process termination. Owner and Collaborator get
current, complete portable copies; account viewers have the same read capability.
Link guests retain scoped anonymous output and immediate revocation checks.
Operator remains content-blind and gets serialized, bounded work on the 2 GB host.
This decision is not evidence of completed fidelity, security, CI or visual review.

## Retained delivery contract

The ticket's rules remain here and in [files.md](../files.md); final
verification and independent review are recorded on [PR #186](https://github.com/mxbaylee/spinel/pull/186).
The ticket is XL because application integration coordinates current snapshots,
viewer-specific Formula evaluation, native layout, cancellation, access races,
resource bounds and complete visual acceptance. The smaller renderer tickets
were delivery slices, not a reduction of this contract.

- [SPN-097](SPN-097.md) established feasibility and sequencing;
  [SPN-101](SPN-101.md) supplied the Sheet renderer and shared contract;
  [SPN-102](SPN-102.md) supplied Docs and prepared Formula results. SPN-075
  integrates them and resolves the live editor model gaps needed for export.
- Preserve complete selected Sheet used ranges and all Doc content, including
  formatting, image extents, lists, native tables and full Formula arrays such
  as the 30-row example. No browser print dialog, Spinel Print action, watermark,
  silent truncation or partial aggregate is acceptable.
- Accounts use Document actions → Export → PDF. Guests receive the labelled
  Export as PDF action beside their read/edit badge, following
  [SPN-047's approved composition](SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits)
  and the [editor](../design/editor.md) and [guest](../design/guest.md) design rules.
  Loading, saving, selection, running, cancellation, completion and error states
  have stories and require current light, dark and phone evidence.
- Every current reader has PDF access: owners, editors, account viewers and
  view/edit link guests. Operators remain unable to read. This consolidates
  retired SPN-073 and retains [scoped guest privacy](SPN-016.md#legacy-decision-72-scoped-anonymous-link-capabilities).
  PDFs add no account identity or private Formula source metadata; native JSON
  remains account-only.
- Wait for pending edits to save and load server-confirmed collaboration content.
  Exact Space child identity, host/session/link, immutable image bytes and every
  Formula input are checked through final publication. Host access loss aborts;
  source loss discards the old PDF and replaces that whole Formula during one
  bounded rebuild. Repeated changes fail. Downloaded copies cannot be recalled.
- Sheets use all visible worksheets by default, preserve workbook order and
  allow a subset. Omit hidden rows/columns/sheets. A4 portrait with 12.7 mm
  margins shrinks wide content to one page across without enlargement; content
  continues vertically. Docs preserve saved dimensions, margins and explicit
  breaks, falling back only when absent. Paper remains light in every theme.
- The public `IWorkbookData`/`IDocumentData` rendering boundary remains in
  `lib/print`, with its own contract, tests and Docker integration. App credentials
  and UI remain outside it. Only public open-source native APIs are used; no new
  Pro dependency, source copying, reverse engineering or license workaround.
- Both Pro print packages are removed. Existing Pro collaboration still requires
  its license; [SPN-059](../todo/SPN-059.md) removes the remaining packages and adds
  the no-Pro dependency gate. The old licensed printing flow in
  [decision #70](SPN-031.md#legacy-decision-70-original-browser-printing) is superseded;
  its source issue receives a backlink after the merged SHA is verified.
- Unit, HTTP, native and browser evidence must cover pagination, selection,
  hidden axes, merges/styles/images, Doc lists/tables/breaks, all reader roles,
  exact child scope, access loss and private sources. Download actual PDFs,
  reopen every page, retain PDF/PNG evidence and review formatting, completeness,
  privacy and no watermark. Required CI and independent review remain merge gates.

Physical printing, new page-setup/header/footer controls, custom print areas,
native guest downloads, CSV import (SPN-093), optional format plugins (SPN-094)
and owned native backup/import (SPN-067) retain their separate scopes. Existing
native page-setup features are still part of the saved model that PDF handles.

## Deployment budget and portable fonts

Date: 2026-10-26. Status: accepted implementation choice; final container evidence is tracked in
PR #186. Decider: agent judgment within the retained export contract.

The host has 2 GiB. The original 512 MiB app cap proved insufficient before a PDF
worker started: the first production-container request measured 585,543,680 bytes
of parent RSS and 536,756,224 bytes of live cgroup usage against its 536,870,912-byte
cap. A guarded local probe also found that starting the app with the SDK's default
execution caused RSS to rise rapidly while the main JavaScript heap remained
nearly constant; the watchdog stopped that probe at 2,298.4 MiB combined RSS. This
was an aborted measurement, not a passing resource test.

Use the SDK's published `execution: { mode: 'in-process' }` option for all three
legacy collaboration runtime owners, retaining their eight-unit and 60-second
idle limits. No Pro implementation is inspected or patched. With that setting
and a 256 MiB V8 old-generation / 8 MiB semi-space ceiling, the measured app baseline
is approximately 430 MiB RSS. The two-user service shares the runtime in its main
process; native collaboration work can therefore occupy its event loop, which
the collaboration/browser regression checks must cover. PDF work stays in its
separate disposable process. Development uses a 512 MiB old-generation ceiling
for the additional Vite module compiler; it retains the same PDF resource checks.

Keep the 2 GiB host and set the app's hard container cap to **1 GiB**, including
its child. Caddy keeps its separate 128 MiB cap, leaving 896 MiB for the OS,
Tailscale and management services. Keeping 512 MiB would reject ordinary exports;
increasing only the cap would leave the measured runtime duplication unresolved.
This replaces the initial implementation assumption that the old app cap could
remain unchanged. The later SPN-038 deployment still measures total host use;
container CI does not substitute for that target-host acceptance.

Before loading/cloning and immediately before starting a child, admission accounts
for actual cgroup usage, other work, parent RSS and host availability. Only inactive
file cache is discounted. Leave 32 MiB in the container and require at least
192 MiB for a worker, then poll actual memory during execution. The 640 MiB child
and 1,536 MiB parent-plus-child ceilings remain outer host safeguards; the smaller
remaining container budget is authoritative. RSS sampling is not a hard native
allocation cap; bounded inputs and process termination also apply. Work which
cannot fit fails without a PDF.

Application limits include an 8 MiB snapshot, 8 MiB of encoded images, 8 million
decoded image pixels, 100 pages, 16 MiB output and a 30-second child deadline.
One transfer lease spans preparation and response completion, and native work
shares admission with Formula calculation. The production container smoke test
exercises real Sheet and multipage Doc exports, controlled cgroup memory-pressure
refusal without PDF bytes, capacity recovery and a still-responsive server.

The worker embeds static, unmodified OFL fonts with pinned source notices. It
uses documented Liberation substitutes for common proprietary font families,
plus Atkinson Hyperlegible and Noto symbol fallback. It lays out content with
those actual bytes; it does not promise identical browser-installed typography
or universal Unicode. Unknown families or missing glyph/style combinations fail
the complete export. See the [font policy](../../src/server/pdf/fonts/README.md)
and [renderer model contract](../../lib/print/README.md).

Owner and Collaborator get repeatable, complete readable copies within explicit
limits. Link guests get the same preparation and do no native work on their
phones. Operator gains no content access and retains the 2 GiB host with explicit
app, child and proxy budgets. The container smoke test must verify ordinary exports,
pressure refusal, recovery and a responsive server on the final revision.
