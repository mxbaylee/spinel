# SPN-048 — Dashboard migration

## Unified search draft and recovery

2026-10-23 — accepted by agent judgment with independent all-persona concurrence,
under the owner's current backlog-run delegation (agents may choose a decision
when every persona agrees). This refines [decision #126](SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits) without changing the
server's five search fields or authorization model.

The question was how typing, options and removable chips can edit one query
without quietly losing filters when a draft is incomplete. A last-value-wins
parser would silently discard duplicate constraints; treating every malformed
qualifier as ordinary text would conceal mistakes. Instead:

- Exact lowercase `type:`, `owner:`, `tag:` and `modified:` are qualifiers.
  Unknown colon words, including URLs, remain literal text. Double quotes group
  values; escaped quotes and backslashes decode inside them. Quoting a whole
  literal query protects words such as `type:sheet` when the form serializes it.
- Duplicates, unfinished quotes/qualifiers, invalid enumerated values and
  oversized decoded fields produce no partial query. The visible draft remains
  editable, with an associated error and polite announcement. Results, request
  debounce, focus/visibility refresh and polling pause. In-flight responses from
  the superseded request effect are ignored.
- Chips explicitly show the **last valid filters** while paused. Options and
  chip removal are disabled with an explanation; typing and Clear remain usable.
  Valid typing retains the raw field text and caret instead of canonicalizing
  the field on every keystroke. Form Apply and chip removal serialize safely.
- **Search this as plain text** deliberately uses the entire draft as `q` and
  retains every last-valid filter and the current scope. It never truncates;
  above 200 literal characters the action is disabled with a reason. Normal
  parsing applies the existing bounds to decoded fields, not combined notation.
- Touch-visible Search help explains both the syntax-free form and quoting
  literal qualifier words. Chips have text labels and explicit remove buttons.

Owner and Collaborator gain one predictable query and recoverable editing on
keyboard and touch; neither loses a filter invisibly. Link guests remain limited
to their document and gain no dashboard/search. Operator accounts gain no file
access and no new indexing service or storage requirement. Independent review
concurred with these effects and required the visible paused state and request
lifecycle described above.

## Scope and return context

2026-10-23 — accepted by agent judgment with independent all-persona concurrence
under the same owner delegation. This is the integration contract; the initial
parser/control preparation does **not** complete it.

My files retains the existing global search across accessible owned and shared
items, including unfiled shares. A folder scope includes descendants but excludes
the folder itself. Shared with me restricts to non-owner results, including File
admin. Search all files removes only the scope, preserving all five query fields
and the return context. Clear restores the prior folder/shared context. Opening
and returning from a file must preserve retrieval state, including view and scroll.

Both canonical ancestry and personal placement count toward folder reachability;
deduplicate item IDs. Personal placement may target only the caller's owned
ordinary folders. Traverse only accessible folder metadata and protect against
cycles. Spaces remain outer files, never expanded into search results. Scope
must use a complete authorized metadata graph refreshed with each search, not
only filtered results or a stale loaded cache. Loading and errors must never
broaden a scoped result set.

Owner gets folder retrieval without losing global search. Collaborator retains
personal filing and visible roles without exposing private ancestors. Link guest
and Operator access remain unchanged. The alternative of filtering paths or
already-filtered results cannot establish reliable scope membership, so it was
rejected. No new backend search grammar is introduced.

## Private retrieval state across navigation

2026-10-23 — accepted by agent judgment with independent all-persona concurrence
from the parent and recovery reviewer, under the owner's delegation. Browser
Back needs an entry-specific snapshot, while the explicit Files link from a Space
reload cannot assume a history index. Store versioned navigation hints in
`history.state`, with a once-consumed session-storage fallback used only by an
explicit exact-target return marker. The snapshot contains the current account,
a random noncredential authenticated-tab epoch, folder/shared scope, five query
fields, raw draft, list/grid choice and finite scroll position. It contains no
result bodies, paths or names as separate fields; query text itself is private.

Only exact UUID folder IDs, fixed enums, existing decoded query bounds, drafts
up to 2,048 characters and scroll between zero and ten million pixels persist.
An overlong draft remains in the current page's memory and is never truncated.
Unknown root fields are discarded; invalid/storage-failed records are ignored.
Sign-out, rejected authentication and account switching invalidate the epoch,
including old history entries when the same account later signs in again.
Cross-tab account cancellation invalidates this tab's epoch too. A stored hint
never grants access: restored folders and searches request current authorized
metadata, and missing folders cannot widen search. Offline launch uses its
existing saved catalog and does not restore an online search with no search UI.

Owner and Collaborator can return to a query without exposing a previous session's
private words. File admin capabilities remain intact. Operator accounts neither
save nor consume retrieval snapshots; Link guests retain their isolated document
view. No new server persistence, authentication token or permission bypass is
introduced. Full reload alone does not prove safe restoration; lifecycle tests and
browser return/access tests are required before acceptance.
