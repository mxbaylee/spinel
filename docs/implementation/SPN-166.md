# SPN-166 — Stop the Playwright smoke jobs from flaking

## 🎲 Scope and persona decision

**2026-11-17, agent decision with the owner's chat choices; landed with diagnostics and one
fix. Hosted acceptance is pending (see the end).** The ticket began as one `ECONNRESET`
(PR 289, CI run 43789748511, `offline-recovery.spec.ts:342`, passed on retry but the job
still exited 1). Workflow history showed several causes, so the owner chose **one ticket,
one checkpoint per cause** over a three-way split, and effort rose from M to L. Owner chat,
2026-11-17.

**All four personas:** Operator (L) gains a `Playwright smoke` gate that fails for real

## 📊 Workflow history (2026-11-17)

The last 300 `ci.yml` runs (2026-11-06 to 2026-11-17) had 62 runs with a failed Playwright
smoke job attempt. 15 distinct cases failed their first attempt and passed on retry, 23
case-run hits in all. Counts are **lower bounds**: job logs for multi-attempt runs can return
the passing attempt. Most frequent: `collaboration.spec.ts` (two cases), the `restore.spec.ts`
preview case and two `offline-upgrade.spec.ts` cases (2 runs each); eight others in 1 run each.

## Restore preview popup

Observed on PR 294 (run 43992274196, attempts 1 and 2): `restore.spec.ts` "sheet preview is
read only and restore preserves the state seen by both editors" in `development 2/2` failed its
first attempt both times. The popup never showed the heading "Preview — Restore example" in 5 s.

**Most likely cause, unproven until CI shows it:** the heading shows the item's name only once
`data` loads (`web/VersionPreview.tsx:142`), and the Restore button is enabled by the same
`ready` state (`:131`), the load the test gives 30 s. The check ahead of it used Playwright's
default 5 s (`expect` has its own default, separate from `page.setDefaultTimeout`), an
unplanned shorter deadline. The load takes 2.3 to 2.9 s locally and may have exceeded 5 s on the
slow CI runner; no CI load time was measured. The history page seen in the popup is an
unexplained observation: a popup that had not yet navigated is an alternative.

**Fix:** `e2e/restore.spec.ts` waits for readiness under its one 30 s budget first (worst case
35 s, as before: old 5 s heading + 30 s button, new 30 s button + 5 s heading), and records the
time as a `preview-ready-ms` annotation. The case still fails when the preview does not load.
This is a changed pass/fail boundary (a preview ready between 5 and 30 s now passes); **the owner
confirmed it is not a relaxed budget (chat 2026-11-18).** The CI annotation values will show the real load time.

## Offline-upgrade worker that never activates

Same run, attempt 1: `offline-upgrade.spec.ts` "interrupted emitted updates preserve exact
native work, a live old client and cold offline startup" stayed `installed` for 120 s, passed on
retry. Three runs (43992274196, 42662177748, 42661952543) show the same trace: the new worker
reaches `installed` within 21 to 518 ms, `skipWaiting()` never takes effect, the old worker stays
active. The spec says a waiting worker activates only when the active one has no in-flight
extendable event (a hypothesis here, not observed); the old worker's `message` handler holds one
through the runtime Web Lock for up to 180 s (`web/service-worker.ts`), the leading suspect. The 13
outright failures of the SPN-054 eager-client case came from branch `codex/spn-146-mobile-flush`
(attributed by branch name, not re-checked per run) and are treated as that branch's own.

**Diagnostic added:** the timeout error now includes `navigator.locks.query()`: held and pending
lock name prefixes before `:`, modes and numbered clients, capped at 2 s (the 120 s failure can
arrive up to 2 s later). It was later shown to run locally with two real git checkouts ([SPN-167](SPN-167.md#-reproduce-it)).
**Remainder:** [SPN-167](SPN-167.md) delivered a separate test-race repair.
[SPN-169](SPN-169.md) later captured Chromium restart/idle starvation and was
resolved **won't fix** by the owner on 2026-11-23. The browser defect remains;
the earlier failures' unrecorded internals are not retroactively proven.

## ECONNRESET on the test client

`apiRequestContext … read ECONNRESET` recurred in `development 2/2`: `restore.spec.ts` (the same
preview case), `portable.spec.ts:10` (`GET /api/items/<id>/sheet`) and `space-guests.spec.ts:892`
(a Space item export). The endpoint varies, so it is not specific to the collaboration endpoint.
PR 289's own log is not recoverable. A throwaway repro (not committed) of the default Node 5 s
keep-alive against a Playwright request context did not reset at 4.9 to 6 s idle, so that cause was
not reproduced in that one setup.

**Diagnostic added:** `e2e/reset-diagnostics-reporter.ts` (CI reporter, observe-only, best effort)
logs one content-free `econnreset-diagnostic` JSON line per reset failure with the call
(`GET /api/items/<id>/sheet`) and the owned server's `server-<port>.json` state (pid, exited,
signal, failed flag, byte counts, evidence age), and saves the newest 50 to
`playwright-report/reset-diagnostics-<project>.json`. No ids, queries, error text or server output
are kept. The config loads it only where the file exists, because the paired doc baselines copy
`playwright.config.ts` over older checkouts. Tests: `scripts/ci/reset-diagnostics.test.ts`.

## Collaboration flakes

"revoking one login preserves another login's queued edit…" flaked on 2026-11-07, 11-08, 11-14 and
11-15 because navigation can close the revoked socket without any Playwright event. SPN-149 and
SPN-161 (merged 2026-11-17) diagnosed and fixed it; 3 CI runs since were green, too few to call it
closed, so watch for a recurrence. "two document editors merge text and navigate to a collaborator
selection": 8 of 9 job-attempts were branch `codex/spn-146-mobile-flush` (copied-text mismatch); the
ninth (run 42938326822) was the strict one-second delivery budget missed by 5 ms (1005 ms). That
budget is the product's contract, so it stays unchanged. No code change here.

## Rules kept

- Do not weaken the gate: no exclusions, added retries, relaxed assertions or budgets; a flaky pass
  keeps failing the job. The `Playwright smoke` aggregate stays required.
- Observe-only diagnostics never change a result, retry or exit code.
