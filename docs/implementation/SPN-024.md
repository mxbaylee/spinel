## Legacy decision 56: Names bind exact saved versions

**Recorded:** 2026-10-18. **Status:** accepted.
**Authority:** Agent history interaction judgment.
**Source:** [original decision #56](https://github.com/mxbaylee/spinel/issues/56).

**Question:** What naming rules and current-state capture semantics should SPN-024 use?

**Options considered in the original source:**

A — trim names, require 1–120 characters, permit duplicate names, capture the confirmed revision
observed by the request, and recheck current edit permission/session before commit; B — enforce
globally unique names and hold live editing while naming, adding conflicts and collaboration
disruption.

**Outcome, rationale and current boundary:**

Allow duplicate trimmed version names of 1–120 characters, attached to the exact confirmed revision
and gated by current Edit access. Disable naming while local edits are unsaved; capture and retry
migration safely rather than silently naming a later state. Unnaming returns a version to ordinary
retention eligibility, while named versions stay retained. Guests gain no account-history access
from this control.

**Persona tradeoffs recorded at the time:**

Owner can label important moments without losing history; Collaborator can label shared documents
only with edit access, and must wait for local edits to save; Operator gets bounded metadata in
existing backup storage; Link guest receives no new access beyond the existing resolver (anonymous
sharing remains SPN-016).

## 🧪 Viewer fixture isolation during dependency acceptance

2026-11-06, [PR #244](https://github.com/mxbaylee/spinel/pull/244). Source
`020dc68fdbc9fad45558393642842f0ce5a05d0c`, tested merge
`aa583ee69ba4d4bc01dbd0464af97eb1bc4eebad`, failed the first Sheet history attempt
in [development 2/2](https://github.com/mxbaylee/spinel/actions/runs/42250569910/job/128032633529).
After replacing the live owner's cookie with a viewer cookie, `page.reload()`
reported `net::ERR_ABORTED`. Retry 1 passed, but `failOnFlakyTests` correctly kept
the shard failed: 74 passed, one flaky and one runtime-inapplicable case. Artifact
`13530910546`, SHA-256
`adfcbd388b2b6f13141142bd465430750afbfad1826933985b107d962dce764b`, retains the
error, blank failure screenshot and successful retry trace. It has no first-attempt
network trace, so the precise competing navigation is not proved.

The old sequence changed authentication while the owner's editor remained mounted.
Its `spinelSync` access poll runs every second and can end authentication and
navigate to sign-in after a 401; history/auth APIs also redirect on 401. Clearing
cookies creates an unauthenticated interval before the explicit reload. This is
a source-supported unsafe fixture sequence, not evidence of a Vite runtime defect
or a trace-proven first-attempt interleaving.

The two existing history cases now use the established console-recovery/admin
fixture boundary: await `about:blank`, replace cookies, then navigate explicitly
to the same item as the viewer. Unloading the old document removes its polling
and navigation work before authority changes. The genuine earlier owner reload,
saved content, exact stored checkpoint, rename/unnaming persistence, viewer history
visibility and absent mutation controls remain. Same-profile state, page-error
collection, 90-second case/30-second readiness bounds and retry policy remain.
File-scoped tracing retains a future first failure without a new diagnostic job.

**Test plan and evidence:** fresh ordinary development and production own the
actual Sheet/Doc fixture and permission acceptance. Preserve the failed attempt;
do not catch navigation errors, retry the account handoff or relax assertions.
Local static/collection results and their exact source identities belong in the
PR; the previously observed local workspace-lease socket restriction does not
supply a browser pass. Both independent reviews and all selected current-head
checks remain required before merging.

Owner and Collaborator retain exact saved history and edit authority. Link guest
receives no additional account-history access. Operator gets an isolated fixture
using an existing pattern, with the original failure and its evidence limits kept.
