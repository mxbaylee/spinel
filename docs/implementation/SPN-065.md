# SPN-065 — Make a copy of a Sheet or Doc

## Server checkpoint

This is an unfinished implementation checkpoint. The account-only server capability,
contract tests and copy-name helper are authored; UI integration, native browser
proof, independent review, screenshots and CI remain required. The ticket stays open.
No local typecheck, lint, unit, native browser or build execution is claimed; the
owner permits CI validation and local memory pressure prevents heavy workloads.

## Same-instance copies reuse the atomic native writer

**Date:** 2026-10-23. **Status:** accepted agent implementation decision, within the
original ticket's existing copy, budget and authorization requirements.

**Question/context:** How can a trusted copy preserve Formula source bindings and
50 MiB of independent images without going through the external importer's 20 MiB
base64 envelope or stripping source-backed Formula objects?

**Options:** exporting and importing would lose bindings and reject valid larger
image sets; a second writer would duplicate atomicity, image and ID handling.
Instead `PortableFiles.copy` reads the current confirmed collaboration generation,
then shares the existing byte validator and private transactional writer with import.
External imports retain their sanitization and serialized-file limit unchanged.

Only an authenticated everyday account can copy a currently readable ordinary Doc
or Sheet, or an exact authorized Space child through its Space namespace. An
account viewer, editor or File admin may copy; no source edit permission is needed.
Guest, Operator, MCP, private history and unscoped in-process credentials cannot use
this capability. There is no whole-Space, folder or offline copy operation.

The source generation is fixed before preparation. The original credential,
source access, generation and destination ownership are rechecked after preparation,
materialization and each image decode, and inside the final synchronous transaction
before publication. A restoring or changed generation refuses the operation. A
client disconnect before commit refuses publication but does not release transfer
admission while native work still runs. Shared process-wide file-transfer admission
keeps this work within the existing import/export resource policy.

Copies retain native formatting and Formula definitions with deliberate stable
source bindings. Formula calculations are viewer-local and are not read or serialized
by the copy operation; no source grant is created. Copying does not reinterpret source
IDs as permission. Ordinary formula evaluation still authorizes each source for the
new owner. Source history, named versions, personal tags, direct grants and guest
links are not copied. The normal first-save observer may create a new baseline for
the new item; that is not imported history.

Image-bearing native fields are rewritten to fresh item-scoped URLs. Each distinct
source asset receives its own stored bytes under the new item. Image IDs remain the
SHA-256 of their validated bytes: identity is `(itemId, hash)`, so the new item supplies
independent authorization and lifetime without breaking offline/history integrity.
Random image hashes would violate that existing contract; changing bytes solely to
change the hash would be needless corruption of copy semantics. The coordinating and
entry-review agents concurred with this choice across all four personas: Owner and
Collaborator retain usable images after source revocation; Guest gains no authority;
Operator retains digest verification without a format migration. Only authorized
same-source PNG, JPEG and WebP bytes are read; remote URLs are never fetched. Shared
validation enforces 5 MiB/16 megapixels/static images, 50 MiB total images and the
existing 10 MiB stored-content limit. No copy result is published until the complete
snapshot and all images are committed. A save/observer failure rolls back every new
item, snapshot and image row.

**All personas:** Owner gets the confirmed template content, independent images and
unchanged source. Collaborator can copy readable content without gaining access to
its private Formula sources. Link guest gains no durable-copy capability and remains
bound to the original link. Operator gets one admitted transfer, existing bounded
image validation and one atomic writer, without document access or another dependency.
**Decider:** implementing agent, following SPN-065 and the owner's delegated
all-persona decision authority; independent review and execution are still pending.

## Placement, naming and uncertain outcomes

**Date:** 2026-10-23. **Status:** accepted agent decision; discussed with the coordinating
and independent entry-review agents under the owner's delegated decision authority.

The server accepts `POST /api/items/:id/copy` and
`POST /api/spaces/:spaceId/items/:itemId/copy`, with JSON
`{ name?: string, parentId?: string | null }`, and returns `201 { item }`.
The result is always a new standalone item owned by the calling account. Origin,
account session and exact source namespace are required; guest namespaces have no
copy route. Only the two documented fields are accepted. The optional name defaults
to `<source> (copy)`; the base is shortened to retain the suffix within the existing
120 UTF-16-unit limit without splitting a surrogate pair. The UI and server use the
same `defaultCopyName` helper.

An omitted destination keeps an owned ordinary source in its owned folder; other
sources default to My files. Explicit `null` means My files. An explicit folder must
be an ordinary folder owned by the caller, still accessible at commit. Existing
inherited grants from a chosen destination folder apply normally: no source direct
grant is copied, and copying into an already shared folder does not promise privacy.
A private copy belongs in My files or an unshared owned folder.

The alternative of a durable creation receipt adds retention/replay/deleted-result
policy that the existing importer does not have. This slice uses a truthful uncertain
outcome instead: never automatically replay the copy POST. Definitive validation,
access and budget refusals create no partial copy. A lost or unreadable response may
follow a committed copy, so the UI must retain the draft, explain uncertainty and
require checking the destination before a deliberate new copy, rather than blindly
retrying. Cancelling an HTTP request cannot promise rollback if commit already
completed. Unexpected server errors are conservative failures, not proof that no
copy exists. UI completion and navigation must still respect the source editor's
unsaved-work guard; a copy must not discard local unconfirmed edits.

**All personas:** Owner and Collaborator receive predictable placement and keep their
source drafts; they are protected from silent duplicate creation after response loss.
Link guest is unaffected because the capability remains absent. Operator avoids a
second durable request ledger while retaining atomic failure semantics and bounded
server work. No new backend idempotency guarantee is claimed.

## Authored verification

- Real SQLite contract tests cover confirmed versus stale legacy content, fresh IDs,
  edit independence, caller ownership, inherited versus direct grants, Formula binding
  preservation without source grants, exact Space child copies and excluded identities.
- Image tests cover PNG/JPEG/WebP validation and byte independence after original access
  revocation/deletion and SHA-256 integrity, Sheet background and rich cell images, content/per-image limits,
  the full 50 MiB aggregate boundary and rejection beyond it. The aggregate fixture uses
  a tiny valid raster with padded stored bytes to test accounting without a huge raster.
- Controlled preparation/materialization/decode races cover source/session/destination/
  generation changes and disconnection; save-observer failure/final reauthorization
  tests check complete rollback. Real history integration checks a fresh baseline only.
- Real HTTP contracts cover account/Origin/body/namespace gates, transfer admission
  through cancellation, no copy before a disconnected load settles, and one committed
  item after a deliberately lost acknowledgement. These tests are authored, not passed.
