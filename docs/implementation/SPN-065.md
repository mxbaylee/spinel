# SPN-065 — Make a copy of a Sheet or Doc

## Scope and capability checkpoint

2026-10-29, initial scope checkpoint; implementation updated 2026-10-30. The owner requested a pull request and
asked that copying live inside the native editor experience as an addon. This
request does not authorize merging. The complete outcome remains effort **L**:
one Doc/Sheet copy operation, native editor and dashboard entry points, independent
content/appearance assets, Formula semantics, access revalidation, and verification.
Folder and whole-Space duplication are excluded. No acceptance is split out.

The current import path already provides native identity rebasing, image
validation and atomic publication. Its Formula-detachment policy is specific to
import and must not be applied to copying. Saved appearance lives outside the
snapshot and must be copied into independently authorized storage. The copy reads
the server's confirmed state rather than serializing a possibly stale browser.

The pinned open-source Univer SDK exposes command/menu registration and native
dialog components. The capability investigation confirmed those public extension
points work in both desktop and phone presets. Account viewers retain the embedded
entry point without edit permission; guest views register no copy addon. This is
an application addon, not a replacement SDK package, so it lives with the editor
adapters in `web/` and adds no dependency or service.

## Embedded copy experience

- **Date/status:** 2026-10-29 direction, implemented 2026-10-30; accepted.
- **Question:** Where should someone copy the document they are working in?
- **Context:** Existing sharing and collaborator controls sit in Spinel's outer
  editor header. The owner explicitly requested a more native integration for copy.
- **Options:** Another outer-header action; a dashboard-only action; an editor
  addon using the SDK's native command/menu and overlay services.
- **Decision:** Use the embedded editor addon, plus the ticket's file-row action.
  Reuse one destination/name form and the same server operation. Keep the document
  visible behind the task and use the existing theme and dialog design pattern.
  The native integration uses `ICommandService`, `IMenuManagerService` and
  `IDialogService`: the existing native Others toolbar group/desktop overflow and
  phone More menu open a native dialog/drawer. Signed-in phone Doc viewers keep
  that toolbar while Edit header controls and the editing footer stay hidden.
  `CopyFileForm` supplies the same production form in the dashboard Modal.
- **Personas:** Owners can reuse their current work in place. Collaborators can
  copy authorized read-only content into their own files and explicitly choose an
  editable shared folder. Guests gain no new action or scope. Operators retain
  their separation from document access and no new service dependency.
- **Source:** Owner, current SPN-065 chat request; agent implementation judgment
  for the shared form and existing public SDK extension points.

## Confirmed state and independent publication

- **Date/status:** 2026-10-30, accepted.
- **Question:** How can copying reuse import without silently changing Formula
  bindings or exposing source-private assets?
- **Evidence/options:** Browser serialization can be stale or include an
  unfinished edit. Export then import adds an unrelated 20 MiB transfer envelope
  and deliberately detaches Formula bindings. The existing import preparation and
  publication primitives already validate native content, rebase identity and
  publish atomically; they accept an explicit source-binding map for existing
  recovery/archive callers.
- **Decision:** Load the server's materialized confirmed collaboration state,
  read authorized stored image bytes directly, and reuse those preparation and
  publication primitives with copy-specific binding preservation. Check content
  and image sizes before large allocation. Capture source revision, restore
  generation, saved appearance and destination ownership, then revalidate them
  with the original session and exact access scopes inside the final transaction.
  An intervening change yields a retryable conflict, rather than a partial or
  ambiguously outdated copy. Appearance and independent uploaded-cover bytes join
  that transaction; source sharing metadata never does.
- **Personas:** Owners receive independent copies of confirmed work. Collaborators
  retain read-based eligibility and current Formula authority, with clear shared
  destination ownership. Link guests gain neither copy capability nor source
  scope. Operators keep their document separation, bounded memory/storage budgets
  and the existing storage topology.
- **Source:** Ticket rules carried from SPN-031, SPN-033, SPN-069 and SPN-086;
  agent implementation judgment based on the existing validated import path.

## Native drawer dismissal and completion

- **Date/status:** 2026-10-30, accepted.
- **Question:** What happens if a phone user drags the native drawer away while
  the server is publishing a copy?
- **Evidence/options:** The pinned SDK's native drawer supports drag dismissal
  even when mask, keyboard or close-button options restrict other ways to close.
  Its returned `open()` disposable closes all dialogs, so it cannot safely serve
  as this addon's cleanup. Ignoring dismissal while busy leaves stale addon state;
  treating dismissal as cancellation cannot undo an already published request.
- **Decision:** Close only the addon's dialog ID and always track actual dismissal.
  Keep the in-flight request and native command's busy state in the plugin. Once
  it settles, announce the outcome through the native message service and retain
  the created item for **Open copy** when the drawer reopens. Do not issue another
  copy request. Explicitly closing a completed task clears that retained result.
  Recheck current save/connectivity state before automatic or explicit navigation;
  unfinished edits, image/Formula input, recovery and offline state stay protected.
- **Personas:** Owners and Collaborators can dismiss a phone task without losing
  its outcome or accidentally creating a second copy. Link guests and Operators
  never receive the addon. No global SDK overlay behavior or other dialog is
  modified.
- **Source:** Independent review finding, pinned open-source SDK investigation,
  and agent implementation judgment.

## Retained copy contract

- Copy the latest confirmed native content with a fresh root/native identity and
  independent image and uploaded-cover bytes, within existing budgets.
- Retain explicit icon/color and applicable cover attribution; do not inherit
  history, versions, tags, shares or guest links.
- Retain Formula definitions and deliberate bindings, discard computed results,
  and evaluate under the new viewer's current authority.
- Permit read-authorized everyday accounts, including File admins; reject server
  Operators and guest credentials. Revalidate after asynchronous preparation.
- Default to the actor's current owned folder, otherwise My files. An explicit
  editable shared-folder destination belongs to that folder's owner and records
  the copying account as creator, following SPN-069.
- Copy authorized internal Space Docs/Sheets into standalone files; never expose
  an incomplete whole-Space copy action.

The maintained user/access/budget contract is in [Files](../files.md#make-a-copy).
