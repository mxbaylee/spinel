# SPN-065 — Make a copy of a Sheet or Doc

## Scope and capability checkpoint

2026-10-29, implementation in progress. The owner requested a pull request and
asked that copying live inside the native editor experience as an addon. This
request does not authorize merging. The complete outcome remains effort **L**:
one Doc/Sheet copy operation, native editor and dashboard entry points, independent
content/appearance assets, Formula semantics, access revalidation, and verification.
Folder and whole-Space duplication are excluded. No acceptance is split out.

The current import path already provides native identity rebasing, image
validation and atomic publication. Its Formula-detachment policy is specific to
import and must not be applied to copying. Saved appearance lives outside the
snapshot and must be copied into independently authorized storage. The copy reads
the server's confirmed state rather than serializing a possibly stale browser.

The pinned open-source Univer SDK exposes command/menu registration and native
dialog components. Those are the first integration choice. The early checkpoint
must also prove account viewers and phone layouts retain a usable embedded entry
point, without exposing editing actions or granting guests copying authority.

## Embedded copy experience

- **Date/status:** 2026-10-29, accepted direction; implementation/verification pending.
- **Question:** Where should someone copy the document they are working in?
- **Context:** Existing sharing and collaborator controls sit in Spinel's outer
  editor header. The owner explicitly requested a more native integration for copy.
- **Options:** Another outer-header action; a dashboard-only action; an editor
  addon using the SDK's native command/menu and overlay services.
- **Decision:** Use the embedded editor addon, plus the ticket's file-row action.
  Reuse one destination/name form and the same server operation. Keep the document
  visible behind the task and use the existing theme and dialog design pattern.
  The native integration must survive read-only grants and phone controls.
- **Personas:** Owners can reuse their current work in place. Collaborators can
  copy authorized read-only content into their own files and explicitly choose an
  editable shared folder. Guests gain no new action or scope. Operators retain
  their separation from document access and no new service dependency.
- **Source:** Owner, current SPN-065 chat request; agent implementation judgment
  for the shared form and existing public SDK extension points.

## Copy contract to verify

- Copy the latest confirmed native content with a fresh root/native identity and
  independent image and uploaded-cover bytes, within existing budgets.
- Retain explicit icon/color and applicable cover attribution; do not inherit
  history, versions, tags, shares or guest links.
- Retain Formula definitions and deliberate bindings, discard computed results,
  and evaluate under the new viewer's current authority.
- Permit read-authorized everyday accounts, including File admins; reject server
  Operators and guest credentials. Revalidate after asynchronous preparation.
- Default to the actor's current owned folder, otherwise My files. An explicit
  editable shared-folder destination belongs to that folder's owner and records
  the copying account as creator, following SPN-069.
- Copy authorized internal Space Docs/Sheets into standalone files; never expose
  an incomplete whole-Space copy action.
