reproducible evidence and this rubric. Review contexts exclude prior grades,
requested grades and the other reviewer's conclusion. Each reviewer records concrete
deductions, severity, evidence and a proposed correction.

## Public native integration and history boundaries

Accepted implementation decision, 2026-11-01, agent judgment under the current
request. Every editor, snapshot viewer, confirmed replica and authoritative native
model installs the same `@spinel/sync-transform` boundary after plugin registration
and before unit creation. The package has no application-path or rendering import.

The public document `change$` stream runs inside model application, before native
structure validation and view reset. A separate public JSON1 replacement canonicalizes
custom ranges in that actual model, including header, footer and note segments.
Cached header/footer models are reset through their public API. This preserves
the native range identity convention without changing TextX or suppressing native
validation; remote edits and Undo/Redo use the same boundary.

The native Docs manager's public constructor accepts a state interceptor. Its DI
factory creates the same exported manager class and composes the existing optional
UI interceptor, retaining desktop/mobile IME behavior. An unconditional second
interceptor registration was rejected after browser CI exposed the duplicate.
Only replacement retains carrying paragraph metadata require isolated history
publication. Paragraph insert/delete metadata alone does not force a boundary:
ordinary typing, Enter and the existing bounded-history budget keep their grouping.
Core's paragraph composition is therefore never relied on to merge a paragraph
replacement with an earlier formatting state.

The 1.1.0 IME producer audit found no paragraph-style REPLACE retain entering its
internal composition cache: ordinary candidates insert/delete text, initial
selection deletion disables bullet inheritance, and inverse capture removes
paragraph fields absent from a forward retain. Whole-body replacement restores a
blank paragraph by insertion. The UI integration tests exercise the real native
IME cache, interceptor and manager, including selection/layout metadata; they do
not substitute for browser command/event acceptance or claim complete DOM IME
coverage from a seeded cache.

The hyperlink command repair accepts only the local native producer's pure-retain
shape with one consistent link identity. Mixed content edits, opaque attributes
and remote/synchronization-only commands remain outside that repair. The transform
layer separately preserves winning replacement style keys, including falsy values,
and explicit empty paragraph replacement slices at unstyled retain/insertion
boundaries. Overlapping attribute conflicts retain their native producer scope.
A transient empty decoration
marker exists only during stock transformation and is removed before native apply
or transmission. It does not introduce decoration writes or mutate caller-owned
inputs; tests distinguish stock decoration semantics from marker provenance.

For the Owner, Collaborator and editable Link guest, these boundaries preserve
formatting, link identity, native history and synchronized content. The Operator
retains a reproducible stock-core install and independently guarded non-core
packages. No UI layout, authorization rule, wire format or SDK version changes.
The retained collapsed-drawing rendering limitation remains documented in
[collaboration](../collaboration.md#pinned-open-source-drawing-refresh-repair): saved
image geometry and continued editing are distinct from canvas visibility.

exercise. Native tests use the same installer and real command, model, history and
collaboration-publication services as the application. The stock failure controls
establish that the integration remains necessary.

| Styles and paragraph retains preserve whole links; a lone suffixed fragment regains its root | Native custom-range cases, including an edit outside the link |
| A link builder spanning paragraph boundaries cannot publish negative retains | Three actual `BuildTextUtils.customRange.add` selections, captured operations and reversible results |

Production server and browser imports both select Univer's ESM export. The server
runs `server/index.ts` from the root ESM package; browser and Vitest configurations
do not override SDK module resolution. Native integration tests therefore exercise
the production ESM class/token graph. Dual-format Docs guard tests qualify the
ES/CJS manager source with their stated imported-core fixture, while the separate
stock-byte test verifies both core distributions. They are not described as two
independent native application runtimes.

An added synthetic paragraph COVER fixture omitted the bullet that the native
deletion producer requires. It exposed upstream's arbitrary COVER paragraph-style
limitation, already called out in the ticket, rather than a supported producer
regression. The maintained concurrency test now obtains its operations from
`BuildTextUtils.paragraph.style.set`, which produces REPLACE retains, and checks
the exact accepted-first style. Deletion and QuickList COVER producers retain
their bullet and inherited metadata. The SDK's same-text selection replacement
helper can also produce COVER paragraph writes; the inspected Spinel call sites
use collapsed insertion, text-only label replacement or deletion/insertion rather
than the divergent same-text paragraph-style shape. The source-based distinction
is recorded beside that test. No original regression or supported native
acceptance obligation is removed.

A second adversarial fixture combines a paragraph replacement and a comment write
inside the same action. Stock application implicitly clears decorations under a
replacement even when its decoration array is omitted, while stock transformation
does not consistently arbitrate that implicit clear. The removed core repair did
not change this behavior, and direct stock/adapted operations and per-order models
match. Spinel has no comment plugin producing this combined action. The example
remains an explicit stock negative control and noninterference check, not a claim
that arbitrary synthetic paragraph/comment writes converge. This work does not
introduce a new comment-conflict policy to conceal a pre-existing upstream defect.

The first runtime checkpoint (`98bb7db`) exposed formatting/test-type errors,
duplicate UI interceptor registration, and over-broad paragraph history isolation.
Those failures are retained in its CI run rather than relabeled as transient
successes. Their corrected behavior is verified on the later candidate identified
in the PR's acceptance record; a prior head's successful subset does not substitute
for the required current-head checks.

## Retained drawing activation and reopen qualification

Added 2026-11-01 after independent review identified that the existing native
queue/raw-reopen checks do not establish canvas behavior. The two
`retained collapsed drawing` cases in `e2e/sync-client.spec.ts` run in the existing
sync-development and sync-production browser partitions. They seed retained zero
and signed widths through the native drawing service, then use the validated
portable-file import path to store self-contained PNGs. The existing native queue
tests separately prove how valid drawing geometry can become collapsed; these
browser cases isolate activation and reopen of that retained state.

The same magenta image first renders at a normal size on a control tab, proving
the source can be fetched and decoded. On the retained-drawing tab, the actual
canvas must show more than 1,000 pixels of the unaffected green image and no
magenta pixels. The checks repeat after switching away/back and after reopening
both clients. Full saved drawing resources must retain identity, source, anchors
and exact finite geometry, while real cell edits before and after reopen must save
and converge across both browsers and the server. Screenshots, pixel counts,
stored resources and native model/wire diagnostics are retained on failure.

This preserves the accepted omission of an invalid-size image without claiming
automatic visual recovery. Owner, Collaborator and editable Link guest keep their
saved image and can continue work; viewing guests retain the same renderer
boundary. The Operator gains a distinct regression for saved-state versus rendered
state, with no additional SDK repair or production observation interface.

The browser-test source typechecked locally. Local browser execution was blocked
before fixture execution by missing pinned Chromium revision 1248. The official
download returned an HTML "Site Unavailable" response in place of the ZIP, which
the installer reported as a truncated/invalid archive. Neither is a behavioral
pass or failure. The current-head hosted browser results in the PR remain the
acceptance record for these new cases.

A separate fixture-only diagnostic used the exact browser helper and actual
portable import/image store for both widths. It verified rebased IDs, hashed
item-scoped URLs, exact geometry and every decoded PNG pixel (1.62 seconds,
203.2 MiB peak). That check corrected the test's expected native batch order to
`['visible', 'collapsed']`; complete resource/order preservation remains required.
This fixture check is not counted as canvas evidence.

A subsequent diagnostic exercised native placement and model refresh with the
same imported fixtures. Headless open preserved all resources, but the first
positive-image refresh added axis defaults and native header offsets; a second
refresh was stable. The source control moved from `(264, 100)` to `(310, 120)` and
the unaffected image from `(88, 100)` to `(134, 120)`. Both collapsed cases were
rejected by public placement with `SHEET_DRAWING_PLACEMENT_EXTENT_INVALID` and
remained exactly preserved. The monitored diagnostic used 192.7 MiB / 1.31 seconds.

The fixture therefore seeds only its ordinary-sized controls through public
`getSheetDrawingPlacement` / `applySheetDrawingPlacement` using the real native
sheet skeleton before batch insertion. Retained zero/signed geometry is unchanged.
This makes the valid controls canonical before activation while preserving every
canvas, complete-resource, edit, and convergence assertion. No production behavior
changes, and the diagnostic does not replace actual hosted rendering acceptance.

The corrected exact-helper diagnostic passed both widths, including stored PNG
bytes, complete resource equality on the first and second native refresh, and
strict rejection/preservation of the collapsed entry (195.3 MiB / 1.18 seconds).
Full typecheck including the integrated main changes passed at 1,846.1 MiB /
10.51 seconds, including a brief wait for the serial lock. Hosted checks still
qualify actual canvas behavior on the published candidate.
