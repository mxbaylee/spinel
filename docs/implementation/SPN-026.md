## Legacy decision 81: UTC history navigation

**Recorded:** 2026-10-18. **Status:** accepted.
**Authority:** Agent history presentation judgment.
**Source:** [original decision #81](https://github.com/mxbaylee/spinel/issues/81).

**Question:** Which day boundary and preview behavior should history browsing use?

**Options considered in the original source:**

A — label timeline/calendar times as UTC, keep all retained checkpoints on each day selectable, and
browse in the existing isolated preview tab. Debounce rapid slider selection and dispose the
previous native viewer; keep restore confirmation, current permissions and generation checks. B —
use local calendar days and embed preview beside the live editor, adding timezone ambiguity and
another renderer to the editor page.

**Outcome, rationale and current boundary:**

Use UTC calendar dates consistent with retention, keep every retained version selectable and preview
in an isolated read-only native view. Restore still requires current Edit access and the independent
complete restore protocol; selecting a row does not mutate live content. Named versions and the full
timeline retain their semantics. Guests gain no history route and the Operator gains no content
privilege.

**Persona tradeoffs recorded at the time:**

Owner wants predictable recovery dates and named versions; Collaborator needs the same timeline and
current read/edit boundaries; Operator benefits from calendar days that match existing UTC retention
without new storage; Link guest must gain no history endpoint or document metadata.
