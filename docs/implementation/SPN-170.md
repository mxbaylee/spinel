### 📝 Editing contract

Use synthetic modern Docs with known text and surrounding formatting. Cover
typing at the start/middle/end, paragraph insertion, backward deletion, desktop
forward Delete, selection deletion and replacement, and deletion at paragraph
boundaries. Include Unicode characters and safe empty/start/end boundaries.
Mobile uses the platform's supported deletion action; it does not need a key its
software keyboard lacks. Check caret/selection, undo/redo, exact native and saved
content, surrounding metadata and reopen persistence. Preserve read-only and
traditional phone-layout restrictions. Do not replace actual input with direct
snapshot/command mutation merely to get the expected text.

If the reported failure is reproduced, retain detecting evidence and fix it with
the test. If it cannot be reproduced, record the bounded attempts and remaining
unknowns; passing emulation is not a claim that the reported phone problem is
fixed. Any failing current acceptance case remains a blocker.

## Mobile opt-in contract

**Owner decision:** mobile editing execution is on demand. **Agent choice:**
use a dedicated, default-off suite and one-shot requests rather than enabling it
for every later commit on a labeled PR. The names below were proposed at
registration and are implemented on the SPN-170 candidate; they are not
described as landed until that PR merges.

- PR label: `ci-doc-editing-mobile`. Adding this exact label to a same-repository
  PR requests one run on its recorded immutable head. Keeping the label on the
  PR does not request another run on synchronize, reopen or metadata edits.
  Removing and re-adding it is an explicit new request, not a silent retry.
- Manual input: `run_doc_editing_mobile`, boolean, default `false`. Explicit
  `true` requests the mobile suite on the chosen revision. Resolve and report
  its SHA; an ordinary manual/full run with the input absent or false does not.
- Runtime flag: `SPINEL_DOC_EDITING_MOBILE=1`, default off, for the selected
  runner and a documented explicit local invocation. A dedicated
  `@doc-editing-mobile` test tag prevents default collection/execution.
- Unlabeled PRs, later pushes, main pushes, schedules, `ci-full`,
  `ci-performance`, unknown diffs and full-plan fallbacks do not select this
  **new** mobile matrix. Existing required coverage retains its current rules;
  do not repurpose `phone-compatibility` or `@phone-ordinary`, or retag existing
  automatic mobile cases into the opt-in suite.
- A requested worker must reach a truthful aggregate: missing, skipped, failed
  or cancelled selected work cannot produce a pass. Unrequested work is
  explicitly inapplicable. Keep first failures and exact requested/tested
  identities, so removing a label cannot rewrite a failed observation as passed.
- Keep desktop editing checks in their normal automatic source/dependency
  routing. Document the flag, label, manual action, applicable revision and
  output locations in `docs/testing.md` when implemented.

The alternatives were always-on new mobile coverage or a broad mobile-CI opt-out.
