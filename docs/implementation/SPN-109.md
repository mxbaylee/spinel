## Preserved acceptance and boundaries

The Operator can freshly authenticate and create an encrypted complete-workspace
download using a recovery key and valid runtime/image metadata, without cloud
credentials. The real shared backup implementation creates the artifact; private
bounded jobs cover cancellation, expiry, restart and streamed authorized delivery.

For filesystem or DigitalOcean Spaces, automatic publication, complete-artifact
catalog retrieval and retention use the same recovery services. Admin separates
effective policy, actual destination, successful publication, offsite coverage and
isolated restore verification. AWS S3 is retained as post-production SPN-114.

The [original backup-options decision](SPN-063.md#proposed-backup-options-and-assisted-restore)
and [accepted pre-deployment boundary](SPN-063.md#accepted-decision-implement-recovery-before-deployment),
owner chat 2026-10-27 and originating PR #205, remain authoritative. SQLite stays
concrete; the existing filesystem/Spaces configurations and independent CLI
recovery remain supported. Deployment owns policy and secrets. Browser requests
accept no paths, arbitrary file/database/SQL input, endpoints or secret values.
Workspace and diagnostics names stay fixed, with live expiry, artifact retention
and document history independent.

Fresh Operator authorization, CSRF/origin protection, private session-owned job
state and a short-lived delivery capability protect the complete encrypted copy.
Neither browser nor server buffers the whole archive; Admin offers no content
preview and does not bundle the recovery key. Catalog selections hold the artifact
against retention. Actual private-access/signing/publication provider evidence,
target-host acceptance and cold recovery remain the open SPN-038 launch gate.

Live workspace activation remains SPN-112, pause/restart control SPN-111 and
diagnostics expiry SPN-110. Completing downloads does not complete those tickets
or authorize live recovery. All four personas and independent light/dark/phone
review apply to this implementation.

## Deployment policy and manual-only operation

**Accepted, 2026-10-27 — agent judgment under the standing delegation.**
Extend the existing private flat configuration with `version: 1`,
`dataset: "workspace"`, `automatic` and `manualDownload`. A new versioned policy
defaults automatic jobs off; existing unversioned filesystem and Spaces files
retain their schedule. `type: "manual"` supplies recovery prerequisites without
cloud fields or an automatic destination. It cannot enable automatic jobs.

The Admin surface reads effective policy; it does not edit deployment credentials
or accept paths, SQL, archive keys, endpoints or a dataset chosen by the browser.
Workspace artifact retention stays at seven daily, four weekly and six monthly
points, separately from live expiry, diagnostics and document history. Diagnostics
continues its existing distinct export; diagnostics expiry is SPN-110.

Operator can prepare a recovery copy without a shell while retaining one source
of configuration truth. Owner gets the existing complete encrypted format and
separate-key guidance. Collaborator's acknowledged work uses the same consistent
SQLite snapshot. Link guests get no new access or backup metadata.

## Private bounded jobs and native delivery

**Accepted, 2026-10-27 — agent judgment.**
Use the existing persisted recovery lease for snapshot, catalog retrieval and
retention exclusion. Keep one private export per database across preparation,
ready and delivery; concurrent work receives a truthful busy response. The
database-specific staging namespace prevents one database from reconciling
another's files. Preparation, ready time and delivery are bounded, with explicit
cancellation, expiry, interrupted-delivery cleanup and dead-process reconciliation.

Creating and downloading require current Operator authority and fresh
account-bound passkey proof. JSON mutations require the configured Origin;
delivery uses an Origin-checked native POST form. A one-use, 60-second capability
is hashed in server memory and bound to the cookie session and exact job. It is
sent in the form body, never a URL. Authorization is checked after asynchronous
work, before bytes flow and during delivery. Responses are `no-store` and content
is streamed with backpressure; no browser `blob()` or whole-archive server buffer.

Catalog IDs are opaque and derive only from recognized complete artifacts. The
shared lease holds a selected point against retention while it is authenticated
and delivered. A retained bundle may name its original immutable application
image: downloading an older recovery kit is useful after an upgrade and does not
activate it. Origin, inventory, encryption and retained key identity are checked.
Live activation and maintenance remain SPN-112 and SPN-111.

Operator sees status and cancellation without contents. Owner keeps a complete
recovery artifact without its decryption key alongside it. Collaborator edits
are not paused through a browser transfer. Link guest boundaries survive because
only an independently authenticated Operator can initiate or receive an export.
The synchronous SQLite copy can still briefly occupy the application's event
loop; target-host interference measurements remain a launch requirement.

## Configuration changes during recovery work

**Accepted and repaired, 2026-10-27 — agent judgment following independent review.**
A catalog refresh can reload deployment configuration while an automatic upload
or verification is awaiting I/O. Reading mutable service configuration after that
wait could attribute destination A's successful operation to newly selected B,
including two Spaces prefixes using the same provider. That would falsely report
recovery protection at B.

Each configuration read now validates and returns its own local configuration.
Only the latest read generation may publish visible policy/readiness, so a slow
older validation cannot replace a newer result. Each publication or verification
captures its destination identity before asynchronous work and records that same
identity on completion. Switching destinations therefore hides the previous
destination's success until the newly selected destination has its own evidence.

Three controlled-barrier regressions cover upload attribution, verification
attribution and overlapping key/readiness validation. The verification-attribution
test substitutes only the verifier outcome to isolate this race; the existing
real isolated-verifier acceptance is still required in CI.

Operator sees the destination actually protected. Owner and Collaborator retain
truthful recovery evidence for their acknowledged work. Link guest has no new
access or metadata exposure. This uses local state and generation checks without
adding another configuration service or database adapter.

## Design and review

Reuse existing health facts, disclosures, passkey confirmation, status and action
patterns from the [Admin playbook](../design/admin.md). There is one primary
prepare/download action. Policy, successful publication, restore verification
and browser handoff are distinct facts. A successful handoff is not proof that
the Operator retained the file or that offsite recovery has been tested.

Production-component stories cover the policy and every new job state. The
implementation PR embeds proposed designs and current light/dark/phone native-flow
screenshots, with captions distinguishing checkpoints from the final reviewed
commit. Both independent grades and visual findings/approval must refer to that
same final commit. **Agent review only.** Passing capture tests alone are not
visual approval or permission to bypass the seven required CI gates.

### Pending DigitalOcean and launch evidence

The owner authorized a bounded provider test using the connected DigitalOcean
secrets. The GitHub provider probe could not perform the contract because its
access-key identifier was missing or malformed. It therefore establishes **no
live DigitalOcean acceptance**. Supply the complete valid credential pair for the
selected private Space and rerun the bounded contract; do not infer a provider
pass from local filesystem tests, SDK contract tests or an unavailable probe.

Only test-owned objects in a generated prefix may be written/deleted. Secret
values must never be logged, committed or included in reports. The selected
provider's real private-access/signing/publication/readback/download/retention
and credential-rotation contract, target encrypted mount and operating budgets,
independently retained archive/key/image access and timed cold recovery remain
open in [SPN-038](../todo/SPN-038.md). Public launch must still satisfy those gates.
[SPN-114](../todo/SPN-114.md) keeps AWS S3 after production and does not weaken the
DigitalOcean launch requirement.
