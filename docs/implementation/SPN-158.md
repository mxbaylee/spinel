## 🧭 Complete outcome and persona decision

**Date/status/source:** 2026-11-13, accepted registration and scope; implementation
and acceptance pending. Agent delivery judgment under the owner's continuous
backlog instruction and [standing persona authority](../todo/process.md#decisions).
The manager and SPN-090/SPN-157 agents independently inspected the named boundary.

**Question:** how should a newly demonstrated fixture readiness gap be repaired
without weakening authentication admission or hiding the distinct unfinished
supervisor investigation?

Options were to retry authentication, treat a session response as sufficient,
fold the failure into the two original SPN-157 scenarios, or give the narrow
admission fixture boundary its own complete outcome. Choose the last option:
**M, pre-launch**, blocking SPN-090. Waiting for the state needed by the next
operation is preferable to retrying an authentication mutation or changing the
production gate. SPN-157 retains its full L diagnosis/repair and SPN-098 dependency.
This is not a diagnostics-only split to obtain a validation grade.

The complete outcome includes the existing crash fixture and shared HTTP helper,
deterministic paused/running HTTP controls, content-free stage diagnostics,
authentication and acknowledged-write persistence, bounded process cleanup and
actual Linux integration. Strengthen the existing **single 20-second** postcommit
wait to require both application-observed phase `running` and the existing session
401 condition. Do not introduce another budget, authentication retry, sleep-based
readiness, runtime admission change or weaker crash/content assertion.

**Early capability checkpoint:** establish that the probe observes the same
application gate as the gated authentication endpoint, and use the real HTTP
fixture to hold it paused. Share the exact probe with the crash scenario; prove
the original session-only condition would admit the held-paused state and fail
the new control. If evidence identifies a separate product defect or wider
lifecycle change, reassess the full scope before implementation rather than
concealing it in the fixture change.

**All four personas:** Operator gains a useful first-attempt recovery verdict and
bounded diagnostics. Owner and Collaborator retain authenticated candidate
selection, acknowledged-write durability and exact content/cleanup checks. Link
guest is unaffected by this operator fixture and receives no new admission,
document or management authority. Registering the repair separately permits
honest sequencing while keeping both failed PRs open.
