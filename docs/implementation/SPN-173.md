## Scope and persona decision

**2026-11-23 — accepted as the investigation direction by agent judgment under the owner's request.** Retain canonical Sheets/native Docs on Spinel's existing native OT. Compare a separately versioned prose channel using maintained Yjs bindings, and a ProseMirror-step authority where applicable. Reuse existing authorization/lifecycle/storage infrastructure where its contracts fit; do not pretend an existing WebSocket endpoint accepts a different document protocol. Choose the final architecture after the probes; adopting Yjs is a recommendation to evaluate, not a completed decision or requirement imposed on the local MVPs.

| Persona | Decision and tradeoff |
| --- | --- |
| Owner | Concurrent typing, local undo and named formulas must preserve intent and history. Retain native Spaces during migration and fence old clients during restore. |
| Collaborator | No lost peer edits, duplicate first-load content or false save claims; each viewer's formula results respect their own source permissions. |
| Link guest | New prose rooms inherit exact Space root/child access, View/Edit rules, anonymous presence and revocation; no generic public Yjs room is acceptable. |
| Operator | Keep bounded processes/data on the existing small host; size persistent updates, compaction, backups, offline recovery and rollback once, with no required paid service. |

Formulas remain **Space-only**. Named formula definitions and their stable targets are authored state; values, type previews, backlink counts and awareness are derived/ephemeral. Standalone Docs remain non-evaluating per SPN-172; native Sheets retain their engine. A spike may identify a larger or smaller winning implementation, but cannot omit parity boundaries simply to call an extension “S”.

## 🔎 Current collaboration architecture

The app implements **server-authoritative OT over native Univer mutations**, not Yjs or generic JSON patches. No standard binding from the five candidates directly speaks this wire format.

| Boundary | Exact current implementation | Compatibility implication |
| --- | --- | --- |
| Transport | `src/server/sync/transport.ts` / `attachSync`, `scope`, `identify`, `current`; `ws` JSON frames | Native `/sync-api/items/:itemId`, guest, `/spaces/:spaceId/items/:itemId` and guest-Space scopes each expose ticket/snapshot/socket. Transport library reuse does not mean protocol compatibility. |
| Admission | Same transport: 30-second single-use tickets, current session cookie/unit/privacy/maintenance identity; 64 connections, 64 KiB message bound, bounded buffered bytes/pending messages | New provider needs explicit equivalent admission/backpressure. A client-selected room name or arbitrary awareness map is not authorization. |
| Ordering and transform | `lib/sync-server/src/server.ts` / `SyncServer.submit`; `lib/sync-transform/src/transform.ts` | Transform past accepted revisions, apply native mutations, validate snapshot, then guarded durable commit. Unknown operations and formula-derived writes are refused. |
| Snapshot types | `lib/sync-server/src/types.ts`; `src/server/sync/store.ts` | `NativeSnapshot = IWorkbookData | IDocumentData`; only `sheet`/`doc`, including SQLite CHECK. Candidate JSON, PM steps and Yjs updates cannot be inserted into this envelope. |
| Durability | `src/server/sync/store.ts` / `SQLiteSyncStorage.commit` | Authorization is rechecked in the writer transaction; receipt/revision/snapshot commit before acknowledgement. Yjs state synchronization still needs an application-level durable-save contract. |
| Replay/retention | Native server/client types and transport resume | Ordered revisions, immutable retry receipts, 10 MiB snapshots and bounded 128-revision/16 MiB transform window. CRDT state vectors/compaction have different guarantees. |
| Client state | `lib/sync-client/src/{client,types,native}.ts` | Acknowledged replica, immutable sent envelope, inflight edits and unsent queue; `ClientCheckpoint` is native-only. |
| Undo | `lib/sync-client/src/native.ts` | Accepted peer revisions clear local native undo/redo and Doc history; own acknowledgements preserve it. A prose CRDT must use one collaboration-aware undo owner, not blindly inherit this behavior or run competing stacks. |
| Presence | `web/syncPresence.ts`; `src/server/collaboration/guestPresence.ts`; transport cursor handler | Server-owned identity and bounded native Doc-offset/Sheet-cell selection grammar. Rich-editor relative positions/overlays need a new validated shape. |
| Authority and revocation | `src/server/collaboration/service.ts` / `authorizeSync`; `workspace/document-access.ts` / `resolveDocument`, `sourceDocumentContext` | Current root/child/session/owner/grant/unit/privacy/maintenance checks, including per-recipient delivery and periodic socket revalidation. Reuse these policies on each new ingress and broadcast. |
| History/restore | `src/server/collaboration/{service,generations}.ts`; history services | Drain admitted writes, retain Before restore, create a fresh live generation and switch identity. Old prose updates must not merge deleted future content into the restored generation. |
| Offline already exists | `web/offline/{offlineStore,OfflineSession,accountExit}.ts` | Account-scoped IndexedDB, exclusive Web Lock writer, native checkpoint/outbox, recovery and replay. New prose needs a versioned format, not a claim that offline is unimplemented. |
| Backups/copies/archive | `src/server/backup/`, `src/server/workspace/`, `docs/backups.md`, `docs/files.md` | Infrastructure and lifecycle policies are reusable; new persistent schema/update logs/checkpoints require actual inclusion, restore and format validation. |

Reusable contracts: authentication, authorization resolution, root/child scope, privacy/maintenance lifecycle, transaction infrastructure, diagnostics, backup orchestration and shell status patterns. **New work:** prose codec/model, update log/checkpointing, schema/version admission, durable provider acknowledgement, cursor representation, undo ownership, offline format and restore adapter. Keep this distinction in the final compatibility matrix.

## Candidate compatibility matrix

Official binding support below means support for the editor's own model over Yjs; it does **not** mean compatibility with Spinel's current OT server. Pin one stable binding/provider version per experiment. Do not initialize a Y.Doc from fresh editor JSON on every reconnect.

| Candidate | Supported collaboration path | Custom formula/naming fit | Main incompatibilities and risks |
| --- | --- | --- | --- |
| Tiptap | `@tiptap/extension-collaboration`, `@tiptap/y-tiptap`, Yjs and a compatible provider; separate caret extension | PM schema attributes can carry a versioned formula ID/definition/name; React NodeView renders derived state. | Disable ordinary StarterKit undo/redo when collaboration owns it. Schema mismatch may otherwise delete unknown nodes and sync the deletion; qualify protected content checking/read-only admission at the chosen versions. |
| Lexical | `@lexical/yjs` with React collaboration plugin (Yjs 13); newer `@lexical/y` targets Yjs 14 with a different layout | DecoratorNode fields need complete serialization/binding registration or supported NodeState. DOM rendering alone is insufficient. | Do not mix binding layouts. Null/bootstrap state, custom properties, selection, local undo and provider compatibility need evidence; official Yjs-13 docs identify y-websocket as supported. |
| Plate | Current `@platejs/yjs` over Yjs/slate-yjs, with provider lifecycle and awareness support | Inline void nodes hold definitions; React views and backlink/type rendering stay derived. | `skipInitialization` when Yjs owns initial state; Slate normalization/empty children, history origins and remote cursor overlay geometry. Use current `platejs`/`@platejs/*`, not mixed `@udecode` generations. |
| Raw ProseMirror | Maintained `y-prosemirror` for stable Yjs 13, or native `prosemirror-collab` versioned steps/central authority | Explicit schema atom attributes and step/relative-position mapping; custom NodeView is outside shared data. | More owned presence/history/plugin assembly. `prosemirror-collab` still requires a new backend step protocol. Raw PM does not require inventing a CRDT when using an existing binding. |
| BlockNote | Official Yjs integration with provider/XML fragment; current docs show `withCollaboration` | Custom inline schema carries stable formula identity and serializable definitions; reuse existing candidate schema. | Block normalization, custom-property formats, stripped-down prose ergonomics and wrapper upgrades. Convert blocks to Yjs only for first import; repeated conversion loses collaborative history. |

Tiptap/BlockNote/raw PM share ProseMirror ancestry but are separate public APIs and schema contracts. Do not reach into unsupported BlockNote/Tiptap internals to force one universal binding. Do not base a production plan on unstable Yjs-14 development APIs merely because a repository's default README shows them.

## ⚠️ State-sync risks and required decisions

1. **One authority per authored definition.** Expression, stable bindings, formula ID, name and format must be a coherent versioned edit. Field-by-field merging can pair one author's expression with another's references. Probe concurrent edits of the same formula; prefer an atomic definition transaction with explicit deterministic whole-definition conflict behavior unless validated text-aware semantics are provided. No mixed invalid definition may be evaluated.
2. **Names and backlinks.** Stable IDs survive rename; concurrent duplicate aliases must resolve consistently or expose a conflict, never silently retarget references. Count actual committed incoming references, including other pages, with source/page access filtering. Backlinks are rebuilt/indexed from authoritative definitions; they are not user-authored counters in the CRDT. Distinguish local MVP counts from production scope and test rename/delete/undo/offline reconnect.
3. **Derived values stay out of shared prose.** Result refresh, pending/error state, type hints and source labels discovered at runtime are per-viewer presentation. Do not broadcast/store evaluated private values or add recalculation to prose undo/history. Shared source edits remain canonical workbook mutations; a pill must not write them back.
4. **Two clocks, no fictitious atomicity.** A prose edit and workbook edit commit in different protocols. Default to confirmed-source results with definition/source revisions; show pending/unavailable on stale input. Optimistic results, if chosen, must be explicitly labeled and fenced. Define multi-source read semantics; individually current snapshots do not imply an atomic workspace snapshot.
5. **Result fencing.** Match formula/node revision, room generation, source item/current unit generation/revision, credential/privacy epoch and request sequence. Delete/recreate, account change, delayed evaluation, restore and page switching invalidate old results. A matching visible name is insufficient.
6. **Undo ownership.** Local undo must not erase peer edits. One prose collaboration undo manager owns formula-definition edits; calculation contributes no undo step. Sheet focus routes undo to native Sheets, returning focus restores prose history. Test remote edits between local edit and undo, grouped typing and names/embeds.
7. **Schema skew and normalization.** Old clients must not silently strip formula/name/embed nodes and sync deletion. Version admission or lossless read-only handling is mandatory. Test old/new schemas and failed migrations with the actual binding; a JSON round trip alone does not establish safety.
8. **Bootstrap, replay and durability.** Two simultaneous first opens cannot seed twice. Persist real CRDT/step state, not fresh JSON conversion on reconnect. Duplicate delivery, server restart before/after commit, long disconnect and compaction retain durable acknowledgement and content. “Connected” is not “Saved”.
9. **History/restore and lifecycle.** Restore creates/fences a generation so an old tab cannot resurrect later edits. Include rename, subtree trash/permanent deletion, owner transfer, session/link revocation, View downgrade, maintenance and workspace recovery. Revalidate every recipient of data/awareness, not only admission.
10. **Presence and identity.** Cursor locations use model-aware relative positions with validated bounded payloads. Server determines identity; guests remain anonymous. Expire stale cursors and remove them on revocation. Do not trust arbitrary client awareness profile fields.
11. **Canonical embeds.** An embed is a stable source reference plus view configuration, not a replicated workbook snapshot. Reuse an existing canonical native session/controller where possible; any additional session must have explicit ownership/disposal. Concurrent resizing/view changes cannot alter workbook identity or duplicate writes.
12. **Privacy/offline.** A prose collaborator may lack source access. Clear values/type previews/catalog metadata on authority loss; preserve definitions without leaking results. New offline state obeys account locking, exclusive writer/recovery and cleanup. Generic y-indexeddb/y-websocket examples do not prove these guarantees.

## Spike tasks and exit criteria

### 1. Reconcile the completed bake-off

Record exact SPN-172 candidate source/dependency versions, all five scores/failures, schemas, node IDs, named-formula representation, clipboard/selection contracts and chosen front-runner. Recheck current Spinel authority/storage/restore code. List differences from this inspection; do not reuse stale native SDK or transport assumptions.

### 2. Establish the shared test harness and protocol alternatives

Use synthetic Space/page/Sheet fixtures, two independent authenticated browser contexts and an owned local server/provider. Keep one native canonical Sheet as the source. One small test-only room/provider harness may serve all candidate probes, with explicit limits and cleanup; it is not production transport. No paid external service is necessary. Pin versions, retain first results and keep the MVP's original local drafts unchanged.

Demonstrate an actual Spinel-authenticated lifecycle slice for the leading protocol: join, durable update, reconnect and revocation. Separately run editor-binding probes for each candidate. Distinguish an in-memory/provider sample from that app-integrated evidence. Do not implement five full production backends merely to produce estimates.

### 3. Run the identical bounded two-client matrix

| Probe | Required observation |
| --- | --- |
| Simultaneous initialization and adjacent/cross-paragraph typing | One document seed, both authors' intended text, convergent native serialized state, no duplicate content after reload. |
| Formatting, paste and atom-boundary selection | Correct marks/paragraph structure, unique formula IDs, no cursor trap or missing custom node. |
| Concurrent formula edit/edit and edit/delete | Deterministic whole-definition behavior; expression/bindings stay coherent; late evaluations do not resurrect a deleted pill. |
| Concurrent names and backlinks | Same-name collision, rename with live references, deletion/undo and unmounted-page reference counts converge without misbinding or leaking inaccessible metadata. |
| Native source edit while prose changes | Both authorized viewers update from the canonical committed Sheet revision; source-inaccessible peer sees unavailable, never another viewer's value. |
| Local undo after peer edit; optional embed focus | Undo preserves the peer's text, keeps calculation out of history, and targets the intended prose/Sheet context. |
| Disconnect/reconnect, duplicate updates and provider restart | Retained content and identity, explicit pending/durable statuses, no double initialization, lost update or false receipt. |
| Schema/version mismatch | Unsupported nodes are preserved behind admission/read-only behavior; no silent normalization deletion. |
| Revocation/downgrade and restore while connected | Room/data/presence close or downgrade correctly; old-generation updates/results cannot apply. Full production lifecycle parity is estimated even if the narrow spike implements only selected paths. |

For each probe record candidate/version, actual supported behavior, first outcome/failure, cause confidence, remediation and changed estimate. Unexecuted probe cells are **unknown/pending**, never supported. Framework-level tests own deterministic transactions/convergence; browser input owns caret/clipboard/awareness/focus; server tests own auth/durable ordering. Keep one meaningful owner per contract rather than a duplicated full application matrix for every candidate.

### 4. Measure operational cost and resolve architecture

Measure update size/rate, two-client memory/process lifecycle, update-log growth/compaction behavior, snapshot size and reconnect costs on the same fixture. State sample size and test-host limits; this is not a production capacity claim. Use existing diagnostic policy and serial/2 GiB watchdog for local workloads. Investigate the actual cause of failures; no blind retries, weakened assertions or raised budgets.

Document one recommended protocol/storage/version/generation/undo/presence strategy for the winner, with reasons and alternatives. If two choices remain close, identify the smallest discriminating probe and complete it or name the concrete unavailable prerequisite. Do not defer a decision merely for human preference when the evidence and delegated persona judgment suffice.

### 5. Publish a concrete handoff

The spike is complete only when its record contains:

- A five-candidate matrix with first-class binding support, native-protocol compatibility, node/name/history/cursor/offline/restore results, exact versions and evidence links.
- Revised S/M/L/XL component and complete-outcome estimates, confidence/unknowns, shared work counted once, and explicit higher-effort custom-binding/normalization paths.
- The selected architecture and all four persona tradeoffs, plus a schema outline for coherent named formula definitions and per-viewer result fencing.
- A complete winner implementation/rollout estimate covering auth, persistence, offline, history, backup, migration, observability and verification; coherent proposed tickets/slices with dependencies and original requirements retained.
- Clear boundaries between measured probe support and unbuilt production acceptance. Failed experiments remain evidence; a source-level binding claim is not a passing app-integrated test.
