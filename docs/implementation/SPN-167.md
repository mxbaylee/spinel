## 🔬 What was found

- **The case runs locally.** The ticket's "cannot run locally" was wrong. It needs two real git
  checkouts, not archives (the spec runs `git archive` on them).
- **A second flake, a test race.** After the reload, `spinelUpgradeExposure` could be read before
  the file list rendered, so `private` was empty (`offline-upgrade.spec.ts`, the
  `{ started: [b, a], private: [a] }` assertion). The added waits only wait for state the unchanged assertion needs, with the default `expect`
  deadline, because they guard rendered state, not a page load. It failed 36 of 60 local repeats and passed 30 of
  30 after the case now waits for both file names. Seen only locally, never on hosted CI, so it is
  probably not the hosted flake.
- **The runtime lock was not the holder in the one captured hang.** One hang reproduced (Docker, 1 CPU, repeat 98 of 100; the 102 ms and snapshot details below are the author's observation, no log kept).
  Its lock snapshot held only the editor page's own per-item lock; the runtime lock
  (`spinel-offline-runtime`) was free and nothing was pending. The new worker was `installed` at
  102 ms and the old worker stayed active for 120 s.
- **Rate.** One hang in about 300 runs at 1 CPU (a single event, too few for a rate): the first Docker capture (100 repeats, hang at
  repeat 98), then a 200-repeat run with the observer (`--cpus=1 --memory=4g`, one worker, no
  retries) that passed all 200 in 1.6 h; the first capture was also 1 CPU. These counts (and 36 of 60
  / 30 of 30 locally) are the author's own run results; the logs are not kept in the repository, so
  treat them as unverified by a reader.

## 🔭 The observer

`e2e/worker-inflight.ts` wraps `ExtendableEvent.waitUntil` and `FetchEvent.respondWith` inside the
old worker and lists events still unfinished when the activation wait times out: event type, a
fixed request-type allowlist, a path with id-like segments (any with a digit or 16+ characters) collapsed and an age. Short
alphabetic segments are kept. It is test-owned, observe-only
and content-free; `scripts/ci/worker-inflight.test.ts` covers it. The report format is covered by the fake-scope unit test and was run once in a real Chromium
service worker under Playwright's TypeScript transform (a throwaway spec, not committed): it
named a held `message` and a held `fetch` with ids collapsed. No real failure has produced a report
yet.
Caveats: observing a worker promise attaches a handler to it, so a rejected promise counts as handled; a worker restart clears
it (the report then says `not tracking`) and events started before `trackOldWorkers` are missed.

## ♻️ Reproduce it

1. Clone the legacy (`c2e8cac0fcdec36d992d6ebf3f377c9b579a8002`) and previous
   (`3a0e2238fb5be3907d04120eabda2aafd6565d63`) commits, run `npm ci` in each, and set
   `SPINEL_LEGACY_OFFLINE_SOURCE` and `SPINEL_PREVIOUS_OFFLINE_SOURCE` to them.
2. Run `SPINEL_E2E_PROJECT=offline-upgrade npx playwright test --project=offline-upgrade -g
"interrupted emitted updates" --repeat-each=N --workers=1 --retries=0`; one run takes about 20 s.
3. For hosted-like CPU pressure use Docker, not load generators on the Mac: `node:26.12.1-bookworm`
   with `--cpus=1 --memory=4g --shm-size=1g` (that image was the Node 26.12.1 build available then; `.nvmrc` is 26.13.0), the three trees copied in and `npm ci`'d, and
   `npx playwright install --with-deps chromium`. Inside Docker the DNS maps `registry.npmjs.org`
   to localhost, so set `npm_config_registry` to the Twilio Artifactory virtual npm.
