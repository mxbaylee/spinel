# SPN-132 — Native Doc composition eligibility

## Separate the pre-existing typing correction from SPN-071

**2026-11-02 · Accepted · agent judgment, independently assessed by a
nonimplementing reviewer during [SPN-071 PR #226](https://github.com/mxbaylee/spinel/pull/226).**

SPN-071's current mobile responsiveness check failed at 165.8 ms against its
unchanged 100 ms flush limit. A bounded diagnostic also failed at 113.5 ms
unprofiled and 197.7 ms profiled. The incomplete profile attributes most of the
instrumented peak to garbage collection; it does not establish the cause of
either untraced failure. Preserve the [first failure](https://github.com/mxbaylee/spinel/tree/077692be14832b230ce5ec705b4f8557d1b08597/docs/review-assets/spn-071-mobile-first-failure)
and [diagnostic limits](https://github.com/mxbaylee/spinel/tree/593a65d9a3aadfca48c4a7c875077a3c950186e1/docs/review-assets/spn-071-flush-diagnostic).

The [finite allocation investigation](https://github.com/mxbaylee/spinel/tree/e1331e196daca748f8d814a93fae13976014d0ae/docs/review-assets/spn-071-allocation-proof)
captured eight actual 32-state mobile keyboard caches. Sync capture sets the
native `__textXPreserveParagraphIds: true` marker before mutation; core preserves
it through composition. The existing SPN-121 allowed-field guard rejects that
marker, so ordinary typing uses the original fold rather than the intended
balanced path. This mismatch also exists on current main, df1d910.

Options were to absorb an unrelated runtime optimization into SPN-071, introduce
a new per-character composition shortcut, or correct the existing eligibility
guard separately. Choose the last. The shortcut was abandoned after real input
exposed the simpler mismatch; its failures and review finding remain archived.
The marker-only experiment preserved exact native publications in ES/CJS across
288 synthetic cases and eight captured caches. Seven plain caches activated;
the paragraph-containing cache retained complete fallback. A typical plain
cache's measured clone allocations fell from 23,436 to 8,658. This is primitive
work evidence, not proof that the original timing failure is resolved.

SPN-132 owns the marker-aware qualification, regression coverage and fresh
normal performance/correctness acceptance. Admit only absence or own marker
exactly `true`; keep all other body/structural guards, grouping, ownership,
publication order, timers, retention and budgets. Preserve rich/unknown inputs
on the existing native fallback. Do not introduce the abandoned shortcut.

The correction is an independently useful defect fix, outside SPN-071's complete
Hide/Show, private access-provenance and live-permission-upgrade outcome. Keep
SPN-071 draft and retain all its original acceptance, failed checks and pending
grades. Sequence SPN-132 first, then integrate it and obtain fresh SPN-071
acceptance. This dependency does not claim the correction guarantees a pass.
SPN-071 remains L for its original outcome; SPN-132 is XL for the sustained
native algorithm investigation and substantial semantic/runtime verification,
despite its expected small production diff. Count this investigation here once.
The registration PR changes no runtime and completes neither ticket. Preserve
the grooming counter/date; this is scoped maintenance, not full grooming.

**Personas:** Owner and Collaborator need responsive typing with exact content,
Undo/Redo and peer synchronization. Link guest receives the same document
semantics without any access change. Operator benefits from less unnecessary
work and honest bounded diagnostics; no new service or storage requirement.
