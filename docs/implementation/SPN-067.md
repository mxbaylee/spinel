## Stream exports and publish imports atomically

**Accepted — implementation decision, 2026-10-26.** The archive preserves the
owned, live My files graph, including empty folders and whole Space trees. Its
versioned manifest records names, dates, parent links and Space positions. Native
members reuse the existing portable-file validation and image handling. Import
assigns new IDs throughout; Formula references to included members are remapped,
while external or missing sources receive unavailable IDs. No permissions,
history, guest links or cached Formula results cross the boundary.

A whole-archive browser Blob or in-memory server buffer would make memory grow
with the workspace. Export instead uses a native browser download and a small
authenticated progress task. It produces one native member at a time under
output backpressure. Import receives a bounded ZIP on private temporary disk,
validates and stages its members, then publishes the complete tree in one
synchronous database transaction. Nothing is added on a rejected archive.

The existing process-wide native-transfer admission remains in force, with at
most one pending or running archive export per account. Archive limits are 10,000
items, an 8 MiB manifest and 8 GiB each for compressed and expanded input; each
native file retains SPN-031's 20 MiB and structural/image limits. Temporary data
is removed when processing settles, including cancellation and failure. Staging
uses the private writable database volume, not production's 16 MiB `/tmp` tmpfs.
The upload cap is 8 GiB and the physical SQLite staging cap is 9 GiB; free-space
checks also reserve destination/WAL growth and a 64 MiB floor. Aged, abandoned
import directories are reclaimed on a later import after two hours. The existing
512 MiB app container memory limit remains in place. Export
tasks expire, and a disconnected request retains admission until pending work
has actually settled. Progress completion means bytes were sent to the browser;
it does not prove the browser saved them. A lost import response is reported as
unconfirmed, because it can follow a successful commit.

Node's default five-minute request-body timeout would reject a multi-gigabyte
upload before the archive deadline. The HTTP parser therefore has a finite
one-hour ceiling with the existing one-minute header timeout. Ordinary request
bodies retain a five-minute application deadline; only an authenticated,
admitted archive upload replaces that deadline with its abortable one-hour
transfer window. See [Node HTTP requestTimeout](https://nodejs.org/api/http.html#serverrequesttimeout).

Use pinned MIT-licensed `yauzl` and `yazl` through their public streaming APIs,
with application checks for entry paths, duplicates, declared/actual lengths,
CRC, expansion bounds and manifest graph integrity. This avoids maintaining a
ZIP parser. `yauzl` 3.4.0 includes the stream lifecycle fixes needed on Node 26
([upstream issue 176](https://github.com/thejoshwolfe/yauzl/issues/176)).

Owner and Collaborator gain an independent, round-trippable copy of their own
work, without accidentally importing another person's access. The Operator's
memory and temporary-storage use are bounded; archive content is not logged.
Link guests gain no archive access. Existing modal, More-menu and task-status
patterns cover the UI; no new design-system pattern is needed.
