## Legacy decision 79: Authorized metadata search

**Recorded:** 2026-10-18. **Status:** accepted.
**Authority:** Agent search semantics judgment.
**Source:** [original decision #79](https://github.com/mxbaylee/spinel/issues/79).

**Question:** How should dashboard search combine visible paths, personal filing and filters?

**Options considered in the original source:**

A—case-insensitive substring search over title, visible canonical folder paths, personal filing
paths and caller's tags; combine type, mine/shared, tag and elapsed modification filters. Return
each item once, newest modified first with ID tie-break. Keep access checks on server, client
filtering for immediate loaded results. B—content/full-text index with new service; outside ticket
scope and unnecessary at two-user scale.

**Outcome, rationale and current boundary:**

Combine q, type, owner, tag and modified with AND semantics over current authorized metadata; bound
fields and queries and exclude document contents. Derive visible paths only through accessible
parents/personal placement, never fetching private ancestors. Include personally filed shared-folder
descendants without duplicating results or moving source items. Search does not broaden guest scope
or Operator document visibility. Later dashboard query/scope UI must preserve these server
authorization and privacy rules.

**Persona tradeoffs recorded at the time:**

Owner wants predictable discovery across folders; Collaborator wants shared items without losing
personal organization; Operator wants a bounded metadata query with no document-content index or
extra service; Link guest must have no dashboard/search API access.
