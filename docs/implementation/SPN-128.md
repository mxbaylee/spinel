## Fresh cold-host authority and immutable restore history

2026-11-01, accepted by agent judgment under the standing persona delegation.
The question is how an Operator authorizes recovery when the interrupted
restore's application proof has expired. Renewing that proof would change the
meaning of the immutable intent; requiring a fresh application login would be
impossible while the workspace is closed. The existing private host control
socket supplies deliberate authority without either dependency.

The existing private, service-UID-owned control socket is the Operator's
cold-host authority when application sign-in is unavailable. A deliberate
`recover-original --operation UUID` command obtains a new bounded grant for the
exact unresolved job. It never refreshes the old passkey proof or rewrites its
intent. The original phase/execution and each interrupted recovery attempt stay
available as historical evidence. Missing or contradictory evidence keeps the
workspace closed.

Each grant uses the existing two-minute supervisor budget, with a hard ten-minute
upper bound for configured test budgets. Each job retains at most eight cold
attempts and still obeys the existing 64 KiB record bound; exhausted capacity
refuses another attempt without deleting any evidence.
These limits keep the command finite and the retained journal inspectable.
Increasing operation lifetime and safely pruning retained evidence remain the
separate SPN-124 and SPN-125 outcomes.

Recovery uses the witnessed frozen original as the only content/access source
and `reconcileRestoreRollback` for the existing access, receipt and generation
reconciliation. Every known complete attempted image contributes negative
evidence. A partially overwritten live database is retained as raw evidence and
never opened as SQLite. An interrupted private trial must still match its sealed
prepared fingerprint before its closed tuple can supply negative evidence.

The existing `original` permit, private readiness and durable commitment protocol
opens the result. A committed winner is immutable: retry/restart can finish
opening that current generation but cannot reinstall old bytes over subsequent
acknowledged work.

A trial permit is journaled before the main journal adopts its child. A crash
between those writes can leave a private process outside the main child field.
Fresh host authority may stop only the exact selected planned group after
checking the predecessor generation and operation authority, then the process
boot, start time and ownership token. Recovery checks unchanged evidence and
physical handle closure before granting a new attempt; other live groups still
keep the workspace closed.

Operator: a supported bounded command replaces manual fresh-host recovery.
Owner and Collaborator: preserve work accepted after the most recent backup,
including history, filing and access, with the established reconciliation fences.
Link guest: old capability access is revoked as in ordinary original recovery.

## What the fingerprint proves

The frozen source's full logical fingerprint must match the independently
persisted pre-shutdown witness. Reconciliation intentionally changes sessions,
native generations, negative receipt evidence and the recovered notice. Therefore
the final live fingerprint matches the newly prepared recovered output; original
user content and access are checked separately. No fingerprint fields are
excluded or weakened to force equality.

## Verification

The acceptance harness uses actual SIGKILL and restart at eleven historical
restore cuts and six cold-command cuts. Fixture-only clocks expire the original
proof and previous cold grants; this is clock-controlled expiry, not a wall-clock
soak. Checks bind the source to its shutdown witness and the live result to the
reconciled output before fresh authentication, verify revoked sessions and guest
links, and preserve an acknowledged Owner edit and passkey counter across another
restart and repeated command. Missing or altered originals and a changed private
trial fingerprint must refuse without changing the live tuple or barrier.
Exact executed source, check and review identities, measurements, and failure
dispositions are maintained in [PR 229](https://github.com/mxbaylee/spinel/pull/229).
Final CI and independent reviews must identify the same current committed source;
this description of the harness does not claim those gates have already passed.
