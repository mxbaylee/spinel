## Legacy decision 14: Private tree identity and moves

**Recorded:** 2026-10-17. **Status:** superseded in part.
**Authority:** Agent storage and navigation judgment.
**Source:** [original decision #14](https://github.com/mxbaylee/spinel/issues/14).

**Question:** How should private folders and empty documents be stored and navigated before sharing
and editors land?

**Options considered in the original source:**

A — one owned item table with a parent folder, stable UUID, kind, name and timestamps; transactional
parent/ownership/cycle validation; browser navigation with breadcrumbs and explicit move
destinations. B — introduce editor snapshots, shared permissions and drag/drop now, expanding this
ticket and increasing migration/UI complexity.

**Outcome, rationale and current boundary:**

Use owned stable UUID items and transactional owned-parent/cycle checks. Names are trimmed, 1–120
characters without slashes or controls; duplicates are allowed because names are not identity. Empty
records originally included Slides, later removed by decision
[#104](SPN-074.md#legacy-decision-104-remove-unsupported-slides). Initial owner-only routes
intentionally preceded sharing; subsequent grant and File Admin decisions extend access explicitly,
never through guessed IDs or administrative account privilege. Do not infer editor formats from
empty placeholders.

**Persona tradeoffs recorded at the time:**

Operator needs a small SQLite schema and no administrative document access. Owner needs persistent
nested folders, immediate navigation and safe moves. Collaborator needs the same private ownership
boundary until explicit sharing exists. Link guest must not see any tree or document by guessing an
ID.
