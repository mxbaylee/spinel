# SPN-056 decisions

SPN-056 adds `lib/sync-transform/`, Spinel's own transforms for concurrent
Univer Sheet and Doc mutations. This file is the ticket's decision log, kept in
place of decision issues (owner, chat 2026-10-22). Each rule is also written as
a `Decision (owner|agent, chat …)` comment where the code makes it, with the
option not taken; the [README](../../lib/sync-transform/README.md) describes the
behaviour and its known limits.

## Defined names and cuts to another sheet (2026-10-22)

These came with the scope of two branch-only tickets, for defined names and
cross-sheet moves, which never reached main. Both were folded into SPN-056
before landing and deleted (owner, chat 2026-10-22).

### 1. Refuse a defined-name edit that races a row, column or sheet edit

**Owner.** `src/names.ts` `racesName`, `rewrites`. Status: accepted (owner, chat 2026-10-22).

- **Question:** one person sets a defined name while another makes an edit
  that makes Univer rewrite names. Merge them, or refuse the later one?
- **Decided:** refuse the pair either way round (`'name-race'`). That covers row
  and column inserts, removes and moves, range moves and shifts, sheet
  removal, and sheet and workbook renames.
- **At the content's edge (owner, chat 2026-10-22):** refuse there too. A
  delete that reaches the content's last line sends no MoveRange, only cell
  writes and the command's own set of each name that refers to its sheet, so
  a rename against it was two sets of one name: with the delete accepted first the rename was
  lost, and with the rename first the name sat a row off. Univer's
  CommandService sets `params.trigger` on every mutation a command sends, to
  that command's id, so each mutation a shift command sends counts as a
  rewriting edit, and so does a name set or removal that no defined-name
  command sent (`rewrites`). The sender keeps `trigger` (README, "What a
  sender must do"; decision 23 for a name edit without one), and so does the
  transform: each write it returns carries the `trigger` of the edit it
  transformed, even one that replays the other side's write, so a stored
  edit never counts as the other side's shift.
- **Personas:**
  - Owner and Collaborator want a name to keep pointing at the right cells, and
    would take a visible refusal over a silently wrong name.
  - Operator wants no server state.
  - Link guest: one who edits through a link is affected as a Collaborator.
- **Not taken:** rewriting the set's references past the move. That would copy
  Univer's unexported range remap, and the sender would have to map sheet names
  to ids.
- **Cost:** some harmless pairs are refused, such as a name on one sheet and a
  row insert on another. Every row, column or shift command on a sheet
  re-sends each name that refers to that sheet, moved or not, so in a book
  with one name every such edit on its sheet is refused against every
  concurrent edit that rewrites names. SPN-058's sender could cut these
  refusals by dropping re-sends that change nothing
  ([SPN-058](../todo/SPN-058.md)).

### 2. Two edits of the same defined name: the first accepted wins

**Owner.** `src/names.ts` `transform`. Status: accepted (owner, chat 2026-10-22).

- **Decided:** the first accepted edit keeps its whole record, and the loser's
  set or removal is dropped, as for a Doc formula.
- **Removals that refuse instead:** a removal and a concurrent edit that makes
  Univer rewrite names, such as a row insert whose command sets the name it
  moves, are refused (decision 21), so a removal is dropped only by another
  edit of the same name.
- **Commands' rewrites refuse instead:** a name set that another command
  sends as its rewrite of the name, or one with no `trigger`, races a
  concurrent name edit (decisions 1 and 23), so this rule holds between edits
  the defined-name commands sent.
- **Renames too:** a rename against a rename, repoint or removal of the same
  name follows this rule. The cell formulas that the rename's command rewrites
  follow the cells' own first-accepted rule, so they name the name that stands.
  `tests/names.test.ts` checks this. A formula write is exempt from decision
  22 only against an edit of a name its own edit also sets or removes, and
  only where it is that edit's rewrite: after the edit, one formula per cell,
  in cells the other edit also writes. So renames of two different names that
  one formula uses are refused instead, and so is a rename against a batch
  that types a formula and edits the name, except a formula typed after the
  rename into a cell where the other side also typed a formula after its own
  rename, which is harmless.
- **Personas:**
  - Owner and Collaborator want both screens to agree.
  - Operator prefers a rule with nothing extra on the wire.
  - Link guest: one who edits through a link wants the same as a
    Collaborator; one who only views is unaffected.
- **Not taken:** merging per field, which would need the sender to send the
  record as it was before the edit.

### 3. Refuse a cut to another sheet that races an edit of its source or target

**Owner.** `src/cells.ts` `perSheet`. Status: accepted (owner, chat 2026-10-22).

- **Decided:** refuse it, as for drags (`'moved-cells'`). The cut is transformed
  as two moves, one per sheet, so the drag rule applies to its source on one
  sheet and its target on the other.
- **Personas:**
  - Owner and Collaborator want moved content never lost or duplicated, and
    accept redoing a refused edit.
  - Operator is unaffected.
  - Link guest: one who edits through a link is affected as a Collaborator.
- **Not taken:** letting edits follow the moved cells. Within a sheet, that lost
  writes silently.

### 4. Refuse two names given the same text at once

**Agent.** `src/names.ts` `racesName`. Status: proposed — agent judgment (2026-10-22), applied in the code; the owner reviews it with the PR.

- **Decided:** two sets of different ids that give the same text are refused
  (`'name-race'`), in any letter case and any scope.
- **Why:** Univer resolves a name to the first match in the order each screen
  added it, including across a sheet scope and the workbook. So the two screens
  would compute different results. This follows the owner's rule that races are
  refused rather than allowed to diverge.
- **Personas:**
  - Owner and Collaborator want formulas to compute the same thing on both
    screens.
  - Operator is unaffected.
  - Link guest: one who edits through a link is affected as a Collaborator.
- **Not taken:**
  - renaming one of the two, which a stateless transform cannot do consistently
    with the sender's formulas;
  - comparing scopes, which still diverges.

### 5. Treat a number format written as a cell style as a format change

**Agent.** `src/cells.ts` `formatRace`. Status: proposed — agent judgment (2026-10-22), applied in the code; the owner reviews it with the PR.

- **Decided:** a SetRangeValues style that names `n` races a value-less write to
  the same cell (`'format-race'`), as numfmt mutations already did (decision
  12, below).
- **How it was found:** the cross-sheet fuzz. The two screens disagreed on a
  boolean under '@' when a '0%' style and a style clear landed at once. Only the
  sender knew the type.
- **Cost:** a value-less style write of `n` and any concurrent value-less write
  to the same cell, such as a bold, which used to merge, are now refused.
- **Personas:**
  - Owner and Collaborator want a value to keep its type on both screens, and
    would redo a refused format or style over a value shown differently on
    each.
  - Operator wants no server state, and the rule needs none.
  - Link guest: one who edits through a link is affected as a Collaborator;
    one who only views is unaffected.
- **Not taken:** retyping in `retype`, which cannot recover the type.

## Later decisions (2026-10-22)

### 20. Refuse a cut to another sheet that races a removal of its target sheet

**Agent.** `src/cells.ts` `refuseCutsToRemoved`. Status: proposed — agent judgment (2026-10-22), applied in the code; the owner reviews it with the PR.

- **Decided:** a cut to another sheet and a concurrent removal of its target
  sheet are refused either way round (`'moved-cells'`), checked on the whole
  sequences before the cut is split per sheet. `transform` joins the two moves
  it splits a cut into again before it returns them, so a cut the server
  stored, or a client rebased, is still a cut and is refused the same way.
- **Why:** the removal drops the target sheet's part of the cut, while the
  part that clears the source still clears it, so the cells are lost on both
  screens. This extends the owner's rule that a cut and an edit of its target
  are refused (decision 3) to the most destructive edit of the target. A
  removal of the source sheet still converges, with the cells on the target,
  since nothing is lost.
- **Personas:**
  - Owner and Collaborator would redo a refused cut rather than lose cells.
  - Operator is unaffected.
  - Link guest: one who edits through a link is affected as a Collaborator.
- **Not taken:** letting it converge with the cells lost.

### 21. Refuse a name removal that races an edit that rewrites names

**Agent.** `src/names.ts` `racesName`. Status: proposed — agent judgment (2026-10-22), applied in the code; the owner reviews it with the PR.

- **Decided:** a name removal and a concurrent mutation that makes Univer
  rewrite names are refused (`'name-race'`), either way round. This extends
  decision 1, which refuses a set against such a mutation, to the other name
  edit.
- **Why:** the removal's command also rewrites the formulas that use the name
  to `#REF!`. A row insert, sheet rename, range move or workbook rename that
  moves the name sends a set of it, and if that is accepted first the removal
  is dropped (decision 2) while its formula rewrites stand: the name exists
  and its formulas read `#REF!` on both screens.
- **Personas:**
  - Owner and Collaborator would redo a refused removal rather than find a
    formula silently turned into `#REF!` while its name still stands.
  - Operator is unaffected.
  - Link guest: one who edits through a link is affected as a Collaborator.
- **Not taken:** keeping first-accepted-wins and documenting the damage.

### 22. Refuse a formula write that races an edit that rewrites formulas

**Owner.** `src/names.ts` `refuseFormulaRaces`. Status: accepted (owner, chat 2026-10-22).

- **Question:** Univer's row, column and move commands, renames and name
  edits send SetRangeValues that rewrite formula references, computed on the
  sender's screen. Against a concurrent edit those were plain `f` writes, and
  the first accepted won whole: two row inserts above a cell that `=One!A8`
  reads left `=One!A9` on both screens, where the two in turn give
  `=One!A10`, and two renames of different names one formula uses left
  `#NAME?`. Merge them, or refuse?
- **Decided:** a SetRangeValues that writes a formula (a cell with `f`, or a
  shared formula's `si`), or an InsertSheet whose `sheet.cellData` holds one
  (a sheet copy, or undo of a sheet removal), and a concurrent mutation that makes Univer rewrite
  formulas, in the same workbook, are refused either way round
  (`'formula-race'`), checked on the whole sequences before any pair is
  transformed. Those mutations are the ones that rewrite names (decision 1)
  and every defined-name set or removal, except one of a name the formula's
  own sequence also sets or removes, where the formula write is that edit's
  rewrite (decision 2): two edits of one name keep decision 2, since their
  formula rewrites follow the name that stands, which holds only for formulas
  both senders had. A new reason,
  rather than `'name-race'`, because the edits it refuses need not touch a
  name. A command's rewrite of a formula (a formula write in a sequence that
  holds one of those mutations) is also refused against a concurrent write to
  the same cell that sets its `v`, `f` or `si`, or the whole cell, with no
  formula, such as a value typed over it, which sends `v` and `f: null`, or a
  clear: accepted first, the rewrite would put the formula back over the
  value. A style there merges. `transform` marks those rewrites, and the cells
  transform refuses them where they meet such a write once positions line up;
  a write with a formula there is left to the sequence check, so two edits of
  one name stay first-accepted.
- **At the content's edge (owner, chat 2026-10-22):** a delete that reaches
  the content's last line sends its formula rewrites as plain cell writes,
  with no MoveRange, so they merged past a formula typed at once, or a value
  typed over them. The `trigger` that decision 1 reads marks them too: each
  mutation a shift command sends counts as an edit that rewrites formulas,
  in `refuseFormulaRaces` and `markRewrites`. An undo or redo of such a
  delete carries the undo command's `trigger`, so where no name refers to its
  sheet, and it sends no name set, its rewrites still merge (README, Known
  limits).
- **Why:** this is the cells counterpart of decision 1. The rewrite was
  computed for the cells before the other edit, and a stateless transform
  cannot redo it.
- **Univer's rewrites:** `UpdateFormulaController` rewrites on the commands
  `getReferenceMoveParams` lists, the same as `UpdateDefinedNameController`
  plus the name set and removal commands, and on sheet table renames and
  removals, which use mutations the transform rejects.
  `FormulaReorderController` rewrites on sort (ReorderRange), also rejected.
- **Personas:**
  - Owner and Collaborator want a formula to keep reading the cells it meant,
    and would redo a refused edit over a silently wrong reference.
  - Operator wants no server state.
  - Link guest: one who edits through a link is affected as a Collaborator.
- **Not taken:** remapping references inside the transform, which would
  re-implement Univer's unexported reference rewriting.
- **Cost:** more refusals in books with formulas, measured in the README's
  refusal table and accepted by the owner (decision 16), except the three
  `commandEdit` rows the edge rule raised (8.76%, 3.64% and 6.03% refused per
  edit), each by less than one point. The agent accepted those, since the
  owner delegated the call (chat 2026-10-22); the owner reviews them with the
  PR. Re-measured 2026-10-23, once border edges conflicted separately and the
  generators wrote borders, the 4×3 and real-book rows rose to 8.80% and
  3.65%, each by less than a tenth of a point, and the book with formulas
  fell to 5.87%: accepted by the agent under the owner's delegation (chat
  2026-10-23), since no refusal rule changed and border edges now conflict
  separately; the owner reviews them with the PR. A number format on a
  cell whose formula a concurrent command rewrites is refused as a format race
  (decision 12), since one of the rewrite's writes sets no value (README,
  Known limits). Every row, column or shift command on a sheet re-sends each
  formula that reads that sheet, moved or not, so a book with one formula on
  a sheet refuses every such edit there against every concurrent edit that
  rewrites formulas, such as two row inserts below all content. SPN-058's
  sender could cut these refusals by dropping re-sends that change nothing
  ([SPN-058](../todo/SPN-058.md)).

### 23. Count a name edit with no `trigger` as a command's rewrite

**Agent.** `src/names.ts` `rewrites`. Status: proposed — agent judgment (2026-10-22), applied in the code; the owner reviews it with the PR.

- **Question:** decision 1 tells a person's name edit from another command's
  rewrite of a name by `params.trigger`, the command Univer records on each
  mutation. What does a name set or removal with no `trigger`, or with an
  undo's or redo's, mean?
- **Decided:** a command's rewrite: it races any concurrent name edit
  (`'name-race'`), and decision 2's first-accepted rule no longer applies to
  it.
- **Why:** the transform cannot tell which command sent it. Taking it for a
  person's edit could let the first-accepted rule drop a rename silently, as
  at the content's edge; refusing it is visible and redone.
- **Personas:**
  - Owner and Collaborator would redo a refused edit rather than lose a
    rename. An undone rename is refused against any concurrent name edit,
    even of the same name.
  - Operator wants no server state, and the rule needs none.
  - Link guest: one who edits through a link is affected as a Collaborator;
    one who only views is unaffected.
- **Not taken:** rejecting one with no `trigger` as a sender bug, since Univer
  leaves it unset on a mutation run outside any command.

### 24. Merge a cell border one edge at a time

**Owner.** `src/cells.ts` `piecesOf`. Status: accepted (owner, chat 2026-10-23).

- **Question:** two people set different edges of one cell's border at once,
  such as a top and a bottom border on One!A1. Univer merges a border into the
  cell one edge at a time (`mergeBorderData`), but the transform took the
  whole border as one style key, so the first accepted write dropped the
  other's: the server showed the top edge only, the other screen both.
- **Decided:** each edge of a border (`s.bd.t`, `s.bd.b`, …, Univer's
  `BORDER_KEYS`) conflicts on its own: of two writes of one edge, the first
  accepted stands, and different edges both land. A border cleared whole
  (`bd: null`) covers every edge: it beats an edge it wins over, and an edge
  that wins over it lands after it. A whole-cell write and an override style
  keep their meaning.
- **Personas:**
  - Owner and Collaborator see both borders they drew, the same on both
    screens.
  - Operator wants no server state, and the rule needs none.
  - Link guest: one who edits through a link is affected as a Collaborator;
    one who only views is unaffected.
- **Not taken:** keeping the border one key, which diverged, and refusing two
  border writes to one cell, which would refuse edits that merge.

### 25. Drop a losing write that a forced commit overwrites

**Agent.** `src/cells.ts` `settles`. Status: proposed — agent judgment under the owner's delegation; the owner reviews it with the PR.

- **Question:** a Clear All of A2 that loses to n editor commits under `@`
  (`{ s: { n: '@' }, v, p, t: 1 }`) went apart and replayed each commit, and
  each replayed commit met the next and replayed it again under the rule that
  a type forced with a value sticks to the next. The output doubled per
  commit: 256 mutations at eight, and the growth cap (`'growth'`) at nine.
  Stop it where?
- **Decided:** a losing write to a cell is dropped, before any replay rule,
  where the winner's write covers every part of it and forces its type (`t`),
  sets a value and rich text (`p`, null or not), and sets no formula (`f` or
  a shared formula's `si`).
  Univer's getCellType takes a forced `t` as it is, and every other key such a
  write sets replaces what was there (`mergeStyle` per style key, `p` and `f`
  overwritten), so the covered write leaves nothing it reads, not even the
  `t`, `p`, `ft` or `fd` Univer derives, and it lands the same after it as
  without it. A run of commits, equal or taking turns, now transforms to the
  clear and the last commit. A loser that clears its formula (`f` null or
  empty, with no formula id in `si`) also deletes `ft` and `fd`
  (`mergeCellData`), so that implicit clear is two pieces of its own, `ft`
  and `fd` null: a winner that writes a formula, or `si`, leaves them, so they
  survive and land, and the commit's own `f: null` covers them.
- **Evidence:** with a separate `bd: { t: null }` style in `cellEdit`, seed 719
  of the dense 1,000 × 40 run grew 1 mutation past 9 into 65; with the fix
  all 1,000 seeds pass. Seed 183 of the dense 1,000 × 40 and × 100 runs,
  commits under `@` taking turns, no longer trips the growth cap, and the
  README's refusal table did not move.
- **Personas:**
  - Collaborator: pressing Enter again and again in a text-formatted cell while
    another person's stale clear arrives no longer refuses that person.
  - Owner: same as a Collaborator, and the server no longer broadcasts a
    doubled run.
  - Operator wants no server state, and the rule needs none.
  - Link guest: one who edits through a link is affected as a Collaborator;
    one who only views is unaffected.
- **Not taken:** dropping only a loser equal to the winner, which still
  multiplied commits that took turns (seed 183), and dropping any covered
  loser: unforced, the type reads what the loser left, so `v: '1'` with number
  format `0`, over forced text under `@`, lands text once and a number twice,
  and the two orders would diverge.
