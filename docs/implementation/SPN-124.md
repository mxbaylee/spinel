## Separate admission freshness from bounded work

2026-11-01, accepted; agent judgment. Merely extending an upload timeout would
leave the supervisor's copy, frozen proof and release checks bound to five minutes.
Extending all passkey verification would grant unrelated sensitive actions a longer
freshness window. Instead the private restore proof records:

- `verifiedAt` / `verifiedUntil`: the original exact passkey check and its existing
  freshness window; create and confirm require it to be fresh.
- `authorizedAt`: when the server captured this operation grant.
- `expiresAt`: the immutable operation deadline, at most 30 minutes after capture
  and no later than the session's original expiry.

Preparation and the separately confirmed supervisor operation receive their own
grants. A new confirmation cannot extend the original preparation's expiry, and
retries reuse the exact confirmed intent. All proof fields are part of the durable
intent hash and custody-ACK comparison. A changed or shortened session, disabled
account, lost Operator role, missing/transferred credential or changed verification
invalidates the proof; re-verification cannot renew an existing intent. The original
current database, and then its witnessed frozen image, remain the authority source.
Archive credentials never authorize restore work.

Legacy five-field journal proofs stay readable with their original expiry and
five-minute maximum. Missing/partial new fields cannot make a legacy grant longer.
Neither upgrade nor supervisor restart synthesizes new authority or retries an
uncertain cutover.

Only an owned, current preparation extends the ordinary HTTP body timeout. The
registry's original operation timer still aborts and disconnects the upload. The
private RPC reply bound accommodates a full operation while retaining pending-call
and message-size bounds. Ordinary maintenance continues to use its five-minute
authority. The supervisor caps the whole stopped execution at the captured expiry;
individual shutdown, preparation/worker, trial and original-recovery phase budgets
remain separately bounded. Failed-trial evidence may be retained under its existing
negative-evidence budget, which grants no authority to reopen the workspace.

Expired preparation uses the existing expired state. No visual design or new UI
state is introduced; current rendering and interaction checks still apply.

### Persona effects

| Persona | Effect and tradeoff |
| --- | --- |
| Operator | One fresh check at each admission can cover a slow restore. Finite deadlines and the existing recovery procedure remain explicit. |
| Owner | Large valid backups can finish; current credentials, durable content and replay fences remain protected. |
| Collaborator | The workspace can reopen after a valid longer restore, with no relaxation of grants or silent replay. A bounded operation can keep maintenance active longer than before. |
| Link guest | No restore authority is gained; revoked links and restored-generation fences remain unchanged. |

## Verification contract

Focused regressions exercise the old five-minute boundary at upload, worker
completion, preview, supervisor preparation, activation and original recovery.
They retain deadline, revocation, target, exact-intent and synchronous-I/O rechecks.
Clock-controlled tests are deterministic boundary evidence, not elapsed-time
measurements. Existing real archive and supervisor tests still exercise workers,
IPC, journals, candidate content, original recovery and fail-closed behavior.

The fixed `images-256m` browser acceptance uses the current production Dockerfile,
real HTTPS/Admin/passkey/application/supervisor flow, and 1,024 MiB / 0.75 CPU / no
swap / 128 PID limits. Eight documents contain eight valid PNGs each: over 256 MiB
of image data, below each image and document service limit. The report records
actual database/archive sizes, phase and HTTP durations, exact source/image,
resource observations and final snapshot/image digest equality. It uses no injected
delay. This is a synthetic image-heavy workload, not a multi-GiB throughput claim.

CI runs this acceptance when its application/runtime/harness dependencies change;
unavailable ranges run it conservatively. Its disposition is part of Playwright
smoke. Only safe measurement JSON and an optional synthetic failure screenshot are
uploaded; keys, sessions, source archives and bootstrap credentials remain private.
The final PR must preserve the actual timing summary and reviewed/tested identities;
14-day CI artifacts are supplementary.

Independent review uses the repository rubric: scope/acceptance 35, correctness and
access/data integrity 25, meaningful verification 20, CI/operations 10, and
maintainability/documentation/complexity 10. Both nonimplementing reviewers assess
the same committed full diff and original ticket, without a supplied target score
or one another's grades. Final outcomes are recorded in the PR after validation.

## Diagnostics impact

No metric schema, collector, content payload or attribution changes. Existing
restore states now last for their bounded operation lifetime; expiry still reports
through the existing expired preparation or fixed supervisor failure boundary.
New timings are synthetic CI acceptance evidence only, never product telemetry.
