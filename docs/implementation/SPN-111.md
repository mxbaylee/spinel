## Accepted decision: one deployment-owned recovery supervisor

2026-10-27 — accepted by agent judgment under the standing delegation.

The workspace, authentication and collaboration now share one SQLite connection,
but read-looking routes can prepare documents, record OAuth state and clean up
placements. A method-only HTTP pause would leave real writers running. Admit
HTTP, sync and background work before it starts, retain admission until its
actual asynchronous work finishes, and enforce the pause again at the shared
database boundary. Drain has a fixed deadline; timeout remains maintenance.

A small Linux supervisor owns the fixed application process and its descendants.
Its private journal, operation authorization and cold-host control socket live
outside both workspace and diagnostics. It only controls the configured
application generation; it cannot run a supplied command or replace a dataset.
Live restore remains SPN-112. Missing or uncertain recovery state stays closed.

Operator gets bounded, visible control without a Docker socket. Owner and
Collaborator retain an honest distinction between accepted and local pending
work. Link guests see only public maintenance status and keep existing access
and revocation boundaries.

## Accepted decision: announcements do not schedule destructive work

2026-10-27 — accepted by agent judgment, implementing the owner's 2026-10-27
[backup proposal](SPN-063-backup-options.md#pause-resume-and-scheduled-notices).

This delivery supports one-off in-app announcements with an absolute instant,
IANA zone and duration estimate. Missing local times are rejected and repeated
times require an explicit occurrence. A late announcement remains visible;
expiration never silently reports that maintenance succeeded. Cancellation is
explicit. Announcements do not pause the app or authorize recovery. Pause is a
separate current-Operator action with fresh passkey verification, and resume
also requires the expiring operation secret held outside the workspace.

The Operator avoids unattended work or a recurring-schedule system. Owner and
Collaborator see planned and actual status without losing mounted editor input.
The Link guest gets the same minimal notice without operator details. The
existing global banner, admin card and confirmation patterns cover these states;
scheduled-to-paused updates retain the announcement area's geometry.
