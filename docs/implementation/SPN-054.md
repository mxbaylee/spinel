# SPN-054 — Offline recovery copies

Implementation in progress. This record preserves the original ticket's recovery
contract, choices and verification plan; it is not evidence of completed checks.

## Preserve both versions with one durable recovery identity

**2026-10-26 — accepted, agent judgment under the owner's standing delegation.**

When an opted-in offline Sheet or Doc cannot replay safely, retain its confirmed
snapshot and native outbox. Reconstruct the confirmed snapshot plus transformed
inflight mutations and ordered buffered groups; the immutable `sent` envelope is
delivery identity, not a second set of edits. A complete `recoverySnapshot`
supersedes replay. A missing latest-visible snapshot prevents successful recovery.

Freeze the original editor without losing unfinished native input. Recovery waits
for cell input, composition, Formula drafts and image insertion to finish or be
explicitly discarded. Preserve the fixed **Needs attention** save control; its
popover contains recovery progress, **Open copy**, **Open original**, local
**Export as Univer file**, retry and explicit discard confirmation. The editor
does not move. All screenshots and independent visual review remain required,
with **agent review only** disclosed on the PR.

Creating a new file through ordinary import on every retry could duplicate copies
after a lost response. Instead persist an immutable recovery UUID, title/date and
payload on the downloaded item before sending it. The new account-only recovery
endpoint reuses native import validation, image sanitization and transactional
publication, with an account-scoped durable receipt. Repeating the same request
returns the same copy. A changed request, or a copy subsequently trashed, removed
or transferred, retains the device work for export instead of creating another.

Copies are new root-level files owned by the recovering account, named
`<title> (offline copy, <local date and time>)`. The account fence is required on
the recovery request. The original item's permissions are never broadened and
its contents are never written. A Space child's original link retains the exact
root and child; the recovery copy has ordinary account ownership and new image
scope. Guests and operators gain no recovery privilege.

Only after a verified server result does one local transaction remove the old
download, images and outbox. Failure retains the immutable request for retry.
Late native persistence and download events cannot resurrect resolved changes.
Explicit discard removes only the device copy after confirmation; it does not
delete the original or any already-created server copy.

**Personas.** Owners retain both versions and predictable links. Collaborators
recover their own edits without modifying a document they can no longer edit.
Operators get bounded existing imports and content-free recovery counts, without
document access or a new service. Link guests remain online and scoped to their
link; they receive no offline recovery store or account import authority.

## Images, Formula definitions and export

**2026-10-26 — accepted, agent judgment under the owner's standing delegation.**

Use only image bytes already verified for the original downloaded item. Inline
every supported native image location, including drawing resources, background
images, rich cells and Doc segments, and set the native source type accordingly.
Missing or invalid bytes cannot fall back to a network request or silently vanish.

Recovery and local Univer export preserve authored Formula definitions, never
cached calculated values. Same-instance recovery retains validated source
bindings; opening the new Doc reauthorizes each source normally. Ordinary foreign
Univer imports still remove external bindings and require rebinding. Exporting
does not clear local work; the person checks their download before discarding.
Export may retain a file larger than the server's 20 MiB import budget, because
that budget is a reason to need the local fallback in the first place.

An expired/disabled account cannot publish a copy. Its frozen mounted editor
retains export and explicit discard, with a separate sign-in action. The existing
cancellation epoch still blocks new offline launches and cancels access after a
later sign-out/account change.

**Personas.** Owners and Collaborators retain editable content, images and Formula
intent. Operators keep server budgets and authentication intact. Link guests gain
neither private Formula results nor an export capability for account device data.

## Possible unnecessary copies after replay crashes

The immutable `possibleReplayCrash` flag records whether the retained checkpoint
had a sent-but-unacknowledged request. This is a possibility, not proof that the
server already has every offline edit. The receipt records it once per created
copy without source document IDs or contents. Aggregate counts:

```sql
SELECT count(*) AS copies,
       coalesce(sum(possible_replay_crash), 0) AS possible_replay_crash_copies
FROM workspace_offline_recoveries;
```

Receipts survive document deletion/transfer to prevent duplicate publication;
they expire with deletion of the originating account. No diagnostic document
content, export payload or Formula result is exposed to operators.

## Verification plan

Server tests cover both native kinds, repeated/concurrent requests, database
reopen after a lost response, atomic receipt rollback, ownership and session
boundaries, invalid content/budgets, Formula access and independent image scope.
Focused browser acceptance compares actual native Sheet and Doc snapshots against
the untouched original across concurrent edits, restore, trash, revoked and
downgraded access, including prepared Space children. It also verifies repeated
recovery, lost responses, failed local cleanup, export and explicit discard.
Unit checks cover reconstruction order, image completeness, Formula definitions,
account cancellation and storage transaction fences. Current-head CI and both
independent reviews will be recorded on the PR before merge.
