# SPN-032 — Shared diagnostics and operator health

## Event store with typed logs and metrics

**Accepted direction — owner, chat 2026-10-22.** The collaboration rewrite needs
instrumentation reusable by standalone libraries, the frontend and backend. The
owner prefers a generic event/log store with JSON details and first-class metric
types over a metrics-only series/window design. Generic logs include severity.
SPN-032 owns this alongside its existing health screen. Effort increases from M
to L for ingestion, identity, storage/export lifecycle and the operator controls.
This opening section preserves the original grooming direction. Implementation
and current verification status are recorded below; no runtime pass is implied.

Use a small typed interface with a no-op default. Libraries receive an adapter;
they never import Spinel server/web code, open a database or send network traffic.
Keep transforms deterministic, recording timing/outcome around calls or through
optional observation hooks. Backend and browser adapters feed the same event
format, with the origin retained so browser claims are never server facts.

**Proposed schema — agent recommendation, 2026-10-22.** An append-oriented events
table in `diagnostics.sqlite`, separate from application/collaboration databases:

- Event ID and schema version; client occurrence time plus server receipt time.
- Kind (`log`, `metric`, or a registered structured event), stable event name,
  source (`frontend`/`backend`), component and application build/version.
- Optional log level (`trace`, `debug`, `info`, `warn`, `error`, `fatal`) and a
  sanitized message; validated JSON-object details for event-specific fields.
- For metrics, explicit kind/unit/value: counter increments, gauge observations,
  histogram observations. Avoid ambiguous cumulative-versus-delta counters.
- Optional actor/user ID, authorized file ID, route template, and non-secret
  request/operation/run correlation ID. Correlation IDs are not metric labels.

Index common time/name/component/correlation lookups. Use JSON text with validity
checks for portable exported files; verify JSON functions against our existing
libsql runtime. Reject mismatched metric fields and non-finite values. Initial
local SQL can sum counter increments, group histogram observations and select
gauges with explicit scope/time rules. Do not average percentiles. Defer physical
schema details and rollup tables until implementation; preserve schema/version
documentation and sample queries inside the export or accompanying guide.

## Identity without document contents

**Accepted direction — owner, chat 2026-10-22.** Include identity for the user,
file and route being exercised. The previous counts-only diagnostic rule is
superseded specifically for identifiers. Agent interpretation: use existing opaque
user/file IDs, route templates and non-secret correlation IDs, not titles, names,
paths, edits, cell values, formulas or document payloads. The health cards remain
aggregate; diagnostic IDs confer no content access.

The server derives actor identity from current authentication and validates file
context against current access. It must not accept a browser-supplied identity
as authenticated attribution. Revalidate socket sessions/grants and Origin; a
guest, if instrumented, has a pseudonymous actor bound to its current grant, not
a copied share/session token. Route templates replace parameter values, and raw
URLs, query strings, credentials and free-form payload dumps are excluded from
messages, JSON and errors alike. Correlation proves association, not the truth
of a client-reported metric. Operator-only read/export/truncate authorization is
independent of who may submit bounded events.

SPN-098 adds deliberately submitted feedback text as a separate event kind;
that is an explicit submission to the Operator, not automatic document capture.
See [its privacy and persistence contract](SPN-098.md).

Owner and Collaborator gain reproducible diagnoses but their activity IDs become
visible in Operator exports; their document contents stay private. Link guests
gain no diagnostic read permission and no broader file access. Operator gets a
portable investigation artifact, with clear client/server provenance and bounded
storage, without gaining a document reader or Docker control socket.

## Download and truncate, no query surface

**Accepted — owner, chat 2026-10-22.** The owner narrowed the UI to Download
diagnostics and Truncate diagnostics. Do not build a query panel, log viewer or
remote SQL endpoint. An external agent can exercise Spinel, obtain an authorized
snapshot, then use ordinary SQLite/JSON SQL locally. This is a developer/operator
workflow, not an AI feature or a new assistant credential scope in Spinel.

Downloads contain only the separate diagnostics database, with a coherent schema
and snapshot while collection continues. Use a supported consistent-copy method,
not a raw database/WAL file copy. The current wrapper's `backup()` uses
`VACUUM INTO`; evaluate its synchronous pause and export size before reusing it
on a hot path. Serialize/bound exports and remove temporary files on success,
failure or interrupted delivery. No application tables, files or secrets join
the download. Treat exports as sensitive operational metadata.

Truncate requires the existing destructive-confirmation pattern and current
Operator authorization/Origin protections. Clear only diagnostics and queued
pre-clear events, including later retries from the previous collection generation;
new events may continue. Define a clear boundary rather than promising a forever
empty store. Keep cancel/pending/failure/completion honest and never touch document
state, backup archives or durable collaboration queues. Physical compaction and
disk-space reclamation are separate from logically clearing records.

The owner explicitly confirmed that truncation also deletes user feedback and
clears the corresponding admin user flags (unless new reports arrive afterward).
The confirmation must mention feedback, not just logs. SPN-098 owns the form and
flags; its stored events participate in the same export and clear boundary.

**Accepted — owner, chat 2026-10-22.** Database sizes remain visible: show
application/collaboration storage and the separate diagnostics database, growth,
and free space on the data volume. Include physical database/WAL bytes without
double-counting shared files. A cleared record count is not a claim that the
physical file shrank or volume free space increased.

Advanced retention/compaction can wait, as requested. Initial event/batch size,
queue, rate and storage limits cannot be unbounded: stop/drop diagnostics under
pressure and report loss without blocking document work or recursively logging
the logging failure. Record concrete limits and overload behavior in implementation.

## Bounded diagnostics implementation

**Accepted implementation choice — agent judgment, 2026-10-23; parent agent
concurred before implementation.** Keep one coherent SPN-032 PR while the actual
diff remains below the split threshold. The typed contract, ingest/export/clear
lifecycle and health screen form one acceptance path; this preparation does not
defer any original criterion or declare the ticket complete.

The alternatives were a general logger with custom sinks, a new authenticated
socket, and a small registered-event adapter over existing authenticated HTTP.
Choose the last: the existing collaboration endpoint is Pro and diagnostics must
not inherit edit retries, durability or proprietary internals. Guest collection
is omitted. Every account request revalidates its cookie; POST also requires the
configured Origin and JSON. Browser file/Space context is resolved against
current access immediately before its synchronous append. The server supplies
actor identity, source and build. Browser claims stay explicitly `frontend`.
An unauthorized file rejects the batch instead of silently stripping attribution.

The standalone private `@spinel/diagnostics` package is only a registry, validator
and optional sink. It does not implement log formatting, transports or transforms.
Registered enums and numeric fields replace arbitrary strings; log messages are
static. Unknown keys, raw errors, names, paths, formulas, tokens, raw URLs,
non-finite numbers and mismatched metric units/kinds are rejected. Backend
callers supply only already-authorized identifiers. The adapter clones queued
observations so later mutation cannot introduce unvalidated data. Observation
failures never propagate to the observed operation.

Operator gains portable operational evidence and explicit loss counters without
document-reading authority. Owner and Collaborator retain edit reliability and
content privacy while their authorized opaque activity IDs appear in exports.
Link guests send no diagnostics and gain no new account or export surface. These
tradeoffs apply equally to phone and desktop; no Docker socket is introduced.

dedicated on-demand SQLite snapshot worker still needs measured validation.

### Concrete bounds and lifecycle

- One event is at most 8 KiB; one ingress request at most 64 KiB and 64 records.
  Per-process admission allows 120 events per authenticated actor per minute and
  600 globally, with at most 1,024 active actor buckets. Requests cannot supply
  their own actor/build/source. Frontend submission accepts only operation events.
- Browser and backend queues each hold at most 256 records and 1 MiB. The browser
  sends every two seconds, uses five-second request deadlines and stores nothing
  in persistent browser storage. Its adapter exposes a dropped counter. Callers
  must suspend on hidden/offline and permanently stop on account exit; reentry
  creates a new adapter. Session denial permanently stops that adapter. Other
  transport errors suspend collection until explicit reconnect. Backend emission
  only queues; scheduled flushes yield after at most 16 records, 64 KiB or a
  four-millisecond observed budget. A single synchronous SQLite call cannot be
  interrupted by that budget, so actual latency still needs measurement.
- `diagnostics.sqlite` uses schema version 1, validated JSON-object details and
  indexed receipt time/name/component/run IDs. `events` and `diagnostics_state`
  are its only tables. The store refuses a file containing application tables.
  It uses the existing libsql runtime, a 1 MiB SQLite cache and zero writer-lock
  wait; unavailable initialization leaves diagnostics disabled, not app startup.
- Logical payload and SQLite main-file ceilings are 64 MiB. Collection stops at
  a 96 MiB combined database/WAL threshold (one bounded write can cross that
  threshold); passive checkpoints allow recovery after a reader releases the WAL.
  The journal-size setting is a recycling target, not a hard WAL limit. Writes
  stop when the data volume has under 256 MiB free. Storage/queue/validation/stale
  losses are bounded counters since process start, not recursive log messages.
  There is no automatic age deletion or compaction in this initial store: at
  capacity collection drops until the Operator clears it. That is not feedback
  durability; SPN-098 must acknowledge explicit feedback only after durable write.
- Truncate atomically deletes events and replaces a durable UUID generation.
  Only after commit does it discard the backend queue. Old browser batches and
  retries receive 409; the browser discards all old buffers before acquiring a
  new generation. It never assigns a new generation to old records. The request
  includes explicit confirmation and the generation the Operator reviewed.
  Repeated stale confirmation cannot clear a later collection. Failure preserves
  the old boundary and queue. Physical file size need not shrink. Future feedback
  belongs to this same generation and clear transaction; SPN-098 still owns its
  schema and user-flag integration.
- One export lease spans snapshot creation and delivery. Export uses supported
  `VACUUM INTO` from a separate libsql worker, not live-file copying. The worker's
  V8 heap is limited to 32 MiB old/8 MiB young, SQLite cache to 1 MiB, and creation
  to 30 seconds; these do not claim a measured total native RSS bound. Cancellation
  waits for worker termination before cleanup/release. The snapshot is at most
  64 MiB; staging requires 352 MiB free including reserve/WAL headroom. Private
  temporary directories/files are mode 0700/0600 on the protected data volume.
  Normal completion, failure and disconnect attempt staged-file cleanup. A cleanup
  I/O failure increments the unavailable counter and startup retries cleanup;
  it is not reported as successful physical reclamation.
  One server process owns this store; multiple app processes are unsupported.
  Delivery has its own 30-second deadline. Operator permission is rechecked after
  snapshot creation and before release. Truncate during an active download returns
  409 with an explicit retry instruction; it never claims to clear a download
  already being delivered. No application schema joins the artifact.

### Export schema and local inspection

These queries are intended for a downloaded `spinel-diagnostics.sqlite`, not an
admin query endpoint. Run against captured evidence before acceptance; none has
been executed in this source-only checkpoint.

```sql
PRAGMA integrity_check;
PRAGMA user_version;
SELECT name FROM sqlite_master WHERE type = 'table' ORDER BY name;

-- Static leveled logs, correlated IDs and explicit client/server provenance.
SELECT received_at, source, level, message, actor_id, file_id, route, run_id, details
FROM events WHERE kind = 'log' ORDER BY received_at;

-- Counters are increments. Browser and server evidence remain separate.
SELECT source, json_extract(details, '$.operation') AS operation,
       sum(metric_value) AS increments
FROM events WHERE metric_kind = 'counter' GROUP BY source, operation;

-- Raw histogram observations, not averages of percentiles.
SELECT source, json_extract(details, '$.operation') AS operation,
       count(*) AS observations, avg(metric_value) AS mean_ms, max(metric_value) AS max_ms
FROM events WHERE name = 'operation.duration' AND metric_unit = 'milliseconds'
GROUP BY source, operation;

-- Inspect gauge observations in time order; scopes must not be summed together.
SELECT received_at, source, name, details, metric_value, metric_unit
FROM events WHERE metric_kind = 'gauge' ORDER BY received_at;
```

## Account lifecycle and correlated formula observations

**Accepted implementation choice — agent judgment with parent concurrence,
2026-10-23.** Observe the existing account Formula preview flow, including its
public library parse call, without changing the library's pure parser/evaluator
or native worker protocol. The alternatives were adding worker message envelopes
solely for telemetry and instrumenting pure transforms. An external wrapper and
the shared optional sink retain current results/errors with fewer moving parts.

The account App owns one collector per verified user. Guest App has no provider;
local-only startup has no collector. Hidden, offline and reconnecting states
discard the queue and abort delivery. A confirmed navigation guard allows sign-out
to stop collection immediately, before the sign-out network call; rejected
navigation does not stop it. Account replacement/unmount and account-cancellation
storage signals stop the old collector. A failed sign-out does not silently restart
that collector; a verified account remount can create a fresh one.

An expected-account UUID header is compared with current server cookie identity,
never used as attribution. A server-instance-keyed HMAC of the session hash fences
collection against a replacement session, including another login to the same
account. The opaque binding authenticates nothing, is not persisted/exported, and
requires ordinary cookie/file authorization on every request. Binding or storage
generation mismatch discards old buffers before reacquiring a collection; account
mismatch stops the adapter. This closes the race where two tabs share a changed
cookie before a storage event arrives. In-flight and queued loss are counted once;
a late response cannot uncount lost records or charge them twice.

For a reproducible scenario, choose a spreadsheet and sheet through Formula
autocomplete, choose A1, then Preview. The existing selected-reference parse emits
`operation.result` with operation `formula-parse`; frontend preview and backend
evaluation emit `formula-evaluate`, sharing a fresh UUID in the dedicated request
header. Each also records a raw duration histogram observation and a counter
increment; failures use the registered generic warning, never an error message.
The server rechecks the original session and host access after awaited evaluation
before observing it. It supplies the actor and file/Space IDs. Malformed correlation
headers are ignored, not logged or allowed to fail the operation. Guest routes
emit nothing even when a caller supplies a correlation header or observer.

Owner and Collaborator get an inspectable scenario without expression, result,
