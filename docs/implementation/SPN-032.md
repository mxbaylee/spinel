# SPN-032 — Shared diagnostics and operator health

## Event store with typed logs and metrics

**Accepted direction — owner, chat 2026-10-22.** The collaboration rewrite needs
instrumentation reusable by standalone libraries, the frontend and backend. The
owner prefers a generic event/log store with JSON details and first-class metric
types over a metrics-only series/window design. Generic logs include severity.
SPN-032 owns this alongside its existing health screen. Effort increases from M
to L for ingestion, identity, storage/export lifecycle and the operator controls.
This grooming record specifies future work; none of these APIs ship in this PR.

Use a small typed interface with a no-op default. Libraries receive an adapter;
they never import Spinel server/web code, open a database or send network traffic.
Keep transforms deterministic, recording timing/outcome around calls or through
optional observation hooks. Backend and browser adapters feed the same event
format, with the origin retained so browser claims are never server facts.

**Proposed schema — agent recommendation, 2026-10-22.** An append-oriented events
table in `diagnostics.sqlite`, separate from application/collaboration databases:

- Event ID and schema version; client occurrence time plus server receipt time.
- Kind (`log`, `metric`, or a registered structured event), stable event name,
  source (`frontend`/`backend`), component and application build/version.
- Optional log level (`trace`, `debug`, `info`, `warn`, `error`, `fatal`) and a
  sanitized message; validated JSON-object details for event-specific fields.
- For metrics, explicit kind/unit/value: counter increments, gauge observations,
  histogram observations. Avoid ambiguous cumulative-versus-delta counters.
- Optional actor/user ID, authorized file ID, route template, and non-secret
  request/operation/run correlation ID. Correlation IDs are not metric labels.

Index common time/name/component/correlation lookups. Use JSON text with validity
checks for portable exported files; verify JSON functions against our existing
libsql runtime. Reject mismatched metric fields and non-finite values. Initial
local SQL can sum counter increments, group histogram observations and select
gauges with explicit scope/time rules. Do not average percentiles. Defer physical
schema details and rollup tables until implementation; preserve schema/version
documentation and sample queries inside the export or accompanying guide.

## Identity without document contents

**Accepted direction — owner, chat 2026-10-22.** Include identity for the user,
file and route being exercised. The previous counts-only diagnostic rule is
superseded specifically for identifiers. Agent interpretation: use existing opaque
user/file IDs, route templates and non-secret correlation IDs, not titles, names,
paths, edits, cell values, formulas or document payloads. The health cards remain
aggregate; diagnostic IDs confer no content access.

The server derives actor identity from current authentication and validates file
context against current access. It must not accept a browser-supplied identity
as authenticated attribution. Revalidate socket sessions/grants and Origin; a
guest, if instrumented, has a pseudonymous actor bound to its current grant, not
a copied share/session token. Route templates replace parameter values, and raw
URLs, query strings, credentials and free-form payload dumps are excluded from
messages, JSON and errors alike. Correlation proves association, not the truth
of a client-reported metric. Operator-only read/export/truncate authorization is
independent of who may submit bounded events.

SPN-098 adds deliberately submitted feedback text as a separate event kind;
that is an explicit submission to the Operator, not automatic document capture.
See [its privacy and persistence contract](SPN-098.md).

Owner and Collaborator gain reproducible diagnoses but their activity IDs become
visible in Operator exports; their document contents stay private. Link guests
gain no diagnostic read permission and no broader file access. Operator gets a
portable investigation artifact, with clear client/server provenance and bounded
storage, without gaining a document reader or Docker control socket.

## Download and truncate, no query surface

**Accepted — owner, chat 2026-10-22.** The owner narrowed the UI to Download
diagnostics and Truncate diagnostics. Do not build a query panel, log viewer or
remote SQL endpoint. An external agent can exercise Spinel, obtain an authorized
snapshot, then use ordinary SQLite/JSON SQL locally. This is a developer/operator
workflow, not an AI feature or a new assistant credential scope in Spinel.

Downloads contain only the separate diagnostics database, with a coherent schema
and snapshot while collection continues. Use a supported consistent-copy method,
not a raw database/WAL file copy. The current wrapper's `backup()` uses
`VACUUM INTO`; evaluate its synchronous pause and export size before reusing it
on a hot path. Serialize/bound exports and remove temporary files on success,
failure or interrupted delivery. No application tables, files or secrets join
the download. Treat exports as sensitive operational metadata.

Truncate requires the existing destructive-confirmation pattern and current
Operator authorization/Origin protections. Clear only diagnostics and queued
pre-clear events, including later retries from the previous collection generation;
new events may continue. Define a clear boundary rather than promising a forever
empty store. Keep cancel/pending/failure/completion honest and never touch document
state, backup archives or durable collaboration queues. Physical compaction and
disk-space reclamation are separate from logically clearing records.

The owner explicitly confirmed that truncation also deletes user feedback and
clears the corresponding admin user flags (unless new reports arrive afterward).
The confirmation must mention feedback, not just logs. SPN-098 owns the form and
flags; its stored events participate in the same export and clear boundary.

**Accepted — owner, chat 2026-10-22.** Database sizes remain visible: show
application/collaboration storage and the separate diagnostics database, growth,
and free space on the data volume. Include physical database/WAL bytes without
double-counting shared files. A cleared record count is not a claim that the
physical file shrank or volume free space increased.

Advanced retention/compaction can wait, as requested. Initial event/batch size,
queue, rate and storage limits cannot be unbounded: stop/drop diagnostics under
pressure and report loss without blocking document work or recursively logging
the logging failure. Record concrete limits and overload behavior in implementation.

## Logging library and transport investigation

**Proposed — agent research, 2026-10-22.** Evaluate Pino before inventing a logger.
Its official [browser documentation](https://github.com/pinojs/pino/blob/main/docs/browser.md)
describes a `transmit.send` hook; its
[Node transports](https://github.com/pinojs/pino/blob/main/docs/transports.md)
support processing outside the main thread. These are useful building blocks,
not a supplied SQLite metric store, authenticated socket protocol or redaction
guarantee. Check TypeScript/bundler compatibility, browser redaction behavior,
resource costs and supported public APIs before choosing it. No package is added
or version selected in this grooming PR.

Prefer a small authenticated socket adapter if compatible with Spinel's public
transport boundary. Current collaboration uses the Pro endpoint; do not inspect
or extend its internals. Instrumentation must not wait for the collaboration
rewrite or share edit reliability/retry semantics. Document the chosen bounded
transport and its disconnect behavior; use a simpler bounded HTTP batch transport
if a socket would otherwise require coupling or substantial new infrastructure.

Initial evidence should cover one library operation, browser delivery, server
receipt and existing health/job sources, correlated through a reproducible run.
Include SQL examples for leveled logs and metric summaries so an external agent
can verify the exported contract without an admin query feature.

## Sync transform refusals and drops

**Proposed — agent, from owner request, chat 2026-10-22.** SPN-056's transform
refuses an edit it cannot merge safely, and the sender reloads; a refusal beats
a bad merge, but nobody can see how often it happens. These events show which
rules real use hits, so a later ticket can make the costly ones merge instead.
None are built. Each site in `lib/sync-transform` carries a
`Diagnostics (SPN-032, not built)` comment.

The transform stays pure: the sync server (SPN-057) records around each
`transform` call, and the silent drops need an optional observer argument,
no-op by default. Since [SPN-056 decision 29](SPN-056.md) it also reads the
cells at the edits' base revision, which the caller passes in; it still does
no I/O. Its refusal reasons are `'moved-cells'`, `'name-race'`,
`'formula-race'` and `'growth'` (`'format-race'` went with decision 29).
Labels are refusal reasons, rule names and Univer mutation ids, never params,
which hold cell content. File, user and run IDs go on the event, not on metric
labels.

| Event                       | Type      | Labels                    | Log level | What it answers                                             |
| --------------------------- | --------- | ------------------------- | --------- | ----------------------------------------------------------- |
| `sync.edit.transformed`     | counter   | none                      | none      | Denominator for every rate below.                           |
| `sync.edit.refused`         | counter   | reason, the two mutations | info      | Which refusal rule users hit, and against what.             |
| `sync.edit.resync`          | counter   | reason                    | warn      | Refusals that cost a sender a reload (SPN-058).             |
| `sync.resync.pending`       | histogram | none                      | none      | How many pending edits each resync throws away.             |
| `sync.edit.dropped`         | counter   | rule                      | debug     | Silent losses: see the rules below.                         |
| `sync.edit.offset`          | counter   | none                      | debug     | Writes merged off-place beside a clipped shift band.        |
| `sync.edit.unsupported`     | counter   | mutation id               | error     | Sender bugs or a Univer upgrade with a new mutation.        |
| `sync.edit.malformed`       | counter   | check                     | error     | Batches `transform` threw a `TypeError` on (below).         |
| `sync.divergence.detected`  | counter   | none                      | error     | Screens that differ after a merge (SPN-057, below).         |
| `sync.invariant.failed`     | counter   | invariant                 | error     | No sheet left, or none visible (README, Known limits).      |
| `sync.transform.duration`   | histogram | none                      | none      | Time per call, in milliseconds.                             |
| `sync.transform.concurrent` | histogram | none                      | none      | Length of the concurrent sequence: how far apart edits are. |
| `sync.transform.growth`     | histogram | none                      | none      | Peak length against the limit (50 per mutation).            |

The `rule` label of `sync.edit.dropped`:

- `name-first-accepted`: a set or removal of a name that lost to one accepted
  first (SPN-056 decision 2).
- `cell-overwritten`: cells a concurrent write took over (the cells' ghost).
- `merge-cut`: a merge dropped because a concurrent row or column edit cut it.
- `removed-sheet`: an edit to a sheet removed concurrently.
- `setting-first-accepted`: a sheet setting that lost to one accepted first.
- `doc-formula-first-accepted`: a Doc formula's re-insert that lost to an edit
  of the same formula accepted first.

`RefusedEditError` would need to carry the ids of the two mutations that raced
for the `sync.edit.refused` labels; today it carries only `reason`. Growth trips
are `sync.edit.refused` with reason `'growth'`. The first candidates to revisit
are the highest rows of the sync-transform README's refusal table, as
re-measured after decision 29 (2026-10-23): a book with one name (7.26%,
mostly SPN-056 decision 1) and a book with formulas and one name (5.85%, its
decision 22).

**Malformed batches.** `transform` throws a `TypeError`, not a
`RefusedEditError`, on a batch no honest sender makes: a mutation that breaks
the sender rules `check` enforces (inline styles, RemoveSheet's `index`, a
marked shift, no reserved keys), an absolute cell write whose unclaimed keys
differ from its base cell (a forged or edited claim, SPN-056 decision 33), or
base cells missing where they are needed. The server refuses the batch and
resyncs its sender (SPN-057). The `check` label would name which rule failed;
today only the error's message says, so the error would need to carry a code,
as `RefusedEditError` carries its reason. Unsupported mutations stay their own
event above. A rise means a sender bug, a Univer upgrade or a client editing
its claims.

**Self-healing is SPN-057's divergence check**, not a transform rule. At each
commit the server stores a hash of the cells (or Doc body) the revision
touched; a client with nothing pending sends the hash for the latest revision
it applied (SPN-058). On a mismatch the server resyncs that client, as for a
refused edit, and records `sync.divergence.detected` with the redacted shapes
of the revisions since its last match (below), so a divergence becomes a test
without anyone reading the sheet. See [SPN-057](../todo/SPN-057.md)'s Rules.

- **Owner and Collaborator:** refusals they hit become visible, so the rules
  that cost them reloads can be fixed first; their activity IDs appear in the
  export, as for every SPN-032 event.
- **Operator:** a few more event names, all bounded like the rest.
- **Link guest:** unaffected beyond SPN-032's guest rules.

## Reproducing a refusal without document content

**Needs owner — agent proposal, chat 2026-10-22.** The metrics above say which
rule refused, not where, so they cannot rebuild a test. Since SPN-056
decision 29, `transform` is decided by the two edit sequences, which was
accepted first, and the base cells of every cell both sequences write: a
same-cell conflict replays the base cell, the loser and the winner through
Univer's own merge, which reads values (a number typed as text, rich text
whose text equals a value). So a redacted copy of both sequences and of those
base cells, logged at debug with each refusal (`sync.edit.refused.shape`) and
each divergence, would let a test rebuild the case on a made-up book, as
SPN-056's tests already do from captured commands.

| Part                      | Kept                                                                                                                                     | Obscured                                                                                                       |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Cell value `v`            | whether it is set, its type `t`, whether text reads as a number, and which values are equal (in the edits, the base cells and rich text) | the value, as a placeholder per distinct value of the same kind (`'1'` for numeric text, `'x'` for other text) |
| Base cells                | every cell both sequences write, as the cells it lists                                                                                   | the same as the edits' cells, with the same placeholders, so each replay lands alike                           |
| Claims                    | the claimed keys under `sync-transform.cells.claim`                                                                                      | the claimed values, as for `v` and `s`                                                                         |
| Style `s`                 | all of it, including number-format patterns                                                                                              | nothing                                                                                                        |
| Formula `f`, `si`         | functions, operators, cell references, `si` ids                                                                                          | literals as placeholders; sheet and name references as pseudonyms                                              |
| Defined names             | id, scope, reference                                                                                                                     | the text, as `n1`, `n2`                                                                                        |
| Sheet and workbook names  | ids                                                                                                                                      | the text, as pseudonyms                                                                                        |
| Rich text and Docs        | structure, style ranges, Univer's control characters                                                                                     | each character as `x`, keeping lengths, since positions use them                                               |
| Hyperlinks, notes, images | position and size                                                                                                                        | URLs, note text and image sources                                                                              |

- **Pseudonyms per event, not hashes:** a guessable name such as `budget`
  would fall to a dictionary. Names equal ignoring case share a pseudonym, so
  the same-text refusal still reproduces.
- **Fail closed:** `lib/sync-transform` would export `redact(mutation)` and
  `redact(cells)`, since it already knows every mutation's and cell's shape. Like `check`, it rejects a mutation
  it does not know and drops any field it does not recognise, so a Univer
  upgrade that adds a field cannot leak it.
- **Formulas cost most:** keeping references means tokenising, perhaps with
  open-source `@univerjs/engine-formula`'s lexer. A first version can keep
  only that a formula is present and the references it uses.
- **Bounded:** a large paste is truncated to a size limit and marked so.
- **Placeholders must keep the merge's inputs:** Univer's merge retypes text
  that reads as a number and compares a value with its rich text, so a
  placeholder that changed either would rebuild a different case. Equal
  values share a placeholder within one event.
- **Convergence:** a merge whose screens differ is caught by SPN-057's
  divergence check, which logs these shapes (above), not by the transform.
- **Still revealed:** the sheet's layout, text lengths, number formats and
  functions used, enough to tell a kind of sheet but not its contents.

**Owner question:** this loosens the rule that automatic diagnostics never
collect edits or formulas, for redacted shapes only. Until decided, build only
the metrics above.

- **Owner and Collaborator:** a refusal they report becomes a test without
  anyone reading their sheet; the layout of the edited range is exported.
- **Operator:** an export that can rebuild a refusal locally.
- **Link guest:** unaffected beyond SPN-032's guest rules.
