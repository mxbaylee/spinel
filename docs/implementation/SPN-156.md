### 🧩 Observed ownership and selected direction

- `web/offline/useOfflineDownloads.ts` refreshes summaries on foreground events
  and deliberately skips pending copies during clean-download refresh. It owns
  no queue replay. `web/spinelSync.ts` starts reconnect/access/socket work from
  the binding's `watch` method and disposes it with the editor. This supports
  the reported ownership gap; it is not a new browser reproduction.
- `@spinel/sync-client` already publicly exports `NativeReplica` and
  `createNativeSyncClient`. Its maintained `tests/native-session.ts` constructs
  them together without a React editor. The OSS replica registers the existing
  Doc/Sheet/drawing/formula handlers and preserves resource snapshots. That is
  source evidence for a capability probe, not proof of this browser lifecycle.
- `OfflineSession` already checks compatibility, prepared-account epochs and
  scope, acquires the real item Web Lock, verifies images, restores the retained
  checkpoint and persists through `saveCheckpoint`. `ScopedHTTP` binds remote
  requests to the expected account and maintenance epoch. Reuse these owners.
- The existing sync binding rechecks collaboration access before acquiring a
  socket ticket, retains the original mutation envelope on reconnect and keeps
  denied or incompatible pending work recoverable. Reimplementing that protocol
  in a file-list uploader would create a second authority and retry path.

Options considered: send stored frames directly, mount hidden React editors, or
give the existing native/session/binding owners a bounded nonvisual host. Select
the third direction provisionally. Raw upload would bypass native confirmation,
rebasing and persistence ownership. Hidden editors would unnecessarily retain
input, renderer and layout lifetimes. Begin with one pending item at a time,
scoped to the prepared signed-in account, triggered by reconnect/foreground and
relevant durable-change events. Do not introduce periodic idle server polling,
closed-app execution, a new queue, a new package or any Pro dependency.

The first executable capability probe must resolve these concrete boundaries
before broad implementation:

1. Restore a Doc and Sheet checkpoint into the existing native implementation
   without duplicating a unit already created by `loadSpinelDocument`; preserve
   recovery snapshots, drawings, authored formulas and canonical image URLs.
2. Reuse the live binding's access/maintenance and socket path without requiring
   renderer readiness or accidentally changing its recovery-copy rules.
3. Define completion as acknowledged native state **and its committed durable
   checkpoint**, not an empty in-memory queue or a badge change. Expose the
   narrow stop/join boundary needed to drain or safely cancel persistence.
4. Yield the same-item writer before a foreground editor is admitted, and skip
   genuinely contended writers in other tabs. Account changes, sign-out,
   removal, failed persistence and interrupted acknowledgement must not leave
   a late writer or clear pending data prematurely.
5. Bound native instances, active sockets and teardown. Dispose the host and
   session on completion/failure or account lifetime end; retain failed work
   for the existing file-list recovery entry rather than claiming success.

**All four personas:** Operator gets one bounded replay owner and existing
failure diagnostics, rather than another long-running service. Owner and
Collaborator gain exact acknowledged content without reopening files, while
foreground editing, retained work and revocation remain protected. Link guest
does not acquire a prepared account, private store, writer or replay capability.
