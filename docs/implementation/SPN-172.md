### Syntax and graph gaps

Current `parseFormula` accepts `=SUM(Budget.Summary.A1,Forecast.Summary.A2)` and explicitly refuses raw `[]!` qualifiers. `=SUM(Expenses!C2:C20)` is **new syntax/resolution work**. Do not remove that guard globally. `Expenses` denotes a worksheet within a selected workbook context; Space autocomplete must bind one authorized item/worksheet. Ambiguous labels need a picker, not an arbitrary default. Existing qualified syntax remains readable for retained native Space formulas.

Univer **1.3.1**, pinned by Spinel, exposes defined names through `FWorkbook.getDefinedNames`, `getDefinedName` and `IDefinedNamesService`; native sync already preserves `SHEET_DEFINED_NAME_PLUGIN` resources. A named range resolves its current target by stable defined-name ID and scope, rather than freezing an A1 range at insertion. Source rename, retarget, delete/recreate and restore are distinguishable.

Structured-table discovery and references are **retained core requirements**, separate from the optional editable embed. `@univerjs/sheets-table` exists in pinned open-source 1.3.1 but is absent from Spinel's manifest/lockfile. Phase 1 must inventory actual available source metadata and qualify the required plugin, `SHEET_TABLE_PLUGIN` resources, formula integration and mutation/persistence admission. Add the supported integration needed to autocomplete and evaluate a real named-table fixture such as `=SUM(ExpensesTable[Amount])`; a plain rectangular range is not a structured table. Record table/column identity, rename/delete/undo/reopen and canonical source-edit behavior. Finding no current tables does not make future named-table support optional. If integration cannot qualify safely, retain a blocker, remaining estimate and any prerequisite slice; do not declare the bake-off complete by declining adoption. A new general table-management product is not implied, and only the editable live Sheet/table block earns the optional bonus.

### Local persistence contract

Persist authored editor state, formula definitions/IDs/names, bindings, format and schema version. Values, type previews, live handles and backlink counts are transient/derived. Save outside the keystroke path; “Saved on this device” means the transaction completed. Flush on tab/page transitions with the dirty-navigation guard; quota/denial failures keep content dirty and recoverable. A schema mismatch never overwrites content with an empty document.

Use one active writer per draft key or a revision-checked conflict UI so two tabs cannot overwrite silently. This is local storage integrity, not multiplayer prose. Name/usage indexing reads the same account/Space/candidate's saved drafts, not merely mounted pages. Account exit, credential loss, source revocation, deletion and offline privacy epochs clear visible derived data and prohibit another account reading drafts. Integrate cleanup/recovery intentionally with `accountExit.ts`; a new IndexedDB database is not automatically covered. Clearing private results must not silently discard unsaved text.

### Shared Univer formula bridge

1. Discover sources through exact Space-host authorization. Retain logical item/worksheet/defined-name/table identities separately from current generation. Bind capability to the initiating account and host membership; labels are presentation.
2. Compile Space-only syntax to validated stable references. Preserve strings and token spans using a parser/token model. Map named Space formulas to cells in a transient evaluation workbook so dependencies calculate through Univer, not a second JavaScript evaluator.
3. Reuse bounded source loading, queue admission, worker deadline and Facade calls. Selectively retain validated defined-name/table resources supported by registered plugins. Do not pass every plugin resource or client-provided native identity through. Keep current source/result/byte limits unless a separately reasoned, tested change is accepted.
4. Add proposed `/api/spaces/:spaceId/items/:docId/formulas/changes` as a bounded authenticated stream/long-poll. Carry authorized source ID, generation and revision invalidations, not cell values or prose. Coalesce bursts; check host and every source before admission/delivery and after awaits. Commit signals work when a Sheet editor unmounts or another tab changes the canonical source.
5. Commit events alone do not cover rename, deletion, restore, access loss or expiry. Revalidate lifecycle/generation at these boundaries, reconnect and a bounded authority check; dispose listeners on timeout, close, navigation and account change. A missed event requires fresh authorized evaluation.
6. Fence results by node/definition revision, draft identity, account/host authority, source revision/generation and request sequence. Clear obsolete values immediately; reject late completion after edit/delete/switch/restore/revocation. Keep layout stable while pending. Derived updates never enter prose history or authored-state writes.
7. Serialize/coalesce engine execution per session and batch dependent named formulas. Pinned `executeFormulas` result delivery is not a unique per-pill channel; uncoordinated overlapping calls require proof. Never create one hidden native editor/worker per pill. `onCalculationResultApplied` is a one-shot wait; `calculationResultApplied(callback)` is the disposable recurring Facade subscription when needed.

Baseline timing is **confirmed source edit → authorized result painted**; it does not promise uncommitted cell text. An optimistic shared local worker is a separate capability decision if measurement requires it, retaining pending-edit semantics, source authority and generation fences. The current server path creates a real Univer graph per evaluation, not a resident global graph. Record that distinction in results.

### Named formulas, usage and types

Custom formula names are reusable across prototype pages in the **same account + Space + candidate**, separate from workbook defined names and `LET`'s expression-local variables. Store stable formula ID and readable name; validate aliases against function/range/name collisions and disambiguate qualified references. Rename preserves ID-bound targets. Copy/paste creates new node IDs; copied names require uniqueness or explicit renaming, never silent alias capture.

A link count means incoming reference **occurrences** to that formula in the local candidate dataset; zero is meaningful. Repeated references count separately; expanded backlinks group by page/formula and offer keyboard navigation. Include unmounted saved pages. Derive counts from committed definitions: preview/cancel do not alter them; deletion/undo/rename do. Missing targets stay explicit. Label local scope so the count cannot imply server-wide knowledge. SPN-173 sizes production indexing and naming races.

Name dependencies calculate in Univer's graph, update transitively and report cycles/missing names. Expression/bindings/name form one versioned authored definition. Keep display names and expression alias rules explicit; no Coda `WithName`/`.Filter` emulation. Workbook names and formula names use distinct token kinds.

Use exported `IDescriptionService` through a small public plugin/DI adapter for function signature, active argument, optional/repeated parameters and help. `IFunctionInfo`/`IFunctionParam` describe functions; `FunctionType` is a category, **not a static return-type system**. Badges use known source metadata or authorized evaluated shape: number, text, boolean, date/format, range/table, unknown. Currency is formatting. Richer predicted hints need documented/tested rules; do not invent whole-language inference. `FFormula.sequenceNodesBuilder()` and `getFormulaExpressTree()` are parsing/highlighting helpers, not typecheckers; incomplete input needs safe fallback without moving the caret.

### Reproducible benchmark protocol

- Fix production build, commit/dependencies, hardware/browser/OS, viewport/fonts and animation setting. Use 1,000 words/10 pills for everyday use and 10,000 words/100 pills for stress, including lists, code, long expressions and named chains; identical source cells/names/revisions per candidate.
- Run three fresh recorded first-attempt samples per candidate in rotated order. Measure input event → painted state, trigger → usable menu, durable source commit → invalidation → authorized result, local-save latency, lazy chunk bytes, heap and repeated mount/dispose trend. Record p50/p95 and sample counts. Screenshots do not prove latency; profiling/retries are separate diagnostics.
- Proposed everyday targets: input p95 ≤50 ms; menu p95 ≤100 ms without waiting for network; committed source change → painted pill p95 ≤1,000 ms on the documented local setup. Freeze targets at the capability checkpoint **before** candidate comparison; these are proposed targets, not current measurements. Keep stress results visible. Misses require repair or disqualify recommendation; do not increase targets after failure to pass.
- Two nonimplementing reviewers run the same feel task: focus, reversibility, prose continuity and stable layout. Record proposed/current light/dark/phone plus tablet evidence and agent-only visual review. Use actual native keyboard/clipboard events, not editor commands as a substitute.
- Desktop native browsers own caret/clipboard differences; phone emulation owns layout/touch targets and is labeled accurately. OS-keyboard/IME claims require corresponding real input evidence. Existing on-demand mobile Doc editing stays opt-in; it does not automatically test these editors. Identify any additional prototype mobile input owner explicitly.
