## Legacy decision 19: Revision-checked native Sheet snapshots

**Recorded:** 2026-10-17. **Status:** accepted, historical pre-collaboration contract.
**Authority:** Agent persistence judgment.
**Source:** [original decision #19](https://github.com/mxbaylee/spinel/issues/19).

**Question:** How should single-user spreadsheets autosave without silently overwriting another
device?

**Options considered in the original source:**

A — preserve full Univer IWorkbookData JSON, serialize debounced saves with an expected revision and
stable retry ID, show pending/offline/failure/conflict status, and prevent unacknowledged navigation
from silently dropping edits. B — save individual cells in a custom schema or overwrite snapshots
unconditionally, increasing conversion work and risking lost edits across tabs/devices.

**Outcome, rationale and current boundary:**

Preserve complete native IWorkbookData, including resources, with serialized debounced
expected-revision saves and stable retry identity. Reject stale writes visibly rather than
overwriting; an acknowledged response lost in transit must retry idempotently. Bound requests at 10
MiB and retain visible unsaved failures/navigation warnings. Pending edits in an open browser were
not durable offline storage. This initial owner-scoped snapshot path preceded later collaboration
and explicit sharing; those integrations must preserve native data and current authorization rather
than revive an obsolete unconditional snapshot write path.

**Persona tradeoffs recorded at the time:**

Operator needs a small SQLite save path with bounded requests. Owner needs values, formulas, formats
and tabs preserved with visible unsaved/error states. Collaborator needs later collaboration
compatibility without a proprietary interim document format. Link guest must not gain access through
the new content endpoint.
