## Legacy decision 74: Personal filing of shared items

**Recorded:** 2026-10-18. **Status:** accepted.
**Authority:** Agent organization implementation judgment.
**Source:** [original decision #74](https://github.com/mxbaylee/spinel/issues/74).

**Question:** How should personal filing and newest-first ordering work for account-shared items?

**Options considered in the original source:**

A — one personal reference per user/item, shared drawer ordered by recorded grant time, with
transparent legacy ordering; B — copy or reparent the shared item, creating conflicting ownership
and access behavior; C — duplicate shortcuts with arbitrary independent ordering and extra cleanup
states.

**Outcome, rationale and current boundary:**

Store one personal placement per user/item without moving the owner's source, changing ownership or
altering grants. Destinations are the user's own folders; resolve current access for every view.
Shared ordering uses the latest applicable grant timestamp, bounded by item creation for children
created after an inherited grant. Legacy grants keep an explicitly unknown timestamp and display
Older share after dated shares; do not fabricate their grant date from creation or modification time.
Access loss permanently removes personal placement so renewed access does not silently
resurrect it. The shared catalog and authorized folder descendants retain privacy of inaccessible
ancestors.

**Persona tradeoffs recorded at the time:**

Operator benefits from additive SQLite storage and existing access checks. Owner keeps their tree,
ownership and grants unchanged. Collaborator gets every accessible shared item in one drawer,
durable personal filing and clear owner labels. Link guest has no account drawer or personal filing,
and receives no new metadata.
