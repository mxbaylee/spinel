## Bounded admission and recovery

- **Date/status:** 2026-10-23, accepted design; execution and review pending.
- **Question:** How can a foreground Save progress amid two refresh streams
  without increasing worker capacity or retaining unbounded work?
- **Options:** Client refresh pauses or interactive-priority headers add timing
  and protocol complexity. One waiting slot cannot admit a foreground request
  when another reader already waits. Unbounded queuing and higher worker limits
  violate the existing resource contract.
- **Outcome/reason:** Use one shared FIFO admission gate across sheets, resolve
  and evaluate routes and router instances: one active plus at most two waiting.
  Atomically promote the oldest waiter before reacquisition. This guarantees
  ordering after admission, not admission under arbitrary load. Reject overflow
  with the existing busy category. Queue only validated, initially authorized,
  bounded inputs, never materialized snapshots. Bound waiting, remove expired or
  disconnected waiters, and recheck session, host and source access on promotion.
  Release exactly once after active work settles; cancellation must not free a
  permit while materialization or a worker still runs. Preserve worker deadline,
  concurrency, heap and source limits.
- Retain the original recovery contract: classify temporary failures separately
  from invalid/private-source outcomes, retain the expression, support explicit
  bounded retry and at-most-once mutation, and fence stale completions. Existing
  truthful UI can be reused where it already meets this contract; changes require
  stories and actual visual review. No blind Save retry or timing-only test fix.
- **Personas:** Owner and Collaborator gain progress and retained edits. Link
  guest retains fresh scoped access and receives no private source information.
  Operator retains one worker and a fixed small queue, bounded waiting and
  value-free evidence. All four favor this bounded repair over timing workarounds.
- **Decision source:** Implementing agent and independent
  `diagnostics_independent` assessment, under the owner's delegated all-persona
  decision authority in chat. A focused registration PR followed by the repair
  may temporarily exceed the owner's soft two-PR target to unblock existing work.

## Waiting deadline and explicit retry

- **Date/status:** 2026-10-23, accepted implementation decision; source and execution verification pending.
- **Question:** How long can an admitted request wait, without multiplying the
  deadline through the existing client busy retries?
- **Options:** Immediate rejection recreates starvation. A five-second wait can
  expire behind two existing five-second calculations. Reusing busy for queue
  expiry would allow the client to repeat long waits automatically.
- **Outcome/reason:** Bound queued waiting to 12 seconds, covering two preceding
  worker deadlines plus a small scheduling/read allowance. This is not a guarantee
  that materialization finishes within that time. Full admission returns the
  existing busy response; an admitted wait that expires returns temporary
  unavailability for sheets/resolve and timeout for evaluation, which the client
  does not automatically retry. Read-only overflow retries retain their existing
  finite delays. Twelve seconds bounds waiting only: network, materialization and
  active processing are outside that queue deadline, and Save includes both
  resolve and evaluate requests. Do not infer a whole-Save maximum from it.
  The user may explicitly retry a retained edit. The worker's own
  five-second deadline and heap limits remain unchanged. Neither waiting expiry
  nor client cancellation releases an active permit before its work settles.
- **Personas:** Owner and Collaborator get a realistic turn behind two readers
  without a chain of long silent retries. Link guest gets the same bounded wait
  and fresh authorization. Operator retains one active request and two bounded
  waiters with no retained source snapshots or indefinite client wait queue.
- **Decision source:** Server implementing agent `recovery_final_review` and
  primary agent, under the owner's delegated persona decision authority;
  independent reviewer `diagnostics_independent` accepted this policy with all
  four personas considered, while requiring exact-source review and regression
  proof that queue expiration is attempted once and never frees an active permit.

## Implementation and verification checkpoint

Registration [PR #175](https://github.com/mxbaylee/spinel/pull/175) merged at
`9500b12774fa730533cfc69f49204be0957584c9` after independent 100/100 review and
successful documentation-only CI. It registered the contract; it did not repair
runtime behavior. This implementation starts from that actual main.

Server admission and native/dialog cancellation are implemented together.
The UI keeps existing expression, format and source choices, adds safe temporary
failure classification, and prevents duplicate or stale insertion. This follows
the existing inline-error pattern in the design playbook. Runtime tests, native
verification, actual story images, current-head CI and independent final grading
are still pending. Independent server/helper source review found no blockers,
including the monotonic deadline check that rejects expired promotion even if its
timer callback was delayed. The native/dialog slice still needs independent review.
Local memory pressure is elevated (level 2); heavy validation
is deferred to CI under the owner's standing preference.

Authored regression coverage includes FIFO contention, full admission, queued and
active cancellation, revoked source/host/session/guest access, thrown work,
deadline expiration without automatic retries, and actual HTTP disconnect across
account/Space/guest routers. Native adapter tests cover safe failure classes,
single insertion through command settlement and stale/canceled results. Nine new
stories cover retained failures, explicit retry, duplicate submission and canceled
Save recovery; all 36 Formula stories will be reviewed together. Three new native
browser cases force busy, timeout and unavailable responses, verify the unchanged
persisted document before explicit retry, then verify exactly one Formula after
reload and capture light/dark/phone evidence. The original collaborator Save
assertion and its 20-second deadline are unchanged. These tests are authored,
not claimed executed by this checkpoint.
