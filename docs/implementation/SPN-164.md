## ⏱️ Measured boundary and chosen deadline

**Accepted, 2026-11-22, agent decision after the reproduction.** Choose
**3,000 ms across session headers and body**. This is an explicit usability budget,
not a statistical network estimate: it allows the tested 2.5-second success,
exceeds the existing two-second health probe, and prevents the reproduced
15-second stalled wait. Native acceptance allows measured settlement below
4,000 ms, including a 1,000 ms scheduling allowance. OS suspension/event-loop
starvation, service-worker navigation and account/device locks are outside this
request bound. The after experiment measured **3,004.3 ms at headers** and
**3,002.7 ms during body consumption**, both taking the existing outage path.

Apply the budget to all session reads: browser connectivity does not reliably
identify recent reconnects. A readiness probe/retry would add a request and race.
Other authentication reads/item transfers retain 15 seconds; explicit caller
signals retain their cancellation semantics. Known-offline starts still skip the
request. Slow/unavailable service can show the existing device-copy/unreachable
view sooner, without clearing the session cookie, discarding content or granting
online authority. A received session 401 stays a denial if its body stalls or is
malformed: settle that body, fence its owner, then apply existing expiry behavior.

After verified session success, use **saved files** for account/device admission.
This preserves the existing status pattern and makes its phase truthful. Actual
390px screenshots exposed the old status line overlapping the entry footer; its
fixed placement now clears the footer, including safe-area inset. The production
EntryFrame Storybook example asserts this separation. No new design pattern.

**All four personas:** Owner gets a bounded wait with retained notebook content;
Collaborator retains revocation and late-account fencing, accepting conservative
local mode on slow responses; Operator retains existing health/auth architecture,
with no new production polling or telemetry; Link guest's route and authority are
unchanged. Keeping 15 seconds fails the reproduced usability contract; treating
browser-online as authenticated readiness would weaken authority. Both are rejected.
