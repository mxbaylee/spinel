## Legacy decision 64: Personal pins

**Recorded:** 2026-10-18. **Status:** superseded.
**Authority:** Agent organization judgment, later owner removal.
**Source:** [original decision #64](https://github.com/mxbaylee/spinel/issues/64).

**Question:** How should personal pin ordering and access-loss cleanup behave?

**Options considered in the original source:**

A — store per-user ordered references, append new pins, move single references within the current
list and remove references transactionally when access ends. B — keep hidden references after
revocation/trash and revive them later; easier retention, but unexpected sidebar returns. C — accept
last-writer whole-list replacement; simpler API but stale tabs can lose newer pins.

Recommended/decided: A. Pin/unpin is idempotent; ordering sends only `{ id, beforeId }` (null means
end) and moves that reference within the current list, preserving other-tab additions. Missing
source/destination is 409. This keeps request size independent of pin count; review found whole-list
requests exceeded 8 KiB at 210 UUIDs. Removing the last effective grant, moving out of an inherited
grant or trashing removes affected pins; remaining alternate grants preserve them. Restore/regrant
does not repin. All four personas retain their existing access boundaries. No shared content,
ownership, parent or history timestamp changes.

The sidebar appears on all authenticated everyday pages, including Settings and editors. Drag/drop
has Up/Down alternatives for keyboard/touch. Shared references show Shared, and personal tags remain
visible. Open pages refresh after local changes, on focus/foreground and every15seconds while
visible; destinations always recheck access. Owner attribution/shared filing remains SPN-018.
Failures provide a retry; stale list responses cannot overwrite mutation results.

**Outcome, rationale and current boundary:**

The original personal ordered shortcuts preserved source ownership and allowed independent filing of
readable shared items. Decision [#128](SPN-047.md#legacy-decision-128-remove-personal-pinning)
explicitly removes personal pinning and all pin UI rather than renaming it or keeping disabled
controls. This record is retained for provenance only; it does not require a current pins feature.
Named history versions and offline downloads are outside that removal.

**Persona tradeoffs recorded at the time:**

The Owner wants stable daily shortcuts without changing documents. The Collaborator wants an
independent order for owned and view-only shared items. The Operator wants a small additive SQLite
schema and predictable cleanup. The Link guest must never reach another person's personal
references.
