## 🗂️ Action and placement inventory

Audit baseline: `1081e5a3156776bb5ed8d577b01b53224ebd0ad8`. The production
controllers below own the actions; obsolete proposal components are not runtime
proof. Existing role and operation meaning takes precedence over cosmetic
uniformity. Shared ActionMenu supplies keyboard selection, disabled semantics,
decorative icon treatment and focus return; the same sp-control/sp-option rules
supply the existing 44px phone targets. Existing Modal and form controls retain
pending dismissal locks, visible errors and confirmation copy.

- **Dashboard rows, grid and editor actions — `web/Dashboard.tsx`,
  `DashboardFiles.tsx`, `EditorTools.tsx`.** Open is navigation. New offers noun
  type choices. Make a copy…, Share…, Rename…, Move…, File into folder… open
  dialogs; Tags…, Appearance…, Access details…, Versions and Formulas name
  panels. Share/rename/move/trash require file administration; personal filing,
  tags and Hide/Show affect the current account. Move to Trash remains a
  recoverable operation, distinct from permanent deletion. Copy uses copy-plus;
  absent menu icons are intentional text-only placements, not competing icons.
  Save remains a form confirmation, now Saving… while Dashboard is busy.
  Errors keep the form and its values. Shared controls and existing explicit
  finalFocus refs retain keyboard and touch behavior.
- **Offline actions — `Dashboard.tsx`, `SpaceOfflineActions.tsx`,
  `DeviceStoragePanel.tsx`, `offline/useOfflineDownloads.ts`.** Make available
  offline names downloading, Remove from device names only local removal.
  Dashboard now matches Space's Downloading…/Removing… pending wording.
  Available offline and Needs attention remain status labels. Space's accessible
  name includes the file and device; device storage includes the row's filename.
  One transfer at a time, saved-state readiness, account scope, unsynced-data
  confirmation and retry/repair feedback remain owned by the existing hook and
  device-storage flow. This does not promise permanent browser retention.
- **Spaces — `Space.tsx`, `SpaceTree.tsx`, `SpaceRootActions.tsx`,
  `SpaceItemDialog.tsx`.** Root Share/Rename/Move now carry the same ellipsis as
  Dashboard. Child Rename… and Move or reorder… remain distinct from moving a
  whole Space; Move to Trash replaces the ambiguous noun action Trash. The
  editor's Rename Space… deliberately identifies its root target. Root actions
  require file administration; child edits require the Space grant. Saved and
  navigation guards, stale-generation protection, subtree confirmation,
  destination authority, Cancel and pending Save states are unchanged.
  Root icon meanings remain share-2/pencil/folder-input/trash-2; text-only child
  menus avoid a second identity cue beside each page. Pages, Offline copies and
  Trash remain noun destinations.
- **Recovery — `Trash.tsx`, `SpaceTrash.tsx`, `HistoryBrowser.tsx`,
  `VersionNames.tsx`.** Restore is recoverable content restoration; Delete
  permanently/Empty trash require explicit previews and existing version guards.
  A Space subtree and the account's whole Trash are different scopes, so their
  confirmation text/counts differ deliberately. Destructive menu entries retain
  the error foreground/separator; modal confirmations keep their established
  primary-button pattern and explicit consequences. History restore also
  requires its existing save/access guard; Remove name does not delete history.
- **Sharing — `Sharing.tsx`, `GuestLinks.tsx`, `AccessDetails.tsx`.** Share…
  enters management; Save changes applies a staged grant. Turn off link revokes
  access, not content; Change expiry… opens a form. No confirmation is added to
  previously immediate reversible controls. Grant changes and server failures
  retain their existing authority checks, status/alert feedback and focus refs.
- **Account — `ProfileSettings.tsx`, `PasskeySettings.tsx`, `AccessTokens.tsx`,
  `AccountExit.tsx`, `ProfilePage.tsx`.** Save profile, Add passkey, Remove
  passkey…, Create/Copy/Revoke access token and Sign out retain explicit objects.
  Remove passkey… now matches Admin's menu; it still requires fresh verification
  and an explicit final Remove passkey confirmation. Last-passkey protection and
  cancelled/uncertain-proof handling stay intact. Sign-out Keep changes versus
  Delete offline data deliberately names local retention, not server deletion.
  Sections and Continue/Done remain navigation/completion labels.
- **Operator — `AdminUsers.tsx`, `AdminInvites.tsx`,
  `AdminAccountRecovery.tsx`, `AdminDiagnostics.tsx`, `AdminFeedback.tsx`.**
  Disable account… now confirms Disable account / Disabling…, while passkey
  removal confirms Remove passkey / Removing…. The former Confirm removal
  incorrectly implied deletion for disabling an account. Recovery, transfer,
  invite revocation, diagnostics download/truncation and feedback review retain
  object-specific wording and their named consequences. Current-admin/last-key
  protection, pending locks, content-free diagnostics and lack of document access
  remain unchanged. DisablePending is a production story, not a mocked button.
- **Guest — `GuestApp.tsx`, `EditorTools.tsx`, `Space.tsx`.** Guest views expose
  only granted editing, allowed PDF export and formula controls; no account,
  file-management or offline-store entry. Export as PDF identifies the actual
  format while the account Export destination contains several choices.
  Revocation/unreachable states retain their existing recovery guidance.

## ⌨️ Native and alternate invocation boundaries

Public SDK routes were inspected in `nativeCopy.tsx`, `nativeSyncPermissions.ts`,
`syncSheetMenus.ts`, `sheetImageInsertion.ts`, `DocEditor.tsx`, `docPhoneView.ts`
and `lib/doc-formulas/`. No package internals or Pro APIs are used or changed.
`spinel.command.make-copy` opens the same CopyFileForm as the row dialog: opening
an unavailable explanatory form is intentional; publication rechecks canSubmit.
`sheet.command.copy-sheet` rechecks the target's supported stored-cell boundary,
including explicit commands with a different active sheet. Native document/sheet
edit authority comes from projected native permission points and the original
SDK handlers; ReaderCommands only suppresses automatic reader header/footer
startup refresh. Native Make a copy and Insert formula retain the established
SDK/editor punctuation convention without ellipses, while app-owned file menus
use ellipses for an intermediate form. Formula operations retain their own public command and grant guards;
image insertions share prepared-image/readiness checks. Phone history/navigation
uses existing command dispatch and read-only state. The UI label edits do not add
an alternate path, loosen a disabled predicate or mutate persisted data.

Regression owners: `src/ui/nativeSyncPermissions.test.ts` (viewer/downgrade and
policy-write negatives), `syncSheetMenus.test.ts` (direct command and stale menu),
`documentAccess.test.ts`, `historyAccess.test.ts`, plus existing server
sharing/trash/copy tests. Production plays cover Dashboard keyboard menu/focus,
busy Rename, Space menus/destination guards and Admin disable/passkey states.
Existing e2e selectors, including the native desktop harness, are updated to the
visible labels; they retain their original journeys, no retries or weaker match.
All source/shared dependencies remain in the current file-based CI plan.
