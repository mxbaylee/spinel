# SPN-102 — Complete standalone Doc PDFs

## Implementation scope

2026-10-26, in progress. Extend `@spinel/print` from SPN-101 with a bounded,
standalone Doc renderer. The original SPN-102 acceptance remains authoritative:
stored and fallback page geometry, paragraphs/rich styles, nested lists, explicit
breaks, native tables/merged cells, authorized images and complete prepared
Formula tables must survive pagination. Unsupported content fails without bytes.

No application route, UI, authorization resolver, Formula evaluation or Pro
removal is included. SPN-075 retains production integration, final access
revalidation, process isolation/admission and revocation requirements.

## Prepared-content boundary

Status: accepted implementation direction, 2026-10-26, agent judgment under the
owner's request to implement SPN-102 in a PR. Keep the existing public package,
native Canvas backend, public open-source Univer model/layout APIs and licensed
font preparation. Reuse its resource/error/cleanup contract across formats.
Adding a separate renderer would duplicate those boundaries and weaken the
evidence from SPN-101.

The host supplies owned, authorized input values and image/font bytes. The
renderer does not acquire source permissions, evaluate expressions, fetch URLs,
or include supplied identities in metadata. Unavailable Formula content uses a
neutral placeholder for the whole value. Preparation and layout are separate
bounded stages so native page limits cannot conceal truncated content.

Owner and Collaborator need all late paragraphs, table rows and images preserved
or an explicit failure. Link guest receives only already-authorized values and
neutral unavailable content; no source identity is added. Operator gets the same
bounded, isolated native lifecycle and no new service or dependency. Production
capacity and revocation guarantees remain SPN-075 responsibilities.

## Verification plan and checkpoint

The draft PR is opened before implementation is complete. Retain the ticket and
its dependency until every acceptance requirement is either verified or remains
an explicit blocking gap. Use synthetic fixtures; reopen every generated PDF,
render and inspect every page, and retain the PDF/PNG evidence in CI. Check late
content, borders, wrapping, fonts, images, light paper and absence of watermarks.

Required negative cases cover malformed/unsupported content, snapshot/layout/
projection/image/font/page/output/time budgets, cancellation, zero returned
partial bytes and successful cleanup/recovery. Independent review must assess
the original ticket, complete committed diff, all four personas and actual
evidence. No runtime validation or completed acceptance is claimed at this
initial checkpoint.
