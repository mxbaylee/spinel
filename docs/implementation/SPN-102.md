# SPN-102 — Complete standalone Doc PDFs

## Implementation scope

2026-10-26, implementation candidate. Extend `@spinel/print` from SPN-101 with a bounded,
standalone Doc renderer. The original SPN-102 acceptance remains authoritative:
stored and fallback page geometry, paragraphs/rich styles, nested lists, explicit
breaks, native tables/merged cells, authorized images and complete prepared
Formula tables must survive pagination. Unsupported content fails without bytes.

No application route, UI, authorization resolver, Formula evaluation or Pro
removal is included. SPN-075 retains production integration, final access
revalidation, process isolation/admission and revocation requirements.

## Prepared-content boundary

Status: accepted implementation direction, 2026-10-26, agent judgment under the
owner's request to implement SPN-102 in a PR. Keep the existing public package,
native Canvas backend, public open-source Univer model/layout APIs and licensed
font preparation. Reuse its resource/error/cleanup contract across formats.
Adding a separate renderer would duplicate those boundaries and weaken the
evidence from SPN-101.

The host supplies owned, authorized input values and image/font bytes. The
renderer does not acquire source permissions, evaluate expressions, fetch URLs,
or include supplied identities in metadata. Unavailable Formula content uses a
neutral placeholder for the whole value. Preparation and layout are separate
bounded stages so native page limits cannot conceal truncated content.

Owner and Collaborator need all late paragraphs, table rows and images preserved
or an explicit failure. Link guest receives only already-authorized values and
neutral unavailable content; no source identity is added. Operator gets the same
bounded, isolated native lifecycle and no new service or dependency. Production
capacity and revocation guarantees remain SPN-075 responsibilities.

## Verification plan and checkpoint

The draft PR is opened before implementation is complete. Retain the ticket and

Required negative cases cover malformed/unsupported content, snapshot/layout/

initial checkpoint.

## Native layout and physical continuation

Status: accepted implementation decision, 2026-10-26, agent judgment. Public
native traditional table layout can clamp a row to its page height. Increasing
the page height without a bound would only move that problem. The renderer uses
finite virtual native pages at the stored width/margins, with content height
limited by the physical page budget. It verifies source glyph coverage, admitted
font coverage, actual drawn ink and saved row-height preservation before output.

Physical pages use contiguous source slices. Ordinary lines/rows/merged regions
and paragraph keep rules stay together when they fit; taller content continues
at identical source coordinates. Explicit breaks still separate native pages;
cached soft break tokens remain soft. Layout and repeated paint work share the
existing finite work budget. Deadline checks cover incremental native layout,
paint and final cleanup, while hard native interruption remains a host duty.

This retains the public native shaper and painter rather than implementing a
second text engine. The tradeoff is an explicit finite print policy for modern
Docs and rejection of models this policy cannot yet preserve: differing section
frames, parity breaks, repeated headers and the other supported-model gaps in
the package README. Those failures remain SPN-075 acceptance gaps, not hidden
omissions. Owner/Collaborator gain complete long content; Link guests receive
only prepared values; Operator gets bounded work and the shared native lock.

## Exact stored page dimensions

Status: accepted implementation decision, 2026-10-26, agent judgment. The pinned
Canvas PDF backend quantizes its page canvas to integer points. Doc pages use
ceiling dimensions plus the corresponding vertical origin correction, then a
validated standard incremental update replaces only native Page dictionaries'
MediaBox values. Original streams and offsets remain unchanged. The helper only
accepts this backend's ordinary xref/trailer shape, validates every page and
rejects unexpected structure. It is not a general PDF reader or dependency patch.

This preserves fractional stored sizes and exact A4 fallback. Owner,
Collaborator and Link guest keep the intended physical geometry; Operator gains
no new dependency or network surface. Tests reopen actual native fractional
output and verify both the frame and drawn pixels.

## First executable checkpoint

The first guarded focused run passes 26 tests across preparation, native Doc
rendering, PDF geometry and standalone-package isolation. It reopens/rasterizes
20 PDFs / 54 pages, including the 30-row table at a page bottom, every numbered
paragraph, tall ordinary/merged cells and all three image bands. The workload's
observed peak process-tree RSS was 649.2 MiB; this synthetic run is not evidence
of production capacity. Additional break/keep/row-cap assertions and independent
every-page review are in progress. The PR remains draft; the ticket, dependency
and completion counter are intentionally unchanged until acceptance is complete.

## Review repairs and explicit supported-model gaps

The first print-package regression passed 125 tests across 15 files, including
existing Sheet output. Source review and actual PDF inspection prompted these
repairs without relaxing any check:

- Accept a native family list only when every entry is the same admitted face;
  the public shaper can repeat that alias while combining Latin/East Asian hints.
- Materialize modern paragraph defaults and named character/paragraph styles
  before finite geometry and Formula projection. Formula block breaks and fitting
  keep groups follow the result, not only the trailing source paragraph.
- Validate saved minimum/exact row heights before native layout and again against
  complete native fragments. A short string cannot conceal a clipped tall row.
- Account for repeated native painting across physical slices and check deadlines
  throughout that work. Doc and Sheet calls use the same operation lock.
- Keep measured outer horizontal border ink with its row across a physical seam. Native
  line ink stays together, while empty trailing font padding can end a page; this
  avoids orphaning a table border or moving the preceding paragraph unnecessarily.
  Internal shared borders and long vertical borders retain exact contiguous source
  continuation; protecting every shared edge would join all rows into one group.
  A raster check
  rejects a stray table border on the prefix-only page of the keep-lines fixture.
- Admit supported rectangular crop/opacity/flip models, and reject unsupported
  anchors, shapes and custom drawing effects instead of flattening them.
- Reject nested Formula array/table results explicitly. Their source cell may
  auto-fit or span multiple grid cells; duplicating native sizing before layout
  would risk clipped output. Scalar/unavailable results inside cells remain valid;
  ordinary native nested tables retain their own admitted geometry.

These decisions preserve Owner/Collaborator content, keep Link guest output
limited to prepared values with neutral failures, and retain Operator limits and
the public package boundary. They introduce no network resolver, native patch,
new dependency or application behavior. Whole-document headers/footers/notes,
unprepared plugin/custom appearance, heterogeneous sections and the other gaps
listed in the README still fail explicitly and remain SPN-075 acceptance work.

### Empty wrapped-image anchors

Status: accepted supported-model limit, 2026-10-26, agent judgment under the
ticket's explicit unsupported-content rule. Every-page inspection found that a
top-and-bottom wrapped image with an otherwise empty anchor paragraph retained
all pixels but reserved its height twice, adding blank pages. Further probes
found that non-leading and multiple-block anchors also misflowed, and line-relative
caption anchors drifted.
Invisible characters did not repair native layout; a synthetic visible caption,
soft break or different wrap policy would change the saved document. A multipass
anchor-rewriting engine would add a separate flow policy with uncertain fidelity.

Top-and-bottom wrapping therefore requires a leading, paragraph-relative image
anchor followed by authored caption text in the same paragraph; other forms fail
without bytes. The positive fixture retains an authored caption, complete tall
image bands and following text. Owner/Collaborator receive an explicit failure instead of misleading page
layout; guests get no source details in the error; Operator avoids an unbounded
relayout mechanism. This remains an explicit SPN-075 acceptance gap. The public
native table viewport is also checked, so a nested table cannot silently clip a
blank colored column or its borders merely because its text fits.

A related public native probe found that square wrapping whose image and horizontal
wrap distances block an entire column can repeatedly shift preceding content,
adding blank pages. The renderer checks the actual native containing-column width,
including nested cells, and rejects that model without bytes. Narrow square
wrapping remains covered by a complete tall-image fixture. Regression cases cover
empty/invisible, line-relative, non-leading, multiple-block and full-column anchors,
then successful rendering in the same process verifies cleanup and recovery.

## Candidate verification and handoff

The final source review also covers thick saved table borders: their native
outer-border inset changes row positions, so measured strokes are associated
with the actual first/last row edges. The regression uses 12 px source strokes
(9 pt in the PDF), verifies no orphan ink on the preceding page and retains both
complete strokes with every marker exactly once. The unchanged 30-row Formula
and short keep-lines fixtures pass under the original work budget.

The candidate includes standalone-package isolation, shared Sheet/Doc cleanup,
privacy and resource failures, and every-page PDF/PNG evidence. Final regression
totals, the independent rubric and reviewed commit, finding dispositions and
current-head CI results are recorded in [PR #182](https://github.com/mxbaylee/spinel/pull/182).
CI retains the synthetic `doc-pdf-evidence` artifact for seven days. These fixtures
do not establish production capacity or complete SPN-075 acceptance.

This PR prepares SPN-102's ticket retirement and releases SPN-075's dependency.
SPN-075 continues to own the documented model gaps, server authorization and
Formula preparation, bounded process isolation, access revalidation/revocation,
direct account/guest downloads, UI acceptance and Pro removal.
