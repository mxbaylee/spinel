# SPN-096: legacy decision migration

## Migration decision and boundaries

Date: 2026-10-23. Status: repository migration prepared; independent review and
merge are pending. External backlinks are pending until after the verified merge.
The owner requested local records on 2026-10-22 and explicitly authorized
post-merge issue comments on 2026-10-23; see the
[grooming record](grooming-dependency-registration-2026-10-23.md#link-migrated-decisions-from-their-original-issues).
The migration agent chose one canonical entry per source decision, extending
existing ticket records and using named cross-ticket records only for shared policy.

Moving concise rationale and provenance into the repository makes decisions
reviewable beside their implementation. Keeping only GitHub discussions would
leave future work reconstructing chronology; copying full discussions would bury
the decision in a second transcript. Original issues remain intact. Accepted means
a choice was recorded, not that the feature shipped, its checks passed, the owner
approved it, or a historical temporary permission can be reused.

Operator benefits from preserved resource, credential and recovery boundaries and
an auditable retry manifest. Owner retains their exact choices, pending questions
and approval limits. Collaborator retains data integrity, current grants and
private personal organization. Link guest retains anonymous, revocable scope;
migration grants no content, account, history or export capability.

The canonical entries preserve the source question/options, concise outcome and
rationale, source-time persona tradeoffs, authority, status and supersession.
“Recorded” uses issue opening time; it never invents an approval date. Explicit
body/chat dates and comment order are retained. The connector returned null
comment timestamps, so no timestamps have been inferred from numeric comment IDs.
All 12 source comments fetched at inventory time are linked from their entries.
Existing implementation verification/history sections were retained.
