# SPN-043 — fixed save-status presentation

The approved design ([#126](SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits)) is implemented for both native editors in account,
shared-file, anonymous-link and Space routes. The title has one fixed 144 × 44 px
save slot. `SaveStatus` portals the control into that slot and leaves its full
polite live announcement with the editor-owned controller. Saved persists;
errors and Retry stay in a viewport-bounded Base UI popover. Phone titles use a
full row. Existing save, access, connection and pending-navigation semantics
remain authoritative. No new dependency or broad header migration is included.

[Decision #148](SPN-043.md#legacy-decision-148-stable-title-adjacent-save-confirmation) records placement
and lifetime tradeoffs across Operator, Owner, Collaborator and Link guest.
Operators gain no document access; Owners/Collaborators retain clear save and
recovery feedback; guests receive the same scoped control without account UI.
SPN-049 will compose the wider header; SPN-053 adds offline editing states.

## Legacy decision 148: Stable title-adjacent save confirmation

**Recorded:** 2026-10-22. **Status:** accepted; historical pause superseded by resumed run.
**Authority:** Agent UI implementation under approved design; owner run instruction distinct.
**Source:** [original decision #148](https://github.com/mxbaylee/spinel/issues/148).

**Question:** How should SPN-043 place the shared save control beside existing titles without taking
over SPN-049's header migration?

**Options considered in the original source:**

A — lift save controllers/state into all parent shells, expanding lifetime and access coupling; B —
pass the title slot's DOM element into each native editor and portal one shared presentation there,
leaving its controller and polite full-message announcement with the editor; C — migrate all editor
chrome now, overlapping SPN-049.

**Outcome, rationale and current boundary:**

Keep editor-specific save controllers and portal their truthful state into the fixed 144 by 44 px
title-adjacent slot. Expose details and Retry only for actual unsaved failures, not a clean
historical error; preserve native pending-state semantics and exact Sheet/Doc geometry. Guests get
the same feedback without account destinations or identity. Source evidence and independent review
live beside the implementation notes. The owner's request to pause after SPN-043 was a historical
run instruction, later superseded by the explicit resumed backlog request, not a permanent backlog
rule.

**Persona tradeoffs recorded at the time:**

Owner and Collaborator need a persistent save confirmation and reachable Retry without moving their
Doc or Sheet; Link guest needs the same truthful feedback without account destinations or identity;
Operator gains no content access or new service dependency. All retain the existing pending-edit and
access safeguards.
