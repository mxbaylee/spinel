## Legacy decision 25: Reproducible limits experiment

**Recorded:** 2026-10-18. **Status:** superseded by cancellation.
**Authority:** Agent experiment-method judgment.
**Source:** [original decision #25](https://github.com/mxbaylee/spinel/issues/25).

**Question:** How should SPN-010 preserve reproducible evidence without shipping its permissive
experiment server?

**Options considered in the original source:**

A — preserve a separate, never-merge harness branch and per-run source/config/lockfile copies; land
only reviewed findings/ticket updates. B — add the harness to the product, increasing accidental
exposure and maintenance risk. C — discard scripts after observations, losing reproducibility.

**Outcome, rationale and current boundary:**

Keep the permissive loopback-only experiment server on a never-merge harness branch, with frozen
source/config/lockfile provenance. Short 2/3/4/6-identity matrices, six active units and 168
submissions could establish only those tested bounds; visible watermarks remained. The required
two-person Sheet/Doc 25-hour run needed continuous evidence and a post-duration edit; failures,
clock jumps and long gaps invalidated it. The method repair was not a duration pass. Decision
[#76](SPN-010.md#legacy-decision-76-cancel-the-duration-soak) later cancels the soak and retires
SPN-010; no experimental authorization is imported into production.

**Persona tradeoffs recorded at the time:**

Operator needs a disposable loopback-only server with no cloud cost or production credentials. Owner
needs honest limits and retained-document evidence. Collaborator needs distinct identities,
overlapping edits and clear failure UI. Link guest needs this permissive test authorization kept out
of production.

## Legacy decision 76: Cancel the duration soak

**Recorded:** 2026-10-18. **Status:** superseded proposal; cancellation accepted.
**Authority:** Owner domain clarification; later agent-recorded retirement.
**Source:** [original decision #76](https://github.com/mxbaylee/spinel/issues/76).

**Question:** Once `https://spinel.baylee.dev` is deployed, which stable browser runner and
uninterrupted window will drive SPN-010's required 25-hour verification against it?

**Options considered in the original source:**

A — provide an existing separate computer/runner with a stable 25-hour window; B — reserve a 25-hour
local window with other development workloads stopped and the memory watchdog active, accepting that
a guard abort requires another fresh run; C — explicitly revise the duration acceptance criterion if
the owner no longer wants this evidence. A paid disposable host is another option only after
explicit spending approval; none is provisioned here.

**Outcome, rationale and current boundary:**

The initial proposal sought a bounded runner for a future uninterrupted 25-hour experiment and did
not prove that duration. The final source comment records cancellation of the soak and retires SPN-010; it is not an
outstanding deployment/runner prerequisite. Keep the short-matrix observations and failures within
their measured limits, and preserve the independently chosen spinel.baylee.dev launch domain without
treating experiment cancellation as public-launch authorization.

**Persona tradeoffs recorded at the time:**

Operator needs bounded memory use and a reproducible, recoverable test host. Owner needs honest
evidence about normal two-person editing without stalling their computer. Collaborator needs
long-session convergence and recovery evidence. Link guest benefits from not mistaking an incomplete
experiment for a universal capacity claim.
