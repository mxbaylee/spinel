# SPN-085 — History browser presentation

## History selection and restore disclosure

Date: 2026-10-23. Status: accepted as an implementation choice; execution and
visual acceptance remain pending. Decider: agent judgment under the owner's
delegated all-persona decision rule, applying the approved SPN-047 History and
HistoryCalendar compositions and existing SPN-023/025/026 behavior.

The isolated browser places its checkpoint chooser beside the native preview on
desktop. At narrower widths the chooser becomes a disclosure, initially closed;
the selected checkpoint's UTC date, time, name and Before restore label remain
visible above the preview. Today retains the touch/keyboard slider and every
checkpoint row. Older days retains the UTC calendar and complete per-day selector
as well as the rows. The preview is still the native read-only viewer, without a
collaboration client or autosave. This does not sample or shorten retained history.

The approved naming controls use the existing account API. Name current version
explicitly describes the latest confirmed saved content; it does not claim to
capture unsaved work in another tab. Existing checkpoint names can be changed or
removed. The latter restores ordinary retention eligibility; no retention policy
is changed. Naming failures retain the entered text for retry.

Restore uses the shared semantic history modal instead of the browser confirm
dialog. Its title identifies the exact selected UTC checkpoint, and its text
explains the Before restore checkpoint and refresh required in other editors.
Selection/refresh are locked while the confirmation is open or restore is
pending. Cancel leaves both selection and live content unchanged. The existing
generation and per-attempt request ID are submitted unchanged; retries retain
their attempt ID. An interrupted attempt requires reloading the preview instead
of silently starting another restore. The header's portaled action disappears
immediately when the selected checkpoint changes, including while the next
authorized snapshot is pending. Abort signals and disposal guards prevent late
preview, naming or restore responses from updating a departed view.

Alternative: retaining the inline chooser and browser confirmation would preserve
behavior but fail the approved compact hierarchy. Replacing the native preview or
changing checkpoint capture/generation behavior would add unrelated scope.

- Owner: all retained recovery choices remain reachable, and restore confirmation
  identifies the selected checkpoint and current-content recovery copy.
- Collaborator: Viewer can inspect but cannot name or restore; account Editor,
  File admin and Owner retain existing authority. Server authorization remains
  decisive on every request, including late permission changes.
- Link guest: unchanged, excluded from all history routes and account controls.
- Operator: no content authority, new service, retention rule, storage format,
  export permission or background workload is introduced.

For a native Space child, both return links and all requests retain the exact
Space root plus child ID. History is not a snapshot of the Space tree. Existing
image URLs and formula evaluation continue through current authorized services.
