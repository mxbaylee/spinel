# SPN-101: standalone Sheet PDF rendering

Status: in progress. The ticket remains open; the preflight source checkpoint is
not a usable renderer or evidence of fulfilled export acceptance.

## Bounded geometry before native work

2026-10-23 — accepted implementation direction, agent judgment under the owner's
delegation of decisions with all-persona concurrence. Follow the public native
renderer recommendation in [SPN-097](SPN-097.md), but do not turn its small fixture
into a claim of production completeness or memory safety.

Inspect bounded plain snapshot data, worksheet selection, axes, cell/merge
geometry and final image/font requirements before PDF allocation. Return bytes
only after every page and final output limit succeeds. Never return partial
success. The standalone package accepts prepared image bytes; references are
opaque keys and never URLs to fetch. Native cell-image caches have URL fallback,
so they cannot be used without a strictly byte-only adapter or explicit compositor.
Final process-wide memory/time enforcement and source authorization remain in
SPN-075. Limits here may be lowered by callers, not raised past package ceilings.

Owner and Collaborator get complete output or an explicit failure, never an
apparently successful truncated document. Link guests get exactly the prepared
input with no additional source discovery; access revocation remains the host's
responsibility. Operator gets bounded admission and a small independently
testable package, with hard isolation honestly kept outside synchronous JS.

Current preflight does not complete text overflow, filtered rows, images, font
coverage or rendering. Its conservative cell/grid limits are admission policy,
not measured supported capacity. Blank visible sheets receive one blank page;
nonempty cells and explicit cell styles/merges determine the initial occupied
rectangle, with row/column styles applied within that rectangle. Final text/image
bounds may expand it. This avoids adding blank grid solely from a viewport size.

## Tiled worksheet backgrounds have a finite export extent

2026-10-23 — accepted design, agent judgment with parent concurrence; rendered
verification remains pending. Public `IWorksheetBackgroundImage` is a repeating
background, normally excluded by native printing. SPN-101 explicitly includes
it, so the renderer must add it rather than inherit that omission.

Use the configured finite worksheet rectangle, with hidden axes collapsed, for
a worksheet with a background, including a background-only worksheet. Keep the
native origin and tile phase throughout all page slices. The alternative of
clipping to other occupied cells would lose a background-only worksheet; one
tile's bounds would invent a native image extent. The finite configured rectangle
is intentional content here, not surplus grid from a render viewport. Reject
before output when that rectangle exceeds grid/page/image limits.

Owner and Collaborator retain the visible background and its relationship to
cells. Link guests receive the same authorized prepared extent without image
fetches. Operator receives explicit bounded failures for oversized configured
grids rather than unbounded tiling. All four prefer a clear failure to hidden
omission. Tests must include background-only and mixed content, hidden axes,
tiny positive scales and cross-page phase before this behavior is considered
implemented.

## Unresolved production evidence

The public PDF backend rounded requested A4 `595.276 × 841.89 pt` to `595 × 842 pt`
in SPN-097. No new precision tolerance has been adopted in this checkpoint.
The final renderer needs a documented backend choice and actual MediaBox/margin
tests. It must not silently claim exact unrounded geometry.

Existing licensed assets include only Atkinson Hyperlegible Bold for the social
card and Noto Color Emoji for artwork. They do not demonstrate regular, italic,
bold, Unicode fallback or PDF embedding. Prefer a small deterministic licensed
set, with explicit supported fallback and missing-glyph handling; prepared font
bytes can preserve package boundaries but still require validation and proof.

Source tests have been authored, not run. No local install, formatter, typecheck,
test, build, browser or render was attempted because parent reports elevated
memory pressure. CI, every-page PDF/PNG inspection, resource measurements,
dependency/Docker wiring and independent review remain outstanding. No landing
bookkeeping or completion claim has been made.

An additional source checkpoint adds image admission with the already-used
`sharp` runtime: byte signatures restrict decoding to PNG/JPEG/WebP, metadata
must be static and dimensioned, aggregate encoded bytes and decoded pixels are
bounded, and required bytes are copied before asynchronous work. References are
never passed as decoder paths or fetched. This is header admission, not complete
image validation or rendering; full decoding and actual fixtures remain required.
Tests for metadata, aggregate exact limits, mutation during asynchronous work,
missing bytes, malformed input and cancellation are authored and unrun.

## Explicit prepared fonts and public worksheet services

2026-10-23 — accepted implementation direction, agent judgment with parent
concurrence; native rendering/embedding proof remains pending. A font input names
its exact family/aliases, weight, italic state, licensed bytes and provenance;
fallback order is explicit. The alternative of relying on host fonts can change
metrics, pagination and missing-glyph behavior between CI and a server. Reject
unsupported static-font tables, embedding restrictions, undeclared families or
styles and missing grapheme coverage before native layout. Do not fetch font
references or silently synthesize a different family. A bounded SFNT cmap reader
checks glyph coverage; it is not a shaper and does not prove correct native
embedding or complex-script rendering.

Owner and Collaborator get repeatable layout and a clear failure for unsupported
text. Link guests get the same prepared representation without external font
requests. Operator avoids machine-specific system-font dependencies, retains
licensed provenance and receives font-byte/count limits. The tradeoff is that
the host must provide a deliberately supported font set; these checks are not
permission to reject common workbooks and call SPN-101 complete.

Tests use unmodified Atkinson Hyperlegible regular/bold/italic/bold-italic and
Noto Sans Symbols 2 from the existing pinned Google Fonts revision. Licenses and
source provenance are retained in the package; this 1.4 MiB fixture set is not an
automatic production font replacement. Static assets were retrieved; no fonts
were rendered or tests executed locally.

`PrintWorksheet` uses public numeric-format and filter models because the probe's
bare `Worksheet` omits editor interceptors. It preserves raw cell values,
composes inherited styles, produces numeric display strings and honors the saved
native filter cache/recomputation behavior. Filter ranges and criteria are bounded
before native scans. Native worksheet construction fills defaults in place, so
the adapter owns a clone. Raw merged-cell index area is bounded independently of
visible grid area because hidden cells still cost native merge-index memory.
These adapters and tests are unverified source; they are not connected to a PDF
output path yet.

## Three bounded source repairs before renderer integration

2026-10-23 — author self-assessment, not an independent review or completion
grade. A later source pass identified three concrete defects and the parent
authorized only these repairs while full implementation remains paused:

- Admission now charges sparse array holes to the aggregate node and byte
  budgets and rejects excessive logical length before enumerating entries. A
  sparse resource array must not reach a consumer that loops over billions of
  positions simply because it has no enumerable elements. Authored regressions
  cover a maximal sparse length, aggregate sparse arrays, and small exact node
  and conservative byte boundaries without allocating array contents.
- Admission inspects all own keys and descriptors. Non-enumerable accessors
  are rejected without invocation; non-enumerable data and symbol properties
  are rejected rather than silently lost during native cloning. The intrinsic
  array length is the explicit exception. Authored regressions cover the actual
  row-data geometry read, hidden data and symbol accessors. This plain-data check
  is not a sandbox for arbitrary JavaScript proxies; the host owns input
  preparation and process isolation.
- The worksheet adapter now formats numeric strings explicitly marked with
  the native NUMBER cell type, as the public native number-format interceptor
  does. Currency/date display and raw values have authored regressions;
  ordinary and forced strings remain literal. Non-finite, blank or malformed
  formatted numeric strings fail with a generic error rather than being
  coerced to a successful zero/invalid display.

These fixes preserve Owner and Collaborator formatting without changing saved
cell values. Link guests retain the same prepared-input boundary and generic
errors without private content. Operator gets bounded sparse-input admission
and no accessor invocation through hidden properties. No new renderer, image
geometry, font registration, export route or wider acceptance claim was added.

The parent formatted the twelve existing package TypeScript files using cached
pinned Prettier in a tool isolate; that completed formatting is not runtime
validation. The repair source and regression tests still require final formatting
and CI. No local install, typecheck, test, build, browser or render was run. The
ticket remains open and unpublished, with no PDF renderer or landing bookkeeping.
