## Complete native Sheet slices and prepared-content boundaries

**Date/status:** 2026-10-25, accepted implementation decisions; final acceptance is
bound to the reviewed commit in PR #177. **Authority:** implementing agents, under the owner's instruction to
complete SPN-101 next, publish WIP commits and use CI for testing.

**Question/context:** The published draft had a working small plain-text fixture
but explicitly rejected rich/rotated/multiline text, cell images and page-spanning
cells/merges. Its earlier CI also identified type/lint defects and an exact
floating-point-sum assertion. Current main now contains the independent library
test partitions and the completed SPN-049 editor work.

**Options:** retain the narrow candidate; implement another text/image renderer;
or keep native public rendering while measuring complete native layout and actual
ink, using a byte-only image compositor and exact contiguous PDF clips.
**Outcome/reason:** choose the native route. It preserves native number formats,
rich runs, alignment and rotation without duplicating shaping. Public cache-query
bounds expand outward so native integer rounding cannot omit a fractional row
tail; output clips remain exact. Full native cell/merge layout is reused across
pages, with all-or-error admission when the model itself clips text. Actual text,
border and transformed-image extents update the final used range and budgets.

Prepared static images retain native anchors, crops, rotation/flips, cell-image
alignment and continuous page phase. EXIF orientation is normalized only after
aggregate header admission; source keys are never fetched. A standard image cell
is composed separately and removed only from the owned native text clone, avoiding
the SDK's asynchronous URL cache. Background phase stays at worksheet zero over
its deliberately finite configured extent.

An independent source reviewer identified malformed merge semantics and missing
formula-result risks. Admission now rejects whole-axis/overlapping merges; visible
formula cells require a prepared cached value (`null` is an intentionally blank
result). Nonempty unknown plugin resources fail explicitly rather than silently
dropping appearance such as conditional formatting. Unsupported drawing/rich
models are listed in the package README. These errors retain SPN-075's complete
export contract; production preparation must support them or preserve a clear
failure, never silently strip their visible content.

The independent boundary review also requires a shared displayed-text budget
across native filter preparation and rendering. It counts formatted values even
when a filter later hides them, without charging repeated cell reads twice. The
owned worksheet identity is its validated workbook key; the ledger stores that
key once per worksheet, so long input IDs cannot amplify every cell key.
Generated rich tab leaders fail explicitly because their repeated glyphs are not
part of the prepared text/font contract. Native highlight rectangles contribute
to measured ink, including highlighted trailing spaces. Cleanup attempts each
owned resource independently; a `cleanup` error takes precedence over an earlier
render failure and tells the host to discard that process. The final return checks
the signal and deadline after cleanup, and reported duration includes it. A
deterministic cancellation during font cleanup proves that even completed bytes
are discarded when the operation has been cancelled before publication.

Reopened PDF evidence caught an italic-only face substitution that visual review
alone missed: the prepared Italic font was absent from the embedded resources.
The pinned [Canvas font parser](https://github.com/Brooooooklyn/canvas/blob/adce718ec8ff82f9e896875752fd621c46b1c04e/src/font.rs)
can interpret native `italic normal` shorthand as a normal style.
Each already-admitted face now gets its own native family alias, so backend font
style matching cannot substitute a sibling face. Native style flags remain intact.
The regression requires the named regular, bold, italic, bold-italic and Unicode
fallback fonts, distinct selected text resources and actual page inspection.

**Personas:** Owner and Collaborator receive complete visible content or a clear
failure, including late text/images and every continuation slice. Link guest gets
only supplied scoped bytes, with no identity, credentials, new source access or
private input in errors. Operator retains one native package, bounded admission,
generic errors and process cleanup, with hard termination and aggregate RSS
admission explicitly left to SPN-075. None receives a new production download UI
or a claim that small fixtures establish safe capacity on the 2 GB host.

## Image coordinate precision repair

2026-10-23, source repair after independent review of `4f78991`. A finite but
unbounded absolute coordinate such as `1e20` absorbed a positive image width when
added in JavaScript, making it look like an intentional zero-area drawing. The
planner could therefore return a blank page without requiring the image bytes.

Coordinates and their resulting edges now stay within the existing maximum axis
domain: 50,000 rows times 100,000 layout pixels, plus one 100,000-pixel offset.
In addition, adding a positive image dimension or marker offset must produce a
strictly greater finite coordinate. Precision loss fails with the generic invalid
layout error before zero-area omission; genuinely zero-sized drawings still omit
normally. This also protects ordinary-sized coordinates with subnormal positive
dimensions, rather than fixing only the reported enormous-coordinate example.

This is a correctness repair to the existing all-or-error geometry contract, not
a new export mode. Owner and Collaborator avoid silent missing images; Link guest
retains scoped prepared bytes and errors without source details; Operator gets a
