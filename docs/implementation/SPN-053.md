## One durable queue and conservative reconnect

**Date/status:** 2026-10-26, accepted implementation direction.
**Authority:** Agent judgment implementing the owner's SPN-053 request and its
existing app-owned-outbox decision.

**Question/context:** How should downloaded editors survive termination without
forking the native sync queue or replaying edits into a changed document?

**Options:** maintain a separate offline mutation log; persist the existing
native client checkpoint; or store a replacement snapshot and overwrite the
server. Persist the native client checkpoint. It retains the confirmed snapshot,
ordered optimistic groups and original immutable retry identity. The server
remains the durable revision authority; a whole-snapshot overwrite is excluded.

**Outcome:** Store checkpoint and scoped download metadata atomically in the
account's IndexedDB database. Reconstruct the same native editor before capture
starts. Local-save claims follow transaction completion, and synced claims follow
server acknowledgement plus committed local cleanup. A changed base, generation
or access retains the queue for SPN-054 and reports Needs attention. Refresh and
removal must never erase pending work. Bind remote reads and socket ticket
acquisition to the downloading account and the current local cancellation epoch.

**Personas:** The Owner and Collaborator retain edits across offline restarts
within their original document permissions. The Operator gains no document
access and no additional service. Link guests keep their existing live access
boundary and receive no offline store or outbox.
