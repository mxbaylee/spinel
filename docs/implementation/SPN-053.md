# SPN-053 — durable offline editing

## Delivered scope and preserved boundaries

Downloaded native Sheets and Docs use the same editor and the same native sync
queue online and offline. The queue survives repeated offline reopening and is
replayed only into its unchanged original live base. Owner/editor grants can edit;
viewer downloads remain read-only. Prepared Space children retain their exact
root/child destination. Guests and Operator accounts gain no offline queue.

The existing save slot reports **Saving on this device**, **Saved on this device**,
**Synced** or **Needs attention**. A local-save failure keeps the navigation
warning and retry action. Connectivity remains a separate control.

Conflict-copy creation/export (SPN-054), storage-management/persistence UI
(SPN-055), physical-phone verification (SPN-090) and offline creation (SPN-051)
remain separate. This implementation does not claim those outcomes. The
maintained [offline contract](../offline.md) retains their requirements.

## One durable queue and conservative reconnect

**Date/status:** 2026-10-26, accepted implementation direction.
**Authority:** Agent judgment implementing the owner's SPN-053 request and its
existing app-owned-outbox decision.

**Question/context:** How should downloaded editors survive termination without
forking the native sync queue or replaying edits into a changed document?

**Options:** maintain a separate offline mutation log; persist the existing
native client checkpoint; or store a replacement snapshot and overwrite the
server. Persist the native client checkpoint. It retains the confirmed snapshot,
ordered optimistic groups and original immutable retry identity. The server
remains the durable revision authority; a whole-snapshot overwrite is excluded.

**Outcome:** Store checkpoint and scoped download metadata atomically in the
account's IndexedDB database. Reconstruct the same native editor before capture
starts. Local-save claims follow transaction completion, and synced claims follow
server acknowledgement plus committed local cleanup. A changed base, generation
or access retains the queue for SPN-054 and reports Needs attention. Refresh and
removal must never erase pending work. Bind remote reads and socket ticket
acquisition to the downloading account and the current local cancellation epoch.

The wrapper stores account/item/Space/unit/generation identity once. The native
checkpoint stores confirmed snapshot/revision, exact immutable `sent` envelope,
transformed inflight mutations and ordered buffered groups. Array order provides
the original design's sequence; the native mutation `id`/`params` retain authored
commands; `sent.mutationId` supplies a durable delivery identity before first send.
Unsent groups are not assigned a second log identity. See the mapping in
[How offline editing works](../offline.md#how-offline-editing-works).

First replay additionally carries an admission-only `expectedRevision`. The
server checks it after asynchronous preparation and before receipt lookup or
commit, so a peer write between resume and send cannot be silently merged.
The guard does not change the retry hash. A crash after server acceptance but
before local cleanup may leave an already-applied envelope in the checkpoint;
an advanced base then retains it for attention rather than replaying it again.

**Personas:** The Owner and Collaborator retain edits across offline restarts
within their original document permissions. The Operator gains no document
access and no additional service. Link guests keep their existing live access
boundary and receive no offline store or outbox.

## Preserve visible recovery without a server snapshot overwrite

**Date/status:** 2026-10-27, accepted implementation repair.
**Authority:** Agent judgment following independent review of the SPN-053 data
preservation requirement.

**Question/evidence:** A supported native command can apply visibly before the
sync queue rejects its transport size. Saving only the prior queue would lose
that visible edit after restart while claiming it was retained. A 70 KiB native
Sheet value and Doc insertion reproduce this boundary.

**Options/outcome:** Retain a bounded canonical `recoverySnapshot` with the
failure checkpoint instead of silently losing the edit or uploading a replacement
snapshot. On reopening, validate before native allocation, create the visible unit
from recovery, and skip queue replay over that already-complete visible state.
The confirmed replica still uses the original checkpoint snapshot. Recovery is
never transmitted. A failed capture records `recoveryMissing`; even a committed
failure marker then retains the keep-this-tab-open warning. Retrying can recover
the still-open original renderer, but cannot pretend a missing renderer survived
restart. Incoming-frame failures retain the coherent pre-frame checkpoint rather
than partially applied remote state.

**Personas:** Owner and Collaborator keep recoverable visible edits and receive
an explicit warning when that cannot be guaranteed. Operator keeps the existing
native byte/geometry limits and gains no document access or new service. Link
guest behavior is unaffected.

## One writer, safe removal and clean-cache refresh

**Date/status:** 2026-10-27, accepted implementation choice and review repairs.
**Authority:** Agent judgment implementing pending-edit protection.

**Question/evidence:** Two tabs must not overwrite one item's durable queue.
Removing a copy while an editor has uncommitted cell input is unsafe even if its
stored queue is clean. Conversely, removing the final download must not be
treated as account sign-out and destroy unrelated in-memory live queues.

**Options/outcome:** Use the browser's per-account/item Web Lock for a single
writer, acquired before reading the authoritative checkpoint. Other tabs and
browsers without Web Locks open downloaded copies read-only. Removal must obtain
the same lock; the person closes writable copies in every tab first. The IndexedDB
transaction then refuses pending/failure work. Final removal clears only the
prepared marker; real sign-out still changes the cancellation nonce and fences
all old sessions. No cross-tab queue arbitration or background writer is added.
An online-account marker distinguishes reopening the same account with no
downloads from a genuine account switch; ordinary live queues survive the former.
Authentication captures the cancellation fence before reading session headers
and JSON, so a delayed earlier account cannot reclaim a newer account's device.
The session-loading effect also cancels obsolete attempts, including the first
development StrictMode pass, before they can claim data, clear preparation or
reload the current sign-in screen.
An account catalog Web Lock also serializes download insertion with the final
empty-catalog check, so another tab's newly prepared item cannot lose its marker.

A clean download may outlive the server's replay-retention window. Intercept
that stale response before it becomes a retained failure: check unfinished host
cell input, IME and image insertion, freeze native input, drain persistence,
recheck cleanliness, download the fresh authorized bundle and reload. Pending
work never enters this path. Incoming transport count/bytes are bounded before
asynchronous image loading, and disconnect aborts that work.

Verified 403/404 clean access loss follows the same freeze/drain/recheck sequence before
scoped removal under the item's writer ownership. Clean role or generation
changes fetch a fresh authorized copy. An expected-account mismatch never
authorizes either action; queued, recovery or unfinished host work remains
retained. A failed clean refresh or removal reports attention without inventing
a recovery checkpoint for a document that had no local edits.

A verified 401 instead ends remote replay and cancels preparation for the entire
account without deleting downloaded records or queues. The mounted editor freezes
input and attempts a bounded local save before going to sign-in. If storage fails,
times out or host input remains, that frozen tab stays open for local recovery and
retry. Its narrow exception cannot make HTTP requests, prepare downloads or survive
a later sign-out/account switch. Repeated 401s in the same expired account epoch
do not invalidate this held recovery tab; a successful new account claim resets
expiry handling. Local saving/failure takes display priority over Needs attention,
so an unsaved recovery state never claims that its latest visible work is retained.
The expired recovery lifetime is installed before the first drain await, so a
second tab's matching expiry cannot interrupt the held local write. HTTP admission
closes immediately, including delayed response bodies and image hashes.

An unfinished Sheet draft has an additional native boundary: `SheetEditEnded`
means the editor hid, while a cross-sheet formula can commit after asynchronous
sheet activation. After expiry, cancel confirmation through `BeforeSheetEditEnd`
and retain the draft for copying instead of guessing when to freeze permissions.
The save notice explicitly asks the person to copy the unfinished text; Escape
remains an intentional discard. Existing committed device edits remain intact.
An explicit expired-sign-in flag exposes the handoff in Save details after host
input finishes, including when the retained queue is already durable. The action
rechecks persistence and host input before navigating without falsifying `dirty`.
Cold-offline shells react only to actual cancellation or account removal/change
events after mounting. Unrelated preference writes or same-account preparation
must not reapply their old startup fence and unmount that held recovery editor;
initial asynchronous reads still require a current account before publication.

The Space shell distinguishes a saved device queue from unfinished input. A tree
refresh that removes the selected child keeps its mounted editor while it holds
device work, allowing access revalidation to retain the queue and show Needs
attention. That retention does not block deliberate navigation after local save;
clean documents and guest revocation keep their existing removal behavior.

**Personas:** Owner and Collaborator trade concurrent offline writers and
in-editor removal for protection against silent loss. Normal live collaboration
remains available; unrelated live editors survive download removal. Operator
gets bounded queues and one storage authority without another coordination
service. Link guests remain outside the offline lifecycle.

## Images, Formula privacy and account scope

**Date/status:** 2026-10-27, accepted implementation choice.
**Authority:** Agent judgment preserving the existing image and Formula contracts.

**Question/options:** Local renderers require object URLs, while sync hashes,
native mutations and durable storage require canonical image sources. Recursively
rewriting every URL-looking string would corrupt cell text and opaque metadata.

**Outcome:** A shared schema-aware native image walker visits actual drawing,
background, rich-text and known drawing-resource fields, including mutation
payloads. It preserves ordinary text and opaque resource bytes. Verified object
URLs are reversed before hashing/storage/wire; image bytes and checkpoint share
one IndexedDB transaction. Existing images survive reload and native movement or
resize. The OSS Sheet `IMAGE()` derived-result command is cancelled while offline
because its renderer loads URLs directly; no native command is re-registered.

Doc Formula definitions remain authored data. Results never enter the checkpoint.
The editor clears them on connection loss, shows unavailable offline and checks
current source access after reconnect. Dialog suggestions, resolution and previews
use the same account/epoch-bound transport, including delayed JSON-body checks.
An unfinished Formula expression/format stays in its dialog across connection
changes; previews clear and the draft blocks automatic clean-cache replacement.
Expected-account headers are checked before server document access/404 handling,
so switching the cookie account cannot erase or replay the prior account's work.
Socket tickets and callbacks retain exact root/child, account and epoch checks.
Failed initialization disposes any native unit that has no capture binding and
releases its device writer instead of leaving an editable but unsaved canvas.

**Personas:** Owner and Collaborator keep existing imagery and Formula definitions
without exposing live source values offline or across accounts. Operator gains no
content access; existing image/storage budgets remain. Link guests gain no offline
store, token persistence or unscoped request fallback.
