## Access contract

- A trusted ingress selects exactly one current credential family: everyday
  account session, root guest session, or MCP credential. Mixed, incomplete or
  mismatched credentials fail closed. Space document work carries both the exact
  root and stable child, and checks the current live generation where applicable.
- Existing `customData` carriers retain this context through preparation, native
  reads/writes, materialization and every asynchronous integration. A narrow
  shared resolver rechecks current credentials, owner, role, membership and live
  ancestry. Ordinary `WorkspaceStore.get()` remains closed to Space rows.
- View/Edit root guests cover every current and future child. Edit manages the
  current tree and content; guests get no outer account destinations, identities,
  history, recovery collection, child sharing or native-file export. Existing
  native Print policy is preserved; no new PDF/export format is added.
- A root link's privacy epoch fences every child admission and room, including
  previously issued tickets. Rotation/revocation/downgrade drains affected work
  and removes affected sessions without disturbing unrelated documents.
- Formula hosts and every source keep independent current authorization. Root
  guests may use only same-Space sources. Account/MCP callers may use external
  sources only through their own access. Syntax, stable bindings, formatting and
  unavailable results remain the existing Formula implementation.

## Ordinary file and recovery integration

A Space is one outer file. A separate outer-file union and metadata-only facade
compose ordinary files with valid Space roots. Native document types and the
Doc/Sheet/folder internal child whitelist stay narrow. Account listings/search,
tags and personal filing may expose the root, never its internal pages.

Only the Owner administers the outer root; account View/Edit remains uniform
through readable outer-folder grants. Personal filing must survive unrelated
ordinary operations and must not mutate canonical ownership or location.
Creation and canonical moves use My files or an owned ordinary folder; creation
inside another person's shared folder remains SPN-069.

Whole-Space Trash changes the root and preserves earlier internal deletion
batches. A containing outer folder must stop at each Space root rather than
stamping its children with an ordinary deletion batch. Recovery groups containing
Space data remain without automatic expiry. Explicit permanent deletion requires
an exact, complete bounded graph confirmation; internal recovery stays account-only.

Operational acceptance must run the actual BackupService with an injected object
storage transport, restore its encrypted archive, compare preserved SQL state,
reopen fresh native services and execute SPN-064's ownership handover on restored
Space data. Prove IDs, content, sibling order, Formula bindings, images, checkpoints,
live generations and earlier internal Trash survive. Keep this evidence distinct
from any remote-host recovery drill.
