## Legacy decision 16: Private deployment startup guard

**Recorded:** 2026-10-17. **Status:** accepted, historical deployment design.
**Authority:** Agent deployment judgment.
**Source:** [original decision #16](https://github.com/mxbaylee/spinel/issues/16).

**Question:** How should Compose enforce the private network and encrypted-storage requirements?

**Options considered in the original source:**

A — native Tailscale, host-network Compose, Caddy bound to the exact tailnet IP, non-root
containers, immutable image digests and systemd running TypeScript preflight before every start. B —
a container-managed tailnet and ordinary Docker restart policies, which add networking state and can
bypass mount checks during daemon restart.

**Outcome, rationale and current boundary:**

Use native Tailscale, host-network Compose, exact tailnet-IP Caddy binding, non-root containers,
immutable image digests and systemd preflight before every start. Verify the active LUKS mount,
canonical data paths, tailnet identity and private environment. Docker restart policies stay off so
daemon restarts cannot bypass preflight; operator unlock follows reboot. Formatting an identified
empty device remains manual. This choice itself authorizes no resource purchase, provisioning,
destructive disk operation or deployment. Public launch is separately gated by decision
[#40](SPN-038.md#legacy-decision-40-public-launch-timing) and current SPN-038/SPN-063.

**Persona tradeoffs recorded at the time:**

Operator needs auditable deployment and bounded memory on a small host. Owner needs persistent
encrypted data through restart. Collaborator needs a stable private HTTPS origin for passkeys and
future reconnects. Link guest must never gain public network access just because a link exists.

## Legacy decision 17: Retired private-host acceptance evidence

**Recorded:** 2026-10-17. **Status:** accepted, historical evidence only.
**Authority:** Owner evidence and explicit IPv6 scope revision.
**Source:** [original decision #17](https://github.com/mxbaylee/spinel/issues/17).

**Question:** Can the owner complete the fresh-droplet acceptance checks for SPN-029?

**Options considered in the original source:**

Continue waiting for an unavailable external IPv6 vantage point, or accept the owner's explicit
omission while retaining firewall closure and the completed bounded IPv4/private-host evidence. The
owner chose the latter for this retired test deployment only.

**Outcome, rationale and current boundary:**

The 2026-10-17 disposable tailnet host passed recorded setup, encrypted restart/unlock, private TLS
1.3, image update, preserved users/passkeys and two-editor checks. The owner removed external IPv6
scanning from this acceptance because no vantage point existed; no IPv6 pass is claimed. Initial
public TCP22 exposure was corrected and a full IPv4 TCP scan then reported all ports filtered. UDP
open-or-filtered could not prove filtering; provider firewall UI/API was not independently
inspected. The host was subsequently retired. This evidence and narrow historical waiver do not
authorize a new host, public deployment or broader verification waiver.

**Persona tradeoffs recorded at the time:**

Operator verifies private access and recovery; Owner verifies preserved documents; Collaborator
needs stable editing across updates; Link guest must retain access isolation.
