# 💬 SPN-089 — consistent dialog titles

## 🧭 Required title cues

**2026-11-04 — accepted, agent judgment under the owner's request for a verified
SPN-089 PR, all-dialog screenshots or a Storybook preview, and a common modal
requiring an emoji.** This completes the title-icon audit requested on 2026-10-21
in [the approved redesign](SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits).

Use the existing `Modal`; require exactly one explicit semantic `icon` or literal
`emoji`, alongside the textual `title`. Remove the implicit `info` default. The
existing entity and Lucide icons remain useful, while emoji render as Unicode text.
Do not introduce a second modal framework, an arbitrary React-node icon API, or a
new emoji parser. `ModalTitleContent` supplies the same fixed-size decorative cue
and title text to the standard modal and the native title owners.

The cue is hidden from assistive technology. The real heading/title primitive
continues to name the dialog; it never announces the emoji or icon twice. Long
titles wrap, and the close control retains its own space. The shared icon/emoji
contract is enforced by normal TypeScript checking of every consumer.

The alternatives were an optional fallback (which hid missing selections), an
emoji-only migration (which unnecessarily replaces established entity/semantic
icons), and replacing every native dialog lifecycle (which risks editor focus
and pending-operation behavior). The explicit icon-or-emoji contract is the
smallest complete change.

Owner and Collaborator gain recognizable file, editor and recovery actions.
Operator receives the same treatment in account, maintenance and backup dialogs.
Link guests retain scoped editor/dialog access and unchanged permissions. Every
persona keeps textual accessible names, keyboard dismissal and focus restoration.

## 📦 Scope checkpoint

The verified audit found 41 production calls to the shared modal and four other
app-owned entry points: formula Insert/Edit, the icon picker, Space contents, and
the native editor's Make a copy addon. Title and state variants remain part of
those families. Historical, unmounted redesign mocks are not product dialogs.

The original S estimate becomes **M** for the complete coordinated outcome:
required shared API, four title owners, missing production preview states, native
SDK verification and independent visual review. This is a finite audit and API
refinement, without a new component system or an editor/dialog lifecycle rewrite.

## 🪟 Native and browser boundaries

- Formula Insert/Edit uses the shared title with 🧮 and an explicit heading ID.
  Preserve its native `showModal()` lifecycle, cancellable pending save, and the
  synchronous close before restoring document focus.
- The native icon picker uses the shared `shapes` cue. Preserve nested Escape
  handling, keyboard navigation, selection and explicit parent focus return.
- Space contents uses the common title layout inside its existing Base UI drawer;
  remove its competing title-layout rules and retain its final-focus target.
- Native Make a copy supplies the shared title through the public Univer
  `IDialogService` title/`ICustomLabelProps.title: ReactNode` API. Retain the
  existing native desktop/mobile wrapper, busy handling and mobile naming fallback.
- Browser-owned `window.confirm` and `beforeunload` safeguards cannot receive an
  app-owned title cue. They remain unchanged. SDK-owned dialogs without a supported
  extension point, tooltips and nonmodal popovers are outside this audit. Native
  Make a copy is app-owned and is included, not excluded as SDK internals.
