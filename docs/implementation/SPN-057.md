## 1. Keep the new server isolated until integrated review

- **Date/status:** 2026-10-26, accepted implementation decision.
- **Question:** How can the server land without switching existing clients?
- **Context:** SPN-104 supplies the transform; SPN-058 supplies the new browser
  protocol and SPN-056 retains the independent integrated review. SPN-059 owns
  activation, retained-data conversion and Pro removal.
- **Options:** Replace the active transport immediately, or expose the new
  server only under an explicit disabled-by-default server flag.
- **Outcome:** Use `SPINEL_SYNC_SERVER=1` only for development/integration of the
  new protocol. Default behavior retains the current transport. Reject an
  attempted new-server open of an already prepared legacy unit and a legacy
  open of a unit owned by the new log. Backend ownership survives flag changes;
  disabling serving leaves purge available. Legacy documents in a mixed test
  database still restore through their own backend. Converting retained
  collaboration data belongs to SPN-059.
- **Personas:** Operators retain the current deployment path; Owners and
  Collaborators retain their accepted edits and history; Link guests keep
  exact document and Space scope, root privacy epochs and immediate revocation.
- **Source:** Agent implementation choice within the owner's staged landing
  direction, [staging record](sync-staged-landing-2026-10-25.md).

## 2. One durable authorization boundary

- **Date/status:** 2026-10-26, accepted implementation decision.
- **Question:** Where should final access checks and accepted edits commit?
- **Context:** Authorization can change while asynchronous materialization or
  transport work runs. The library must remain independent of application code.
- **Options:** A separate authorization check before storage, or a synchronous
  guard within the adapter's compare-and-swap transaction.
- **Outcome:** `lib/sync-server` owns ordering, exact-base transformation,
  bounded headless materialization and hashes. The SQLite adapter in
  `src/server/sync` owns durable receipts, revision rows and one current
  snapshot per unit. It invokes the application's final credential, ancestry,
  role, privacy and generation guard inside the same transaction as the
  revision write. Retries carry a stable actor/mutation identity and payload
  fingerprint.
- **Personas:** Operators get one recoverable database; Owners and Collaborators
  get durable acknowledgments and reconnect retries; Link guests cannot use
  revoked access or cross-document mutations.
- **Source:** Agent implementation choice preserving SPN-057's existing rules.

## 3. Bounded replay and native validation

- **Date/status:** 2026-10-26, accepted implementation decision.
- **Question:** How can an exact revision be reconstructed without retaining a
  native runtime or whole snapshot for every revision?
- **Context:** The transform validates absolute claims against exact base cells;
  row/column moves and removed sheets can change their coordinates. Native
  handlers also accept some malformed geometry that would allocate excessively
  or normalize an invalid worksheet identity before it could be rejected.
- **Options:** Full historical snapshots, guessed base cells, or sparse native
  before-images with a conservative retained window and explicit resync.
- **Outcome:** Retain changed-cell before-images with styles inline for at most
  128 revisions and 16 MiB of working data per unit. Reconstruct worksheet order
  from the accepted structural log and validate original and transformed
  positional metadata against the correct pre-step order. Keep one current
  snapshot; accepted mutations, receipts and hashes remain durable. Requests
  outside the window fail closed and resync.
- **Limits:** Eight cached units, 60-second idle eviction, 64 queued submissions,
  1,024 mutations per batch, 10 MiB request/candidate snapshots, 64-level nesting,
  bounded aggregate range work and worksheet dimensions, and 1,024 worksheets.
  Socket frames are limited to 64 KiB, with eight pending frames per connection,
  64 connections, 256 outstanding tickets and 16 MiB outbound buffering.
  These are conservative admission limits; rejected edits are never acknowledged
  as saved. The package README records the precise native geometry limits.
- **Expanded cells:** A separate 10 MiB cumulative budget per expanded snapshot,
  touched footprint, transform-base reader and touched-cell hash charges encoded
  address keys and resolved inline values before retention or cloning. A difference
  has separate old/new/footprint budgets, bounding their combined counted work to
  30 MiB while preserving small edits beside a large unchanged cell. Current and
  historical base reads share one reader budget. Compact shared styles and long
  worksheet IDs can otherwise multiply into gigabytes across a bounded cell range.
  An operation on a snapshot below 10 MiB can still be refused; this conservative
  admission tradeoff preserves bounded working memory and explicit resync while
  allowing ordinary long IDs. Streaming hashes preserve the existing canonical
  representation for admitted inputs.
- **Invariants:** No empty or entirely hidden workbook; consistent IDs, snapshot
  keys and order; unique case-insensitive names; valid native Doc body. Validate
  both requested worksheet identities and the actual serialized candidate.
  Scope Sheet geometry checks to native mutation paths; Doc Formula references,
  cell rich text and opaque metadata retain their own field meanings.
  Apply the exact transform output through headless OSS Univer, retaining
  triggers, claims, Formula metadata and opaque resources. Failed candidates
  are disposed before the next read or write.
- **Personas:** Operators get bounded active memory and deliberate backpressure;
  Owners and Collaborators get exact bases and explicit refusals rather than
  lost edits; Link guests cannot exploit geometry or cross-document references.
- **Source:** Agent implementation and independent review of PR #183, preserving
  SPN-104's replay and worksheet-identity contracts.

## 4. Metrics-only diagnostics and deterministic divergence recovery

- **Date/status:** 2026-10-26, accepted implementation; shape collection remains
  **needs-owner** under its existing separate proposal.
- **Question:** What can be observed without copying document data into logs?
- **Context:** Transform errors and native handler logs can contain sender text.
  Native serialization may add benign keys that a client has not yet added.
- **Options:** Capture arbitrary failures/shapes, or emit strictly validated
  counters, histograms and static-message logs with allowlisted labels.
- **Outcome:** Register and record the events from
  [SPN-032](SPN-032.md#sync-transform-refusals-and-drops), sanitize unknown IDs to
  `other`, and suppress native runtime logs before loading content. Observation
  failures cannot change delivery. Guests remain outside the collector. No
  [proposed diagnostic shapes](SPN-032.md#reproducing-a-refusal-without-document-content)
  are collected or approved by this implementation.
- **Outcome counts:** Publish dropped-edit and offset-write counts only after a
  durable commit. Refused or rolled-back attempts retain attempt, timing, growth
  and refusal telemetry without claiming a delivered loss or counting a retry twice.
- **Divergence:** Store a hash of each accepted revision's touched cells or Doc
  body, including same-value writes. Native-only defaults are normalized using
  the transform fuzz conventions; ordering is locale-independent. A pending-free
  client reports the latest applied revision/hash. A mismatch requests resync and
  emits `sync.divergence.detected`; the event contains no hash or cell values.
  SPN-058 owns pending-edit counts, UI status and the actual browser resync cost.
- **Personas:** Operators see rates and fixed reasons without content; Owners and
  Collaborators get detectable divergence and repair; Link guest document and
  identity privacy are preserved.
- **Source:** Existing owner metrics-only direction (2026-10-22/23), SPN-032's
  proposal, and independent PR #183 review. No new data-collection consent.

## Preserved rules and integration boundaries

- The existing [recovery database decision](SPN-012.md#legacy-decision-37-one-database-for-collaboration-recovery),
  [authenticated boundary](SPN-012.md#legacy-decision-43-authenticated-collaboration-boundary),
  [document-scoped tickets/audit](SPN-017.md#legacy-decision-49-document-bound-websocket-admission)
  and [integration boundary](integration-boundaries.md#legacy-decision-92-stable-integration-boundaries)
  remain evidence for the requirements. The library's storage interface preserves
  consistency without making SQLite a permanent product constraint; no second
  production adapter is added before the prelaunch database decision.
- Ordinary and Space paths use the same credential resolver at admission and
  final commit, including exact root/child, live ancestry, root privacy epochs,
  File admin semantics and content-blind Operators. Root link changes fence all
  child rooms. See [SPN-092](SPN-092.md) and [SPN-079](SPN-079.md).
- History initial capture, revision reconciliation, checkpoints, restore
  generations, permanent Before restore snapshots, retry receipts and the purge
  queue operate against the selected backend. Already admitted submissions drain
  before a restore switches generations; new admissions are refused.
- MCP expiry, scope, resource/connection identity, disconnect, account and grant
  revocation are checked at the same final write boundary. A new stale assistant
  write receives the established conflict response; a successful request remains
  retryable after OAuth refresh through its stable connection identity.
- The existing workspace and shared checks include the new package. Its manifest
  is copied before build-stage `npm ci`; the production stage receives complete
  workspace source and installed production dependencies. TypeScript only; no
  new Pro dependencies or changes to their internals.
- SPN-058 supplies the browser client/presence, retained SPN-056 independently
  reviews the integrated path, and SPN-059 owns activation/data conversion/Pro
  removal. No existing acceptance gap is deferred to those tickets.

## Verification and review disposition

Cover ordering and exact-base transforms; durable acknowledgement and failed
commit rollback; duplicate/restarted retries; malformed/unsupported/refused
batches; whole-workbook and size invariants; two real sockets; divergence and
metrics privacy; revoked credentials and Space scope; assistant exact-revision
writes; history, restore generation fencing and retryable purge. Reuse OSS
Univer handlers, retain Native Formula metadata, and keep eight loaded units
with idle eviction.

Focused core, SQLite and diagnostics tests run with the pinned Node runtime and
the shared serial runner plus process-tree monitoring. Wider local imports hit
the 2 GiB watchdog or a reduced JavaScript heap during startup; those attempts
are recorded as aborted and are not passes. Enabled service/history/MCP/transport
and the complete unchanged regression suites require hosted CI evidence.

The independent first pass found geometry/worksheet-position admission gaps,
incorrect structural metadata acceptance, native logging leakage, locale-sensitive
hash ordering, backend flag rollback/purge hazards, an unaudited socket viewer
refusal, and loss metrics emitted before durable commit. Each is repaired in this
PR with a regression. The review also corrected
history idle-timing and compatibility-status assertions, and required real
MCP/OAuth and altered-client-snapshot divergence evidence. Final dispositions,
score, reviewed SHA and all seven required gates are recorded in the PR after
verification; a provisional assessment is not approval.

Hosted integration then exposed a valid Doc Formula reference being mistaken
for Sheet geometry and older history test doubles still using SDK hooks. The
geometry admission now recognizes native Sheet paths, with a real Formula
regression and retained allocation controls; the history doubles implement the
application hooks while preserving their baseline, access and revocation assertions.

A fresh independent review identified cell-footprint and shared-style expansion:
a 30 KiB worksheet ID and compact number-format range could repeatedly allocate
that ID, while many sparse cells could inline one large shared style. Cumulative
budgets now reject those expansions before retaining keys or cloning values,
including lazy exact-base reads. Bounded regressions check each path, unchanged
canonical hashes and independent copies, plus a real submit's unchanged durable
head/receipt after refusal and successful subsequent edits.

The fresh review also found that internal ghosts of overwritten cell edits could
be counted again as clipped-shift offsets or removed-sheet losses. Ghosts now
retain their move-refusal role without emitting those delivered-outcome counts.
Regressions preserve transform outputs, both ghost arrival directions and the
existing moved-cell refusal while verifying that losses are reported only once.
