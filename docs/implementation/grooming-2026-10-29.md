## Feedback exports and useful metrics

SPN-098 retains its existing feedback mechanism and compact Admin flag action.
The approved extension offers **user metrics** and **all-system metrics for the
same timeframe**. Both use one immutable snapshot/cutoff and the same trusted
receipt-time interval covering the selected user's full retained span. This
slice adds no time-range query controls. User output includes retained frontend and
backend rows for that actor; system output also includes other actors and
unattributed process/system rows. No sampling or silent row truncation is allowed.
Both disclose retention, drops, gaps, schema, units and snapshot/window metadata.
Exports remain an Operator/Admin capability and recheck authority throughout
preparation/delivery. The [SPN-098 decision](SPN-098.md) defines empty data,
truncation, bounded pairing lifetime and cleanup. SPN-110 coordinates TTL with
that frozen view while keeping feedback durable.

SPN-123 fills concrete instrumentation gaps: distinguish local durable save from
server acknowledgement; observe open/search/restore, reconnect/resync and pending
age, flush reason/groups/failure, checkpoint outcomes, maintenance phases and
bounded CPU/event-loop observations. Its [inventory and limits](SPN-123.md)
preserve content-free fixed schemas, actor attribution where available, guest
exclusion and negligible observer effect. It does not promise a new dashboard,
data warehouse, raw input logging or a generalized tracing framework.

## Timely and resilient tests

SPN-115 owns applicability and cost: explicit suite inputs/dependency closure,
stable required aggregate names, recorded base/head/reason, conservative unknown
fallback, cheap metadata-only validation and full scheduled/manual coverage.
A required aggregate may succeed after proving that no relevant inputs changed;
a missing selected job, failed classifier or absent evidence cannot become a
pass. Native correctness stays covered when expensive paired historical
performance comparisons are inapplicable. Measure wall time, runner minutes,
first-attempt failures, time to useful diagnostics and coverage before/after.
This grooming does not change the current CI classifier or waive its gates.

SPN-120 owns reliable execution of the recorded cases: wait on actual readiness,
use a verified deterministic authentication fixture when login is not under test,
and retain a separate real authentication/access lane. At most one classified
idempotent setup/transport retry may fit inside the original total budget while
the server is healthy. Authentication mutations, denials, expiry, wrong identity,
server crashes and product assertions remain fatal. Preserve first-attempt
diagnostics and bounded ongoing process logs; server death should fail immediately.
This is a finite harness correction, not an unlimited retry or timeout increase.
