## Legacy decision 130: Literal bounded CSV import

**Recorded:** 2026-10-21. **Status:** accepted, post-launch implementation pending.
**Authority:** Agent grooming semantics, 2026-10-21.
**Source:** [original decision #130](https://github.com/mxbaylee/spinel/issues/130).

**Question:** Should the first CSV import preserve all fields literally, or infer formulas, dates,
numbers and headers automatically?

**Options considered in the original source:**

A — import UTF-8 comma-separated fields literally, preserving row/field order, empty values, quoted
commas/newlines, escaped quotes, leading zeros and the first row as data; B — automatically infer
numeric/date/formula/header meaning, risking irreversible reinterpretation and a broader validation
surface; C — add mapping, type and data-cleaning controls to the foundation, expanding scope.

**Outcome, rationale and current boundary:**

Import UTF-8 comma-separated fields literally, preserving BOM support, CRLF/LF, Unicode, row/field
order, empties, quoted commas/newlines, escaped quotes, leading zeros and the first row. Do not
infer dates/numbers/headers or execute formula-looking fields. Reuse bounded native validation,
creation access and cleanup; invalid/oversize or revoked creation leaves no partial document. This
chooses the narrow SPN-093 behavior after launch, not a delivered importer or owner preference for
future mapping controls. Guests gain no import capability.

**Persona tradeoffs recorded at the time:**

- Owner: literal imports preserve leading zeros, identifiers, quoted content, Unicode and the first row; automatic typing could save cleanup but can silently change data.
- Collaborator: predictable literal cells avoid formula execution and interpretation that differs from the source, while ordinary creation permissions still apply.
- Operator: bounded CSV parsing with no inference framework is easier to maintain; no remote fetching or additional conversion service is needed.
- Link guest: no import or broader document access is added. Preserving formula-looking text avoids introducing behavior into a document that a guest may later be allowed to view.
