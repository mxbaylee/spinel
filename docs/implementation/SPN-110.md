## ⏳ Receipt policy and bounded upkeep

Accepted agent implementation choice, 2026-11-21, preserving the owner's
seven-day maximum target: deployment can select 1–7 whole days, default seven;
invalid configuration fails startup. Use the existing one-minute health timer
and maintenance gate. Scan at most 1,024 candidates plus one lookahead using
only the existing receipt index. Retained feedback counts against that budget.
A process-local `(received_at, rowid)` cursor advances only on successful work;
completed sweeps, restart and truncate reset it. Backward-clock arrivals are
revisited on the next sweep, not silently skipped by a durable watermark.

Delete only observations strictly older than the trusted receipt cutoff, and
subtract their exact bytes in the same transaction. Enqueue captures receipt
time; delayed flush cannot renew lifetime. Invalid clocks fail without deletion.
Keep physical/write-reserve limits and retryable failure; no index allocation,
forced vacuum or scheduler is required before an already-full store can recover.
Expiry never changes the explicit truncate generation or prepared export files.
Maximum age is a target during healthy maintenance, not a completeness guarantee
or a claim about old exports/backups. Counters describe only this process.

Operator gains bounded upkeep and content-free failure status. Owner and
Collaborator retain deliberate reports and idempotent receipts while minimizing
operational data. Link guests gain no diagnostic authority. All personas retain
unchanged workspace history, trash, backups, recovery journal and access rules.
