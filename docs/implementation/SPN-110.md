# SPN-110 — diagnostic observation expiry

## Decision and capability checkpoint

2026-11-02 — implementation in progress on main `18a8759c`. The diagnostics
database already indexes trusted `received_at`, accounts each row's logical
bytes, and uses bounded SQLite snapshots separate from workspace storage. Its
existing health sampling timer provides the maintenance cadence. SPN-098's
candidate keeps explicit feedback in the same table under `name='feedback'`;
its paired exports are immutable files after preparation and already distinguish
feedback-only context from retained observations without claiming completeness.

Use the existing receipt-time index to delete at most 1,024 observation rows per
maintenance call, with exact byte subtraction in the same transaction. Exclude
feedback by name; a partial receipt-time index excludes feedback so selection
does not scan an accumulating feedback history. Index creation obeys the existing
main-file page limit. Do not change the generation, clear queued data indiscriminately,
invalidate existing export files, or touch workspace/recovery storage. Capture
server receipt time when enqueueing backend observations so delayed flush cannot
extend their lifetime. Expired queued observations are dropped at append.

The deployment policy defaults to seven days and may choose a shorter whole-day
period, from one through seven. Reject invalid policy at configuration time;
there is no disabled or indefinite mode and no Admin policy editor. This retains
the accepted seven-day maximum target without a general retention framework.
Use trusted wall time for the cutoff: backward changes preserve future-receipt
rows, forward changes make the bounded older selection eligible, invalid clocks
fail without mutation. Do not infer a lost historical clock trajectory.

Reuse the existing one-minute health maintenance callback and maintenance gate.
Expose the job as a static health row with the existing success/failure state.
The bounded call can report more expired rows remaining; a backlog is retried on
later ticks. Existing disk reserve/logical/physical/queue limits remain. Age is a
maximum retention target, not an assertion that cleanup completes during an outage
or that a full seven days of observations exists. Expired counters describe this
process only; exports and older archives can survive live expiry independently.

Operator gets bounded upkeep and visible retryable failure. Owner, Collaborator
and Link guest retain less operational data without changing document, history,
trash, backup, submitted-feedback or access retention. No external service or
automatic diagnostics archive is introduced.
