# SPN-045 — Profile and appearance navigation

## Implementation

Implementation effort is M: the original S estimate understated the coordinated
account routing, offline Space navigation, shared theme controls, retained drafts
and browser/visual verification. The account-screen scope remains unchanged.

`/profile` replaces Settings and `/settings` redirects there, retaining query and
section fragments. The offline shell handles old bookmarks too. Profile, Passkeys,
This device and Connected assistants use labeled section navigation; the advanced
personal token disclosure stays inside Connected assistants. Account operations
retain their existing API, OAuth consent return, passkey ceremony, cancellation,
connection last-used metadata, Disconnect and token reveal/revoke behavior.
Prepared Spaces open the same offline-capable profile, retaining the local Sign
out action that locks saved documents until the next online sign-in. Phone section
navigation wraps into two columns so every destination remains visible.

The existing theme store drives the same Base UI System/Light/Dark control in the
rail, compact profile and Space headers, and This device. A storage failure keeps
the in-session choice and displays a dismissible error. System still follows OS
changes. Profile icon/color/name remain saved account identity, and saving updates
the avatar immediately. The icon picker retains search/grid navigation; its title
and the color dialog follow the shared semantic title-icon pattern.
