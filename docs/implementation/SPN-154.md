### 🔎 First source boundary

The pinned open-source Univer 1.3.1 clipboard service uses its public
`onBeforePasteImage` hook for file and base64-HTML images. Without that hook it
embeds a base64 image. Spinel currently registers `IImageIoService` for toolbar
image insertion but no clipboard image hook. Its server deliberately admits only
stored, document-scoped image URLs. A rejected native submission can request a
resync and rebuild the editor. This is a concrete hypothesis, not a reproduced
failure or proof of the original phone incident. Distinguish native-editor
replacement from top-level browser navigation.

The inspected boundaries at this base are:

1. `DocClipboardController` sends the native paste to public
   `IDocClipboardService.legacyPaste`. The SDK's `onBeforePasteImage` hook owns
   both clipboard files and base64 images in pasted HTML. Neither current
   Spinel clipboard registration nor its toolbar upload adapter installs this
   hook. The installed open-source SDK and upstream 1.3.1 source were inspected;
   the upstream tag resolves to `c6178bb0aae5b6d13aaadedbb87639a332d3f5e4`.
2. `src/server/workspace/documents.ts` admits stored, document-scoped image URLs.
   `src/server/collaboration/service.ts` installs that validator on native sync.
   `lib/sync-server/src/server.ts` validates the candidate before committing it.
3. `src/server/sync/transport.ts` can turn a validation rejection, while access
   remains valid, into `resync: unavailable`. `web/spinelSync.ts` then either
   retains the prepared offline copy or requests `DocEditor` replacement. This
   trace does not establish that a particular browser actually took the path.

If native evidence confirms this boundary, assess the existing public clipboard
hook and stored-image adapter first. Do not relax server validation. A failed
upload must throw rather than return `null`: the SDK's HTML path otherwise keeps
the original base64 source. The busy lifetime also extends beyond upload through
image dimensions, conversion and native mutation; preserve selection/permission
generation checks and retire pending work on editor disposal. These are design
constraints for the future repair, not an implemented or accepted solution.
