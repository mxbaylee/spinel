## Legacy decision 21: Native Doc snapshots and embedded images

**Recorded:** 2026-10-17. **Status:** accepted.
**Authority:** Agent persistence and media judgment.
**Source:** [original decision #21](https://github.com/mxbaylee/spinel/issues/21).

**Question:** How should single-user documents and embedded images persist before collaboration?

**Options considered in the original source:**

A — reuse native snapshot/revision autosave and store bounded PNG/JPEG/WebP image blobs in SQLite
with document ownership checks; B — add separate object storage and a conversion format, increasing
deployment and migration work.

**Outcome, rationale and current boundary:**

Reuse native snapshot/revision/idempotent saves and authenticated document-scoped SQLite image
storage. Decode and validate PNG/JPEG/WebP; reject unsupported media/SVG, with 5 MiB per image and
50 MiB stored per document. Preserve image bytes for undo/retry and retained history until safe
document cleanup; never treat a public static URL or remote fetch as equivalent. A separate object
store/conversion format was unnecessary for this scope. Collaboration and export extend the same
complete native-resource contract explicitly.

**Persona tradeoffs recorded at the time:**

The Operator benefits from one encrypted SQLite store and bounded uploads; the Owner needs complete
rich text and images to reopen unchanged; the Collaborator needs revision conflicts to preserve
edits from separate tabs; the Link guest needs image access to remain isolated until sharing exists.
