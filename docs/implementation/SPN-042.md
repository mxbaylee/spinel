## Legacy decision 132: Verified connection proof and stable presentation

**Recorded:** 2026-10-21. **Status:** accepted.
**Authority:** Agent implementation decision, 2026-10-21; later scoped owner screenshot approval.
**Source:** [original decision #132](https://github.com/mxbaylee/spinel/issues/132).

**Question:** Which existing signals should establish the three connection states without implying
that edits are saved?

**Options considered in the original source:**

**A — Verify the surface that is actually in use.** Use the existing authenticated, no-store
`/api/health` endpoint for account screens without a live editor (one probe every three seconds,
two-second deadline, no overlapping requests). Live editors use public per-document session/room
state plus collaboration and browser events; returning online invalidates the previous room proof.
Reuse their existing bounded document-access checks to detect silent failures. Guest views use only
guest metadata and their own collaboration room. This adds small bounded polling and requires
explicit room-rejoin validation.

**B — Use only browser events or save/sync text.** Simpler wiring, but it can report Online while
Spinel is unreachable, or imply that an ordinary in-flight edit means the connection failed. It also
cannot prove a fresh room subscription.

**C — Add a new service or connection protocol.** Could centralize signals, but adds operational and
maintenance work that is unnecessary for this ticket.

**Outcome, rationale and current boundary:**

Separate reachability from Saved. Account screens use bounded authenticated health probes; live
editors require current public room proof and guest screens only their own metadata/room. Browser
recovery invalidates old proof and forces a fresh room lifecycle. A healthy retry or HTTP-only
interruption may retain continuously valid room proof; metadata removes a reachability veto but
never manufactures JOIN proof. Use the accessible Base UI Popover, not a visual-only tooltip.
Preserve editor geometry through connection/shared-list failures and keep a stale catalog timestamp
independent of a healthy room. The source records exact CI/Storybook evidence and later PR #133
screenshot approval; this routine signal decision alone supplied no merge authorization.

**Persona tradeoffs recorded at the time:**

- **Operator:** A reuses existing endpoints and public SDK APIs, adds no service or dependency, and keeps account probes out of guests. The bounded request cost is reasonable for Spinel's small instance; this is not an operational monitoring dashboard.
- **Owner:** A reports reachability truthfully and preserves the independent unsaved-edit warning and navigation guard. The local catalog's “Files as of” detail moves into the connection popover without automatically promoting a read-only local session to live editing.
- **Collaborator:** A waits for the actual document room to rejoin, preserving access/read-only checks and keeping normal pending edits Online.
- **Link guest:** A exposes only connection state for the shared document, preserves unfinished edits through transient failures, and retains authoritative link revocation. No identity, dashboard navigation, or account health/session request is added.
