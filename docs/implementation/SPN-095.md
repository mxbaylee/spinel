# SPN-095 — Space Trash retention

## Match the ordinary 30-day recovery window

**Accepted — owner, chat 2026-10-22.** At the time of this decision, Spaces and
internal deleted pages remained until manually purged, while ordinary Trash had
30 elapsed UTC days.
During grooming the owner chose the same 30-day recovery window for Space Trash
instead of keeping it manual-only. SPN-095 implements that shared deadline.

Owner gets predictable recovery dates; Collaborators keep their existing internal
recovery rights until expiry; Link guests still cannot browse recovery collections.
Operator gets bounded eventual cleanup without document names or contents.
Existing deletion batches, prior independent deletions and ownership handover
must retain their meaning. Review age of deliberately retained test data before
activation; do not extend timestamps or purge live content to simplify cleanup.

## Reuse the existing recovery and cleanup boundaries

**Accepted — agent judgment under the owner's standing delegation, 2026-10-27.**
Reuse the ordinary startup/daily cleanup job, the complete Space structure
validator, immediate database transactions, leaf-first cascades, and durable
collaboration purge queue. A second scheduler or a new retention state machine
would duplicate working mechanisms. All recovery paths use one elapsed-UTC
constant, including restoration through an enclosing ordinary folder.

The cleanup is a system storage operation, not an impersonated Owner request.
It validates current ownership and the exact outer deletion identity inside the
write transaction. Disabled owners retain the original deadline; disabling an
account neither grants recovery access nor extends retention. When Space
exposure is disabled, Space expiry is disabled too, and ordinary cleanup still
protects hidden Spaces and their containing subtrees.

Each sweep selects at most 256 root metadata rows through an indexed ordered
page, then validates at most 16 eligible graphs. Each Space transaction validates
at most 10,000 members and removes either the whole expired root or complete
independently expired internal batches. The sweep checks a one-second elapsed
budget between units of work; an individual transaction can exceed that budget.
Its in-memory cursor advances past live roots and failures, so malformed or
oversized trees cannot starve unrelated Spaces. Restart begins a fresh sweep.
A failed transaction remains intact and is retried when a later daily sweep
revisits it. Ordinary cleanup still runs when a Space is retained for repair.
Logs expose only counts or static status, never names, locations or arbitrary
exception text.

Collaboration cleanup runs at startup, each minute and during shutdown, processing
at most 100 ordered queued generations per pass. It checks the same one-second
elapsed budget between generations; an in-progress generation can take longer.
The cursor advances before a failure, allowing the next pass to reach unrelated
entries before wrapping back. It never removes a still-active generation or
acknowledges an unsuccessful deletion. Startup and minute failures leave the
application available with its durable retry queue; a failed shutdown attempt
also preserves remaining work for the next startup.

Operator health reports the Space job's real configured, running, last-attempt,
last-success and failure state. It is **Not configured** when Space exposure is
disabled. A successful bounded pass is evidence of that pass, not a claim that
the full retained backlog is empty.

Owner and Collaborator get the familiar recovery deadline and a disabled Restore
action after expiry. Only the Owner retains early permanent deletion. Link guests
gain no recovery collection. Operator gets bounded work and existing job status
without names, locations or content. Existing backup retention remains separate.

## Previously retained data and activation

The prior Space exemption is retired without rewriting any deletion timestamps
or batch IDs. Existing outer folders, Spaces and internal batches become eligible
at their original `trashed_at + 30 * 86400000`. Old rows already past that date
are immediately ineligible for restoration and eligible for bounded startup
cleanup. Older independent internal deletions remain older after an outer
restore, retrash, or ownership handover, and can expire while the outer Space
is still within its own recovery window. Legacy retained-batch markers do not
extend the deadline when Spaces are enabled. Backup retention remains separate;
restoring an archive preserves the recorded timestamps rather than renewing them.

This repository is pre-launch; this change does not deploy or activate an
instance. No deployed database is available in the implementation workspace.
Before starting the new server against deliberately retained or restored test
data, inventory a consistent database copy with these read-only count/date
queries. Substitute the intended activation time in UTC epoch milliseconds for
`:now`, and record that time with the aggregate results. Do not start the new app
against the copy before reviewing the inventory, because startup performs cleanup.
Preserve any needed recovery copy before activation; never reset deletion ages
or batch identities to manufacture a new recovery window. The inventory does not
validate malformed graphs or authorize content inspection through Operator UI.

```sql
PRAGMA query_only=ON;
BEGIN;

SELECT kind, COUNT(*) AS deleted_count, MIN(trashed_at) AS oldest_deletion,
       COALESCE(SUM(trashed_at <= :now - 2592000000), 0) AS expired_count
FROM workspace_items
WHERE space_id IS NULL AND trashed_at IS NOT NULL
GROUP BY kind;

SELECT COUNT(*) AS internal_batches, MIN(trashed_at) AS oldest_deletion,
       COALESCE(SUM(trashed_at <= :now - 2592000000), 0) AS expired_batches
FROM workspace_space_trash;

ROLLBACK;
```

Malformed ownership, membership, recovery metadata, cycles or oversized trees
are retained as complete transactions. Investigate them on a backed-up copy
through the existing structural checks; cleanup never guesses a repair or logs
their private metadata. Recovery and expiry tests cover pre-existing markers
and original timestamps. The PR records the executed checks and independent
reviews; this decision record alone does not claim those checks passed.
