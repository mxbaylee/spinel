## Covers and gem collection

The owner liked the soft, borderless Spinel heart whose facets extend across the

## Optional cover theme variants

**Accepted — owner, chat 2026-10-22.** A cover from any source may use one image
for both themes or optionally have separate light/dark images. The owner clarified
that two variants are optional, including for Gems; requiring every cover to have
a pair would add unnecessary work. Follow the active theme when a pair is present,
and otherwise retain the shared image without automatic darkening or changing the
selected cover. Keep the current shared-image Storybook drafts as that valid case;
SPN-086 must add paired-cover stories and verify both paths during refinement.

Owner can choose consistent or theme-specific artwork. Collaborators and Link
guests see the appropriate variant for their active theme without changing saved
identity or gaining appearance permissions. Operator asset bounds, cleanup and
access checks must cover both variants when present; a pair cannot bypass quotas.

## Site default and browser text selection

**Accepted — owner, chat 2026-10-22.** Spinel is the site-wide default accent and
browser text-selection color. A Space's chosen accent overrides `::selection`
inside that Space and stops applying when leaving. This means selected browser
text, explicitly not an authored formatting highlighter, saved Doc/Sheet fills,
or native editor selection overlays. Test selection foreground/background contrast
in both themes and keep global defaults separate from scoped Space overrides.

## Persona tradeoffs and implementation boundaries

Owner gains recognizable personal spaces; Collaborators and Link guests retain
readable identity and current access. Operator receives no document access and
needs bounded image storage/provider work. Appearance cannot change authority or
leak assets after access loss. Existing Storybook choices/uploads/search are local
fixtures, not persistence or live Unsplash. Decide the exact asset/write policies
using current identity permissions in the design playbook before implementation.

## Quiet photo attribution

**Superseded placement — owner, chat 2026-10-26; see refinement below.**
The owner liked the banner artwork and requested a less visible attribution or
removal of the Unsplash credit. The bundled sample's standard Unsplash License
does not require attribution, but the planned API integration requires credit
when displaying photos, including a link to the photographer's profile. Rather
than design a prototype that needs an intrusive credit added back later, move it
from the image overlay to a small muted line directly below the cover. Keep it
visible on phones and keyboard-accessible; no hover-only or collapsed credit.
Use separate photographer/Unsplash links with the required referral parameters.

Compared with dropping credit or hiding it behind an icon, this keeps the photo
unobstructed while retaining clear provenance. Owner gets quieter artwork;
Collaborator and Link guest can still identify the source without extra steps;
Operator gets no new provider calls or service. Final placement awaits owner
visual review. Source: [Unsplash attribution guidance](https://help.unsplash.com/en/articles/2511315-guideline-attribution),
checked 2026-10-26. This is a local fixture, not a claim of complete API compliance.


### Attribution overlay and stable cover modal refinement

**Accepted direction — owner, chat 2026-10-26.** Move credit back onto the photo
and remove the solid badge background. Keep the linked text visible, using a small
white treatment and subtle shadow; move it to the upper left on phones to avoid
the Change cover control. The owner asked about hover as an option, then explicitly
chose restoring the overlay without the background. Always-visible text preserves
touch/keyboard discoverability and the planned provider's attribution requirement.
The earlier below-cover implementation is superseded.

The owner also requested a consistent Page cover modal height across Gems,
Upload and Unsplash. Use a viewport-bounded fixed popup height, reserve preview
and crop-control slots, and scroll the source contents. Very short screens allow
the picker region to scroll so controls remain reachable. Selection/removal,
empty results and upload errors must not resize the popup.

Owner and Collaborator gain stable controls and unobstructed artwork; Link guest
retains visible provenance without needing edit authority; Operator is unaffected.
Sizing and fallback scrolling are agent implementation judgments for local owner
review. These changes do not affect production permissions or the graded gem art.

## Production identity, assets and provider boundary

**Accepted implementation — agent, 2026-10-26, under the owner's request to fully
implement SPN-086.** The owner also explicitly required icon choice at creation
and editing, a deterministic default when omitted, and no no-icon option.

Keep the existing filename hash as the default and store only explicit identity
choices. Use separate item-keyed appearance and asset tables, avoiding changes
to the validated Space item schema or native snapshots. This keeps personalization
independent of authored content, history and exports. Existing metadata authority
applies: outer owner/admin, Space-child editor, no ordinary guest/Operator writes.
A revision compare-and-swap prevents concurrent dialogs from silently overwriting
one another. Asset access rechecks the exact item and Space root after awaits.

Uploads are normalized private WebP blobs, 8 MiB/16 MP input, 4096 px output,
16 MiB per item and 100 MiB per current owner. Storage-reducing changes are allowed
when a transfer puts an account over quota. Transactional replacement, FK deletion
and owner-derived quota avoid orphan cleanup jobs and duplicate ownership state.
Trash/restore retain metadata and assets; full database backups include them.
Account offline bundles carry verified cover bytes; guests retain their existing
no-download boundary. Native exports intentionally omit decorative metadata.

Unsplash uses its supported server API with `UNSPLASH_ACCESS_KEY`, returned image
hotlinks, download tracking and photographer/provider links. Rehosting provider
photos as private uploads was rejected because it conflicts with the API's
hotlinking requirement. Selection metadata is private; provider photos are public.
Offline Unsplash uses an explicit connection-required placeholder, avoiding an
unapproved cache/proxy. Missing credentials and provider failures are visible
errors with usable Gem/Upload alternatives. Response bytes, request concurrency
and upload admission are bounded for the 2 GB deployment target.

Owner gains durable creation/editing choices and safe replacement. Collaborators
see consistent shared identity without new outer-file authority. Link guests see
only their exact current scope; Space editors keep their established child-edit
capability. Operator gains bounded storage/provider work without content access.
This accepts a configured provider dependency for search while retaining complete
local alternatives and truthful failure/offline states.

The production playbook is [Item appearance](../design/appearance.md). Earlier
prototype-only statements in this record describe the historical handoff; this
section supersedes them for the shipped implementation. Storybook is consolidated
to one interactive production-control playground and one paired-art gallery.

## Unified icon and emoji search

**Accepted — owner, chat 2026-10-26.** Documents use icons and emojis
interchangeably. Extend the existing weighted name/keyword/typo search with the
pinned Emojibase 17 English compact dataset, packaged locally with the app.
The same picker handles creation and editing, plus exact pasted emoji sequences;
Reset restores the name-hashed default. The data-only dependency avoids maintaining
an incomplete hand-written word list or adding a network service. Profile avatar
URLs retain their existing icon-only contract; item identity opts into emoji search.
Owner and Collaborator gain one discoverable choice, Link guests see the saved
identity, and Operator gains no external calls or credential requirements.

## Automatic gem themes

**Accepted — owner, chat 2026-10-26.** Gem covers expose only the gem name and
always switch artwork with the active light/dark theme. Only Upload and Unsplash
offer a shared image or separate light/dark images. Remove the unnecessary gem
mode override from the picker, shared type and accepted API payload. This keeps
Owner and Collaborator choices simple, gives Link guests the intended theme pair,
and adds no Operator storage or service requirement.

## CI provider verification

**Accepted — owner, chat 2026-10-26.** The owner supplied Actions variables
`UNSPLASH_ACCESS_KEY` and `UNSPLASH_SECRET_KEY` for integration verification;
deployment credentials can wait. CI passes only the access key to the Playwright
application server, after the frontend build. The public photo API uses Client-ID
authentication; no OAuth secret or credential enters a browser bundle. One
production-browser case exercises real search, selection/download tracking,
image loading and credit links when the variable is configured. Other provider
failure/host/metadata checks use deterministic fixtures without consuming API quota.
