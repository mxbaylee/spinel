## Bounded capability decision

**Accepted candidate for implementation, 2026-11-04; native result unproven.**

The current shared script explicitly imports all AppKit bridge symbols before
calling `NSRunningApplication`. Apple's [JXA release notes](https://developer.apple.com/library/archive/releasenotes/InterapplicationCommunication/RN-JavaScriptForAutomation/Articles/OSX10-10.html)
document default Foundation availability and that framework imports consult
bridge-support files. Apple's [Loading Bundles guide](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/LoadingCode/Tasks/LoadingBundles.html)
documents `NSBundle` loading executable code and Objective-C runtime symbols.
[`NSClassFromString`](<https://developer.apple.com/documentation/foundation/nsclassfromstring(_:)?language=objc>)
resolves a loaded class by name or returns nil.

Choose the narrow public candidate: retain an `NSBundle` for the fixed system
AppKit framework throughout the helper's lifetime, explicitly load its executable,
resolve `NSRunningApplication` by an explicit NSString name, and call the same
PID lookup and properties. Record separate bundle, load, class-resolution and
existing identity phases. Fail closed on a nil bundle, failed load, nil class or
thrown bridge operation. Keep all PID, liveness, Safari bundle, executable-path,
launch-time and reuse validation unchanged, plus `Application(pid)` and the
existing identify/title/evaluate/quit/baseline behavior and deadlines.

This still loads AppKit. It chooses a supported initialization route without
establishing which work consumed the measured interval or guaranteeing a faster
cold start. Reject a broader import fallback, prewarming, retries, extra deadline,
process-name approximations or termination of an unverified process. The existing
failure remains the first cause if diagnostics or cleanup also fail.

Operator gains bounded, attributable validation without weaker cleanup authority.
Owner and Collaborator retain genuine content and recovery proof; this harness
change adds no product behavior. Link guest keeps the existing access/revocation
coverage and gains no authority. A separate prerequisite keeps these obligations
visible while preserving SPN-137's accepted scope.
