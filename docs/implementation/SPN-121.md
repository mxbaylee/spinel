## Bounded native action-shape discriminator

The continuation declared one synthetic public-native API proof before execution:
24 and 32 inserts each, with minimal, empty-metadata, same-style and same-style
paragraph bodies. The [retained script, raw output, logs and manifest](evidence/SPN-121-composition-evidence.zip)
include exact installed source hashes and all eight cases. An initial sandbox
launch failed at watchdog process visibility before any case output; the actual
proof then completed under pinned Node 26.12.1 and the serial 2 GiB watchdog,
with a reported 250.5 MiB peak and no resource abort.

The public `ActionIterator` adds own undefined metadata keys when slicing a plain
insert. Those keys prevent `TextX.push`'s data-stream-only coalescing fast path:
two direct plain inserts combine into one action, but their sliced equivalents
remain two. All eight native cases retained growing redo action lists of 1 through
24 or 32; the corresponding final undo list had one action. Exact native bodies,
style metadata, paragraphs and Undo/Redo remained intact in the original code.

This establishes a concrete action-shape mechanism to investigate, not the cause
of either unprofiled browser pause. Real UI inserts carry text-style runs, so merely
removing undefined metadata keys is not a sufficient repair. Paragraph input here
uses the public insert command with a paragraph body, not a browser Enter event.
The raw `inputTextActionVisitsLowerBound` field is an operand action-count sum,
not measured visits, allocations or CPU time. No production patch, native policy
change or timing acceptance is claimed; a remedy still needs semantic review and
original browser acceptance.
