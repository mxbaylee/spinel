## Bounded native action-shape discriminator

The continuation declared one synthetic public-native API proof before execution:
24 and 32 inserts each, with minimal, empty-metadata, same-style and same-style
paragraph bodies. The [retained script, raw output, logs and manifest](evidence/SPN-121-composition-evidence.zip)
include exact installed source hashes and all eight cases. An initial sandbox
launch failed at watchdog process visibility before any case output; the actual
proof then completed under pinned Node 26.12.1 and the serial 2 GiB watchdog,
with a reported 250.5 MiB peak and no resource abort.

The public `ActionIterator` adds own undefined metadata keys when slicing a plain
insert. Those keys prevent `TextX.push`'s data-stream-only coalescing fast path:
two direct plain inserts combine into one action, but their sliced equivalents
remain two. All eight native cases retained growing redo action lists of 1 through
24 or 32; the corresponding final undo list had one action. Exact native bodies,
style metadata, paragraphs and Undo/Redo remained intact in the original code.

This establishes a concrete action-shape mechanism to investigate, not the cause
of either unprofiled browser pause. Real UI inserts carry text-style runs, so merely
removing undefined metadata keys is not a sufficient repair. Paragraph input here
uses the public insert command with a paragraph body, not a browser Enter event.
The raw `inputTextActionVisitsLowerBound` field is an operand action-count sum,
not measured visits, allocations or CPU time. No production patch, native policy
change or timing acceptance is claimed; a remedy still needs semantic review and
original browser acceptance.

## Mixed edits reject unrestricted reassociation

The first focused ES/CJS regression run passed 5 of 9 tests. Its original SDK
control failed an invalid assumption: a native inverse does not necessarily
reconstruct the handbuilt seed's exact text-run partition, and a native delete
can initialize an empty `customBlocks` array. The second run used independent
sequential inverse application and passed 7 of 9 tests, including actual
insertion-heavy Undo work reduction. Its original aggregate Undo still differed
from sequential Undo in where adjacent equal-style runs were partitioned.
Both failed test sources and complete logs are retained; neither is passing
mixed-operation evidence. No production code changed between those attempts.

Source inspection explains this reference boundary: `insertTextRuns` splits
and normalizes its runs, while `deleteTextRuns` retains its resulting list
directly. A sequential reference is useful for authored style semantics, but
exact run segmentation is not a universal inverse/composition invariant. The
candidate must still preserve the original native manager's complete results.

Before adjusting that oracle, a second finite observation collected all nine
existing scenarios in both ES/CJS formats: empty/noop/singleton states, an
insert between noops, five and eleven mixed operations, a divergent history
baseline, and each empty companion cache. It retained complete native inputs,
publications, all available applied snapshots and sequential references before
comparing them. It performed no style projection or metadata normalization and
never reported a test pass.

The [complete observation archive](evidence/SPN-121-mixed-composition-evidence.zip)
is 96,119 bytes, SHA-256
`38a8ae21cea2f214bda869db8260b1bb1eae547c1318218b7cc9d483ba456118`.
It includes the frozen unrestricted patch, collector, fixture, plan, every raw
V8 record, disposition and both launch records. The restricted launch failed
process monitoring before any case was recorded; no task process remained.
After adding fail-closed watchdog cleanup, the identical collector/fixture/plan
completed once outside that restriction in 0.764 seconds, with 121.21 MiB
observed peak RSS and no resource/monitor abort. The initial launch is failed
environment evidence, not a pass.

All 56 available full applied snapshots matched between candidate and original,
with no input mutations, errors or pending caches. However, 10 of 18 complete
publication comparisons differed. Independent raw inspection counted 120
missing-versus-own-undefined property differences in action-body `paragraphs`,
`customBlocks` and `customRanges`. No defined value, action order or outer
publication metadata differed. Iterator slicing and body composition assemble
these optional fields differently, and reassociation can change which assembly
occurs last. Their presence also matters to native action-shape/coalescing
decisions, so the exact-publication requirement is not waived merely because
the observed documents match.

**The unrestricted four-fold candidate is rejected.** The next candidate keeps
the demonstrated insertion benefit behind a conservative eligibility check and
uses the original reducer for every other complete fold. The earlier 63%/70%
figures characterize the unrestricted diagnostic's primitive work, not a
measured overall improvement for this revised production candidate.

## Temporary improvement and removal

**2026-10-29 — accepted candidate design, agent judgment under the standing
delegation, as a necessary prerequisite to the owner's SPN-118 merge request.**

The owner subsequently explicitly paused SPN-118 and directed work on SPN-121
instead. SPN-121 is now the active ticket; PR #213 stays draft and unmerged,
and this run does not resume its integration or landing.

The pinned OSS manager composes history redo, history undo, collaboration redo
and collaboration undo through four separate left folds. Native sliced inserts
retain their action entries, so the growing prefixes are traversed and cloned
again at every fold step. The source, passing profile and bounded experiment
support reducing that repeated work. They do not establish that this work
caused every historical outlier or that any algorithm can prevent arbitrary
browser scheduling pauses.

The revised candidate balances only qualifying single-character insert folds
in pinned public `@univerjs/docs` 1.1.0. This can be typing redo or the inverse
of a plain deletion sequence. Every delete fold keeps the original left fold:
in the diagnostic, balancing those folds saved only 184 recursive clone calls
and 80 clone allocations across the complete workload. Keeping them unchanged
retains almost all demonstrated insertion savings while narrowing the claim.

Eligibility covers one root-body `text-x` edit per state, one single-character
insert with an optional plain positional retain, and one consistent contiguous
position pattern across the fold. Ordinary character styling is retained.
All C0 controls and DEL, longer edits, attribute retains, replacements, other JSON/segment
paths, mixed action types, incompatible cursor positions, specialized or
nonempty structural/range metadata and unfamiliar shapes use the original
complete left fold. The guard only inspects; it never strips keys, rewrites
bodies, shares cache results, splits a history group or computes both versions
at runtime.

The pinned public keyboard path supports this eligibility boundary.
`DocInputController` builds an ordinary character body with `dataStream`,
`textRuns`, `customRanges` and `customDecorations`. For a collapsed selection,
`buildInsertTextActions` emits an optional plain retain followed by one insert,
wrapped by `JSONX.editOp` at the root `body` path; the manager caches those
applied actions. Empty range/decoration arrays and ordinary whole-character
styles qualify. Active annotations, inherited defined style IDs, replacements
and other segments retain the original fold. The original browser workload
contains 15 Enter events; any fold containing one also falls back in full.
Only the revised candidate's original browser acceptance can establish its
overall latency improvement.

The public `DataStreamTreeTokenType` enum places its structural tokens in the
C0 range. Tests cover all 33 excluded C0/DEL values with empty metadata arrays,
so a bare page/column break, custom-block marker or table delimiter also takes
the original composition path. These isolated-token cases compare complete
publications and primitive work; they do not pretend that an unpaired delimiter
is a valid complete document.

Redo order and reversed undo order remain the same. Each cache/direction makes
its own eligibility decision. Existing native metadata, publication, cache
reversal/clear order, timers and segment boundaries remain owned by the SDK.
The guarded ES/CJS installer validates the complete known upstream bytes,
rejects partial or unknown builds and validates both formats before writing
either. Apache-2.0 attribution is retained. No Pro package is inspected or
changed.

Alternatives considered were smaller groups, removing undefined metadata,
sharing mirrored-cache results, or balancing association. Smaller groups had
already failed to establish a repair and would change history policy. Removing
undefined keys does not solve browser-shaped styled inserts. Sharing cache
results would require alias and divergence assumptions. Balanced association
directly reduces the demonstrated repeated work while leaving those policies
and boundaries alone. The unrestricted variant failed exact representation
preservation, so the conservative insert fast path is paired with the unchanged
native fallback. Semantic/native regressions and original browser acceptance
remain necessary to establish that this narrower candidate is suitable to ship.

- **Owner:** retains exact document metadata, finite complete Undo/Redo and the
  original latency limits while the candidate reduces measured work.
- **Collaborator:** retains independent collaboration composition, exact peer
  convergence and selection/access boundaries; no mirrored-cache assumption is
  introduced.
- **Link guest:** gains no capability, and native read-only, revocation and IME
  fencing remain acceptance requirements.
- **Operator:** receives a small, fail-closed and attributable temporary patch
  with retained counterexamples and a removal owner. The cost is one additional
  guarded install step until supported upstream behavior can replace it.

[SPN-122](../todo/SPN-122.md) owns eventual stock-Docs adoption after launch,
coordinated with the separate core and Docs UI release checks in SPN-099 and
SPN-119. No upstream PR was submitted by this task and no claim is made about
uninspected later releases. Future work must inspect the actual released bytes,
preserve aligned package versions and all acceptance, then remove the guard,
postinstall step, patch-specific tests and notice. It cannot simply port the
temporary algorithm indefinitely or erase other independent guards.
