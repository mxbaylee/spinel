## Legacy decision 104: Remove unsupported Slides

**Recorded:** 2026-10-20. **Status:** accepted.
**Authority:** Owner explicit removal.
**Source:** [original decision #104](https://github.com/mxbaylee/spinel/issues/104).

**Question:** Can SPN-074 remove unsupported Slides before the redesign?

**Options considered in the original source:**

A — remove Slides entirely before redesign, including its type, schema choice, search filter and
placeholder, while retaining stories/screenshots/owner UI approval for the supported UI. B — keep an
unnecessary legacy path or delay removal until redesign.

**Outcome, rationale and current boundary:**

Remove Slides and its entry points rather than offering a document users cannot edit. Because Spinel
is pre-production, no hypothetical live-data migration or compatibility layer is required for
unsupported records. The screenshot waiver applied only to this removal, not future UI changes.
Existing Sheet/Doc access boundaries remain unchanged and no Pro dependency is added.

**Persona tradeoffs recorded at the time:**

Owner and Collaborator stop being offered documents they cannot edit. Operator avoids unsupported
code and unnecessary compatibility machinery. Link guests gain no access or unsupported editor.
