### Registered budgets

These targets are recorded before installing a production scheduling change.
Both measured builds use the same harness, lockfile, input and machine, with
snapshot cloning, screenshots and Playwright tracing disabled during timing.
Separate profile samples collect causal evidence and disclose profiler overhead.
The mobile preset uses coarse-pointer native controls and 4× browser CPU
throttling; it is emulation, not a physical phone or OS keyboard result.

| Measure | Desktop | Mobile preset, 4× CPU |
| --- | ---: | ---: |
| Keydown to next animation-frame opportunity, p95 | ≤100 ms | ≤200 ms |
| Longest observed browser task | ≤200 ms | ≤500 ms |
| Explicit paired native history/collaboration flush, p95 | ≤16 ms | ≤50 ms |
| Explicit paired native history/collaboration flush, maximum | ≤50 ms | ≤100 ms |
| Last key to both native queues drained | ≤1,000 ms | ≤1,000 ms |
| Improvement when matched baseline composition stalls exceed 1 second | ≥90% reduction | ≥90% reduction |

Frame timing is a presentation-opportunity proxy, not measured pixels. Report
actual key event count and inter-key gaps (including gaps above the SDK's 300 ms
idle debounce), total typing/drain time, all long tasks and blocking time, native
queue high-water counts, exact saved/peer content and selections, and heap/RSS
observations. Save status alone never proves native history is idle.

The relative comparison uses a deliberately conservative, task-to-task scalar.
For each reducer family, take the longest baseline task that certainly contains
a sampled `_pushHistory` or `_emitChangeState` frame after aligning the CPU
profile to a bracket on the browser clock. Compare that duration with the
candidate's longest **entire browser task** across all three plain samples and
the profile sample. When the baseline task exceeds one second, this upper bound
on candidate composition stalls must be at least 90% smaller. CPU sample totals
are supporting evidence, never the denominator for a longest-task comparison.
Missing baseline reducer attribution is unavailable and blocks a causal
conclusion. If a short candidate flush is not sampled, its native attribution
remains unavailable; the directly timed public paired flush and the entire-task
upper bound still conservatively cover both reducers. Long-task observations
censor tasks below 50 ms, so their absence supplies a 50 ms upper bound rather
than zero work. Baseline capacity-flush measurements are unavailable, not
zero-duration successes. Retain uncertain clock alignment rather than assigning
an ambiguous sample to a task.

The three unprofiled baselines must independently corroborate the slowdown:
each must contain a browser task over one second, and the same conservative
candidate task upper bound must be at least 90% smaller than each plain
baseline's longest task. These are whole-task comparisons; only the separate
profile supplies native reducer attribution. A slow profile alongside three
unaffected plain runs is `needs-evidence`, not proof of unprofiled improvement.

### Correctness and review gates

Require exact local, saved and peer text/selection; useful undo/redo groups;
pending-history undo; body/header/footer boundaries; active/final composition;
disconnect/reconnect without lost or duplicate replay; denied viewer and revoked
guest writes; and complete disposal of listeners. Existing remote-edit history
invalidation is a separate coordinate-safety policy and must not be weakened.
First attempts and failures remain evidence; a passing retry is not acceptance.

Two independent nonimplementing reviewers assess the same final committed SHA:
35 points scope/acceptance, 25 integrity/access, 20 regression/evidence, 10
CI/operations, and 10 maintainability/complexity. Each must score strictly above
95 and have no unresolved blocker. Any data loss, permission failure, unsupported
SDK patch, suppressed collaboration, cleared history used to hide work, missing
causal evidence, or failed budget blocks merge regardless of the numerical grade.

## Architecture choice

**Date/status:** 2026-10-27, implemented direction.
**Authority:** agent judgment after independent architecture/measurement review.

Native edits already update the local model before Spinel queues synchronization;
downloaded documents retain that queue in account-scoped IndexedDB. The diagnosed
freeze occurs in two synchronous SDK composition reducers on the browser thread.
Moving network or database work alone would not remove those reducers. Keep the
existing local-first/sync path and use the supported public native queue/flush
APIs to bound this specific work. No dependency upgrade, private-cache rewrite,
SDK patch, history clear or collaboration suppression is justified by the cause.

The proposed policy closes a native group when either public pending cache
reaches 64 state changes. The SDK still decides idle, undo, segment and IME
boundaries; its existing 300 ms debounce remains. Sixty-four changes keep the
original uninterrupted fixture within the native 50-group history capacity and
avoid one undo per character. The existing IME interceptor remains installed.
No extra timer or deferred work should survive access loss or editor disposal.

**Personas:** Owner and Collaborator gain bounded typing work with retained
content and comprehensible undo. Link guests get the same performance behavior
without additional authority or diagnostic collection. Operator retains the
existing sync/storage architecture and receives reproducible, bounded evidence
instead of another service or database.

## Implementation and verification checkpoint

The integration subscribes immediately after native capture is installed, before
awaiting rendering readiness. An independent source review identified that
installing later could leave an early writable editor unbounded; that gap was
repaired. The listener reads the two public cache lengths and calls the native
paired flush at 64 entries. It leaves the existing IME interceptor and all
mutation admission/sync paths in place. Remote emissions, other units and
`noHistory` composition intermediates do not create a new boundary. Disposal
unsubscribes; it neither flushes nor clears native state.

A group is a count of completed native state changes, not characters or grapheme
clusters. A paste or completed IME composition remains one native change. The
SDK's existing 50-group retention limit is unchanged; arbitrarily long continuous
writing now has finite undo chunks instead of one unbounded composition. This
ticket makes no universal latency promise for a single very large paste or every
possible document size.

The existing SPN-032 schema adds `doc-compose` for optional capacity-flush duration
histograms/counters. These aggregate observations use the existing verified
account lifetime and contain no content, key values or selections. Guests have
no sink. A missing, full or throwing observer does not affect native input.

### Reproducible browser comparison

The required CI job runs desktop and mobile on separate runners, and runs each
baseline/candidate pair sequentially on the same runner. Baseline application
source is immutable `a0c3154ae6b548d68ba8be9d143df781e47dc623`: current main plus
only read-only observation and this preregistered contract. Copy the current
`e2e/doc-responsiveness*.ts` and `playwright.config.ts` into that checkout; do not
copy application files or enable a runtime production bypass. Each preset runs
three unprofiled samples and one CPU-profile sample per source. The candidate
additionally runs mounted composition/cancellation and pending-guest-revocation
scenarios. Every attempt is retained with harness/lockfile hashes.

Each new paired job has a 40-minute execution allowance for two builds and the
fixed samples. Each individual measured case retains its five-minute deadline.
The baseline permits up to 120 seconds to observe the known native drain stall
under 4× CPU throttling; the candidate observation window is 30 seconds. These
are evidence-collection deadlines, not latency acceptance thresholds: the
candidate still must drain within the registered 1,000 ms budget. Existing
regression deadlines and all performance budgets remain unchanged.

```bash

  --project=doc-responsiveness --grep 'desktop sustained native typing'
# Candidate: enforce the registered budgets and all boundary cases.
SPN108_BASELINE=0 SPINEL_E2E_PROJECT=doc-responsiveness npx playwright test \
  --project=doc-responsiveness --grep 'desktop '
```

The comparator checks all four samples per source, a single immutable source SHA
per role, identical effective environments and workload hashes, completed
correctness assertions, raw-profile/clock-sidecar hashes and every registered
gate. Its focused tests reject missing samples, mixed sources, changed lockfiles,
tampered profiles, absent causal witnesses and an expensive profile sample hidden

Dependency changes require an explicit rebaseline: preserve this evidence,
