## Architecture choice

**Date/status:** 2026-10-27, implemented direction.
**Authority:** agent judgment after independent architecture/measurement review.

Native edits already update the local model before Spinel queues synchronization;
downloaded documents retain that queue in account-scoped IndexedDB. The diagnosed
freeze occurs in two synchronous SDK composition reducers on the browser thread.
Moving network or database work alone would not remove those reducers. Keep the
existing local-first/sync path and use the supported public native queue/flush
APIs to bound this specific work. No dependency upgrade, private-cache rewrite,
SDK patch, history clear or collaboration suppression is justified by the cause.

The policy closes a native group when either public pending cache reaches 32
state changes. A lifecycle-owned visible-frame check also flushes pending
completed changes after the same 300 ms quiet interval when native timers are
delayed. The SDK's existing timers, undo, segment and IME boundaries remain.
Docs configure the public constructor's
history retention to 100 groups, preserving all 66 groups of the original
uninterrupted fixture while avoiding one undo per character. This amends the
earlier 50-group implementation choice after both 64- and 44-state candidates
missed the fixed latency target, as recorded below. The existing IME interceptor remains installed.
No extra timer or deferred work should survive access loss or editor disposal.

**Personas:** Owner and Collaborator gain bounded typing work with retained
content and comprehensible undo. Link guests get the same performance behavior
without additional authority or diagnostic collection. Operator retains the
existing sync/storage architecture and receives reproducible, bounded evidence
instead of another service or database.

## Implementation and verification checkpoint

The integration subscribes immediately after native capture is installed, before
awaiting rendering readiness. An independent source review identified that
installing later could leave an early writable editor unbounded; that gap was
repaired. The listener reads the two public cache lengths and calls the native
paired flush at 32 entries. It leaves the existing IME interceptor and all
mutation admission/sync paths in place. Remote emissions, other units and
`noHistory` composition intermediates do not create a new boundary or postpone
the completed-state quiet deadline. While pending work exists, one owned frame
rechecks both queues; it stops when empty or hidden. Visibility can resume a live
policy, never a disposed one. Access fencing cancels it before any preserved-IME
early return. Disposal cancels, removes the visibility listener and unsubscribes;
it neither flushes nor clears native state.

A group is a count of completed native state changes, not characters or grapheme
clusters. A paste or completed IME composition remains one native change. The
SDK's public history-retention option is 100 for live Doc instances; native
eviction and the default settings of Sheets and confirmed/server replicas remain.
Arbitrarily long continuous writing has finite undo chunks instead of one
unbounded composition. The group count is not a retained-byte bound. This
ticket makes no universal latency promise for a single very large paste or every
possible document size.

The existing SPN-032 schema adds `doc-compose` for optional public paired-flush duration
histograms/counters. These aggregate observations use the existing verified
account lifetime and contain no content, key values or selections. Guests have
no sink. A missing, full or throwing observer does not affect native input.

### Browser-reported long-task duration correction

**Date/status:** 2026-10-27, after inspecting the rejected 44-state desktop raw
artifacts and before the next paired measurement.
**Authority:** agent judgment with independent measurement review.

Two unchanged `PerformanceObserver` entries report 49 ms, one in baseline plain
sample 1 and one in the candidate profile. The initial analyzer incorrectly
required every reported duration to be at least 50. The
[Long Tasks draft processing model](https://w3c.github.io/longtasks/#report-long-tasks)
applies the admission threshold before coarsening timestamps and truncating the
exposed duration to an integer. Validate finite nonnegative reported durations,
retain the raw entries unchanged and preserve all timing-window checks. Keep
`max(50, all candidate reported task durations)` as the conservative reporting
comparison, and retain all absolute/relative thresholds. This fixes interpretation
of browser evidence, not runtime behavior; it does not rescue the failed flush
budgets or retroactively accept this attempt.

The measured Chromium revision implements the same endpoint conversion and
integer-duration calculation in
[`Performance::AddLongTaskTiming`](https://github.com/chromium/chromium/blob/f842f52ef39fd97b449eb27cff414bf05a98ddce/third_party/blink/renderer/core/timing/performance.cc#L819-L838).

### CPU profile reader correction

**Date/status:** 2026-10-27, after the failed mobile baseline profile and desktop
candidate profile in run `40592509873`.
**Authority:** agent judgment with separate nonimplementing architecture and
measurement review; fresh complete pairs remain required.

The mobile profile contains 238,310 timestamp/sample pairs and one -1 microsecond
delta, which reverses two adjacent rendering samples. Every cumulative timestamp
is inside the original profile range, and the raw profile hash matches its clock
sidecar. The initial reader incorrectly rejected every negative delta.
[Chromium's profile reader](https://chromium.googlesource.com/devtools/devtools-frontend/+/9a696c4e723caa3c7e1f78886da353f1f06a79b0/front_end/core/sdk/CPUProfileDataModel.ts)
reconstructs cumulative timestamps and sorts them together with their samples.
The corrected reader follows that ordering in a derived copy, validates every
timestamp against the original start/end bounds, and reports negative-delta and
reordered-sample counts. It neither clamps nor drops samples nor changes the raw
profile bytes. Its preceding-interval weights are sampling estimates, not exact
CPU duration; the whole accounting interval plus the full browser-clock bracket
must still fit inside a task before that task supplies a causal witness.

The failed records remain incomplete and cannot become accepted retrospectively.
Workload, sample counts, timing budgets, hashes and causal gates are unchanged.
This only changes evidence interpretation: Operator gets a reproducible profile
reader; Owner, Collaborator and Link guest runtime behavior is unaffected.
