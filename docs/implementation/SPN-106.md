# SPN-106 — view-only Doc initialization

## Capability and decision checkpoint

2026-11-02 — implementation in progress, not accepted. Current main is
`18a8759c498574a1d9cc24a969a558cd97a798ed`. The pinned OSS Docs UI 1.1.0
dispatches `doc.command.refresh-header-footer-fields` with the document's unit ID
and `onOpen: true` when its current model first appears. The native permission
controller emits a denial before that command can determine that a viewer has
no editable fields. The original browser evidence is retained in SPN-075; fresh
viewer-startup verification remains required here.

The public `CommandService`, `ICommandService` and dependency override API expose
a boundary before command listeners and execution. Use a small subclass through
the existing grant binding: refuse only that exact initialization command for
the binding's current viewer grant and exact unit ID. Delegate all other commands
and mutations, including explicit field refresh and real edits, unchanged. A
refused initialization returns false and never changes document fields, native
permission points, notification delivery or collaboration credentials. No SDK
source patch, private controller replacement or notification suppression is needed.
Both synchronous and asynchronous public entry points retain this contract.

Public references: [dependency overrides](https://docs.univer.ai/zh-CN/blog/univer)
and the installed `@univerjs/core` public declarations for `CommandService`.
This is a proposed supported-boundary implementation; native permission controls
and real application startup must verify its wiring before acceptance.

Owner retains saved content, fields and sharing grants. Collaborator and Link
guest can read without a false warning while denied edits still produce truthful
feedback. Operator gains no document access or service. The existing binding's
live downgrade/upgrade state also governs initialization refusal. Internal editor
units and other commands keep their native behavior.

## Acceptance and landing status

removal and the generated backlog update for eventual landing only; no merge or
completion is claimed. Original scope remains plain and date-field-bearing Docs,
account and anonymous viewers, desktop/phone load and reload without warnings,
unchanged saved body/fields/grants, truthful genuine edit denials and revoked

main has no Redesign group to migrate. All four personas and sustainable testing
requirements above remain part of acceptance.
