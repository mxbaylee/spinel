# SPN-059 — Spinel sync cutover

## Retain the entire source through an explicit offline transition

**Date/status:** 2026-10-26, accepted implementation choice.
**Authority:** Agent judgment within the requested SPN-059 implementation and the
owner's pre-production retention rule. No live deployment or data deletion is
authorized or performed by this work.

The repository is pre-production. No production dataset or selected subset of
retained work has been supplied for this run. The transition therefore retains
**every document and every application-owned row** in its source database by
default, including trash, Spaces and their internal topology, deletion batches,
images, Formula definitions, grants, named checkpoints, restore generations and
ownership handover. Fresh disposable fixtures are tested separately.

Automatic conversion at application startup would require the old SDK and could
turn an ordinary restart into a long data operation. Rebuilding only visible
documents could lose recoverable work or exact-root access. Instead an explicit
offline tool makes a consistent source copy, materializes old collaboration units
through the pinned legacy SDK's public API, and imports them into a separate full
database copy. The original and its source copy remain available throughout.
Progress is restart-safe and tied to the exported source; the application refuses
an incomplete conversion. No source content is printed in progress logs.

The source and frozen recovery copy are opened read-only. After public snapshot
export, a separate metadata copy is sanitized through the old SDK's public
hard-delete API for every application-known legacy ID. A fresh public reader
confirms deletion, and application-table hashes must remain identical. Import
uses this sanitized copy, so later native permanent deletion cannot leave an old
collaboration snapshot behind. The original remains independently recoverable.
Unknown purge-only IDs block native activation until this verification completes;
a durable native-only activation marker permits ordinary interrupted native
cleanup on later restarts.

Pre-cutover trial instances could leave a native unit and an old SDK unit under
the same application ID. The sanitizer therefore probes every application-known
document, native unit, generation and purge ID through the public SDK, including
IDs whose active content is already native. All native-table hashes must remain
unchanged. Previously prepared databases without native-only activation or a
verified transition receipt require the explicit offline check once; a fresh
empty database still initializes normally.

Initial copies are written to disposable paths and published atomically only
after integrity checks. Per-unit receipts support interrupted import, and a
retry after publication re-verifies the exact output. It refuses a subsequently
edited or damaged output without overwriting it. Validation covers all retained
image resources, including opaque resources hidden by a name collision.

The Operator gets an inspectable, repeatable transition without new live service
dependencies. The Owner keeps all content and recovery metadata. Collaborators
keep existing grants and authored work. Link guests retain exact-root access and
revocation; migration does not create grants or widen credentials.

## Formula verification and headless calculation

**Date/status:** 2026-10-26, accepted implementation repair. **Authority:** Agent
judgment from integrated browser failures, within native cutover acceptance.

Native browser calculation writes scalar result caches into formula/shared-formula
cells without an authored edit. Comparing those caches against the authoritative
server snapshot caused false divergence and resync. Canonical verification now
omits only those computed scalar values, using the public formula/identity checks.
It retains formula identity, rich text, styles, array metadata and ordinary values.
Tests use a real browser-side native engine before acknowledgment and after reconnect,
with negative controls for actual authored changes.

The server's headless native model applies authored mutations and reference rewrites;
it does not calculate formulas. An IMAGE formula in a retained snapshot exposed
asynchronous browser-only work and crashed Node. Public formula-engine configuration
now disables background computation there while retaining formula services. A real
Node subprocess verifies initial and later IMAGE formulas, unchanged stored caches,
and ordinary edits without a DOM shim. Live editor calculation remains enabled.

The Doc soak's initial substring oracle also rejected valid inserts inside earlier
inserted text. Independent replay of the recorded edits matched both snapshots.
The repaired oracle uses unique characters per insertion and verifies exact inventory
and within-insertion order, allowing interleaving while detecting lost, duplicated,
replaced or reordered authored characters. Checkpoints still compare complete native
models and reject resync; Sheet checkpoints additionally verify computed values
through the live editor clipboard rather than an optional persisted formula cache.

## Scope reassessment after integrated validation

**Date/status:** 2026-10-26, accepted implementation boundary; final counted
size is recorded in the PR. Formatting and the two previously missed HTTP
regression ports brought the non-generated diff just above the 10,000-line soft
threshold. The additional browser verification exposed a formula-cache hash
defect that must be repaired before native activation can ship.

The retained-data transition, native-only activation, preserved access/history/
purge regressions and unsupported-menu checks form one acceptance boundary.
Landing activation without its transition or leaving legacy-only positive tests
would ship an unsafe or incompletely verified cutover. The formula hash repair
is also required for ordinary supported formula editing. Keep those repairs and
their direct evidence in SPN-059; there is no separate safe feature slice to
defer merely to reduce this count. Existing standalone library boundaries remain
unchanged. After SPN-075 landed, the owner explicitly brought the final dependency
cleanup and gate back into SPN-059; that small integration now completes the original
acceptance without the previously planned follow-up. The hard limit,
two independent reviews and every required CI gate still apply.
