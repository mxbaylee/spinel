# SPN-050 — Native Sheet fill controls

## Remove the duplicate entry point and retain stored semantics

2026-10-22 · accepted. Implements owner-approved ticket Rules and
[design #126](SPN-047.md#legacy-decision-126-approved-redesign-and-its-limits);
agent judgment for the minimal removal, no new palette decision.

Remove the separate `FillPresets` control, its application callback and obsolete
stories. Keep the native Univer fill picker, all sixteen palette constants,
profile color controls, and stored-preset display/edit interceptors unchanged.
The native picker already supports cell color edits. The separate eight-choice
enhancement was subsequently [retired as SPN-088](SPN-088.md#retain-native-colors-and-retire-the-extra-palette-proposal)
on 2026-10-23; it was never needed to remove the duplicate toolbar.

Owner and Collaborator gain editor space and keep existing document appearance.
Link guests retain view/edit permission boundaries without an extra toolbar.
Operator account capabilities are unaffected; fewer UI components need upkeep.
The shared `.fill-palette` styles remain because profiles use them.

Browser coverage seeds legacy pairs instead of clicking the removed toolbar, so
existing pixel, rich-text, formula, revision and theme-switch checks remain.
A native-picker regression applies colors in each theme, reloads, then opens the
same Sheet as a viewer and checks its disabled fill control. When run, the test
captures light/dark/phone screenshots. The approved native Sheet stories already
omit the duplicate toolbar; no new component or state is introduced.

Legacy color semantics remain [decision #66](SPN-027.md#legacy-decision-66-canonical-colors-and-appearance).
