## Legacy decision 113: Live authorized document formulas

**Recorded:** 2026-10-20. **Status:** accepted.
**Authority:** Owner expanded formula scope; agent safety semantics.
**Source:** [original decision #113](https://github.com/mxbaylee/spinel/issues/113).

**Question:** How should live formulas appear in Docs while preserving each source's access
boundary?

**Options considered in the original source:**

A — One native Formula object stores expression, stable source bindings and display format, with
viewer-specific results kept transient; B — persist rendered results in the document, which
simplifies offline viewing but leaks source values to readers without source access; C — only allow
calculations in Sheets, which misses the requested report workflow.

**Outcome, rationale and current boundary:**

Support scalar/range and cross-document array formulas with recognizable references and stable
source identity. Results are transient and viewer-specific: authorize every input before
evaluation/aggregation, never expose a partial aggregate, infer access from a target or persist
another viewer's authorized result into shared native content. Recheck sources and generations;
offline/export paths cannot reuse cached results as fresh authority. Guests cannot escape their
allowed scope. No implicit source grant or extra formula engine is authorized by the requested
product behavior.

The maintained [formula rules](../formulas.md) specify source binding, import and
copy behavior, transient results, resource bounds and native layout constraints.

**Persona tradeoffs recorded at the time:**

The Owner wants recognizable references and live report calculations; the Collaborator needs stable
references, ordinary editing and results only from sources they can read; the Link guest must not
gain access to another document through the host; the Operator needs bounded computation on the 2 GB
instance and no new licensed dependency.
