## 💾 Durable submission and access boundaries

Feedback uses its dedicated synchronous transaction with FULL SQLite synchronization and returns its receipt after COMMIT, separate from the lossy observations queue. Generation checking precedes duplicate lookup; exact actor/message/context matching prevents a changed payload from borrowing an existing receipt. Existing retries bypass admission without adding another row. Server-derived identity, persisted-session generation binding, verified current file/Space access, fixed route templates, exact request keys and account header checks preserve the intended boundary. The same persisted session can retry across process restart; explicit truncate fences resurrection.

The UI keeps an unconfirmed submission object for exact retry, locks its message/context after attempting it, preserves the draft in the current mounted view, and does not turn an unconfirmed response into success. Stale generation/session requires deliberate new submission. Guest and Operator submission are excluded; page context does not automatically attach titles, contents, secrets or raw URLs. Draft retention is intentionally view-local, not promised across navigation or sign-in.

## 📦 Paired snapshot and lifecycle

The worker first freezes the live SQLite source, checks its generation, derives inclusive min/max server receipt times from all retained rows attributed to the selected actor, and produces both complete filtered databases from that same source. New output databases avoid deleted-but-recoverable private rows in free pages. Raw-row equality and excluded raw-byte assertions in the real-SQLite tests materially support this choice. The system file intentionally includes every actor and unattributed rows within the same window; this is Operator-only, not an everyday-account export.

No-user-row returns empty rather than borrowing a system window. Feedback-only cases accurately disclose missing observations. Manifest counts, snapshot identity/watermark, build, retention and process-lifetime loss limits distinguish retained completeness from historical completeness. Pending SPN-110 expiry is simulated at this layer and explicitly remains a separate implementation-order integration obligation.

The one-job lease, bounded worker, disk admission, artifact caps, expiry and generation/session checks cover preparation and transfer. Cancellation/clear abort the owned worker or stream; cleanup failure keeps a cancelled lease occupied rather than silently allowing more staging. Streaming rechecks authority per chunk and retains a timeout through destination finalization. The direct controls for post-EOF stalled destination, revocation before another chunk, live abort, failed temporary removal, full-store reopen and a disconnected prepared JSON response are valuable and should remain selected.
