## 🔐 Routing, privacy and bounded observations

The `diagnostic_kind` input defaults to `driver` and is consumed only by the diagnostics job. `mode=diagnostics` excludes capability execution; the diagnostics lane has its own non-cancelling concurrency group and only checkout, Node setup, collector and artifact steps. It does not install/build/start a fixture or Local tunnel. Network selection constructs a single endpoint list containing `networklogs`, with one HTTPS GET to the validated 40-hex session under the fixed BrowserStack API origin. No allocation or WebDriver command exists on this path. Invalid kind fails before any request. Default two-driver-log behavior is unchanged.

The official [BrowserStack session API](https://www.browserstack.com/docs/automate/api-reference/selenium/session) documents `GET /automate/sessions/{session_id}/networklogs` returning HAR JSON. This establishes endpoint/schema authority, not availability of data for this particular session. Credentials remain solely in the HTTPS authorization header. Redirects and a different response URL are rejected. HTTP denial, empty/malformed/unsupported-version HAR and invalid UTF-8 fail with fixed public classifications and no alternate endpoint/session or retry.

Existing bounds remain **8 seconds per request, 30 seconds overall including journal writes, 1 MiB of response bytes**. Streaming byte counting enforces the ceiling even without Content-Length; initial failed persistence prevents GETs; the timer aborts fetch and cancellation is requested for an acquired reader. This is a small completed-response collector, not a native resource owner; it does not assert that an arbitrary noncooperative custom fetcher has synchronously settled when cancellation is requested. The production path uses native fetch. Shared tests cover stalled headers/body, empty chunks, deadlines, encoding, initial/final journal failure and response bounds.

Only up to **128 valid entries** survive as fixed metadata: entry index, fixture-host boolean, pathname SHA256, coarse kind/MIME, status and bounded/null timings and size. Raw URLs, query/fragment/userinfo, host strings, arbitrary headers/cookies/content, POST bodies, page titles, comments and remote error text are excluded. The report's `structure` contains only enums/counts, not parsed keys or values. A path hash is a correlation identifier, not a claim of cryptographic anonymization of guessable public paths; this does not expose raw private content. The current fixed synthetic fixture and deliberate field omission make the retained report proportionate.

Malformed entries and valid entries beyond the retention limit increment separate counts and set `network.complete=false`. `status=available` means the response was retrieved and interpreted, not that every entry was retained or the application worked. A valid empty HAR is available with zero observations, not proof that resources loaded. Negative/invalid/missing timing and body-size measurements become null; status zero remains zero. Even a syntactically complete network report retains `diagnosis=unclassified` and `capabilityAcceptance=not-assessed`. Consumers must preserve those distinctions; no code promotes HTTP 200, empty HAR, known MIME or unknown timings to a root-cause or phone pass.
