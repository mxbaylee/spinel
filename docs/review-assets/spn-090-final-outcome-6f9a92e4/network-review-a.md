## 🔐 Privacy and parser assessment

The new parser accepts only HAR 1.2 with an entries array. Entry admission requires object request/response, bounded URL length, an HTTP(S) URL and an integer status 0–599. It constructs fresh output objects rather than forwarding provider properties. Persisted fields are index, fixture-host boolean, pathname SHA256, a closed resource-kind/MIME classification, bounded finite durations and nonnegative safe-integer body size. Query/fragment/userinfo/host text, headers, cookies, request or response bodies, titles, arbitrary provider messages and extension properties are not copied. Existing structure summaries expose fixed shapes/counts, not raw strings. Invalid JSON has a fixed safe error code.

The 128-entry ceiling retains the first valid entries and separately counts malformed and omitted entries. Unknown/negative/overlong durations and invalid sizes become null; status zero remains zero and is not labeled a measured success or diagnosed cause. `complete` means the selected entry metadata had no malformed/omitted entry, not that the HAR records all browser traffic, validates every HAR field or proves successful application loading. Path hashes permit matching known resource paths; they are not a promise of irreversible anonymization of guessable paths. These limits are appropriate to the synthetic completed-session investigation.

Controls inspect privacy with secret-bearing URLs/body/header/cookie fields, valid empty versus invalid HAR, malformed/omitted counts, unknown timing and status zero, invalid selection, refusal, malformed response and oversized response. The existing bounded receiver checks bytes both through Content-Length and actual streamed chunks. No new raw HAR artifact or console path is introduced.
