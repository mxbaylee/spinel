1. **Name the measured graph precisely.** `web/main.tsx` imports the application, then sequentially awaits every `manifest.css` entry before `startApplication`. `vite.config.ts` constructs that CSS list from the whole offline shell, not the application's static JavaScript closure. Report the static JavaScript dependency closure as such, and separately expose the actual final descriptor's CSS and shell inventory plus bootstrap entry/HTML preload information where present. A graph of application JS alone is not the complete pre-render critical path. Dynamic-only chunks must remain outside that JS closure without implying that all their associated assets are deferred. Worker update preparation is another distinct path; do not label all offline inventory as startup fetches.

2. **Bind final archived bytes, not just hook-time observations.** Use `writeBundle` for its graph metadata, then enumerate/hash the contained final dist after the single `await build()` completes. Reconcile the final member set with the bundle metadata, explicitly account for any copied/non-bundle assets, and reject missing or changed declared members. Read and validate the actual emitted HTML descriptor against the emitted application entry, CSS and shell files. This matters because the existing plugin modifies the worker and HTML and emits installation assets. A hook-time graph file must not look terminal-successful if a later build hook fails. A small terminal result containing the original failure and available partial inventory is sufficient; a new collection framework is unnecessary.

3. **Make containment and incomplete-input behavior real.** Path-string validation is necessary but not sufficient if the file reader can follow a symlink outside dist. Either reject symlinks or verify real-path containment. Keep file/count/total-byte bounds and fail clearly on malformed metadata, missing import edges, absent/ambiguous entry, unsupported external edges or duplicate/conflicting members. Do not silently invent graph completeness. Bound reads before buffering unusually large files where feasible. Retain first failure even if final reporting also fails.

4. **Keep sizes and identity honest.** Record Node, Vite and the pinned bundler dependency identity through the lock/installed version, normal mode, the allowlisted evidence flag, exact Git head/tree/event-before and the config/script/source hashes. Do not serialize the whole environment. Module rendered lengths are metadata about emitted contribution, not independently additive transfer sizes or evaluation time. Label gzip totals as the sum of independently compressed files with recorded compression settings/runtime; they are not the observed CDN content encoding or historical HAR bytes. Normalize local absolute module paths without changing module identity or inventing source attribution.

5. **Use the lowest meaningful controls.** The proposed pure graph plus actual temporary-file tests are appropriate. Include CSS outside the application JS closure, exact final-member reconciliation, final-byte change/missing member, containment failure and descriptor mismatch in addition to static/dynamic edges, cycles, shared chunks and absent entry.
